## 2026-05-20 - [Orchestrator/Executor Concurrent Mutability Leak]
**Learning:** The Campaign Orchestrator iterates through inline JIT tasks to spawn them, but it schedules them to run concurrently via a wait group without utilizing `ExecuteAsync`. However, it first calls `SetSessionContext` directly on the shared `session.Executor` instance (which lacks thread-safe synchronization for this particular property during concurrent invocation) before each call. Because it uses the *same* executor, the last caller to set context poisons the context for all running tasks, leading to hallucinated file edits and context bleed. The system silently swallows this if the LLM makes a guess. This is an architectural invariant violation that normal unit testing won't catch because unit tests typically run sequential executions of a single task against the executor.
**Action:** When designing testing around multi-task concurrent components, ensure integration tests spin up the full pipeline under contention, explicitly validating that context data remains tied only to the task ID it was dispatched with, specifically testing thread contention at the configuration boundary.
