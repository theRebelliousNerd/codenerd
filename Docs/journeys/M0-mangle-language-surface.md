## 2. Data model and types

**Constant representation** — one struct for every value: `ast.Constant{Type ConstantType, Symbol string, NumValue int64, fst, snd *Constant}` (`ast/ast.go:257-280`). `ConstantType` enum (`ast/ast.go:227-252`): `NameType, StringType, BytesType, NumberType, Float64Type, TimeType, DurationType, PairShape, ListShape, MapShape, StructShape`.

- **Names** `/a/b`: `ast.Name` (`ast/ast.go:284-300`) requires leading `/`, non-empty parts, no `"`. Lexer `CONSTANT : '/' CONSTANT_CHAR+ ('/' CONSTANT_CHAR+)*` with `CONSTANT_CHAR = letter | digit | . - _ ~ %` (`parse/gen/Mangle.g4:186-187`). `NumValue` = FNV-64 of the symbol.
- **Numbers**: int64, `NUMBER : '-'? DIGIT+` (`Mangle.g4:168`); parse via `strconv.ParseInt(…,10,64)` (`parse/parse.go:486`) — overflow is a parse error.
- **Floats**: float64; `FLOAT` needs a dot or leading dot, optional exponent (`Mangle.g4:169-170`); stored as `math.Float64bits` in `NumValue` (`ast/ast.go:318`). **1 and 1.0 are different constants** (`Equals` compares `Type` first, `ast/ast.go:755`; probe R: `q(X) :- p(X), X = 1.0.` over `p(1)` derives nothing; probe X: `1 != 1.0` holds). **Integral floats do not round-trip through `String()`**: `FormatFloat64` is `strconv.FormatFloat(f, 'f', -1, 64)` (`ast/ast.go:92-94`), so `Float64(2.0).String()` is `"2"` and `1e21` prints as `"1000000000000000000000"`; re-parsing gives a `NumberType` constant that is *not* `Equals` to the original (probe T). Every surface that serialises with `String()` and re-parses — `SimpleColumn` (§9), `provenance.EmitFacts`, log lines, codeNERD's fact dumps — turns `2.0` into `2`.
- **Strings**: `"…"`, `'…'`, or backtick multi-line (`Mangle.g4:189-201`); escapes `\n \t \" \' \\ \xHH \u{…}` and `\<newline>` (`ast/serde.go:146-217`); `\xHH` ≥ 0x80 is rejected in strings but allowed in bytes (`ast/serde.go:180`); CR/CRLF normalised to LF in strings (`ast/serde.go:97,243`). Equality is byte equality (`ast/ast.go:763`).
- **Bytes**: `b"…"` (`Mangle.g4:190`); `ast.Bytes`; never equal to a string of the same bytes (type differs).
- **Time / Duration** (fork extension): `ast.Time(nanos)`, `ast.Duration(nanos)` (`ast/ast.go:324-332`); no source literal — `String()` renders them as `fn:time:parse_rfc3339("…")` / `fn:duration:parse("…")` so they round-trip through the parser (`ast/ast.go:582-585`). Only reachable via functions or temporal binding.
- **Pairs / tuples**: `fn:pair(a,b)`; `fn:tuple(a,b,c,…)` is right-nested pairs and `fn:tuple(x)` is `x` (`functional/functional.go:210-228`). Source has **no pair literal** — the spec's "no way to express a structured constant directly" (`docs/spec_datamodel.md:70-71`) holds only for pairs; lists/maps/structs do have literals.
- **Lists**: `[a, b]` → `ApplyFn{fn:list}` (`parse/parse.go:597-610`), evaluated to cons cells (`ListShape`, `fst`=head, `snd`=tail, `ListNil` sentinel; `ast/ast.go:344-381`). Equality is structural in order.
- **Maps**: `[k: v, …]` → `fn:map` (`parse/parse.go:564-578`); entries are sorted by **key hash** at construction (`ast.Map`, `ast/ast.go:384-404`) so equal maps have one representation. Empty map literal is not parseable (`[]` is a list); write `fn:map()` (`ast/ast.go:607`).
- **Structs**: `{ /label: v, … }` → `fn:struct` (`parse/parse.go:580-594`); labels must be name constants only at type-check time (`symbols/symbols.go:621`), the runtime `ast.Struct` accepts any constant key; sorted by label hash (`ast/ast.go:408-428`). Empty struct `{}` parses.
- **Tagged unions**: **a type, not a value** — `fn:TaggedUnion(/tag, /v1, fn:Struct(...), /v2, ...)` expands to `fn:Union(fn:Struct(/tag, fn:Singleton(/v1), ...), …)` (`symbols/typeexprs.go:174-197`). Values are ordinary structs carrying the tag field. Destructure with `:match_field`.
- **Option type**: `fn:Option(T)` and `fn:some(x)` exist as symbols (`symbols/symbols.go:196-197,296-299`) but `fn:some` has **no evaluation case** (`functional/functional.go#EvalApplyFn` falls to `EvalNumericApplyFn` → `unknown function`, `:978`) and the TODO at `symbols/symbols.go:298` says "Implement runtime representation". `fn:list:get` is typed as returning `Option(X)` (`builtin/builtin.go:92`) but returns the bare element or an **error** (`functional/functional.go:418-443`).
- **Booleans**: no bool type; `/true` and `/false` name constants (`ast/ast.go:82-83`); `BoolType()` is `Union(Singleton(/true), Singleton(/false))` (`symbols/typeexprs.go:122-124`).

**Type expressions** (bounds): base type constants `/any /bot /number /float64 /string /bytes /name /time /duration` (`ast/ast.go:72-84`; `/name`, `/time`, `/duration` are accepted by `hasBaseType` `symbols/symbols.go:537-556` but `IsBaseTypeExpression` `symbols/typeexprs.go:27-44` lists only any/bot/float64/number/string/bytes — `/name` passes `WellformedType` because any name constant does, `symbols/symbols.go:583`). Constructors `fn:List fn:Pair fn:Tuple(≥3) fn:Map fn:Struct(…, fn:opt(label,T)) fn:Union(≥1) fn:Singleton(name) fn:TaggedUnion fn:Option fn:Fun fn:Rel` (`symbols/symbols.go:321-335`); dot syntax `.List</number>` etc. (`Mangle.g4:103,183-184`; `parse/parse.go:633-659`). **A bare name constant is a type**: `/foo` as a bound means "names with prefix `/foo/`" (`hasBaseType` default branch `symbols/symbols.go:554`; conformance by string prefix `symbols/symbols.go:793`). Type variables (capitalised) are allowed in bounds and treated as `/any`-ish (`symbols/symbols.go:395-407`, TODO admits this is "wrong").

**Comparison and hashing** — `Constant.Equals` (`ast/ast.go:746-814`): type + `NumValue` (hash) must match, then payload; for numbers/floats/time/duration the hash *is* the value, so no collision issue; for strings/names/bytes the symbol is compared. `Constant.Hash()` = `NumValue` (`ast/ast.go:867`). Structured values hash by Szudzik pairing of child hashes shifted by shape (`ast/ast.go:823-839`). `Atom.Hash` = FNV over predicate name + arg hashes (`ast/ast.go:1317-1335`). Fact stores key facts by `Atom.Hash()` — `SimpleInMemoryStore` stores **one atom per hash** and does not compare on collision (`factstore/factstore.go:159-170`), `MultiIndexedArrayInMemoryStore` keeps a slice per hash and compares (`factstore/factstore.go:844-857`). **Collisions are real and cheap to hit** (probe 3, `C:/Temp/mangle-study/probe3/run2.txt`): `Number(n).Hash()` is `n` itself, `ListNil`, the empty struct and the empty map all hash to `0`, `Float64(0.0)` hashes to `0` too, and a one-element list `[1]` hashes to `65792` (`hashPair` shifts the head hash by the shape and Szudzik-pairs it, `ast/ast.go:823-839`). With `SimpleInMemoryStore`, `p(0). p([]).` keeps only `p(0)`; `p(65792). p([1]).` keeps only `p(65792)`; `p(0). p(0.0).` keeps only `p(0)`; `p({}). p([]).` keeps only `p({})` — the second fact is **silently dropped**, and derived facts follow. `MultiIndexedArrayInMemoryStore` keeps both in every case. codeNERD uses `SimpleInMemoryStore` for kernels under 1024 facts (`codeNERD/internal/core/kernel_eval.go:841-846`) and in `internal/mangle/engine.go:153-157`. There is no ordering relation on constants except numeric `< <= > >=` on int64 only (`builtin/builtin.go:263-299`; float comparison "TODO: support float64" `symbols/symbols.go:348`) and `:time:*`/`:duration:*`.

**Term shapes** (`ast/ast.go`): `Variable{Symbol}` (uppercase start or `_`), `Atom{PredicateSym{Symbol, Arity}, Args []BaseTerm}`, `NegAtom`, `Eq`, `Ineq`, `ApplyFn{FunctionSym{Symbol, Arity}, Args}`, `Clause{Head, HeadTime *Interval, Premises []Term, Transform *Transform}`, `Transform{Statements []TransformStmt{Var *Variable, Fn ApplyFn}, Next *Transform}`. Builtin predicates are those whose symbol starts with `:` (`ast/ast.go:910-912`); functions always start with `fn:`. `Package`/`Use` are modelled as pseudo-decls with predicate `Package`/`Use` (`symbols/symbols.go:317-319`).

## 3. Declarations

**Grammar** (`Mangle.g4:35-48`): `Decl <atom> ['temporal'] ['descr' '[' atoms ']'] ('bound' '[' terms ']')* ['inclusion' '[' atoms ']'] '.'` The declared atom's arguments must all be variables (`ast.NewDecl`, `ast/decl.go:445-450`; a parse error otherwise, `parse/parse.go:292-296`). Module decls: `Package name!`, `Use name!` (`Mangle.g4:27-33`); package names must be lowercase (`parse/parse.go:251`); a package prefixes every declared/defined predicate with `name.` and rewrites bound predicate names (`packages/packages.go:80-135,159-195`); referencing `other.pred` requires `Use other!` (`packages/packages.go:153-155`) — but an unprefixed unknown predicate is passed through (`:146-149` "transition stage" TODO).

**Descriptor atoms** (`ast/decl.go:22-55`): `doc(...)`, `arg(V, "...")`, `extensional()`, `external()`, `mode(...)`, `reflects(/prefix)`, `synthetic()`, `private()`, `name(...)`, `desugared()`, `fundep([..],[..])`, `merge([..], "pred")`, `deferred()`, `temporal()` (also via the `temporal` keyword, `parse/parse.go:280-282`), internal `internal:maybe_temporal`. Unknown descriptors are ignored (`analysis/declcheck.go:87-88`).

What `CheckDecl` enforces (`analysis/declcheck.go:38-101`): at most one `doc` atom, its args are strings; every `arg` names a declared variable, and — if any `arg` atom is present — **all** arguments must have one (`:94-96`: error "missing arg atoms" fires when some but not all are documented); `external()` requires exactly one `mode` (`:91-93`); each `bound` has exactly arity entries, each a well-formed bound (`:106-115`). Contrary to `docs/spec_decls.md:43-44` ("All arguments need to be described"), zero `arg` atoms is fine.

**Modes** (`ast/decl.go:134-214`): `mode("+","-","?")` — string constants, not bare `+` (the readthedocs form `mode(+, -)` at `readthedocs/declarations.md:144` does not lex; **discrepancy**). Multiple `mode` atoms allowed; `unifyModes` (`analysis/rulecheck.go:564-583`) merges them position-wise: if two modes disagree at a position the result is `?`. What the mode analysis enforces in `CheckRule` (`analysis/rulecheck.go:83-118`): for the **head**, input positions count as already bound; for a **body atom** of a moded predicate only output/`?` positions bind variables — so an unbound variable in an input position is an error "variable … is not bound". Builtin predicates have one fixed mode (`builtin/builtin.go:32-67`) checked by `Mode.Check` (`ast/decl.go:159-180`): an input position holding a free variable → "expected … to be constant or bound variable"; an output position holding a non-free term → "expected … to be a free variable". Order matters: "will not have a value yet; move the subgoal to the right" (`analysis/rulecheck.go:131`).

**`deferred()`**: the semi-naive engine never derives the predicate bottom-up (`engine/seminaivebottomup.go:739-741`) and evaluates each call top-down with `QueryContext.EvalQuery` using `decl.Modes()[0]` (`:850-852`; `engine/topdown.go:139-165`). `EvalQuery` binds head variables in input positions from the goal and runs the body left-to-right (`engine/topdown.go:40-78`). `docs/spec_decls.md:49-50` says a deferred predicate must have all positions input-only; the code does not check that (nothing in `declcheck.go`), and `mode("+","-")` works (probe DA: `dbl(X,Y) :- Y = fn:mult(X,2).` called from `q(Y) :- p(X), dbl(X,Y).` gives `q(6)`). **Four defects confirmed by probe 4** (`C:/Temp/mangle-study/probe4/`):
  1. **Stored facts of a deferred predicate are ignored.** `EvalQuery` iterates only `q.PredToRules[query.Predicate]` (`engine/topdown.go:41`) and never consults `q.Store` for the goal predicate, so `tag(1,/one). tag(2,/two).` under a `deferred()` decl yields nothing (probe DF), and a recursive definition with a base *fact* (`down(0,0).` + `down(X,Y) :- X > 0, X1 = fn:minus(X,1), down(X1,Y).`) returns nothing (probe DC). Base cases must be rules (`down(X, 0) :- X = 0.`).
  2. **No memoisation, no cycle guard, and the failure is fatal.** `loop(X,Y) :- loop(X,Y).` under `deferred()` recurses in Go until `runtime: goroutine stack exceeds 1000000000-byte limit / fatal error: stack overflow` (probe DD, `run3_recursive.txt`) — a `fatal error`, not a `panic`, so no `recover()` in the host can catch it; the process dies. `WithCreatedFactLimit` does not apply (nothing is created).
  3. **The callee shares the caller's variable namespace.** `EvalQuery` runs the callee body under the caller's `uf` (`engine/topdown.go:52-63`) without renaming, so a callee variable that happens to be bound in the caller is silently captured: `dbl(A,B) :- B = fn:mult(A,2).` called from `q(Z) :- p(X), r(B), dbl(X,Z).` yields nothing (probe DH), while the same program with `r(W)` yields `q(6)` (probe DI). Deferred rules must use variable names that no caller uses.
  4. **A head constant in an input position is not matched against the query** — `EvalQuery` only unifies head *variables* in input positions (`engine/topdown.go:44-48`) — and the mismatch is discovered later when the result is unified with the premise (`:153-156`), where `unifyTermsUpdate` returns `cannot unify 2 1` (`unionfind/unionfind.go:216-218`) and **aborts the whole evaluation** (probe DG). Probe DE only "worked" because the callee's `X` was captured by the caller's `X` (defect 3 masking defect 4).

**`external()`**: an `ExternalPredicateCallback` (`engine/seminaivebottomup.go:86-93`) must be registered for it (`WithExternalPredicates`) or, if registered for a non-external decl, evaluation fails at start (`:213-221`). Protocol (`engine/topdown.go:82-137`): if the store already has any matching fact, no call; else `ShouldQuery(inputs, filters, pushdown)`; else `ExecuteQuery` and each output tuple becomes a stored fact (constant filters applied post hoc). Pushdown: other body atoms mentioning the output variables, with the current substitution applied (`engine/seminaivebottomup.go:891-919`). Called from `oneStepEvalPremise` for every solution row (`:819-839`) — so once per binding of the input positions.

**`extensional()`**: rules with a body for the predicate are rejected when the decl came from `extraPredicates` (`analysis/validation.go:204-209`); facts are fine. Nothing else.

**`reflects(/prefix)`**: `p(X)` in a body is rewritten to `:match_prefix(X, /prefix)` when X is already bound or the mode says input (`analysis/rewriteclause.go:60-71`; note the `&&`/`||` precedence at `:66`).

**`fundep([Src],[Tgt])` + `merge([Tgt], "pred")`** (`ast/decl.go:268-357`): custom lattice. Engine support (`engine/seminaivebottomup.go:421-511`): exactly one fundep, **one target column** (`:450-452` "not implemented" otherwise); on merge of the delta, an existing fact with equal source columns is compared via the merge predicate evaluated top-down with mode `(+,+,-)`; the existing fact is `Remove`d if the store supports `FactStoreWithRemove` and the merged fact added. The merge predicate arity is computed as `2*len(tgt)+1` (`ast/decl.go:351`). `engine/map_lattice_test.go` exists (not read).

**Bounds and desugaring**: a bound entry may be a type expression or a **string** naming a unary predicate, e.g. `bound ["even", /number]` (`symbols/decldesugar.go:138-171`) — that is turned into a type bound (the unary predicate's own bound) plus an inclusion-constraint alternative `even(X)`; circular predicate bounds error "circular dependency" (`:72-88,148-149`). After desugaring every decl has a `desugared()` marker, one type bound per alternative, and `Constraints.Alternatives` (`:185-189`). `inclusion [atoms]` adds consequences (`ast/decl.go:404-437`). **The engine never checks inclusion constraints or bounds at runtime**: `engine.InclusionChecker.CheckFact` (`engine/inclusioncheck.go:53-109`) and `builtin.TypeChecker.CheckTypeBounds` (`builtin/builtin.go:760-774`) are host-callable utilities; grep shows no engine call site. Static bounds checking happens only if the host passes `analysis.ErrorForBoundsMismatch` (or `LogBoundsMismatch`, which computes and discards) to `AnalyzeAndCheckBounds` (`analysis/validation.go:370-381`); `AnalyzeOneUnit`/`Analyze` use `NoBoundsChecking` (`:77-84`). codeNERD calls `analysis.AnalyzeOneUnit` everywhere (`codeNERD/internal/core/kernel_eval.go:121`, `codeNERD/internal/mangle/engine.go:337`, `schema_validator.go:452`, `synth/compile.go:67`), so **declared bounds are documentation only in codeNERD** — no type is ever checked. The interpreter uses `ErrorForBoundsMismatch` (`interpreter/interpreter.go:202`).

**Synthetic decls**: any predicate used without a `Decl` gets one (`analysis/validation.go:232-252`): bounds all `/any`, marked `synthetic()`. So "all predicates need Decl before use" (root `CLAUDE.md` guardrail) is a codeNERD convention, not an engine rule; the engine rule is: a predicate defined by clauses in a source unit cannot also be in `extraPredicates` (`:204-213`), cannot be declared twice (`:173-175`), and a body predicate must be declared, defined, builtin, or extra (`analysis/rulecheck.go:394-421` — error lists available arities on an arity mismatch).

**EDB vs IDB** (`analysis/validation.go:293-351`): a predicate is IDB iff it is the head of some clause *with a body*; a predicate with both facts and rules is IDB. Everything else mentioned is EDB. `InitialFacts` are the bodiless clauses, evaluated once with `functional.EvalAtom` (so `p(fn:plus(1,2))` as a fact is legal and stores `p(3)`, `:324`).

**Temporal decls**: a predicate is temporal if declared so or if any clause head carries `@[...]` (`analysis/validation.go:133-151,263-278`); then every clause head must carry an annotation (`analysis/rulecheck.go:65-69`), and using it as a bare atom in a body is an error (`:110-115`); annotating a non-temporal predicate is an error (`:140-146`).

## 4. Rules

**Syntax** (`Mangle.g4:50-83`): `head [@[t1,t2]] (':-' | '⟸') body '.'`; body is `literalOrFml (',' literalOrFml)* ','?` then zero or more `|> transform`. A literal is `[temporalOp] term [@[...]] [(= | != | < | <= | > | >=) term]` or `'!' term`. Comments `#`. Trailing comma before `|>` or `.` is allowed. `⟸` is `\u27F8` (`Mangle.g4:126`).

**Comparisons**: `=` → `ast.Eq`, `!=` → `ast.Ineq`, `< <= > >=` → builtin atoms `:lt :le :gt :ge` (`parse/parse.go:451-466`). `:gt`/`:ge` exist in this fork (`symbols/symbols.go:49-53`) — `docs/spec_builtin_operations.md:5-10` lists only `< <=`. Numeric comparison is **int64 only**: a float operand is a runtime error "value … is not a number" (`builtin/builtin.go:624-633`) which **aborts the whole evaluation** (`engine/premise.go:32-35` returns the error; `engine/seminaivebottomup.go:747-750` propagates). Use `:time:lt` etc. for times, `:duration:lt` for durations; there is no float comparison predicate at all.

**Equality semantics**: `X = expr` unifies after evaluating any `fn:` on either side (`engine/premise.go:89-99`); a failed unification is a non-solution, not an error. `!=` succeeds iff unification fails (`:101-111`) — with an **unbound** variable on one side it always fails (unbound var unifies with anything). Both sides are compared as constants: `1 != 1.0` is true.

**Safety** (`analysis/rulecheck.go#CheckRule`): every variable in the head or body must be bound by (a) a positive non-builtin atom (non-input positions if moded), (b) `X = <const>` / `X = fn:...(bound vars)`, (c) an output/`?` position of a builtin, (d) union-find chains `X = Y` where the other side is bound, (e) for head variables, a `let` in the transform. Order of evaluation is left to right and binding must precede use for builtins and `fn:` calls; positive atoms are order-independent for safety but the engine evaluates them in written order (§7). Wildcards `_` are replaced by fresh `X0, X1…` in premises before checking (`analysis/rulecheck.go:56`; `ast/ast.go:1291-1305`) — but only in the *checked copy*; the engine sees `_`.

**Negation**: `!p(...)` on a user predicate or a builtin (builtin negation just inverts `Decide`, `engine/premise.go:64-73`). Evaluated against the **full store** `e.store` after the lower strata have reached fixpoint (`engine/seminaivebottomup.go:855-856`) — stratified/semipositive semantics. `RewriteClause` (`analysis/rewriteclause.go:36-119`) moves every negated atom to after the first point where all its variables are bound by positive atoms/equalities so left-to-right evaluation is sound. **The trap**: a negated atom whose variables never all bind is left in `delayNegAtom` and never appended (`:78-92`, loop end `:118`) — it is **silently removed from the rule**, and because `CheckRule` runs on the *rewritten* clause (`analysis/validation.go:300,319`), no "not bound" error is raised unless the variable also appears in the head. `_` counts as a variable named `_` here (`ast.AddVars` adds it, `ast/ast.go:1403-1404`), and it is "bound" only if an earlier positive atom in the same clause also contains a `_`. Hence:

- `q(X) :- p(X), !r(X, _, _).` → the `!r` literal is dropped; `q` = `p`. (This is the "wildcard negation does not exclude" gotcha in `MEMORY.md`.) **Confirmed empirically (probe A)**: `ProgramInfo.Rules` prints `q(X) :- p(X).` and `q` = `{q(1), q(2)}` although `r(1,/a,/b)` exists.
- `q(X) :- p(X, _), !r(X, _, _).` → `_` was "bound" by `p` as far as `RewriteClause` is concerned, so the literal survives the rewrite — and then **`CheckRule` rejects the rule**: it first calls `clause.ReplaceWildcards()` (`analysis/rulecheck.go:56`), which turns every `_` into a distinct fresh variable `X0, X1, X2` (`ast/ast.go:1291-1305`), adds every premise variable (negated atoms included) to `seenVars` (`:93`), and then fails the final loop with `variable X2 is not bound in q(X) :- p(X,X0), !r(X,X1,X2).` (`:226-246`). **[corrected 04:05]** The earlier claim that this form "does exclude correctly" was wrong: it never reaches the engine (probe B). So a wildcard inside a negation is either silently deleted (no earlier `_` in the clause) or a hard analysis error (an earlier `_` exists) — it is never evaluated. The engine's own wildcard handling (`unionfind.UnifyTermsExtend` skips `_`, `unionfind/unionfind.go:184-203`; `Matches` treats any variable as a wildcard, `factstore/factstore.go:377-384`) is only exercised by *positive* atoms and by projection rules such as `r1(X) :- r(X,_,_).`, which work (probe C: `q` = `{q(2)}`).
- `q(X) :- p(X), !r(X, Y).` with `Y` nowhere else → also silently dropped (probe D: `q` = `{q(1), q(2)}`). Unsafe negation is not rejected by this engine; it is deleted. The rejection path in `CheckRule` only fires for negations that *survive* the rewrite.
- `q(X, Y) :- p(X), !r(X, Y), s(Y).` → the rewrite moves the negation after `s(Y)` (`q(X,Y) :- p(X), s(Y), !r(X,Y).`) and it evaluates correctly (probe V). Binding order in the source does not matter for negation; only *whether* every variable is bound somewhere by a positive atom or equality does.
- Safe forms: negate only literals whose every argument is a bound variable or constant; project first (`r1(X) :- r(X,_,_). … !r1(X)`) exactly as the memory note says.

**Stratification** (`analysis/stratification.go`): dependency graph over IDB predicates; an edge is "negative" if the body literal is negated **or** the rule has a `do`-transform (recursion through aggregation is treated like negation, `:55-61`); SCCs via Kosaraju; any negative edge inside an SCC → "program cannot be stratified" (`:88-95`). Strata are topologically sorted (`:182-214`). Recursion through positive atoms and through `let`-transforms is allowed. EDB predicates never appear in the graph, so a negated EDB literal is always fine.

**Recursion through aggregation**: rejected as unstratifiable when the aggregated predicate depends on the aggregating one (e.g. `e(N) :- s(N).` with `s(N) :- e(X) |> do fn:group_by(), let N = fn:count().`). When no cycle, do-transforms run **once, after the stratum's fixpoint** (`engine/seminaivebottomup.go:617-659`) over the full store.

**Temporal literals** (fork): `p(X)@[S, E]` binds `S`/`E` to `/time` constants (`engine/temporal.go:437-460`) when the interval bounds are variables, filters by containment when concrete (`:117-127`); `<-[d1,d2] p(X)` / `[-[d1,d2] p(X)` / `<+[...]` / `[+[...]` are "sometime/always in past/future" relative to the evaluation time (`engine/temporal.go:158-243,333-433`); both bounds are required by the grammar for the *operators* (`Mangle.g4:87-90`); the `@[...]` *annotation* accepts one bound (a point, `@[2024-01-01T10:00:00]`) or two, and a bound may be `_` for unbounded (`Mangle.g4:54-64`; `VARIABLE : '_' | …`, `:178`). An unbounded end binds `E` to `2262-04-11T23:47:16.854775807Z` (`MaxInt64` nanos, probe TE); `now` is a bound token only (`parse/parse.go:842-845`), not a term — `:time:le(S, now)` is a parse error. A temporal head `p(X)@[T1,T2]` must have its variables bound in the body (transform-defined variables are not supported, `engine/seminaivebottomup.go:770-771`); `now` resolves to `evalTime`. Temporal literals need a temporal store or evaluation fails ("temporal literal encountered but no temporal store configured", `:870-872`). Mutual recursion through temporal predicates is a **hard error**; self-recursion and future operators in recursion are warnings/errors per `analysis/temporal.go:86-160`. Negated temporal literals (`!<-[...] p(X)`) are not representable: the parser wraps negation as `NegAtom{atom}` only when the term is a plain atom (`parse/parse.go:403-408`), so the `readthedocs/temporal.md:196` example `![-[30d, 30d] certified(...)` is a parse error — **confirmed** (probe AB: `extraneous input '[-'`).

**Head constants and repeated head variables**: allowed; `RectifyAtom` exists but is only used by the bounds inferencer (`analysis/rectify.go`); the engine applies the substitution to the head as written (`functional.EvalAtom(clause.Head, sol)`, `engine/seminaivebottomup.go:762`), so `fn:` calls in heads are also allowed and evaluated per solution.

## 6. Transforms and aggregation

**Syntax** (`Mangle.g4:67-78`): `body |> do fn:group_by(V1, …), let X = fn:reducer(...), let Y = fn:f(...)` or `body |> let X = fn:f(...), let Y = ...`. The grammar accepts several `|> …` segments and the parser chains them via `Transform.Next` (`parse/parse.go:352-361`), but `CheckRule` rejects any chain: "composing multiple transforms not implemented yet" (`analysis/rulecheck.go:258-260`). The `do` term must be an `fn:` application and only `fn:group_by` is dispatched (`engine/transformer.go:125-176`; any other `do` silently emits nothing).

**Rules enforced** (`analysis/rulecheck.go:210-308`): a transform needs a body; `let` variables must not redefine body variables; every variable used in a transform must appear in the clause or be let-defined earlier; in a `do` block every following statement is a `let`; a non-reducer `let` after `group_by` may only mention group-by variables or earlier `let` variables (the per-row variables are gone — "TODO: expose the rest of the bound variables as list values"); `group_by` args must be distinct variables; every head variable is either a group key or let-defined; reducers are forbidden in a plain `let` transform. `let _ = fn:...` is allowed (`:217-218`).

**Evaluation** — let-transforms run per solution row inside `oneStepEvalClause` (`engine/seminaivebottomup.go:788-807`, `engine/transformer.go:78-95`), so they participate in the semi-naive delta loop like ordinary rules. Do-transforms: the stratum is first rewritten so the aggregating rule has a single body atom over a fresh `<pred>N__tmp` predicate whose columns are the body's variables sorted by hash (`rewrite/rewrite.go:36-90`; `_` excluded); the helper rule is evaluated to fixpoint; **after** the fixpoint the aggregate runs once over all `__tmp` facts (`engine/seminaivebottomup.go:617-659`), grouping by an injective string key (`engine/transformer.go:103-113`), evaluating reducers per group and then plain `let`s, and `store.Add`ing each result. Because it runs after the fixpoint, aggregate outputs never feed rules in the same stratum (and stratification forbids that anyway). Naive engine: identical placement (`engine/naivebottomup.go:108-124`).

**Confirmed by probe**: a `let` after `group_by` that touches a per-row variable is rejected at analysis with `variable X in function fn:plus(X,1) must be either part of group_by or defined in the transform` (probe AI); a chained `|> let … |> do …` fails analysis — but with `variable S is not bound`, not the "composing multiple transforms" message: the parser chains segments through `Transform.Next` (`parse/parse.go:352-361`), yet `addTransformVars` (`analysis/rulecheck.go:355-367`) and `Transform.String()` (`ast/ast.go:1270-1286`) walk only the first segment's `Statements`, so a head variable defined in the second segment is "unbound" before the `Next != nil` check at `:258-260` is ever reached (probe N; the printed rule shows only the first segment); recursion through a `let`-transform is allowed and terminates on the guard (probe AK: `n(Y) :- n(X), X < 3 |> let Y = fn:plus(X,1).` gives `n(0..3)`); recursion through a `do`-transform is rejected as `stratification: program cannot be stratified` — raised by `Stratify` inside `EvalProgram`, i.e. **after** `AnalyzeOneUnit` succeeded (probe K); `fn:count()` over an empty relation derives no fact (probe J); a let-defined head variable works (probe Q: `q(2,4)`).

**Expressiveness limits**: no ordering, no `limit`/top-k, no windowing, no having-clause (write a second rule with `:lt` on the aggregate), no nested aggregation in one rule (use a helper predicate — each aggregation is its own stratum), no `distinct` on `count` (use `fn:collect_distinct` + `fn:list:len` in a second `let`, which *is* allowed because `let` after reducers may use let-defined variables), no aggregation over an empty group (a group needs ≥1 row; the zero case needs a negation rule, exactly as `readthedocs/aggregation.md:123-156` shows), no `min`/`max` over strings or names (int64/float64 only), no `argmax` (do `fn:max` then join back on the value). Group keys are compared by `Constant.String()` so a name and the string with the same text are distinct keys.

## 7. Evaluation

**Pipeline**: `parse.Unit` → `analysis.AnalyzeOneUnit/Analyze/AnalyzeAndCheckBounds` (→ `ProgramInfo`) → `analysis.Stratify` → `engine.EvalStratifiedProgramWithStats(pi, strata, predToStratum, store, opts…)` (`engine/seminaivebottomup.go:184-263`). `EvalProgram`/`EvalProgramWithStats` are marked Deprecated but just call `Stratify` for you (`:148-180`).

**Per stratum** (`engine/seminaivebottomup.go:265-327`): a fresh sub-engine over the shared `store` with its own `deltaStore` (`MultiIndexedArrayInMemoryStore`); `rewrite.Rewrite` splits do-transform rules; then `eval()` (`:513-661`):
1. First round: every non-do rule is evaluated by `oneStepEvalClause` against the full store; derived facts go to `deltaStore` (duplicates against the store are not filtered here — `Add` dedups within the delta).
2. If the delta is non-empty: build **delta rules** — for each rule and each positive non-builtin body atom whose predicate has a decl in this stratum's decl map, one copy with that atom prefixed `Δ` (`:349-419`). `mergeDelta` moves the delta into the store (merge predicates applied here). Loop: evaluate all delta rules (Δ-atoms read the *previous* delta, everything else reads the full store, `:841-848`), collect facts not already in store/delta into `newDeltaStore`, merge, swap, until no new fact. Facts derived by let-transforms are counted the same way.
3. Do-transforms once (see §6).

This is textbook semi-naive with the "one delta atom per rule copy" expansion; the cost per round is `Σ_rules Σ_deltaAtoms (join)`. Each join is nested-loop in written body order: `oneStepEvalClause` folds premises left to right, keeping a slice of `unionfind.UnionFind` solutions and cloning the map per extension (`:743-758`; `unionfind/unionfind.go:181`); premise lookup asks the store with the partially-substituted atom, so **selectivity comes entirely from which arguments are already bound when a premise is reached** — there is no join planner, no reordering, no sideways information passing beyond that. Put the most selective, most-bound atoms first.

**Fact stores and their costs** (`factstore/factstore.go`):
- `SimpleInMemoryStore`: `map[pred]map[hash]Atom`; `GetFacts` scans **all** facts of the predicate and filters with `Matches` (`:138-147`) — O(|pred|) per lookup regardless of bound args; `Contains` O(1) by hash; no hash-collision check.
- `IndexedInMemoryStore`: extra index on the first argument's hash (`:414-433`); lookups with a bound first argument are O(bucket).
- `MultiIndexedInMemoryStore` / `MultiIndexedArrayInMemoryStore`: index on **every** argument position (`:571-593`, `:760-784`); a lookup uses the first bound position it finds, left to right; the Array variant handles hash collisions and keeps a count; this is what the engine uses for deltas and `TeeingStore.Out` (`:373`, `engine/seminaivebottomup.go:236,310`). Memory: arity× copies of pointers per fact.
- `MergedStore` (many read stores + one write store), `TeeingStore` (base + out, `Add` returns true if the base already has it), `ConcurrentFactStore` (RWMutex wrapper — every `GetFacts` holds a read lock for the whole callback), `SimpleColumnStore` (read-only file; **every `GetFacts` re-reads the file from the start**, `factstore/simplecolumn.go:127-174`; zero indexing; filter applied while scanning).
- `TemporalStore`: per predicate → per atom-hash → AVL interval tree (`factstore/temporal.go:91-96`); `GetFactsAt/During` iterate every atom of the predicate and match args linearly, then query the tree (`:172-221`); 1000 intervals per atom by default (`:83`). The tree (`factstore/interval_tree.go`, read to end) is a standard AVL keyed by start time with a `maxEnd` augmentation: `Insert` O(log n) with rotations (`:48-85`, `:262-352`); `contains`/`findExact` searches both subtrees on equal starts (`:86-113`); `QueryPoint` (`:116-152`) and `QueryRange` (`:155-196`) prune on `maxEnd < start` and recurse right only when `nodeStart <= end`, so a lookup is O(log n + k) for k hits; bounds are **closed** on both ends (`containsTimestamp` uses `<=`, `:373-377`; overlap is `nodeStart <= end && start <= nodeEnd`); `±∞` bounds map to `MinInt64`/`MaxInt64` (`:342-370`); `All` is in-order (`:199-215`); `Rebuild` clears and re-inserts (used by coalescing, `:228-234`) — there is no delete. Intervals are not deduplicated at the tree level (**unverified** whether `Insert` rejects an exact duplicate; `Insert` returns a bool, `:48`).

codeNERD picks the store in `codeNERD/internal/core/kernel_eval.go:842-845` (`MultiIndexedArrayInMemoryStore` vs `SimpleInMemoryStore`) and wraps `SimpleInMemoryStore` in `ConcurrentFactStore` in `codeNERD/internal/mangle/engine.go:153-157`.

**Incremental / differential**: **none in the engine.** `explanation_derived_facts.md:30-43` says as much. There is no retraction, no DRed, no delta between evaluations; `FactStoreWithRemove.Remove` exists only for merge predicates. Re-evaluating the same `ProgramInfo` on a store that already holds derived facts is idempotent for positive rules (adds are set-adds) — that is the only "incremental" path — but stale derived facts from removed inputs survive, and negation-dependent facts can be wrong. codeNERD's `internal/mangle/differential.go` is a host-side scheme over repeated `EvalStratifiedProgramWithStats` calls (`codeNERD/internal/mangle/differential.go:464,516,703`), not an engine feature. Probe AN: evaluate `p(1). q(X) :- p(X).` on a store, then evaluate `Decl p(X). q(X) :- p(X).` (the fact removed from the program) on the *same* store — `q(1)` is still there, and so is `p(1)` (`InitialFacts` are merged into the store, never owned by the program).

**Limits**: `WithCreatedFactLimit(n)` checks (a) solutions per clause step (`:752-754`), (b) delta size per round (`:599-601`), (c) total store size vs `store.EstimateFactCount()+n` captured at start (`:222-224,607-609,808-810`); the error message says "fact size limit reached". There is no time or step budget; a `deferred` recursion or an external callback can run unbounded.

**Determinism**: map iteration order everywhere (rules per pred, strata members, group iteration); `WithDeterministicOrder()` sorts predicates within strata and delta-rule predicates (`:142-146,206-212,553-557`) but body-solution order and group order remain map-dependent (`engine/transformer.go:145`), which affects `fn:collect` order and `fn:collect_to_map` "first wins" only in the presence of hash-map iteration — `collect` iterates `rows` which come from `GetFacts` map iteration, so **list order from `fn:collect` is not stable across runs**.

**Errors abort everything**: any premise error (type error in a builtin, missing map key, division by zero, external callback error) unwinds through `oneStepEvalClause` → `eval` → `evalStrata` and the store is left **partially updated** (facts merged in earlier rounds/strata stay). There is no transactional rollback; the host must snapshot.

**Naive engine** (`engine/naivebottomup.go`): only for `SimpleInMemoryStore`, ignores errors, wrong wildcard negation (`:184-189` adds the substitution per non-unifying fact, i.e. *multiplies* solutions and wrongly succeeds when any fact fails to unify). Do not use.

## 8. Provenance

**Recorder hook** (`engine/recorder.go`): `DerivationRecorder{RuleFired(rule, head, subst, premiseFacts); LetEmit(rule, head, row, output); DoEmit(rule, head, groupKey, inputFacts, output)}`; installed with `WithDerivationRecorder(r)`; fired at `engine/seminaivebottomup.go:779-783` (plain rule, once per solution, delta rules normalised to the original rule text so IDs coincide, `:697-732`), `:795-801` (let/do inside a clause), `:649-651` (post-fixpoint do-transforms with the group's contributing facts). `premiseFacts` has one entry per body position; non-atom positions are zero atoms. Duplicate derivations of the same fact fire again (the engine does not know the fact is old at `RuleFired` time), so the recorder sees every alternative derivation in every round — memory grows with derivations, not facts.

**`provenance.MemoryRecorder`** (`provenance/recorder.go:54-126`): buffers `Event{Kind, Rule, Head, Subst, Row, PremiseFacts, GroupKey, InputFacts, Output, TransformText}` in arrival order and indexed by output hash; `Events()`, `EventsFor(atom)` are host-queryable.

**`BuildFromRecording(rec, store, goal, Options{MaxProofs, MaxDepth})`** (`provenance/recorder.go:128-362`): goal must be ground; memoised, cycle-cut DFS over events; premises recursed from `PremiseFacts`/`InputFacts`; negation re-checked as closed-world absence in the store (contradiction → `Partial`); let rows resolved by applying the row substitution to body atoms; do-aggregates list every contributing fact (sorted by proof ID). `Explain(programInfo, store, goal, opts)` (`provenance/provenance.go:144-167`) is the post-hoc backward chainer: skips rules with transforms, treats temporal premises as partial, needs `programInfo.EdbPredicates` to mark leaves.

**`ProofNode`** (`provenance/provenance.go:87-112`): `ID "/proof/<32hex>"` (content hash of rule ID + goal + sub-proof IDs; EDB leaves hash the fact; absence leaves `absence`+fact; partial nodes `/proof/partial/…`), `Fact`, `Kind ∈ {EDB, Derived, Absence, LetRow, DoAggregate}`, `Rule *Clause`, `RuleID "/rule/<32hex>"` (hash of `clause.String()`), `Bindings`, `Premises`, `GroupKey`, `TransformText`, `Partial`. `EmitFacts` (`provenance/facts.go:47-109`) writes the schema `proves/2 uses_rule/2 premise/3 edb_leaf/2 absence_leaf/2 binding/3 rule_source/2 uses_transform/2 group_key/3` with facts encoded as lists `[/pred, arg…]`, so a host can load the proof into a second Mangle program and reason about it. `Print` renders the tree.

**What a host can ask**: "why does ground fact F hold" (one or N alternative proofs, bounded depth), "which EDB facts support F" (walk leaves), "which rule fired with which bindings", "which input facts fed this aggregate and what was the group key", "is F merely stored" (EDB leaf), "was a negation load-bearing" (absence leaf). What it cannot ask: "why does F *not* hold" (no failed-rule witnessing, `docs/provenance.md:55-59`), anything about temporal intervals (partial), proofs for facts derived through `deferred`/external calls (recorder does not see top-down evaluation or `EvalExternalQuery` adds), or proofs across two evaluation runs (recorder is per run; codeNERD creates one per eval at `codeNERD/internal/core/kernel_eval.go:322-323` and reads it in `kernel_provenance.go:106`).

`mgwhy` (`cmd/mgwhy/main.go`): `-program -facts -mode simple|full -format tree|facts -max-proofs -max-depth GOAL`; loads a simplecolumn store into memory, analyses with synthetic decls for stored predicates, evaluates, explains. Not used by codeNERD.

## 9. Embedding API

The surface codeNERD sits on, in the order a host uses it:

1. **Parse**: `parse.Unit(io.Reader) (SourceUnit{Decls, Clauses}, error)`; `parse.Clause(string)`, `parse.Atom(string)`, `parse.Term`, `parse.BaseTerm`, `parse.LiteralOrFormula`, `parse.PredicateName` (`parse/parse.go:121-141,661-758`). Lexer/parser objects are pooled (`sync.Pool`, `:38-51`) — the ANTLR ATN prediction state is shared, which is why codeNERD serialises through `codeNERD/internal/mangle/parse_lock.go` (`ParseUnit`/`ParseAtom`). Errors are one string with `line:col message` per problem (`:143-152`).
2. **Analyse**: `analysis.AnalyzeOneUnit(unit, extraPredicates map[PredicateSym]Decl)` / `Analyze(units, extra)` / `AnalyzeAndCheckBounds(units, extra, mode)` → `*ProgramInfo{EdbPredicates, IdbPredicates, InitialFacts, InitialFactTimes, Rules, Decls, Warnings}` (`analysis/validation.go:42-59,76-154`). `extraPredicates` is how a host declares predicates whose facts it will assert (a synthetic decl from `ast.NewSyntheticDeclFromSym` is enough); the map is **mutated** (`:188` deletes overridden entries). `ProgramInfo.Rules` are the *rewritten* clauses (§4) — a host that wants to know what will actually run should print these, not the source.
3. **Stratify**: `analysis.Stratify(analysis.Program{Edb, Idb, Rules}) (strata []Nodeset, predToStratum, error)`.
4. **Facts**: any `factstore.FactStore` (`Add(Atom) bool`, `GetFacts(Atom, cb) error`, `Contains`, `ListPredicates`, `EstimateFactCount`, `Merge`); construct atoms with `ast.NewAtom("p", ast.String("x"), ast.Number(1), ast.Name("/n"))`. Facts in `programInfo.InitialFacts` are added by the engine at the start of every run (`engine/seminaivebottomup.go:268-285`). **Retract**: only `FactStoreWithRemove.Remove` on stores that implement it; the engine offers no retraction of consequences.
5. **Evaluate**: `engine.EvalStratifiedProgramWithStats(pi, strata, predToStratum, store, opts...) (Stats, error)` with options `WithCreatedFactLimit(n)`, `WithExternalPredicates(map[PredicateSym]ExternalPredicateCallback)`, `WithDerivationRecorder(r)`, `WithTemporalStore(ts)`, `WithEvaluationTime(t)`, `WithNowMarker()` (adds `__now(T)` **after** `evalStrata` returns, `engine/seminaivebottomup.go:251-258`, and `__now` cannot be lexed as a predicate name — `NAME` must start with a lowercase letter, `Mangle.g4:181` — so it is a marker for the host to read from the store, never a fact a rule can use; probe TE's first form was a parse error). `fn:time:now()` is wall-clock `time.Now()` (`functional/functional.go:488-489`) and ignores `WithEvaluationTime`; the only evaluation-time-relative constructs are the temporal operators and the `now` bound, `WithDeterministicOrder()` (`engine/seminaivebottomup.go:113-146`). `Stats{Strata [][]PredicateSym, Duration []time.Duration, PredToStratum}` is the only telemetry. The `predicateAllowList` option field exists but has no `With…` setter (`:99-100,157-160`) — unreachable.
6. **Query**: there is no query API beyond `store.GetFacts(ast.NewQuery(sym) | pattern atom, cb)`; for on-demand computation use a `deferred` predicate and `engine.QueryContext{PredToRules, PredToDecl, Store, ExternalPredicates}.EvalQuery(goal, mode, unionfind.New(), cb)` (`engine/topdown.go:28-78`) — this is usable by hosts directly for backward-chained questions without a full fixpoint (no memoisation).
7. **External / virtual predicates**: declare `Decl p(...) descr [external(), mode("+","-")]`, register a callback (§3). codeNERD does this in `codeNERD/internal/core/external_predicates.go:103-119` and forwards at `kernel_eval.go:334-341`; `kernel_eval.go:205` notes the differential engine does **not** forward them.
8. **Observe derivations**: recorder (§8). codeNERD: `kernel_provenance.go`.
9. **Persist**: `factstore.SimpleColumn{Deterministic}.WriteTo(store, w)` / `ReadInto(r, store)`; `NewSimpleColumnStoreFromBytes/GzipBytes/ZstdBytes` (`factstore/simplecolumn.go`). Constants are written with `String()` and re-parsed with `parse.BaseTerm` + `functional.EvalExpr` (`:323,362-367`) — time/duration survive via their `fn:` renderings, but **integral floats do not** (`2.0` is written as `2` and read back as the number `2`, §2) — a snapshot/restore cycle silently changes the type of every whole-valued float column. codeNERD's `internal/persist/factsnap` uses the gzip/zstd readers (`factsnap.go:314-320`) and therefore inherits this.
10. **Interpreter** (`interpreter.New(out, root, stats)`, `Load`, `Define`, `ParseQuery`, `Query`, `Pop`, `Preload`, `AddPostProcessor`): a checkpoint/rollback model built from `TeeingStore` layers — every load pushes a new teeing layer; `Pop` restores the previous store (`interpreter/interpreter.go:410-460`). This is the only rollback mechanism in the module and it is copyable by a host.
11. **Type utilities**: `builtin.NewTypeChecker(decls).CheckTypeBounds(fact)`, `engine.NewInclusionChecker(decls).CheckFact(fact, store)`, `symbols.NewSetHandle(typeExpr).HasType(c)` — runtime checks a host can apply on ingest since the engine never does.
12. **Data ingest**: `json2struct.JSONtoStruct`, `proto2struct.ProtoToStruct`.

Concurrency: nothing in the engine is goroutine-safe; `ConcurrentFactStore` only serialises store access. One evaluation per store at a time.

- Runtime silent behaviours (not TODOs, but limits): unsafe negation dropped (§4); `fn:` errors abort evaluation and leave the store partially updated (§7); no float comparison; int64 overflow wraps.

## 12. Notes for the designer

**Features that let a host derive instead of prompt** (push cognition out of the LLM window):

1. **Stratified negation over a closed world** is the executive primitive: "no `X` such that …" is a fact, not a judgement. It is sound because a stratum's negation reads the finished lower strata (§4). Design rule: every "should/may/must not" decision in the kernel is a negated literal whose arguments are all bound — never a wildcard, never a free variable (the engine will *delete* the guard, §4). Add a lint in codeNERD's analyzer gate that diffs `ProgramInfo.Rules` against the parsed clauses and refuses any rule that lost a `NegAtom` — that is a one-function check on `analysis.RewriteClause` output and would have caught the `!pred(X,_,_)` incident deterministically.
2. **`deferred` + `QueryContext.EvalQuery`** gives on-demand backward chaining without a fixpoint (§3, §9). This is the mechanism for "answer this question about the world model now" without materialising every derived fact — but at this commit it is **not production-safe**: no memoisation, a cycle is a fatal (unrecoverable) stack overflow, stored facts of the predicate are invisible, callee variables are captured by the caller's bindings, and a head constant in an input position aborts the run (§3, probes DC–DI). Use it only for non-recursive, rule-only, uniquely-named-variable question predicates, or wait for an engine fix. A host-side alternative with the same shape is an `external()` predicate whose Go callback runs a second, small `EvalStratifiedProgramWithStats` — that gets the fixpoint semantics and the fact limit.
3. **`external()` predicates with pushdown** (§3) are the sanctioned FFI: the kernel decides *when* to call Go (only when input positions are bound and no cached fact exists), Go returns tuples that become durable facts. Vector search, SQLite lookups, CodeDOM queries belong here, not in prompt text. Beware: results are cached forever in the store (any matching fact suppresses future calls, `engine/topdown.go:84-93`), so an external predicate that depends on mutable state needs an explicit version/revision argument in its input positions.
4. **Merge predicates (custom lattices)** (§3) let the kernel keep *one* best fact per key — shortest path, latest revision, highest-confidence classification — and retract the loser. This is the only in-engine retraction and it is exactly the "stale evidence must not survive a source change" requirement in the north star: key the fact on `(target, revision)` with a merge predicate preferring the newer revision. Limit: one target column.
5. **Aggregation after fixpoint** (§6) is how counts/limits/budgets become facts (`count_of_open_obligations`, `tool_calls_this_task`) that rules can then compare with `:lt`. Two-rule idiom for zero-cases.
6. **Provenance recorder** (§8): every kernel verdict can carry a proof DAG with rule IDs and bindings; `EmitFacts` lets a *second* program reason about proofs (e.g. "which policies were load-bearing for this refusal"). Because IDs are content hashes, proofs are stable across runs and can be persisted/diffed.
7. **Temporal facts** (fork extension, §4): validity intervals plus `<-`/`[-` operators are a native way to express "the file hash was X at revision time T" and "has the test been green continuously for 7 days". Requires a temporal store and careful use of `now`; Allen predicates need pairs of numbers, so bridge with `fn:time:to_unix_nanos` and `fn:pair` — **verified** (probe TB derives `before(/one,/two)`; probe TC, the docs form `:interval:before(E1, S2)` on bound time variables, aborts with `expected pair for interval, got 5`). `<-[0d, 7d] login(U)` with `WithEvaluationTime` works (probe TD); `<-[0d, 0d]` selects facts valid *at* the evaluation time (probe TE). `fn:time:sub` + `fn:duration:parse('10m')` + `:duration:le` works on point annotations (probe TA).
8. **Type bounds and inclusion constraints** exist but only bite if the host opts in (`ErrorForBoundsMismatch`, `TypeChecker`, `InclusionChecker`). Turning `AnalyzeOneUnit` into `AnalyzeAndCheckBounds(…, ErrorForBoundsMismatch)` in codeNERD would make the `Decl`-contract mismatches from `internal/mangle/agents.md` (wrong identifier *shape*) at least partially static — a `/name` vs `/string` column mismatch is caught; same-type wrong-content is not.
9. **Structured values** (lists/maps/structs with `:match_*` and `fn:*:get`) allow one fact to carry a whole record; combine with `json2struct` for tool results. The tagged-union type makes the shape checkable.

**Traps** (things that silently produce wrong or no facts):

- Unsafe negation is deleted, not rejected (§4) — unless an earlier `_` exists in the same clause, in which case it is rejected with a confusing `X2 is not bound` (probe B). Wildcards inside negation are the common case; the only safe negation is over a projection predicate whose arguments are all bound.
- `SimpleInMemoryStore` (codeNERD's choice below 1024 facts, `kernel_eval.go:841-846`) loses facts on hash collision: `0` vs `[]` vs `{}` vs `0.0`, `65792` vs `[1]` (§2). Any predicate that mixes a numeric column with a list/struct/map column in the same position — or that legitimately stores both `0` and `0.0` — is corrupt on that store. Use `MultiIndexedArrayInMemoryStore` unconditionally, or add a collision-checking store.
- Whole-valued floats become integers on every text round-trip (§2/§9): a `confidence` column that is sometimes `1.0` will join as `1` after a snapshot restore and fail to unify with `1.0` computed at runtime.
- `1` vs `1.0`, `"a"` vs `/a`, `b"x"` vs `"x"` are all distinct constants; joins across a producer/consumer type mismatch are empty forever, with no error (this is the `agents.md` "Decl is a contract" failure class, and bounds checking is off).
- No float comparison; `X < 2` with a float `X` aborts evaluation; `fn:max` on floats aborts.
- Any `fn:` runtime error aborts the whole evaluation and leaves the store partially merged (§7). `fn:map:get`/`fn:struct:get`/`fn:list:get` on a missing key are errors — guard with `:match_entry`/`:match_field`/`:list:member` instead.
- `fn:collect` order is map-iteration order — never rely on it; `fn:collect_to_map` "first wins" is nondeterministic.
- Do-transforms run after fixpoint and only once; a group needs ≥1 row.
- `fn:count_distinct`, `fn:map:get`, `fn:pick_any`, `fn:some`, `fn:pair:fst/snd` do not work (all probed except `fn:some`/`fn:pair:*`, which have no evaluator/symbol respectively).
- One transform per rule; no ordering, no limit.
- Join cost is nested loops in written order over hash buckets (or a full predicate scan on `SimpleInMemoryStore`); a wide join with the selective atom last is quadratic+. Put bound atoms first; keep `MultiIndexedArrayInMemoryStore`.
- External-predicate results are cached forever per input tuple.
- `deferred` predicates: cycles kill the process (`fatal error: stack overflow`, not a panic); facts are ignored; variable names leak across the call (§3).
- `fn:time:now()` breaks determinism and disagrees with `WithEvaluationTime`; never use it in a rule whose output is persisted. Temporal operators (`<-[..]`) and the `now` bound are the evaluation-time-relative primitives.
- No retraction; a fact store that outlives a source change carries stale derivations. The only host-usable rollback is the `TeeingStore` checkpoint stack.
- `predicateAllowList` and `extraFunctions` look like extension points and are not.
- Everything under `readthedocs/temporal.md` should be treated as aspirational until each construct is tested against the grammar (§11).
- The parser pool is not concurrency-safe (codeNERD already serialises).

1. **§3 "`external()` … Called from `oneStepEvalPremise` for every solution row (`:819-839`) — so once per binding of the input positions." — refuted (M3 item 12, §3 row 21).** Corrected claim: the premise atom is handed to `EvalExternalQuery` **unsubstituted** (`engine/seminaivebottomup.go:831` passes `p`, not `premiseAtom(p, lookupFn, subst)` as the store lookup at `:851` does), and `EvalExternalQuery` does `arg.(ast.Constant)` on every input position (`engine/topdown.go:99`). Consequences: (a) a *variable* in an input position — even one bound earlier in the rule — is a runtime panic, `interface conversion: ast.BaseTerm is ast.Variable, not ast.Constant` (M2 §2 defect E1; `extA_min.mg`, `v_ext_plus_var.mg`); (b) a *constant* input tuple is called once per evaluation when the callback returns at least one row, because the store cache at `topdown.go:84-93` short-circuits on any matching stored fact (`v_ext_plus_const.mg`: three premise evaluations, one call); (c) when the callback returns **no rows** the cache never engages and the callback runs on every premise evaluation — one call per solution row of everything to its left, per delta round (`v_ext_empty.mg`: 6 calls for two rules over three `p` rows; M3 engine surprise 1). The one-line upstream fix is `p = p.ApplySubst(subst).(ast.Atom)` before `:831` (`ast.Atom.ApplySubst`, `ast/ast.go:1023`). Host-side mitigations for (c), both verified on a forked harness (`m2v2/harness/mgv2.exe`, `m2v2/ext_sentinel.mg`): a callback whose `ShouldQuery` returns `false` after its first call in an evaluation (1 call), or a sentinel row that the consuming rule filters out (1 call). Also §3 "an unbound variable in an input position is an error" (probe AE) holds only when *no* positive atom anywhere in the body binds the variable: `q(X,Y) :- dbl_ext(X,Y), p(X).` with the moded external written **before** its binder passes `AnalyzeOneUnit` and panics identically (`v_ext_plus_first.mg`; M3 engine surprise 2) — safety treats positive atoms as order-independent (§4) and does not check the written order of moded user predicates, only of builtins.

2. **§3 same paragraph, "constant filters applied post hoc" — holds, sharpen (M3 engine surprise 3).** A constant in an *output* position of an all-output external is part of the cache key: rows that do not match it are discarded, not stored (`engine/topdown.go:119-133`), so two rules with two different constants each call the external and neither reuses the other's table (`v_ext_filter.mg`: `old(A) :- recall_similar_all(_, "rev-16", A, _)` and `cur(A) :- … "rev-17" …` → two calls with filters `[_ "rev-17" A _]` and `[_ "rev-16" A _]`). A join through a variable (M2 §2 rule 2) fetches the table once.

3. **§6 "a fresh `<pred>N__tmp` predicate whose columns are the body's variables sorted by hash (`rewrite/rewrite.go:36-90`; `_` excluded)" — holds with changes (M3 item 5, §3 row 22, engine surprise 4).** The `__tmp` rewrite — and therefore the `_` exclusion — happens **only for multi-atom bodies**: `rewrite.Rewrite` leaves a clause alone when its body is a single atom (`rewrite/rewrite.go:40`, `isSingleAtomPremise`), so the reducer then runs over the stored facts with the wildcard column still present. `v_agg_wildcard.mg` with `p(1,/a). p(1,/b). p(2,/c). q(1). q(2).`: `c1(N) :- p(X, _) |> do fn:group_by(), let N = fn:count().` gives `c1(3)` (counts facts), `c2(N) :- p(X, _), q(X) |> …` gives `c2(2)` (the `__tmp` relation is over the named variables only — `X` — and dedups before the aggregate), `c3` with `Y` named gives 3, `c4(N) :- p(X, _), q(_) |> …` gives 2. Adding a second atom to an aggregation body silently changes "count facts" into "count distinct named variables". Corpus rule: never put `_` in the body of a `do`-transform rule; name every column; project first if a count over distinct keys is wanted.

4. **§7 "the order of `fn:collect` is map-iteration order" — holds, extend (M3 engine surprise 5).** `fn:collect` also keeps **duplicates**: one list entry per input row, not per distinct value (`v_patternB_collect.mg`: `[/knowledge_hit, /knowledge_hit, /knowledge_hit]` from three candidate rows with the same reason). `fn:collect_distinct` is the set; the order half is confirmed (3 of 8 runs without `WithDeterministicOrder` flipped a two-element list).

5. **§8 "content-hashed `/rule/…` IDs" — holds, sharpen (M3 item 14, engine surprise 6).** The recorded `rule_source` text and the `/rule/<hash>` are of the **analysed, rewritten clause** (`Clause.String()` after `RewriteClause` and the do-transform rewrite), not the source text: negations are moved after their binders (`v_prov_reorder.mg`: `q(X, Y) :- p(X), !r(X, Y), s(Y).` is recorded as `q(X,Y) :- p(X), s(Y), !r(X,Y).` and `!r` is premise index 2, not 1), comparisons are spelled `:ge(Score,Min)` / `:le(Tie,B)`, whitespace is normalised, and an aggregation over a multi-atom body is recorded as two rules (`tie_sum(A,P,S) :- tie_sum1__tmp(...) |> do …` plus the `__tmp` rule; `m2v2/provB_v2.txt`). A string containing a quote round-trips escaped (`v_prov_quote.mg`). Consequence: the hash is stable under cosmetic edits but `nerd why` cannot print a rule the user can grep verbatim in the `.mg` file, and premise indexes follow the rewritten order.

6. **§8 proofs — extend (M3 engine surprise 7; M2 R1 and new R2).** A wildcard in a positive premise drops that premise's sub-proof and every leaf under it, transitively (`v_patternF_B.mg`: `built_before`, `compile_shard`, `prompt_atom` all absent from the first-draft `inject` proof). Separately, a **comparison builtin premise marks the node `[partial]` without dropping any leaf**: `q(X) :- p(X), X > 1.` proves `q(2)` `[partial]` with `p(2)` as its `edb_leaf` (`m2v2/prov_builtin.mg`, `m2v2/prov_fn.mg`), because `provenance/recorder.go:233-241` marks any `ast.Atom` premise with no recorded premise fact partial and continues, while `Eq`/`Ineq` premises are "satisfied by construction" (`:264-265`). `[partial]` therefore does not mean "leaves lost"; count `edb_leaf` rows against the positive premises to tell.

7. **§7 / §12 "no retraction … stale derived facts from removed inputs survive, and negation-dependent facts can be wrong" — holds, sharpen (M3 item 23, §3 row 19).** The concrete mechanism: evaluating `p(1). p(2). q(X) :- p(X).` and then, on the **same** store, `p(3). q(X) :- p(X), X != 1. s(X) :- p(X), !q(X).` (`m0_AN1.mg`, `-reeval m0_AN2.mg`) leaves `q(1)` in the store although the second program cannot derive it, **and `s(1)` is not derived** because the stale `q(1)` satisfies `!q(X)`. A stale positive fact silently defeats a negation in the next program. Any host that re-evaluates on a retained store — codeNERD's differential path, `internal/mangle/differential.go` — must clear IDB predicates first or be tested against exactly this program (**unverified** for codeNERD; M3 open item (d)).
