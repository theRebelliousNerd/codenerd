# Vision — the context economy

> Sections marked **BUILT** describe `internal/broker` as it ships today.
> Sections marked **PROPOSED** are design intent with no implementation and no
> claimed performance benefit. Current truth lives in
> [02-CURRENT-STATE.md](02-CURRENT-STATE.md).

## Thesis

> The agent's memory is a derived task state. The transcript is evidence. The
> prompt is a disposable, provider-specific execution plan.

Everything in this corpus follows from taking that seriously.

A conventional coding agent treats the conversation transcript as its memory. It
replays the transcript to the model, and when the transcript grows too large it
asks another model to write a shorter transcript. That design has three problems
and codeNERD has all three.

**Chronology is the wrong index.** What the model needs to act correctly is not
"what happened in order" but "what is currently believed, required, unresolved,
contradicted, and verified." A transcript is an audit trail. Using it as working
memory means the agent re-reads its own false starts every turn.

**Prose is a lossy and inert compression target.** Summarising "I fixed the null
pointer in auth.go by adding a nil check on line 42" into shorter English keeps
the least useful property of the sentence. Compressing it into
`fix_applied(/auth.go, /null_pointer, 42).` keeps a fact the kernel can join,
negate, and reason over. codeNERD already made this leap in
`internal/context` — it is the strongest thing in the existing design.

**Nobody is holding the meter.** Every subsystem estimates its own costs with its
own ruler, and no subsystem can see the total. This is the problem the shipped
part of this corpus solves, because it is the prerequisite for every other
improvement being provable rather than merely plausible.

## Strategic goals

### Goal B1 — One meter (**BUILT**)

Every inference call in the process passes one admission and accounting
boundary, and the number that boundary reports comes from the provider rather
than from a constant.

Success means: there is exactly one implementation of "how many tokens is this",
every LLM call is charged to one ledger, and the cost of any turn can be
attributed to the component that spent it. This closes gaps B1, B2 and B3.

The reason this is first and not last is not tidiness. A learned or economic
optimizer built on a broken meter does not merely fail to improve things — it
actively discovers and exploits the measurement bug, and reports excellent
numbers while doing so. Instrument first, optimize second, in that order, always.

### Goal B2 — Truthful counts with declared confidence (**BUILT**)

A token count must either be exact or must say how confident it is. Silent
estimation is how a system ends up running a 200,000-token budget with a ruler
that is wrong by twenty percent.

Where a provider offers a counting endpoint, use it. Where it does not, predict,
then compare the prediction to the provider's reported actual and correct the
model. Report which of the three regimes produced any given number.

### Goal B3 — No parallel systems (**BUILT**)

A replacement that leaves the thing it replaces in place is not a replacement.
The heuristic counter, the competing reserve arithmetic, and the orphan
`maxTokens` constants are deleted, not deprecated. Breaking changes are
preferred to a second way of doing the same thing.

### Goal B4 — The manifest is an input, not a report (**BUILT** in narrow form)

The broker cannot emit a request whose cost it has not attributed. The `Receipt`
is produced by the same pass that assembles and dispatches the request, so it
cannot drift from what was actually sent. An audit artifact generated separately
from the thing it audits always drifts; one generated by the same pass cannot.

Today the receipt attributes tokens by segment and records estimate versus
actual. It does not yet explain *why* each segment's content was selected — that
requires the task graph in Goal B6.

### Goal B5 — Obligation-driven selection (**PROPOSED**)

Relevance ranking asks "which atoms look like the current message." The better
question is "what must remain available to perform the next action correctly and
eventually prove the user's request was satisfied."

A constraint like "the public API must not change" has near-zero lexical overlap
with a discussion full of channel and goroutine terminology, and a similarity
ranker will drop it at exactly the moment it matters most. Selection should walk
backward from live obligations through typed dependencies, not forward from
cosine distance.

This requires typed edges the fact store does not currently carry:
`supports`, `contradicts`, `supersedes`, `depends_on`, `satisfies`, `invalidates`.
In a Datalog kernel those are one-line declarations, which is why codeNERD is
unusually well-placed to do this and has not yet.

### Goal B6 — Provenance, and the distinction agreement cannot make (**PROPOSED**)

If three specialists reach the same conclusion by reading the same source span,
that is one piece of evidence, not three. Every ensemble and voting system in
production today counts it as three, which is how confidence gets laundered.

With provenance edges in the graph, independent corroboration becomes a derived
predicate: count distinct evidence roots, not distinct agents. This is the single
capability in this corpus that a similarity-based pipeline structurally cannot
replicate, and it falls out of the substrate codeNERD already runs.

### Goal B7 — Economic layout transitions (**PROPOSED**, gated)

Reorganising a request improves relevance and destroys prefix-cache reuse.
Whether that trade pays is arithmetic, not taste: with a cache-write penalty and
a cached-read discount, replacing a warm N-token region with a smaller M-token
region breaks even after a computable number of calls.

Two things make this dangerous to build early. The break-even depends on the
ratio between write penalty and read discount, which differs per provider, so it
must be a property of a provider profile rather than a constant. And it is a bet
on task length: if the median epoch is shorter than the break-even, the rebuild
never pays and the machinery is dead weight.

Gate: the calls-per-epoch histogram, from real sessions, measured by the broker.
See [13-ROADMAP-AND-GATES.md](13-ROADMAP-AND-GATES.md).

### Goal B8 — Selective lanes, not a committee (**PROPOSED**, gated)

Several persistent contexts, each activated only when it can contribute
something necessary, is a different proposition from three agents answering every
message. The second one just multiplies the bill.

The honest control on this idea is severe: if the single-agent compiler already
selects only the relevant material, partitioning provides no token advantage at
all, and lanes must earn their keep through continuity, reduced re-investigation,
parallelism, or independent verification. Those need separate measurement.

codeNERD already has subagents, a spawner, and campaign orchestration. The
question that must be answered before building lanes is not "should we have
lanes" but "why did the multi-agent structure we already have degenerate into
context-starved one-shots?" The answer appears to be that with no shared task
state, every spawn had to be handed a prose blob, and prose blobs get capped.
Lanes without the graph from Goal B5 are subagents with better branding.

## Guiding principles

1. **Instrument before you optimize.** An optimizer on a broken meter exploits
   the meter.
2. **Exactness where available, declared confidence everywhere else.** Never
   report an estimate as if it were a measurement.
3. **One implementation per concept.** Two token counters is worse than either
   counter alone, because now nobody knows which is authoritative.
4. **Count at the outbound boundary.** Whatever a subsystem believed it was
   sending is not evidence about what was sent.
5. **Fail closed.** A budget that cannot be checked is a budget that is not
   enforced; refuse rather than proceed uncounted.
6. **Correctness outranks economy.** A stale precondition or a changed
   requirement forces the expensive path regardless of what it costs.
7. **Receipts observe, they never authorize.** Telemetry explains a decision; it
   never becomes executive truth.

## Non-goals

- Replacing the Mangle kernel's authority over permitted actions. The broker
  meters spend; `permitted/3` decides effects.
- Moving prompt compilation, context compression, or provider wire formats into
  `internal/broker`.
- Guessing at token counts when a provider endpoint exists.
- Shipping an economic optimizer, a lane router, or an epoch controller before
  the measurements that would justify them exist.
- Non-prefix KV reuse (CacheBlend, KVFlow, KVCOMM). Those require serving-engine
  control and are not portable hosted-API features. Interesting for a future
  local inference backend; not a dependency of anything here.
