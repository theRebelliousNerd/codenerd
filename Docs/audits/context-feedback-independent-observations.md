# Context feedback: count independent observations, not repeated strings

**Status:** source-derived finding and proposed contract; not reproduced with model calls or tests. Inspected main `356f65e0e6bb639adaa90ab36212daa714114871` and feature `c2d39e539ef4fb7dcb6ca6ff809d6c4bc9ada86c`. The relevant store, scoring and compressor files are identical at those revisions.

## The failure mode

When learning is initialized and a successful articulation response contains context feedback, a single response may repeat the same predicate ten times. The store writes **one parent feedback event and ten child rating rows**. Its scoring loop counts the child rows, crossing the default ten-sample floor even though they represent one event. With no previous ratings, ten helpful copies yield usefulness +1 and ten noise copies yield −1. Existing observations can change the outcome. A packet with 100 copies can occupy the entire latest-100-row window.

This is an accounting defect, not a demonstrated model behavior or a claim that every answer is affected. In particular, the learned score affects Go activation scoring only on the compressor's fallback path, rather than overriding successful kernel-selected context.

- Learning initialization must succeed and provide the feedback store to the session and compressor: [factory wiring](https://github.com/theRebelliousNerd/codenerd/blob/356f65e0e6bb639adaa90ab36212daa714114871/internal/system/factory_learning.go#L85-L147), [store wiring](https://github.com/theRebelliousNerd/codenerd/blob/356f65e0e6bb639adaa90ab36212daa714114871/internal/system/factory_learning.go#L413-L426).
- The direct articulation response representation contains string arrays; normalization does not deduplicate their values: [response types](https://github.com/theRebelliousNerd/codenerd/blob/356f65e0e6bb639adaa90ab36212daa714114871/internal/articulation/protocol_types.go#L220-L238), [parser](https://github.com/theRebelliousNerd/codenerd/blob/356f65e0e6bb639adaa90ab36212daa714114871/internal/articulation/emitter.go#L203-L234), [normalization](https://github.com/theRebelliousNerd/codenerd/blob/356f65e0e6bb639adaa90ab36212daa714114871/internal/articulation/emitter.go#L368-L438). The feature branch rejects duplicate object member names; that is different from duplicate array elements. The overall envelope must still pass its admission checks.
- Main chat passes the feedback arrays to storage: [chat processing](https://github.com/theRebelliousNerd/codenerd/blob/356f65e0e6bb639adaa90ab36212daa714114871/cmd/nerd/chat/process.go#L884-L910). The delegated executor has a separate recorder as well: [executor](https://github.com/theRebelliousNerd/codenerd/blob/356f65e0e6bb639adaa90ab36212daa714114871/internal/session/executor_learning.go#L397-L423).
- The default floor is ten, filtering removes empty strings but not duplicate predicate values, and insertion creates a child row for each occurrence: [floor and schema](https://github.com/theRebelliousNerd/codenerd/blob/356f65e0e6bb639adaa90ab36212daa714114871/internal/context/feedback_store.go#L70-L110), [insert](https://github.com/theRebelliousNerd/codenerd/blob/356f65e0e6bb639adaa90ab36212daa714114871/internal/context/feedback_store.go#L141-L194), [filter](https://github.com/theRebelliousNerd/codenerd/blob/356f65e0e6bb639adaa90ab36212daa714114871/internal/context/feedback_store.go#L459-L467).
- The [score query](https://github.com/theRebelliousNerd/codenerd/blob/356f65e0e6bb639adaa90ab36212daa714114871/internal/context/feedback_store.go#L260-L340) counts rating rows, not distinct events. That score contributes up to ±20 to [Go activation](https://github.com/theRebelliousNerd/codenerd/blob/356f65e0e6bb639adaa90ab36212daa714114871/internal/context/activation_scoring.go#L469-L492). [Compressor selection](https://github.com/theRebelliousNerd/codenerd/blob/356f65e0e6bb639adaa90ab36212daa714114871/internal/context/compressor.go#L718-L748) first prefers kernel-derived context; fallback influence is conditional on the documented kernel selection failure/empty cases.

## Proposed evidence contract

Use one admitted rating per **distinct response event and predicate**, not per string occurrence. Canonicalize predicate identifiers, define an explicit disposition when both helpful and noise are claimed, and bind feedback to the actual context disclosed to that response. Unexposed or unknown names should be diagnostic claims, not trusted learning evidence. Use stable session/request/turn identity with idempotent replay; conflicting replay should be visible. Count and window distinct eligible events. Preserve Mangle's selection authority rather than making Go feedback universally override it.

For old rows, a migration should deduplicate by original feedback-event identity and predicate where possible, preserve conflict provenance, and recompute or invalidate derived scores. Do not silently treat historical repeated rows as independent events. Bound retention and avoid unnecessarily keeping prompt contents.

The general lesson is analogous to [Hurlbert's work on pseudoreplication](https://doi.org/10.2307/1942661): multiple measurements from one unit are not automatically independent replications. This code is a heuristic scoring system, not the ecological hypothesis test in that paper; the analogy does not establish a statistical guarantee.

## Evaluation and full costs

In a future deterministic fixture, retain the real default floor of ten. Feed one event containing 1, 9, 10 and 100 copies; each must contribute at most one eligible observation. Ten distinct eligible events should reach the floor. Cover mixed positive/negative duplicates, conflicting replay, duplicate retries, independent sessions with reused turn numbers, unexposed predicates, malformed identifiers, migration and the most-recent-event window. Assert both current and intended scores and exact event counts.

Exercise normal chat with fixed response fixtures and fixed fact snapshots. Check kernel-selected and fallback paths separately; record chosen fact identities, disclosure, response correctness, input/output tokens, and extra retrievals. Compare against unchanged accounting at matched model, work and token budgets. Account for deduplication and joins, database storage/index/migration, additional provenance and retention, fallback latency, and evaluation/repair costs. No measured accuracy improvement or savings is claimed.
