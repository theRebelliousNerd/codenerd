# Campaign deletion rejected by the surviving path micro checkpoint

## Finding and evidence boundary

A deletion-only campaign task can reach a successful worker verdict yet be rejected by a campaign checkpoint that requires a surviving path. For an admitted `/refactor` task that legitimately removes its sole exact target, `runTaskMicroCheckpoint` ignores the observed before-and-after states and tests only whether a declared or attempt-written path currently exists. When none survives, the enclosing transaction fails and successful rollback restores the removed file. This is a completion-contract mismatch, not an authorization bypass. The narrow improvement is to recognize an eligible, attempt-owned, verified removal without accepting arbitrary missing paths.

This assessment is pinned to public repository `theRebelliousNerd/codenerd`, commit `388205138ba6d47c1cff0c5e97c896dfa642a391`. Main was revalidated unchanged on 2026-10-30 at 10:44:42 UTC. The conclusion is a conditional source trace, independently challenged, not a demonstrated model run. No repository changes, runtime execution, tests, model calls, or private data were used. In particular, the analysis does not establish that a model will choose deletion, obtain `/done`, or complete a larger campaign goal.

## Minimal legitimate case

Use a generic obsolete, tracked, clean regular Markdown file, `docs/obsolete.md`, inside the workspace. This is an illustrative fixture, not a claim about an existing repository file. The admitted plan requests its removal through a `/refactor` task, with both the artifact path and the nonempty exact `WriteSet` naming that file. The task has a usable snapshot; mission scope, risk policy, permission, leases, and cancellation state permit execution. The coder performs a permitted `delete_file` with `confirmed=true`; the actual observed executor returns `/done` and no error. Deletion is the only mutation: no replacement document, surviving declared path, or other surviving observed write exists. There is no concurrent writer or intervening external change.

These conditions isolate the campaign checkpoint. Markdown avoids adding a Go-write gate question; it does not waive any session obligation that actually applies. A tool being available to the coder is not permission to use it. The existing recoverability path checks tracked status and cleanliness, with uncertainty remaining behind approval; its separate index-classification assumptions are outside this finding. Neither that rule nor human approval should be broadened to fix completion recognition. [Recoverable deletion](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/session/delete_recoverable.go#L45-L85)

The tool itself requires the confirmation flag, resolves the workspace path, rejects directories, reads the file before removal, and calls `os.Remove`. Thus the relevant effect is an actual removal, not an empty-file substitute or a model's assertion. These tool checks remain necessary but are not substitutes for upstream authorization. [Delete implementation](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/tools/core/file_ops.go#L598-L684)

## Production path and contract mismatch

The task kind matters. `/refactor` is a mutating campaign type, and its effect contract requires a declared target without imposing the intentional no-deletion rule specific to `/file_modify`. [Mutation classification](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/task_mutation_types.go#L6-L19), [target contract](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/task_effect_contract.go#L6-L36)

Campaign type `/refactor` maps to persona `/coder`; task delegation then reads the persona-to-verb mapping, which maps `/coder` to session verb `/fix`. It does **not** run as session verb `/refactor` merely because the task has that name. The coder catalog includes `delete_file`, but that catalog fact does not settle permission. [Task persona and delegation](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/core/defaults/campaign_rules.mg#L638-L691), [coder verb](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/core/defaults/policy/delegation.mg#L517), [tool catalog](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/core/defaults/policy/intent_routing_rules.mg#L355-L360)

The production composition is consequential:

1. The scheduler acquires the write-set lease before launching `runSingleTask`. That function calls `executeTaskWithRollback`; failure goes to `handleTaskFailure`, whereas `completeTask` is reached only on success. [Scheduling and lease](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_tasks.go#L261-L293), [task completion](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_tasks.go#L415-L478)
2. The transaction captures state and opens an attempt before its callback. Inside the callback, a nil error from `executeTask` is followed by `runTaskMicroCheckpoint`, still inside rollback coverage. [Transaction ordering](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_task_transaction.go#L53-L107)
3. `executeRefactorTask` builds the task input, adds its refactor instruction, obtains `taskVerb`, and invokes `spawnTask`. Its generic-file fallback occurs only on a spawn error. A nil-error worker return instead produces the coder result and target path directly. [Refactor handler](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_task_handlers.go#L960-L991)
4. `spawnTask` requires an observed executor, installs the campaign write guard, uses `RunUntilVerified`, and records returned writes. The verdict loop returns successfully on an actual observed `/done` with no dispatch error. This finding does not replace that verdict with prose saying “done.” [Observed execution](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_task_handlers.go#L32-L118), [verdict exit](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/session/verdict_loop.go#L97-L130)
5. The micro-checkpoint appends attempt-write paths to resolved declared paths, then accepts only an `os.Stat` success. For the fixture, both lists identify the now-absent file. Its error returns through the transaction; rollback writes captured existing bytes back if restoration succeeds. [Existence gate](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/micro_checkpoint.go#L23-L56), [restoration](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_task_transaction.go#L489-L499)

The mismatch is therefore not missing deletion observation. It is a downstream consumer reducing a state transition to path existence.

## Boundaries and counterexamples

This is not a claim that every removal fails. A declared directory can remain on disk after a child is removed and satisfy the existing gate. A surviving declared artifact or observed write can also satisfy it; a rename with a live destination will often do so. Nonmutating tasks and tasks with an empty resolved write set skip this checkpoint. Those are current control cases, not recommended ways to disguise deletion work.

Earlier admission, permission, session-verdict, risk, lease, or cancellation gates can refuse the operation before the disputed point. `/file_modify` intentionally rejects deletion of a pre-existing file, and that stronger contract must remain unchanged. [Explicit modify prohibition](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_task_transaction.go#L109-L175)

Rollback itself can fail; the failure is included in the returned error rather than guaranteeing restoration. Retries or replanning may rescue the task, so neither endless failure nor irreversible loss is established. [Failure decisions](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_failure.go#L24-L147) Successful removal alone also does not establish that references, dependencies, or the user's entire goal are correct. [Rollback error propagation](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_attempt_writes.go#L163-L188)

## Narrow repair and broader alternative

The smallest defensible design adds a removal witness alongside the existing surviving-path witness. Require an active attempt-owned canonical path, known existing before the attempt, known absent after its settled effect, and still absent at checkpoint time. The task's admitted effect must permit removal at that target; `/file_modify` remains ineligible. No prose claim, absent path alone, unknown state, prior-attempt record, or unrelated external deletion should qualify.

One wiring gap must be explicit: `attemptRecord` currently retains `Writes`, not `ret.Effects`. `FileWrite` is the final turn snapshot of a path the turn wrote, not proof against every uncoordinated external writer. To demand a settled deletion-call receipt, carry the relevant observed effect and closure into the live attempt record and match it to the path span. The observed return already projects receipts containing call identity, before/after identities, and current closure; the checkpoint cannot read those merely by consulting today's write slice. This is proposed plumbing, not an existing guarantee of isolation. [Receipt projection](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/session/observed_return.go#L83-L86), [receipt and closure fields](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/observation/effects.go#L19-L74)

Aggregate multiple dispatches by canonical path using the first before-state and final after-state. A create-then-delete sequence began absent and cannot count as removal of an existing target. A delete-then-recreate sequence is not a final absence. Reject inconsistent or unknown spans rather than guessing. The rollback code already models first-before/last-after spans and checks whether the current file still matches what the attempt left; that is a useful design precedent, not proof that a new acceptance helper is correct. [Existing span logic](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_attempt_writes.go#L193-L243)

Keep effect evidence separate from permission and task correctness. A settled removal witness should satisfy only this minimal checkpoint, never grant deletion authority or override acceptance, build, test, mission, risk, cancellation, and lease controls. Do not introduce a blanket “skip checkpoint for refactor” flag. Do not advise creating a token surviving file or widening an exact write set to a directory merely to pass.

A broader alternative is typed desired postconditions, such as target existence, content modification, or authorized absence, bound to the admitted goal and revision and adjudicated by the kernel. That makes heterogeneous mutation contracts explicit but touches planning, validation, persistence, and compatibility. Neither approach intrinsically needs an extra LLM call. The narrow live-attempt design is the lower-cost candidate to evaluate first, not an implemented fix.

## Cost and operational tradeoffs

The narrow approach adds canonical-path grouping, evidence validation, and current-state I/O. Existing records already contain preimages and poststates, but retaining and reading them still costs memory and filesystem work. `Return.Writes` is explicitly process-local and never serialized, so this approach does not inherently require a durable schema migration. Persisted typed postconditions could require one. A resumed historical report must not be retrospectively upgraded from prose into a removal witness. If the necessary evidence is missing, keep that decision unresolved and use explicitly authorized reconciliation; do not repeat a completed side effect merely to manufacture a receipt. [Evidence lifetime and shape](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/observation/subagent.go#L172-L207)

A useful diagnostic should distinguish a successful observed removal that lacks a recognized checkpoint witness from a task that produced no evidence at all. The current message says the attempt wrote none of its own, even when the recorded path was deliberately removed. Improving that explanation would help operators but would not itself repair the rejection. Keep such diagnostics factual: identify the path and evidence state without declaring the whole task correct.

Potential savings are avoided rollback, retry, model tokens, and operator diagnosis after valid removal. They are hypotheses, not measured benefits. Costs include implementation review, adversarial regression cases, and the risk that stale or foreign evidence could turn a false rejection into a false acceptance. Larger typed contracts buy clearer semantics at greater migration and rollout cost.

## Fair evaluation not yet run

First test the normal `runSingleTask` production composition with deterministic observed-executor doubles, rather than only calling the micro-checkpoint helper. Admit the exact Markdown fixture under the same valid controls, actually remove it through the relevant effect path, and return an observed `/done`. Establish successful removal before testing the full closure: checkpoint decision, rollback behavior, persisted task status, and eventual campaign outcome. A separate session-level test should exercise real permission and effect production; a fabricated return alone cannot validate those layers.

Compare baseline and candidate with identical fixtures and deterministic returns. Required negative controls include absent-before/no-write, malformed paths, unknown states, stale or prior-attempt records, foreign deletion, inconsistent spans, and a path recreated after observation. Include create-delete, delete-recreate, multiple dispatches, mixed deletion and surviving edits, a directory write set, a rename destination, failed or non-`/done` workers, retries, cancellation, denied permission, lease contention, and rollback errors. Keep `/file_modify` deletion refusal, F12, C2, and applicable build/test behavior unchanged.

Measure removed or restored bytes, observed and persisted task states, checkpoint reasons, attempt and dispatch counts, tokens where models are involved, latency, filesystem I/O, and operator intervention. Then evaluate end-goal correctness separately. No measurements, benchmark gains, passing tests, or model reliability rates are claimed here.
