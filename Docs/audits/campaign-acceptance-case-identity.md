# Campaign acceptance remediation must preserve distinct file identities

## Finding and scope

Final campaign acceptance remediation can silently drop a legitimate file from its scope when two distinct workspace paths differ only in letter case. The normal campaign write-set normalizer preserves that distinction on Linux, but the final acceptance union unconditionally lowercases its deduplication key. This changes both the worker's instructions and the pre-existing-file snapshot used by the hollow-success guard. A correct minimal repair to the omitted file can therefore be refused and rolled back even after the worker has returned an admitted `/done`.

This is a conditional correctness and wasted-work finding, not a write-authorization bypass or false campaign success. The unconditional loss of an input target is source-established. The subsequent repair-and-rollback trace additionally requires a worker that finds the omitted target, makes the necessary modification, and passes all other applicable gates. A worker that obeys the narrowed brief instead may never attempt that repair; that is a different possible consequence, not an observed outcome.

**Baseline:** public main `388205138ba6d47c1cff0c5e97c896dfa642a391`, revalidated 2026-10-30 at 16:13 UTC. Static source inspection only: no application execution, tests, model inference, repository changes or measured performance results. This document is an audit and proposal, not an implementation.

## Contract and legitimate entry point

A campaign with a declared acceptance command is not complete merely because its phases are complete. The normal execution loop calls `settleAcceptance` before completion; a failed, non-exhausted witness appends a remediation phase. That phase is explicitly `/file_modify`, with its `WriteSet` computed from the campaign's declared writes. Its instructions require fixing the failing check without deleting content, weakening true statements or touching the checker. These are implemented controls worth retaining. [Completion ordering](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_execution.go#L173-L201); [Acceptance settlement](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_acceptance.go#L92-L126); [Remediation construction](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_acceptance.go#L214-L288).

This is wired into normal chat campaigns: `newCampaignOrchestrator` provides the session task executor, tactile executor, VirtualStore and user's campaign policy. It is not limited to an isolated helper or a synthetic test. The witness below uses an ordinary campaign, not a mission with extra protection constraints and not a recurse-specific scheduling mode. [Production orchestrator wiring](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/cmd/nerd/chat/campaign_planning.go#L84-L148).

The required identity contract is modest: deduplicating two representations of one target must not erase one of two different targets. Source comments describe the remediation union as every workspace file the tasks declared they write, but implement case-insensitive equality regardless of the actual workspace. Normal `normalizeWriteSetPaths`, by contrast, uses `normalizeAbsolutePath`, which lowercases only on Windows. Thus a Linux campaign can legitimately preserve both `docs/Guide.md` and `docs/guide.md` up to this boundary. [Remediation identity rule](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_acceptance.go#L291-L345); [Normal write-set identity](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/write_set_lock_manager.go#L259-L311).

Case sensitivity is a property to establish, not infer blindly from an OS label. Linux's ext4 documentation explicitly supports both case-sensitive and case-insensitive directories in one filesystem. The clean witness requires a case-sensitive directory containing two different regular files; it excludes symlinks, hard links and case-insensitive aliases. Go's `filepath.Clean` performs lexical cleanup, not a disk-identity test. [Linux ext4 documentation](https://docs.kernel.org/6.6/admin-guide/ext4.html#case-insensitive-file-name-lookups); [Go filepath documentation](https://pkg.go.dev/path/filepath#Clean).

## Source trace and bounded counterexample

### 1 Preserve two original targets

Use a case-sensitive Linux workspace with two included, pre-existing regular files:

- `docs/Guide.md`
- `docs/guide.md`

Give completed original campaign tasks these exact paths in their WriteSets, with the same relative-versus-absolute provenance. Both may be relative originally or both normalized absolute paths. No declared directory or glob covers them. The tasks and phases have completed, but the ordinary acceptance command genuinely still fails because the lowercase document needs one substantive correction. The uppercase document is already correct.

This setup does not assume that a worker's `/done` proves final campaign acceptance: the separate final command exists specifically because it does not. Assume the command is admitted, executes normally, emits its genuine diagnostic, and its failed round is persisted and projected successfully. There must be an available acceptance round and no unrelated risk or permission obstacle.

### 2 Collapse the union and narrow the instructions

`campaignWriteSet` visits every task WriteSet, obtains a cleaned workspace-relative spelling, then assigns `key := strings.ToLower(rel)`. For equal keys it prefers a relative spelling over an absolute-derived spelling, and within equal provenance prefers a mixed-case spelling over an all-lowercase spelling. Therefore the chosen pair retains `docs/Guide.md` and drops `docs/guide.md`, independent of their iteration order. No filesystem alias check occurs. [Unconditional case-folded union](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_acceptance.go#L300-L345).

The builder writes that reduced union into the remediation's actual `WriteSet` and into its description. It supplies no alternate Artifact target. `resolveTaskWriteSet` does not supplement a nonempty WriteSet from artifacts or description, so the failing command's text mentioning the lowercase path cannot repair this scope mechanically. The file-task target resolver also takes the first exact WriteSet entry before inspecting the description. [Scope copied into task](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_acceptance.go#L237-L278); [Nonempty scope takes precedence](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_tasks.go#L569-L595); [File-task target precedence](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_task_handlers.go#L479-L525).

There is a user-visible instruction consequence before any validator runs: `executeFileTask` adds a write-set briefing, and the briefing tells the worker its modification must land in the listed existing files. In this witness that list excludes the file the original campaign declared and the acceptance diagnostic needs. The finding does not require claiming that a compliant worker will ignore this contradictory instruction. [Worker request construction](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_task_handlers.go#L578-L603); [Briefing scope](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_task_results.go#L217-L275); [Existing-file obligation](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_task_results.go#L312-L325).

### 3 A discovered correct repair still fails the local contract

For the stronger conditional continuation, let the worker inspect the actual failure and change only `docs/guide.md`. Require a normal observed return with known before/after write evidence, nil error and an admitted `/done`; all unrelated session checks pass.

The declared WriteSet is not an absolute write-authorization boundary. `spawnTask` installs the campaign write guard and uses `RunUntilVerified`; the guard checks mission protections and acquires a dynamic lease for the actual path, refusing a conflicting sibling owner rather than refusing merely because the path was omitted from the declaration. In the ordinary campaign with no conflicting lease, this write is permitted subject to all other normal tool policy. `spawnTask` records the returned observed writes. [Observed execution and write recording](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_task_handlers.go#L35-L112); [Dynamic write guard](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_attempt_writes.go#L137-L155).

The task snapshot, however, was captured from the reduced declared WriteSet before the worker ran. It contains the existing uppercase file, not the lowercase file. The file-task postcheck sees the retained regular target still on disk, and the microcheckpoint accepts existence in either declared paths or observed writes. Neither reconstructs the original two-file union. [Snapshot source](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_task_transaction.go#L250-L260); [Exact-file capture](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_task_transaction.go#L300-L349); [File-target existence check](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_task_handlers.go#L629-L638); [Declared and observed existence gate](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/micro_checkpoint.go#L23-L56).

After those checks, `validateFileModifyOutcome` examines captured pre-existing files. The uppercase file existed but is unchanged, so `declaredExisted` is true and `modified` remains false. Lines 168–169 return the hollow-success error. The legitimate observed modification to the lowercase file does not rescue this attempt: `changedPreexistingFiles(writes)` is consulted only when no declared pre-existing file existed. This is a sound hollow-success guard operating on an unsoundly reduced declaration. [Post-execution validation](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_task_transaction.go#L97-L107); [Pre-existing-file outcome contract](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_task_transaction.go#L110-L175).

### 4 Undo the correct repair before the next final witness

On refusal, `undoFailedAttempt` separates observed writes not covered by the snapshot. The lowercase path is distinct from the uppercase exact root, so it is in that outside set. With known before/after states, no intervening writer and successful filesystem operations, `undoAttemptWrites` restores the lowercase file's old content. Snapshot rollback restores the declared scope and the task's captured status; the attempt returns an error instead of committing success. Failure handling then chooses the policy-derived retry, failure or replan state. The normal next final acceptance run therefore does not get a completed remediation preserving this correction. [Failed-attempt cleanup](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_attempt_writes.go#L158-L183); [Observed-write undo](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_attempt_writes.go#L186-L228); [Snapshot coverage identity](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_attempt_writes.go#L240-L259).

## Protections and counterevidence

- **Intentional alias repair exists.** The current helper addresses Windows-shaped duplicated absolute and relative spellings and prevents campaign reports under `.nerd/` becoming remediation targets. The tests explicitly expect case-insensitive collapse and preservation of mixed-case spelling, using a `C:/CodeProjects/codenerd` workspace. They are meaningful regression protection for that intended case, not evidence that two actual case-sensitive files are one file. Preserve those results where the inputs are aliases. [Existing scope tests](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_acceptance_scope_test.go#L8-L60); [Spelling-order tests](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_acceptance_scope_test.go#L70-L107).
- **The witness has narrow filesystem conditions.** One physical file with two case aliases does not demonstrate this loss. Neither does a retained directory whose snapshot contains both files, a repair that also legitimately modifies the retained file, or the branch where no declared file existed and observed-write fallback applies.
- **Nothing grants new permissions.** Workspace containment, invalid-path/glob filtering and `.nerd/` report exclusion remain active. Dynamic leasing, mission protections when applicable, session verdicts and normal tool policy remain separate controls. [Remediation path exclusions](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_acceptance.go#L348-L382).
- **The direct-generation fallback does not bypass this error.** A failed `/file_modify` worker refuses the create-style fallback; this witness instead conditions on successful worker execution followed by outcome refusal. [Modify fallback refusal](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_task_handlers.go#L603-L624).
- **Recovery is possible.** Failure handling records the error, supports policy-derived retries/backoff, and can invoke a cap-time replan. A revised exact scope, a legitimate retained-file change or operator intervention may recover. No inevitable deadlock or fixed retry count is claimed. [Failure and recovery handling](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/campaign/orchestrator_failure.go#L24-L160).
- **Rollback is guarded, not infallible.** Unknown original content, an intervening change or filesystem errors can leave the correction in place and report why. The rollback consequence explicitly requires the successful guarded-undo case.
- **Final acceptance remains fail-closed in this trace.** Acceptance must pass before normal completion; policy limits rounds and can block exhaustion. This audit does not allege checker weakening, unsafe acceptance or unconditional campaign failure. [Acceptance policy](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/core/defaults/policy/campaign_core.mg#L33-L54).

## Repair direction and full costs

Repair the identity conversion, not the hollow-success guard. The remediation union should preserve each distinct original target under the workspace's path identity rules while deduplicating proven alternate representations. A narrow implementation can first align this helper with the existing platform-aware normalization contract; broader filesystem-aware alias support must not assume that every directory on an OS shares one case policy. Keep display spelling separate from comparison identity and provide deterministic tie-breaking when distinct retained paths compare equally under a display sort.

Do not fix this by accepting any observed out-of-scope write, automatically widening to the workspace root, renaming user files, disabling rollback, touching the checker or inventing a model-based equivalence judgment. Those changes weaken unrelated controls or create new costs. Preserve the useful Windows alias and report-exclusion behavior. Hard links, symlinks, nonexistent future targets and path replacement need explicit semantics if a physical-file identity optimization is proposed; one transient inode comparison is not a universal path identity.

Already-persisted pending remediation tasks need deliberate handling: changing the helper affects newly constructed tasks, not automatically the reduced WriteSet of an existing task. Original task declarations can support reconstruction when still available, but any repair should update the task, facts and briefing consistently under the existing plan-revision and concurrency rules, without rerunning completed work by default.

This is not a free performance optimization. Retaining the missing target adds scope metadata, prompt text, lease coverage, snapshot reads/storage and outcome comparisons for that target. Proven alias dedup can avoid duplicate work; filesystem identity checks themselves add metadata operations and race considerations. In the two-file witness, the corrected union contains two targets rather than one, and the existing snapshot reads both pre-existing files. More accurate lease coverage may also serialize work previously allowed to overlap.

Potential savings are conditional: avoiding an unnecessary failed attempt and undo can avoid repeated worker tokens, tools, snapshots, backoff and replanning. The number of calls and total latency depend on worker behavior and policy; no measured speedup, token reduction, throughput or failure prevalence is asserted. Charge the proposed design for the newly retained context and verification work as well as crediting any avoided recovery.

## Fair evaluation plan not run

1. Establish the filesystem precondition with two independently addressable regular files and differing content; do not merely assert that a runner is Linux. Compare an actual case-sensitive directory with a case-insensitive alias control.
2. Exercise both input orders and equal relative/absolute provenance. Assert that two distinct targets survive, true normalized duplicates collapse, sorting is deterministic, and existing `.nerd/`, outside-workspace, NUL and glob exclusions still hold.
3. Drive the real acceptance-remediation builder and task transaction, not only `campaignWriteSet`. Begin with completed phases and a genuinely failed declared witness. Inspect the appended task's WriteSet, selected target, briefing, snapshot and projected facts.
4. Supply a controlled observed executor that changes only the lowercase file, returns known write states and an admitted `/done`, while all unrelated gates pass. Baseline should expose the reduced scope and validator refusal; the proposed identity repair should preserve the correction and permit the next unchanged acceptance command to judge it.
5. Negative controls: no write; a new file rather than a modification; deletion; a non-done verdict; an inaccessible file; protected mission target; conflicting sibling lease; unknown write provenance; intervening external change; rollback failure; directory scope; a genuine alias. Do not make these pass merely to obtain a green reproduction.
6. Exercise persisted pending remediation and retry/replan paths, checking task/fact consistency and no duplicated execution. Check that a still-red final witness remains red and that acceptance exhaustion still blocks.
7. For an explicitly authorized later end-to-end evaluation, pair initial repositories and policies, retain the same acceptance command, and count full worker/provider tokens, tool calls, file bytes read/written, lease waits, retries, replans, final witness runs and final artifact correctness. Report both recovered-work cases and cases where preserving the second scope costs extra without changing the outcome.
