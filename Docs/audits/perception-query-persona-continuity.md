# Read-only routing and child persona continuity



**Decision:** extend the restriction-continuity contract with an independent invariant: resolving a worker persona must not silently turn an admitted information request into a write-oriented task. Apply the invariant after **every** source of shard candidates, not only the taxonomy branch. Preserve the feature's corrected `/debug` routing, typed restrictions, exact permission checks and hollow-success gate.

### Main/feature distinction and counterexamples

Main already has the unnormalized fallback and the same scoring behavior; it delegates foreground work rather than using the feature's new background lane. The feature's latest fix therefore closes the corpus-selected `/debug` case, not every path to a coder candidate; the fallback defect is not newly introduced by that fix. [Main resolver, lines 259–281](https://github.com/theRebelliousNerd/codenerd/blob/356f65e0e6bb639adaa90ab36212daa714114871/cmd/nerd/chat/delegation_routing.go#L259-L281), [main scoring, lines 775–822](https://github.com/theRebelliousNerd/codenerd/blob/356f65e0e6bb639adaa90ab36212daa714114871/internal/perception/transducer_llm.go#L775-L822), [main foreground spawn, lines 531–542](https://github.com/theRebelliousNerd/codenerd/blob/356f65e0e6bb639adaa90ab36212daa714114871/cmd/nerd/chat/process.go#L531-L542)

Keep these controls explicit:

- A feature `/query /debug` with the normal corpus mapping now goes to reviewer; do not re-report it as broken.
- A `/mutation /debug` must remain eligible for coder and its existing verification/work-mode obligations.
- An ordinary explanation without workspace-evidence signals may take the direct-answer lane and never encounter this handoff.
- A different domain/affinity table may select reviewer or researcher; below-threshold or clarification cases need not spawn the child.
- A preserved explicit restriction can prevent effects, but preventing a write is not the same as assigning a read-compatible completion contract.

### Proposed refinement, cost and checkable exit

1. **Normalize after candidate resolution.** Candidate provenance—corpus, derived affinity or compatibility suggestion—must not determine whether the existing read-only compatibility rule applies. A minimal implementation can close the missing branch without another model call. Do not change the tie weights merely to conceal this witness; a different candidate source would recreate the mismatch.
2. **Make the actual child operation part of admission.** Resolve the effective child verb before deriving scheduling/work-admission obligations. Retain persona choice separately from the original request's operation/category and restrictions. Mangle remains the authority for compatible execution and background eligibility; Go transports the measured/resolved inputs. Do not add a competing persona-to-verb authority in chat or turn a proposed model shard into permission.
3. **Preserve both safety and task usefulness.** Keep exact `permitted` checks, the typed restriction intersection and post-effect proof gates. Carry restrictions through the already-identified detached boundary. If no compatible executor exists, return a typed unavailable/clarification disposition instead of running a writer and hoping task prose overrides its preset.
4. **Qualify the existing audit language.** The [request-visible-tool audit's journey summary](https://github.com/theRebelliousNerd/codenerd/blob/0806d57a48fba303bdc2193faf28e634798facba/Docs/audits/request-visible-tool-contract-and-investigation-affordances.md#2-the-normal-journey-and-the-five-different-sets) should say that *corpus-selected* read-only coder requests are redirected, and link this remaining candidate-source boundary. No separate generic routing audit is needed.

The narrow common-normalization repair should need no extra inference, source indexing or durable ledger. Still account for added kernel queries, routing metadata and test/maintenance cost. A fuller explicit-operation contract adds carrier fields, compatibility migration and policy derivation work. Compare current behavior, common normalization alone, and normalization plus explicit child-operation admission under the same models, tools and limits. Measure query completion accuracy, write-dispatch count, false hollow failures, total provider calls/tokens, time to useful evidence/answer and human recovery turns—not just faster routing or fewer tool calls. Include authorized mutations as controls so indiscriminately disabling the coder cannot look like success.

**Exit:** normal-entry fixtures demonstrate that an admitted information request preserves a compatible operation/completion contract across every candidate source and the actual preset handoff, while existing authorized mutations and all exact permission/restriction gates retain their behavior. Add this as a leaf exit under restriction transport/admission work, not as evidence that the wider background-ownership or restriction-continuity contracts are already complete.

Independent review qualification: Redirecting to reviewer repairs the persona/completion mismatch, but does not by itself enforce read-only behavior: the reviewer envelope includes CodeDOM tools with edit capabilities. Preserve explicit typed effect restrictions when the user requests them; do not indiscriminately prohibit execution for every query, since some queries intentionally run tests. Existing workspace-effect restrictions do not necessarily cover external effects.
