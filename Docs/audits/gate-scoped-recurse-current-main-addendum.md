This addendum updates the recurse-specific context of [Gate comparison domain admission](https://github.com/theRebelliousNerd/codenerd/blob/d2c5377f4cdedba00eb08b8f496836651bdaeddf/Docs/audits/gate-comparison-domain-admission.md), which is explicitly pinned to `8decae5763cb88bbd842795ca81d3e2559ec2b20`. Main advanced during publication. The source inspected here is [`33260224758a13a243acdc9949eeda947866c69c`](https://github.com/theRebelliousNerd/codenerd/commit/33260224758a13a243acdc9949eeda947866c69c), on October 29, 2026. This is static source inspection, not an executed reproduction or measured performance result.

The earlier report's statement that ordinary recurse measurements use one fixed scope must not be applied to this new revision. Recurse now deliberately narrows selected lint gates and composes their results with a retained baseline. That is implemented behavior, not merely the earlier report's proposed future direction.

## What now happens

`Measurement` now stores `Scope`; `MeasureOptions.ScopedPackages` narrows vet, staticcheck and golangci-lint. A nil scope means full measurement. A non-nil empty package list records the explicit `NoPackageScope` marker, returns pass over that empty domain and does not launch that lint process. Build, tests, vulnerability checking and the other gate kinds are not all narrowed by this option. In particular, the test gate still uses the separate `TestPackages` option and is not constructed with the lint gate's `scoped` flag. [Measurement options and constructors](https://github.com/theRebelliousNerd/codenerd/blob/33260224758a13a243acdc9949eeda947866c69c/internal/gates/errorfree.go#L60-L133), [empty-domain handling](https://github.com/theRebelliousNerd/codenerd/blob/33260224758a13a243acdc9949eeda947866c69c/internal/gates/errorfree.go#L173-L183).

The recurse callback accepts a package list for each measurement. After a changed attempt, the loop obtains package directories from changed `.go` paths, measures the selected gates, and passes `gateBaseline.RestrictTo(after)` with the after snapshot into its ratchet. If the cycle is kept, it updates the baseline through `Overlay`. A reverted cycle does not take this overlay path. [Callback](https://github.com/theRebelliousNerd/codenerd/blob/33260224758a13a243acdc9949eeda947866c69c/cmd/nerd/cmd_campaign_recurse.go#L309-L329), [comparison input](https://github.com/theRebelliousNerd/codenerd/blob/33260224758a13a243acdc9949eeda947866c69c/internal/campaign/recurse_cycle.go#L978-L985), [kept-cycle overlay](https://github.com/theRebelliousNerd/codenerd/blob/33260224758a13a243acdc9949eeda947866c69c/internal/campaign/recurse_cycle.go#L1035-L1053), [changed-file package selection](https://github.com/theRebelliousNerd/codenerd/blob/33260224758a13a243acdc9949eeda947866c69c/internal/campaign/recurse_error_free.go#L103-L125).

`RestrictTo` filters an existing pass/fail measurement's findings to the corresponding after scope and recalculates a findings-only count/status. It retains the other baseline gate rows. `Overlay` keeps old findings outside a measured scope and combines them with the new findings inside that scope; a full-scope or unavailable/unverified after measurement takes a separate replacement path. The ordinary scoped mechanism therefore does more than blindly compare a full baseline count against a narrow after count. [Restriction and overlay](https://github.com/theRebelliousNerd/codenerd/blob/33260224758a13a243acdc9949eeda947866c69c/internal/gates/errorfree_scope.go#L40-L110).

The loop refreshes the full error-free baseline between attempts at startup and when the configured number of scoped cycles has elapsed. The CLI default is ten, while zero requests only the initial full measurement. The configuration comment explicitly acknowledges that a change can affect a package it did not touch. This is an intentional interval-based coverage tradeoff, not evidence that touched-file packages are a complete semantic dependency closure. [Refresh mechanism](https://github.com/theRebelliousNerd/codenerd/blob/33260224758a13a243acdc9949eeda947866c69c/internal/campaign/recurse_error_free.go#L31-L49), [configuration contract](https://github.com/theRebelliousNerd/codenerd/blob/33260224758a13a243acdc9949eeda947866c69c/internal/campaign/recurse_cycle.go#L105-L121), [CLI default](https://github.com/theRebelliousNerd/codenerd/blob/33260224758a13a243acdc9949eeda947866c69c/cmd/nerd/cmd_campaign_recurse.go#L83-L89).

## Which earlier findings remain

The standalone CLI comparison still has no general domain-admission step. Its loader and `Compare` retain the earlier behavior: projection includes status, count and finding keys, but not scope or invocation identity; the result-validation loop visits after-side gates only. `policy/gates.mg` still joins the intersection and derives keepability from absence of a regression. Consequently the earlier conditional CLI examples remain relevant: before-only gates can disappear, unknown selectors can select nothing, and two G3 measurements can use different `--tests` scopes while sharing the same gate name. Adding `Measurement.Scope` for scoped lint is useful, but does not by itself make every caller compare compatible domains. [Snapshot projection and comparison](https://github.com/theRebelliousNerd/codenerd/blob/33260224758a13a243acdc9949eeda947866c69c/internal/gates/errorfree_snapshot.go#L96-L218), [gate policy](https://github.com/theRebelliousNerd/codenerd/blob/33260224758a13a243acdc9949eeda947866c69c/internal/core/defaults/policy/gates.mg#L29-L80), [CLI comparison consumer](https://github.com/theRebelliousNerd/codenerd/blob/33260224758a13a243acdc9949eeda947866c69c/cmd/nerd/cmd_gates.go#L65-L96).

The earlier opaque-failure count concern also remains a separate evidence contract: a process that exits nonzero with no parsed finding is still stored as fail with zero findings. Scoped baseline transformations now add another reason to preserve enumeration completeness explicitly, because `restrict` and the scoped overlay branch reconstruct pass/fail from findings alone. This addendum does not claim an observed incorrect commit. Whether any specific attempt survives all independent target, workspace, metric and forbidden-write guards requires a separate end-to-end witness. [Command classification](https://github.com/theRebelliousNerd/codenerd/blob/33260224758a13a243acdc9949eeda947866c69c/internal/gates/errorfree.go#L225-L251), [findings-only transformations](https://github.com/theRebelliousNerd/codenerd/blob/33260224758a13a243acdc9949eeda947866c69c/internal/gates/errorfree_scope.go#L61-L110).

## How the repair and evaluation should adapt

Preserve the new scoped optimization. Extend its evidence contract rather than forcing every attempt back to a full lint run:

1. Admit comparisons against an explicit required gate and package domain. Scope restriction must be intentional and represented in the resulting assurance statement.
2. Preserve process/observation failure separately from enumerated findings through restriction, overlay and persistence. Zero retained findings is not enough to reconstruct a successful observation.
3. Track the source and scope of retained outside-domain evidence, and distinguish a composed baseline from a freshly measured whole-module snapshot. A snapshot's latest ID alone does not establish that every retained row was remeasured at that revision.
4. Keep periodic full checks, but measure their detection delay separately from per-cycle guarantees. A later detection is valuable without retroactively proving every earlier cycle was regression-free.
5. Test the CLI route independently from recurse. A fix in `Compare` alone does not cover the ratchet's direct snapshot-fact path, and a correct recurse restriction does not repair arbitrary CLI pairs.

Proposed evaluations, not run here, should compare fresh full measurements, current touched-package restriction/overlay, and the enhanced evidence contract on identical edits. Include unchanged controls; indirect-dependent changes; changes with no `.go` paths; unavailable/interrupted/opaque reports; multiple kept overlays; reverted attempts; and the configured full-refresh boundary. Record false assurance, unresolved evidence, detection delay, retained diagnostics, CPU, wall time, I/O, memory, fact volume and any retries or model tokens caused by the verdict. Charge the full periodic checks and baseline maintenance to the scoped strategy. No speedup or quality gain has been measured by this review.

The implementation has moved toward composable partial verification. The remaining architectural requirement is to make each composed verdict state exactly what was observed, what was retained, and what is still unknown.
