# Tester continuation proposal admission

## Finding and scope

CodeNERD should classify a derived test authoring step by its declared effects before deciding whether to launch its worker. The current continuation path can launch a tester without the step level proposal pause required by Propose mode, even when the kernel obligation explicitly says `Write tests for:`. The immediate cause is `isMutationOperation("tester") == false`, justified by the comment “Just runs tests (read-only).” This is a mismatch between the obligation and its admission classification, not proof that a worker writes or that tool authorization is bypassed. [Work mode contract](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/config/work_mode.go#L5-L16), [classification](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/process_continuation.go#L369-L385).

The strongest production witness starts with an already approved dream plan in real execution, not an unapproved plan. Its first worker edits an existing Go source file and returns an otherwise admitted observed result with nonempty `Untested` and a nil error. Under the conditions below, that result generates a test authoring obligation, and Propose admits the derived tester immediately. This is a source traced conditional witness, not an executed reproduction or a prediction of model behavior.

## How the production path reaches the missing pause

The approved dream route supplies a concrete owner and entry point. The handler approves the current plan, starts execution, ends request delivery, installs the plan subtasks, and dispatches the first one. The user has therefore already approved the plan; this finding concerns the additional per step pause promised by the selected work mode, not a missing initial approval or a grant of tool authority. Ending delivery also means the main witness does not require the request delivery gap judge to invent the next action. [Approval and initial dispatch](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/model_handlers.go#L672-L758).

The stock delegation path can supply structured observation rather than parsing worker prose. It selects `ExecuteObservedWithContext` when supported. That method calls the observed executor directly; the separate string returning wrapper uses `RunUntilVerified`. The observed executor copies the result observation and propagates process or result errors. Consequently, the witness requires an actual observed return with nonempty `Untested` and no error, not a custom executor string that happens to mention missing tests. [Delegation adapter](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/delegation.go#L50-L74), [executor entry points](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/task_executor.go#L321-L351), [observed result propagation](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/task_executor.go#L431-L464), [observation fields](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/observed_return.go#L47-L109).

This condition is compatible with, but not guaranteed by, the verification machinery. Untested changes can be recorded as warnings; final closure treats measured build or test failure and acceptance failure as hard errors, rather than missing test debt alone. The repair gate explicitly leaves post-repair uncovered debt to the verdict rather than failing solely for that debt. The hollow success guard separately rejects new source without tests. Choosing an existing source edit avoids that particular guard, not all other guards. The first worker could repair the debt, fail verification, or return an error instead. An otherwise admitted result may honestly remain `/unverified`; the finding does not require false `/done`. [Build and test handling](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/build_verify.go#L334-L395), [closure audit](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/change_evidence.go#L70-L118), [repair gate](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/change_gates.go#L352-L385), [new source guard](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/executor.go#L2940-L3019), [settlement return](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/turn_settlement.go#L104-L152).

The remaining debt is not merely excused by a comment: coverage repair returns through `settleForcingRepair`, which preserves cancellation and other errors but converts a nonconverged verification repair into debt for the verdict. The kernel can withhold verification for untested work and name `/tests_not_written`. These are controls on the witness, not a prediction that a particular model will leave debt. [Repair return](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/change_gates.go#L419-L428), [forcing error settlement](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/change_gates.go#L732-L744), [verification and missing evidence](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/core/defaults/policy/coder_safety.mg#L734-L792).

Given that return, the continuation executor injects observations and records the result before selecting a next step. Its error branch returns failure instead of following this route. The pending test producer treats nonempty `Untested` as sufficient; otherwise it checks changed Go source and absent or unrun tests. It asserts `pending_test` with a description prefixed `Write tests for:`. For the clean witness, use `/unverified` rather than `/hollow` and no structured findings: the former remains terminal for this step rather than creating a same-shard retry, while findings could add a competing coder obligation. [Observed continuation](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/process_continuation.go#L42-L100), [obligation production](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/process_continuation.go#L156-L188), [result vocabulary and test debt predicate](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/process_continuation.go#L208-L251).

Kernel policy turns the pending test into a tester subtask. The witness requires successful fact assertions and queries, no prior tester result with the same description, no interrupt or pending clarification, and the tester obligation to be the sole eligible next step. These are material preconditions: a discharged obligation or a blocker is not this failure. The kernel interrupt predicate should not be confused with a guarantee that every running session receives global cancellation. [Continuation derivation and blockers](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/core/defaults/policy/codedom_continuation.mg#L18-L75).

The admission mismatch then becomes deterministic. `derivedNextStep` asks for `should_auto_continue` and `has_pending_subtask`, but assigns mutation status using the shard name. `nextStep` considers that derived obligation before the delivery judge. The `continueMsg` handler records the result, advances its count, and asks whether to pause. Propose pauses only for a true mutation flag; because tester is false, the handler takes the immediate `executeSubtask` branch. [Next step construction](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/request_delivery.go#L238-L275), [pause decision](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/work_mode.go#L43-L52), [dispatch branch](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/model_update.go#L396-L436).

## What the finding does not establish

Tester is not intrinsically read only. Delegation maps it to `/test`, the task executor categorizes that preset as mutation, and tester tool envelopes include `write_file` and `edit_file`. Those facts refute the classifier's universal premise; they do not establish that a particular tester chooses a write. A legitimate execute only test job can deserve different treatment from test authoring. [Persona intent mapping](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/core/defaults/policy/delegation.mg#L492-L519), [preset category](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/task_executor.go#L261-L264), [tester tools](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/core/defaults/policy/intent_routing_rules.mg#L334-L370).

Actual tool execution still faces catalog and capability availability, authorization, path and revision constraints, exact human approval when applicable, write guards, Dreamer preflight, and verification. The tool executor checks its JIT allowlist and safety decision, can request exact approval and recheck, and fails closed for an empty allowed tools set. Missing the earlier proposal pause neither grants those permissions nor demonstrates that they are weakened. The affected boundary is before launching the derived worker. [Tool admission and guards](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/executor_tools.go#L2445-L2665), [empty allowlist behavior](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/executor_tools.go#L2786-L2794).

## Proposed admission contract

Build on the predecessor audit's exact step receipt rather than introduce a competing mechanism. For this boundary, the request owned record needs a stable step ID, source obligation, description, declared effect class, scope, authority reference, and work mode epoch. The new requirement is that the obligation producer declare test authoring as a write effect. A separately identified execute only testing obligation can follow its own policy. Do not infer this distinction from arbitrary prose or equate possession of write tools with an instruction to write.

Have the kernel derive `requires_proposal` from the declared effect and current mode, with Go marshaling the receipt and policy facts. Propose must hold a write step before worker launch; Explicit must hold every step; Yolo should retain its documented behavior. Unknown effects should be conservative. Missing metadata should fail closed or request clarification rather than silently inheriting a read only persona classification.

The pause must own that exact receipt, not a queue position. Confirmation should revalidate its identity, live obligation, request authority, current work mode, and interruption or clarification state before dispatching the identified step once. Stale, displaced, or already discharged receipts must not execute. A mode change should trigger revalidation rather than make an old confirmation reusable. These checks should share the queue conservation design rather than create a second pending task store.

Do not launch an expensive worker or LLM call merely to wait for confirmation. Prior plan approval should not silently stand in for a proposal required by the current mode; any compatible blanket approval policy would need an explicit, documented change to that contract. Step confirmation must confer no additional tool grants. Exact downstream approvals and guards remain independently binding.

## Evaluation plan with no execution claimed

Start with deterministic adapter and state transition tests, not a model demonstration. Exercise the stock approved dream route through the actual observed return adapter, real continuation policy, and Update handler. Supply an existing Go edit with nonempty `Untested`, nil error, and the eligibility conditions above. In Propose, require zero tester dispatches and zero tester tool calls before confirmation, then exactly the intended receipt after confirmation. Seed the retained initial queue head to catch the predecessor regression rather than testing an artificially empty queue.

Cover Yolo immediate dispatch and Explicit pause, but verify step identity after confirmation in both relevant modes. Negative cases should include already discharged or absent obligations, worker errors, interrupt and clarification blockers, and a new source hollow failure that never reaches this continuation. A string fallback without observation must not fabricate test debt. Exercise genuine run only testing separately from authoring, unknown personas, and opaque literal contexts so classification does not accidentally depend on matching wording.

Keep downstream tests for denied capabilities and rejected exact action approval. They should remain denied after valid proposal confirmation. Check that an honestly unverified result can remain unverified instead of being relabeled successful to satisfy the test. Existing test definitions already inject untested debt and derive a tester with the authoring description, then check discharge by a matching tester result. They establish intended vocabulary, not full TUI admission coverage or an executed result. The existing pause test checks the supplied boolean truth table, not this producer to classifier connection. [Vocabulary tests](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/shard_result_vocabulary_test.go#L30-L90), [work mode test](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/async_test.go#L470-L490).

Compare current behavior, the coarse one line tester classification, and the typed policy candidate. Hold tasks, model, JIT policy, tool catalog, authorization, work mode, and budgets fixed. Only after deterministic coverage should a separately authorized model study examine task outcomes under the same budgets.

Measure proposal unconfirmed step dispatch, wrong step confirmation, unnecessary pauses, final verified quality, and repeated work. Here “unconfirmed” concerns step proposal admission, not a proven tool permission bypass. Account for all tokens, including hidden reasoning, failed attempts, retries, and critics; test CPU and wall time; tool calls; end to end time and human waiting; and receipt storage and policy overhead. No performance or quality improvement has been measured.

## Costs and implementation boundary

Bounded receipt metadata implies storage proportional to retained steps and an additional admission query or equivalent policy evaluation, with no extra LLM call inherently required. Real costs include schema migration, queue integration, audit and UI complexity, and handling interrupted or stale confirmations. Conservative classification can create unnecessary pauses, confirmation fatigue, and availability delays while a user is away. Those costs belong in the comparison rather than being dismissed as free safety.

The recommended acceptance condition is narrow: a live test authoring obligation cannot launch its tester in Propose before confirmation of that exact step, while downstream permissions and truthful verification remain unchanged. This document supplies a source finding and a proposed evaluation contract only. No repository implementation, tests, shell commands, CodeNERD runtime execution, or CodeNERD model calls were performed for this addendum.
