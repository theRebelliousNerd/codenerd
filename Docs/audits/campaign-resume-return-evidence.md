# Campaign resume: completed work without its return evidence

**Status:** source-derived risk and design proposal, not an observed incident or executed test. Inspected main `356f65e0e6bb639adaa90ab36212daa714114871` and feature `c2d39e539ef4fb7dcb6ca6ff809d6c4bc9ada86c`; relevant files are identical on those revisions. This is about the completeness of an otherwise admitted campaign generation, not a claim that its journal admission is defective.

## Why this matters

A dependent campaign task may resume with its predecessor marked complete while a return the plan explicitly requested is absent from its brief. This can discard findings, caveats or verification details that exist only in the predecessor's return. Source files and other declared workspace artifacts can still be available; the source does **not** establish that all outputs disappear or that the dependent task actually makes an error.

2. Completion projects A's return and records it in the orchestrator's in-memory result cache: [completion](https://github.com/theRebelliousNerd/codenerd/blob/356f65e0e6bb639adaa90ab36212daa714114871/internal/campaign/orchestrator_tasks.go#L632-L670), [result cache and rendering](https://github.com/theRebelliousNerd/codenerd/blob/356f65e0e6bb639adaa90ab36212daa714114871/internal/campaign/orchestrator_task_results.go#L78-L208).
3. A saved campaign task retains its status, context edges, artifacts and attempts, but not that return projection or a durable return reference: [task fields](https://github.com/theRebelliousNerd/codenerd/blob/356f65e0e6bb639adaa90ab36212daa714114871/internal/campaign/types.go#L308-L355).

## Existing protections and boundaries

Analysis/research outputs have a separate artifact persistence path; file, test, tool and refactor tasks are treated differently. Declared artifacts are remeasured from the workspace and can be selected independently. Code preloading can make changed source available. These are useful protections but do not necessarily reconstruct return-only findings, caveats or checks. See [artifact handling](https://github.com/theRebelliousNerd/codenerd/blob/356f65e0e6bb639adaa90ab36212daa714114871/internal/campaign/orchestrator_task_handlers.go#L300-L308) and [output persistence](https://github.com/theRebelliousNerd/codenerd/blob/356f65e0e6bb639adaa90ab36212daa714114871/internal/campaign/orchestrator_task_handlers.go#L375-L403). A result projection can itself include a handle to process-local retained content, so persisting the visible string without its backing content does not guarantee a usable long return.

## Proposed contract

Separate **task completion** from **evidence availability**. Bind a return or durable handle to campaign ID, producer task ID, attempt, projection/schema version and admitted snapshot generation. Publish a completed status and its evidence reference consistently; before dispatch, resolve each policy-selected context edge. Surface present, absent, stale, unreadable and expired explicitly as facts. Let Mangle choose a bounded retrieval, a qualified continuation, a block or operator review according to the task's needs. Do not rerun a completed side effect simply to recover its report. For legacy snapshots, explicitly mark evidence unavailable; never invent an empty successful return.

A durable result store, journal events with replay, or versioned artifact references are design alternatives, not a mandate to adopt any one framework. Temporal's [event-history documentation](https://docs.temporal.io/encyclopedia/event-history) describes how durable history enables replay; it does not prove this proposal correct or imply CodeNERD must use Temporal.

## Evaluation plan and costs

With fake deterministic handlers in a future test environment, produce a return-only marker from A, commit a generation, end the process, cold-resume with B pending and capture B's actual input. Require either the correct marker or an explicit policy disposition; compare with uninterrupted execution. Include long returns and backing handles, missing/corrupt evidence, stale attempts, duplicate delivery, crash points between evidence and snapshot publication, both artifact-deduplicated and non-deduplicated paths, legacy snapshots, and concurrent admission. Verify no side effect repeats merely because its report is missing.

Measure bytes retained per task and campaign, extra writes, sync and restart latency, projection/lookup CPU, prompt tokens, handle misses, cleanup cost, and success/repair rate against current behavior under matched tasks and budgets. Preserve privacy and retention limits for potentially sensitive return text; garbage-collect only after dependents and recovery horizons no longer need it. No performance, reliability or token saving is claimed without measurements.
