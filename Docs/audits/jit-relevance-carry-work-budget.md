# Bound JIT relevance work and publish carry from completed prompts

## Finding and status

At main `9dcb01b9736bf4763aa3ac391d29f133d73c6611`, the JIT selector remembers every Mangle-selected flesh atom **before** dependency resolution and final token fitting. The next compile for the same carry key adds every still-eligible remembered atom to its relevance pool, without applying another combined limit. Consequently, atoms that never appeared in a completed prompt can receive carry priority and consume relevance-judgment work on later turns. The configured `atom_relevance_pool` does not bound this combined workload.

This is a source-supported production wiring and resource-contract refinement, not a demonstrated production incident, an infinite memory leak, a permission bypass, or a claim that carry-over itself is accidental. Carry-over and its hysteresis are explicitly documented. The narrower opportunity is to make its publication boundary and total resource budget explicit while preserving its intended prompt-prefix benefit.

Inspection only: no tests, runtime commands, model calls, training, implementation, were performed. The proposal uses public repository sources. Main was checked at this pin on 2026-10-29.

## Existing contract and overlap

The architecture describes a recall pool of normally 40 atoms, followed by carry-over that rejoins previous admitted atoms and retains them through unsettled judgments to stabilize the provider-cache prefix. Thus the documentation already acknowledges the mechanism; it does not establish a hard combined cap. In contrast, the configuration and runtime field comments describe `Pool` as bounding atoms judged per compile. [Architecture and carry policy](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/Docs/architecture/prompt/IMPLEMENTED_SPEC.md#L428-L456), [configuration contract](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/config/typesafe.go#L114-L131), [runtime contract](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/relevance.go#L64-L76).

This is distinct from the existing [generation-aware JIT optimization audit](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/Docs/audits/jit-generation-aware-optimization.md), [dependency-closed budgeting audit](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/Docs/audits/jit-dependency-closed-budgeting.md), and earlier research on section relevance, judgment metadata cache identity, and kernel content identity. Those concern source freshness, admission or final prompt correctness; this candidate concerns the state that the selection phase publishes for future judgment work. Current subsystem guidance keeps relevance admission in Mangle and says failed or late judgments assert nothing; any remedy should preserve that boundary. [Prompt guidance](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/agents.md).

## Producer to consumer trace

1. **Production activation.** System boot resolves TypeSafe configuration and installs `atomjudge.RelevanceFor` on the JIT compiler. A missing/invalid client or disabled use leaves the path off. With a configured section, defaults are pool 40 and judgment timeout four seconds. [Factory](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/system/factory.go#L1862-L1871), [adapter](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/atomjudge/relevance.go#L78-L94), [defaults](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/config/typesafe.go#L121-L180).

2. **Pool extension.** `runSelection` obtains vector slots, calls `recallPool(..., rel.Pool)`, then calls `carriedInto` on that map. The latter appends every eligible carried ID, using zero if it has no current raw vector score. It has no budget parameter or final cap. [Selector](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/selector.go#L816-L838), [carry insertion](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/relevance.go#L148-L169).

3. **Every uncached member is judged.** `judgeRelevance` sorts all pooled IDs, uses request/content memo hits, and sends every remaining atom to the judge under the configured timeout. There is no subsequent count or aggregate input-token limit at this boundary. [Judgment collection](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/relevance.go#L277-L344).

4. **Successful selection publishes carry early.** After querying `selected_result`, `queryFleshAtoms` calls `rememberCarry(cc, selected, carriedRank)`. That function records all selected IDs, not final included atoms. It runs before the compiler's section expansion, dependency resolution, fit, assembly, and final dependency closure. Those later stages may drop atoms or fail. [Publication](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/selector.go#L1240-L1316), [remembered IDs](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/relevance.go#L452-L470), [pipeline ordering](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/compiler_pipeline.go#L301-L343), [final fitting and closure](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/compiler_render.go#L14-L63).

5. **Carry has a downstream preference.** Mangle admits a recalled carried atom unless relevance explicitly refuses it; unsettled is not refusal. The selector marks judged carried atoms and assigns their carried score. This is intentional hysteresis, but an atom omitted from the preceding prompt can now receive that preference. [Mangle rule](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/core/defaults/jit_compiler.mg#L247-L302), [scores and carried marker](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/selector.go#L1277-L1306).

6. **The lifetime crosses real chat turns.** The carry key is shard type, intent verb and target—not request text. Main chat builds a fixed chat shard, sets the turn's verb and latest user utterance, and leaves target at its empty default. Consecutive same-verb chat turns can therefore preserve the carry key while changing both the relevance-request key and compilation hash. The chat directly compiles and uses the result. This establishes an actual producer-consumer route; the particular atom scores and long-session growth remain conditional. [Carry key](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/relevance.go#L142-L146), [chat context](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/persona.go#L318-L402), [chat compilation](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/persona.go#L483-L521), [request identity](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/relevance.go#L45-L53), [compile identity](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/context.go#L731-L735).

## Minimal conditional witness

Use one compiler/selector, working Mangle selection, enabled relevance, a positive pool limit `P`, and vector-slot count no greater than `P`. Keep the carry key and all relevant eligibility gates stable.

- First compile: optional atom A is in the recall pool, receives an applying judgment, and is selected. Make A too large for the final remaining prompt budget, with no smaller rendering that fits, but comfortably below the judge's per-question limit. The mandatory skeleton still fits. The completed prompt omits A, while `rememberCarry` has already retained it. Whole-atom omission is supported by the fitter. [Optional fitting](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/budget.go#L577-L644).
- Second compile: change request text so both caches miss, but retain the carry key. Let its initial recall pool contain `P` different eligible atoms, excluding A. `carriedInto` produces `P+1` pool members. A is asked about again despite not appearing in the preceding prompt.
- If A now receives an unsettled judgment and new atoms receive applying judgments, the carried rule can keep A and the new admissions can enter carry. Repeat with additional distinct requests/candidates, keeping atoms eligible and not refused. The set can grow toward the eligible corpus, rather than being bounded by `P` or the final prompt token budget.

A smaller fixture can use `P=1` and A/B; a default-sized fixture should separately use `P=40`. No live provider behavior is assumed: scripted judge responses suffice to evaluate the wiring later.

A separate publication-boundary control should make a compile fail after selection. Source order permits carry to change although no prompt was returned. That is not needed for the successful-budget-shedding witness.

## Bounds and counterevidence

- **Not unbounded beyond the corpus.** Carry stores IDs of selected atoms. Current eligibility filters, finite source collection and corpus size bound the possible set. The 512 limit bounds remembered task keys, not IDs per task. [Memory structure](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/relevance.go#L111-L140).
- **Not every Pool overrun is caused by carry.** `recallPool` deliberately preserves every vector slot, even when slots already exceed Pool. The witness must hold slots at or below Pool and count the incremental carry extension separately. [Recall algorithm](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/relevance.go#L222-L275).
- **Same-request compiles are cheaper.** Relevance answers are memoized; compiled-result cache hits can bypass selection entirely. Growth requires real selector work and changed or uncached judgment inputs. Do not multiply provider cost by every internal compile.
- **Carry is filtered, not absolute authority.** It excludes absent, mandatory, retrieved-context and context-ineligible atoms. Flesh filtering also checks world state and available tools. Mangle refusal, conflicts and dependencies still apply. A changing target/shard/verb gives a different carry key; a fresh compiler loses this memory. [Carry eligibility](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/relevance.go#L151-L166), [flesh eligibility](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/selector.go#L1143-L1158).
- **All-or-nothing fallback is deliberate.** Failed, late or incomplete judgment leaves vector-only evidence; it does not publish a partially judged carry update through the successful selection path. Carry rejoining is already explicitly asserted by an existing test, which was read, not run. [Fallback](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/selector.go#L818-L834), [existing carry test](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/relevance_test.go#L277-L300).
- **Per-request limits exist.** Atom judging splits at 40 questions or 40,000 estimated guidance tokens and rejects guidance exceeding 30,000 tokens per question. Every batch gets a parallel goroutine; one batch failure fails the whole judgment. Those limits bound individual requests, not the number of batches. Transport/provider limits can constrain actual concurrency; no throughput claim is made. [Batching](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/atomjudge/importance.go#L19-L63), [parallel judgment](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/atomjudge/relevance.go#L24-L75).
- No measured latency, monetary loss, timeout rate, answer-quality regression or observed stock-corpus saturation is established.

## Proposed contract and options

**Separate semantic admission memory from prompt-prefix memory.** Decide whether carry means “previously selected” or “present in the last successfully compiled prompt.” If the purpose is prefix reuse, stage candidates during selection and publish only the final fitted flesh IDs after successful assembly and dependency closure, in actual emitted order. Keep a distinct bounded reconsideration set if selected-but-omitted guidance should remain discoverable. Do not call successful compilation actual delivery to the model; delivery acknowledgement would require a separate owner and contract.

**Define a combined workload budget.** Preserve vector-slot semantics explicitly, then define total judgment count, aggregate estimated input tokens, and maximum in-flight batches. Options are a documented soft Pool plus separate carry budget, or a hard combined cap with reserved capacity for new retrieval. Deterministic eviction or scheduling must be visible; silently truncating carried IDs can harm the very prefix/recall behavior this mechanism protects.

**Keep Mangle in charge of admission.** Resource scheduling should emit explicit bounded nominations and deferred status, not fabricate relevance refusals or treat unasked atoms as “does not apply.” Settle how the existing no-judgment vector fallback interacts with deferred carry. Preserve context/tool gates and complete-judgment semantics unless a separately reviewed policy intentionally changes them.

**Make publication transactional.** Do not advance prefix memory on selection-only success, render failure, cancellation or obsolete source generation. A later implementation must define ordering for overlapping compiles sharing a carry key and for compiled-cache hits; simply moving the existing write later is insufficient if an older completion overwrites a newer one. This is a design obligation, not a separately demonstrated concurrency incident.

## Costs and fair evaluation

The current extra work is proportional to uncached combined pool size, not merely configured Pool: judgment payload includes each atom plus repeated request state per batch; selection also allocates and sorts the wider pool. Additional batches can increase provider usage, contention and the chance that the all-or-nothing result falls back. A four-second deadline limits allowed duration, not work already dispatched. Exact money and latency require the configured provider/model's actual usage and tariffs; none are estimated here.

Publishing final survivors requires carrying selection provenance into finalization and reconciling section expansion, dependency closure, cache hits and concurrent completion. A bounded queue adds state, metrics and fairness rules. Retaining only fitted atoms may repeatedly rediscover budget-dropped but useful guidance; bounding carry can shorten provider-cache prefixes, increase churn, and omit relevant instructions. Reserved new-candidate capacity can improve adaptation but reduce stability. More concurrency restriction may increase tail latency even as it lowers peak load.

A later evaluation should compare the unmodified baseline against: final-survivor publication only; combined-budget scheduling only; and both together. Use identical public synthetic/public-repository tasks, corpus, vector scores, prompt budget and scripted judgments before any separately authorized provider evaluation.

Required deterministic cases:

1. A selected-but-budget-dropped atom does not become prefix carry under the proposed contract; a genuinely included carried atom remains stable.
2. Same-key changing-request sequences with disjoint new candidates remain within the declared combined budget; report eligible-corpus size and slots separately.
3. Context/tool ineligibility, explicit no, changed target, unavailable judge, missing answer, oversized question and timeout retain their documented behavior.
4. Failed/canceled renders and overlapping compile completions do not publish obsolete prefix memory.
5. Cache-hit and repeated identical-request controls avoid unnecessary judgment; dependency and section closure remain intact.

Measure pooled, carried, uncached and finally included IDs; selected-but-omitted carry count; input tokens and batch count; peak outstanding requests; cache-hit rates; fallback rate; compile p50/p95; actual common-prefix bytes; and atom recall/precision against a fixed relevance oracle. Also evaluate task-result quality and relevant-guidance coverage—not just fewer calls. Any later provider comparison needs separate authorization, a frozen versioned model, equal task/context budgets, repeated runs and reported uncertainty. Accept only an explicit cost/quality tradeoff that preserves mandatory instructions, tool authority and complete final-prompt budgeting.
