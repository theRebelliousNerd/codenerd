# Multi-step failures reach the person but not the delivery judge

## Finding and scope

**A failed ordinary multi-step worker can preserve and display its error and measured partial work, yet contribute neither to the later request-delivery judgment.** `executeMultiStepTask` appends a hard-error step to the visible result and then continues before appending that worker's `observation.Return` to its delivery reports. If another step returned without an error, delivery can still run, using only the nil-error reports. The judge that asks whether an external obstacle prevents further work therefore cannot inspect the omitted failure through this input.

This is a **later-consumer residual of the delegated-turn failure-settlement audit**, not a finding that failure settlement or visible partial-state reporting remains unfixed. It is also not the prior multi-step fallback-edge problem, and does not require a conditional plan. The deterministic claim is input loss. Unnecessary continuation, repeated work, or an inaccurate delivery note are **conditional consequences**, not reproduced outcomes or a permission bypass.

## 1. Existing repairs and the narrow remaining boundary

The [failure-settlement audit's as-built account](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/Docs/audits/delegated-turn-failure-settlement.md#L209-L237) correctly credits a common terminal settlement, retained writes and receipts, honest failed verdicts, and `Return.PartialState`. It specifically closes the multi-step visible-observation issue because `withPartialState` now accompanies its error. The source confirms that protection. This report does not reopen that closure: **presentation has the evidence; request-level delivery judgment does not receive it**.

The [multi-step fallback-condition audit](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/Docs/audits/multistep-fallback-condition.md) addresses erased conditional relationships and dependency admission. The witness below uses an ordinary sequential pair whose second step legitimately runs after a nil-error first step. It does not depend on incorrectly running a fallback or equating nil error with verification. The 10:49 verified-delivery change-evidence continuation concerns a different adapter dropping the structured change list of a verified result; here the whole hard-error step is filtered from the request-level consumer.

These distinctions matter to a fix. Keep truthful surfaces, terminal settlement, dependencies, typed authority, and Mangle's continuation decision. Do not restore unfinished model text, assume every error is an external blocker, or turn a report append into a new execution grant.

## 2. Reachable production path

### Admission is real, but conditional

Normal routing extracts multi-step signals, decomposes the input, and asserts the routed plan's steps in [`delegation_routing.go:166–190`](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/cmd/nerd/chat/delegation_routing.go#L166-L190). The [policy](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/core/defaults/policy/routing_arbitration.mg#L224-L266) requires a ready multi-step mutation plan and ordinary work admission, rather than treating every conjunction as executable. The actual [`RouteMultiStep` branch](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/cmd/nerd/chat/process.go#L520-L528) calls `executeMultiStepTask` with the routed steps and original input. Despite its filename, this function is not limited to an approved dream-plan queue.

The required witness is an admitted two-step request: step A returns without a Go error; step B runs and returns a hard error. A is not assumed verified or successful merely because its error is nil. No later independent step is necessary. The source-level finding applies once this route and result shape occur; this review does not claim a particular natural-language request is guaranteed to receive that classification in a live deployment.

### A populated return and a non-nil error can coexist

[`spawnTaskWithContext`](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/cmd/nerd/chat/delegation.go#L96-L105) uses the observed-execution interface when available. On the ordinary inline task path, [`task_executor.go:443–472`](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/session/task_executor.go#L443-L472) calls `ProcessWithIntent`, constructs the observation with measured turn writes, supplies a failure string when needed, and returns both that observation and an execution error.

This is not merely an imagined mock shape. [`runToolLoopPass`](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/session/executor_tools.go#L84-L113) propagates an initial generation error; its [follow-up error branch](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/session/executor_tools.go#L366-L381) can fail after tool work. [`ProcessWithIntent`](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/session/executor.go#L1594-L1608) sends the latter through terminal settlement rather than throwing the measured result away.

For a concrete external-error producer, the [Anthropic transport](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/perception/anthropic_transport.go#L183-L206) returns non-transient non-200 responses as errors, and [`AnthropicAPIError`](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/perception/anthropic_transport.go#L20-L52) retains status, type, and provider message. An authentication rejection naming a credential problem is therefore an example of a hard error that need not cancel the caller context. **For later judgment to run, the delivery judge must remain available.** A shared credential outage that also disables Jev instead reaches the existing judge-error stop; that is a negative control, not this impact witness. No live provider rejection or independently healthy deployment was exercised here.

### The producer separates visible failures from judgment reports

The relevant order in [`executeMultiStepTask`](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/cmd/nerd/chat/process_dream.go#L692-L791) is:

1. Execute the worker and retain `ret.Output`.
2. Publish result/error facts through `ResultToFacts`.
3. If `err != nil`, append a failed status plus `withPartialState(err, ret)` to visible `results`, then continue.
4. Only below that branch, append the shard to `ran` and the observation to `reports`.
5. After the plan, if delivery starts and `len(ran) > 0`, record only `reports` and call `nextStep`.

Consequently, B's error, output, changed paths, and other partial observation are absent from this delivery chain even when the screen reports them. The visible aggregate is not the judge input. The code separately counts verified outcomes, so describing `reports` as “successful steps” would be inaccurate: **they are the nil-error subset**. Dependency skipping and the honest verification distinction remain intact.

The host is not wholly ignorant of failure. [`ResultToFacts`](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/core/shards/manager_spawn.go#L714-L763) emits `shard_error` on the error path. That is useful evidence for other consumers; it is not inserted into the separate `CheckDelivery` state.

## 3. Why the omission can change continuation

Delivery requires a kernel, Jev, enabled instruction coverage, and nonempty request fragments; [`startDelivery`](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/cmd/nerd/chat/request_delivery.go#L46-L69) checks these. The caller additionally requires at least one nil-error routed step. [`nextStep`](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/cmd/nerd/chat/request_delivery.go#L276-L287) gives existing derived obligations precedence, so a clean demonstration must have no earlier ordinary obligation to consume that boundary.

[`judgeDelivery`](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/cmd/nerd/chat/request_delivery.go#L114-L152) supplies the original request, recorded reports, recorded changed paths, and fragments. [`deliveryState`](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/learnjudge/delivery.go#L93-L113) renders those reports into a bounded `result` field. [`CheckDelivery`](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/learnjudge/delivery.go#L45-L90) asks its blocker question about that field. The [question contract](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/learnjudge/report.go#L61-L71) distinguishes an obstacle the agent cannot clear—such as missing credentials, permission, or a user choice—from work it can still do.

An observational-equivalence witness isolates the defect: hold the request, fragments, and all nil-error returns fixed, and vary only B's error/observation between (a) an explicit missing-credential obstacle and (b) a transient provider failure with no lasting external obstacle. Keep the caller context live in both. Both produce the same request-delivery input, although their visible failure evidence differs. This proves the consumer cannot distinguish those outcomes **from the supplied evidence**. It does not prove what an actual probabilistic judge will answer, nor that the original request or A's report cannot independently reveal the obstacle.

The [delivery policy](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/core/defaults/policy/request_delivery.mg#L58-L115) derives a gap only at its missing threshold with no result cut, blocks at its blocker threshold, and suppresses stalled rounds. If B's work is read as missing and the blocker reading stays below threshold, a non-stalled active request can offer a gap step. The [ordinary continuation gate](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/core/defaults/policy/codedom_continuation.mg#L80-L101) blocks interruption or pending clarification; a `shard_error` by itself is not a blanket continuation block in these rules.

This may send another worker toward a known obstacle, consume avoidable calls, or cause it to reconsider already measured partial work without this receipt. It may instead produce a paused offer, no offer, or a useful recoverable retry. Actual dispatch remains subject to [`offerOrDispatch`](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/cmd/nerd/chat/continuation_ledger.go#L76-L90) and work-mode policy. Yolo permits otherwise-admissible continuation; Propose/Explicit can pause. Tool authorization, verification, existing kernel obligations, and interruption still apply. Later worker context or history may also recover the error. **This is not evidence of unauthorized tool execution, erased durable state, guaranteed duplicate writes, or a false claim that the entire plan verified.**

## 4. Repair contract

Repair the producer-to-consumer contract, not just the visible message:

1. **Conserve every attempted step's terminal evidence.** Append a delivery observation regardless of Go error, with stable plan-step identity, task, outcome, failure, report, and relevant measured change/receipt summary. Preserve the distinction between attempted, skipped, nil-error, and verified. Do not promote a failed step into the dependency-success map merely to make it reach delivery.
2. **Carry failure alongside nonempty output.** Merely moving `reports = append(...)` above the error branch is insufficient for the general contract. [`record`](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/cmd/nerd/chat/request_delivery.go#L80-L98) currently uses `Failure` only when `Output` is empty. Failed settled turns can have a nonempty evidence summary. Preserve both, with an explicit terminal-status label; do not choose one as a fallback for the other.
3. **Keep policy interpretation separate.** A hard error is not necessarily an unresolvable blocker. Supply evidence to the existing blocker/coverage contract, or introduce a reviewed typed classification for host-known causes. Do not globally convert any provider error, timeout, or verification failure into a permanent stop. If a deterministic external-blocker fact is added, define its scope, provenance, retirement, and relationship to retries/user decisions before wiring it to policy.
4. **Bound without selectively hiding failures.** Allocate a small protected failure/status section and bounded evidence summaries per step; retain explicit omission metadata and existing cut protections. Avoid embedding full preimages or raw tool payloads in a judge prompt. The history of a failed attempted write is evidence, not a grant to retry it.
5. **Keep request ownership and routing stable.** Do not let a stale failure contaminate a new request, change which completed step satisfies a dependency, or accidentally change `gapShard` selection just because a failed attempt is now recorded. Decide separately whether skipped dependent steps need explicit delivery labels. Preserve current active-request retirement and work-mode pauses.

A minimal structured per-step projection can close the evidence gap without replaying any worker or adding a judge round. A broader redesign can reuse typed observations, but should not copy the entire execution packet or silently alter obligation admission.

## 5. Fair evaluation and costs

Existing [`TestDeliveryMultiStep_APlanThatMissedAPartGoesOn`](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/cmd/nerd/chat/request_delivery_test.go#L333-L353) demonstrates the missing-part continuation with ordinary returns. It directly invokes the multi-step executor; it does not establish the normal perception/routing journey or inspect a hard-error step's blocker evidence. The [named-blocker delivery case](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/cmd/nerd/chat/request_delivery_test.go#L210-L228) is a positive control for evidence that actually reaches the consumer. These test descriptions are static readings, not test results from this review.

Recommended evaluation, **not performed**:

- Enter a normal two-part mutation request through the production chat/perception route, with normal CodeDOM/world context and policy admission. Observe the selected route and step identities; reject fixtures that accidentally exercise dream-plan scheduling or another lane.
- Use a deterministic provider boundary to make A return normally and B fail, first before effects and then after a measured partial write. Keep the caller context alive. Capture the actual `CheckDelivery` state and visible surface; assert that both preserve B's failure and partial evidence after repair. Include a nonempty B output plus failure, not only an empty-output case.
- Compare the observational-equivalence pair above under identical request, nil-error reports, thresholds, and context. First prove the input difference deterministically. Then test conditional policy behavior with fixed readings, and separately evaluate live judge discrimination. Do not report mocked probabilities as evidence of real semantic quality.
- Exercise a named external blocker, a retryable failure, verification failure, canceled caller, absent Jev, disabled coverage, Jev failure, no nil-error steps, earlier ordinary obligation, cut reports, stalled rounds, and interruption/clarification. Verify Propose/Explicit pause and Yolo's ordinary authorization boundaries.
- Inspect tool attempts and workspace effects to distinguish an offered continuation from a dispatched worker and from a duplicate side effect. Confirm the earlier visible partial-state repair and verified-count distinction remain unchanged.

The expected implementation cost is local projection/contract work plus regression coverage. Prompt bytes and judge tokens increase with retained failures, especially after partial tool work; measure bounded state bytes, truncation frequency, calls, latency, and retention rather than assuming the cost is negligible. No additional model round is inherently necessary. A smaller projection costs less but risks discarding task identity or the explanation that makes a blocker interpretable; a full observation dump adds irrelevant, potentially sensitive content and budget pressure.

Measure unnecessary continuations avoided **and** useful recoverable continuations wrongly suppressed. Include final request delivery, remaining unmet work, false-blocker rate, offered-versus-executed steps, repeated tool calls, and user wait time. Compare semantically matched journeys, not a patched full-context run against an unpatched truncated or differently routed run. The static result is a supported evidence-conservation gap; its operational frequency, token cost, and effect on delivered work remain unmeasured.
