# Generated test authority must cover the code that runs

## Finding and evidence boundary

The normal Ouroboros generation flow audits the generated tool implementation, then executes a second model-produced program fragment that the audit did not inspect: `GeneratedTool.TestCode`. The compiler writes that fragment as `tool_test.go` and runs `go test ./...` before producing the final tool binary. The existing default denial of `os/exec` applies to `tool.Code`; no corresponding admission of the generated test file is visible in this path.

This is a source-supported capability-coverage gap, not an observed exploitation report. A narrow, non-destructive witness uses a safe pure-function implementation and a compiling generated test that invokes the already-installed Go executable to obtain its version. If generation reaches its ordinary test gate, that test can start a child process even though `AllowExec` is false. No malicious user, stolen credential, external network request, permanent process, or destructive action is needed for this witness. It is conditional on the model returning that test program and all earlier admission and generation gates succeeding; it is not a prediction that an ordinary model response will do so.

All CodeNERD implementation references below are pinned to main `388205138ba6d47c1cff0c5e97c896dfa642a391`, rechecked on 2026-10-30 at 16:44 UTC. Main had not advanced. The latest research branch examined was `research-main-20261030-1619`, tip `3ef34bc061b497b9cfc471f4cc46f5df595b299d`, containing four documentation additions rather than a repair of this path. This proposal follows static inspection and independent source challenge. No tests, model inference, compiler invocation, benchmarks, or runtime experiments were run for it.

## The authority that already exists

Default configuration intentionally disables both networking and command execution. The `AllowExec` comment explains the decision: permitting `os/exec` grants a materially broader capability and now requires explicit workspace opt-in. The checker constructs its import allowlist from the configuration, adding `os/exec` only when `AllowExec` is true and networking packages only when networking is enabled. The embedded policy derives a violation for an import absent from that list. These are real controls, not merely prompt wording. [Defaults](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/autopoiesis/ouroboros.go#L162-L186), [allowlist](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/autopoiesis/checker.go#L409-L442), [policy](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/core/defaults/go_safety.mg#L1-L26).

The checker fails closed on policy-load, parse, engine, fact-admission, or query errors. Current tests explicitly cover default denial and deliberate opt-in for `os/exec`. This proposal does not weaken those controls or repeat the old missing-policy diagnosis; it concerns executable input never supplied to that checker. [Checker failure paths](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/autopoiesis/checker.go#L268-L360), [default and opt-in tests](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/autopoiesis/checker_failclosed_test.go#L245-L286).

Tests legitimately need some different facilities from shipped tools. The current base allowlist does not even contain `testing`. Thus the repair cannot simply apply an unchanged production-tool policy to every test and call the resulting blanket rejection secure. Nor should it solve this by globally allowing `os/exec` or networking for all generated tools. The missing contract is an explicit test-program authority derived from the authorized operation, with narrowly identified test-only support.

## Normal producer and consumer path

An explicit `nerd tool generate` request calls the orchestrator's full Ouroboros loop. The orchestrator delegates to `o.ouroboros.Execute`; this is the durable generator, not the historical helper that returned planning prose without registration. [CLI consumer](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/cmd/nerd/cmd_advanced.go#L1025-L1056), [orchestrator](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/autopoiesis/autopoiesis_tools.go#L126-L147).

The relevant stages are:

1. **Two separately generated source bodies.** `GenerateTool` obtains implementation code, generates test code, and puts them into distinct `Code` and `TestCode` fields. The test writer receives the tool implementation and a compiled role prompt. A nonempty extracted Go response of at least 50 bytes is returned; a failed or thin response uses template tests. There is no capability check on that extracted test body here. [Construction](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/autopoiesis/tool_generation.go#L83-L138), [test generation](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/autopoiesis/tool_generation.go#L369-L391).
2. **Implementation-only checks.** The preliminary structural validator explicitly receives `tool.Code`. The authoritative Ouroboros safety checker also receives `tool.Code`, as does code-purpose Jev. A safe implementation therefore does not establish that the second field has passed either check. [Structural validator](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/autopoiesis/tool_validation.go#L25-L43), [safety and purpose checks](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/autopoiesis/ouroboros.go#L493-L555).
3. **The arena is not a test-file audit.** PanicMaker is asked about the implementation. `prepareArena` normalizes and writes `tool.Code`, then writes its own host-generated harness. It does not copy the model's `TestCode` into that arena. A successful adversarial run remains useful evidence about the implementation under those attacks, but it does not assess the later model-written test program. [PanicMaker input](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/autopoiesis/ouroboros.go#L565-L578), [arena construction](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/autopoiesis/thunderdome.go#L180-L243).
4. **The second field becomes executable.** After simulation admits the transition, `commitTool` acquires the per-name operation lock, snapshots the old artifacts, writes source and tests, and calls the compiler. The compiler copies and package-normalizes `TestCode` into a temporary `tool_test.go`, runs module tidy, and invokes native `go test ./...` when the field is nonempty. [Transition and commit](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/autopoiesis/ouroboros.go#L676-L704), [publication transaction](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/autopoiesis/ouroboros.go#L850-L921), [test materialization and execution](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/autopoiesis/tool_compiler.go#L105-L175).

The role prompt asks for comprehensive happy-path, error, and edge-case tests in package `tools`. It does not establish a separately approved command or networking capability. Prompt compilation is a useful contract check, but successful compilation of that instruction is not host authorization of every operation in the reply. [Test-writer atom](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/prompt/atoms/autopoiesis/tool_roles.yaml#L196-L217).

## A narrow source-derived witness

Use an authorized fresh generation on a host-compatible target with a working Go toolchain, sufficient parent deadline, and default `AllowExec == false`. Let the implementation be a valid, policy-accepted pure string transformation with the required context/string/error signature. Let the separate test-writer reply be a valid test file longer than the extraction minimum, using only standard-library dependencies, with an ordinary `Test...` function that calls `exec.Command("go", "version").CombinedOutput()` and handles its error through the testing API. The child command is benign; its purpose is to distinguish invocation authority from a successful compiler result.

The witness additionally requires no reuse short-circuit, successful earlier source checks and simulation, and an actual uncached test execution. Compilation or vet failure, expired context, incompatible target, cache reuse, or an earlier generation rejection can prevent the child invocation and are controls rather than successful witnesses. No external dependency resolution is necessary for the selected test.

Go's documented test operation builds `_test.go` files into a test binary and executes it; the selected default vet checks are not CodeNERD's configured import policy. The same Go documentation describes placing the Go toolchain directory on the test process's path. Thus this is a program executed by the host toolchain, not an inert test description. [Go test semantics](https://pkg.go.dev/cmd/go#hdr-Test_packages), [pinned reference implementation and help text](https://github.com/golang/go/blob/6e676ab2b809d46623acb5988248d95d1eb7939c/src/cmd/go/internal/test/test.go#L64-L94).

On that admitted execution, the model-written test program can start the extra Go process. If the same `os/exec` import were in the implementation, the configured safety policy would reject it. The effect happens before final tool registration, so a later build or registration failure does not mean that no test-program effect occurred. Conversely, a successful test does not put its test-only function into the final shipped tool binary; this finding does not claim that ordinary final `go build` packages the test source into that binary.

Checking only named test functions would also be incomplete. Go initializes package variables and runs `init` functions before entering the program's main function. Admission must cover the complete selected test compilation unit, including helpers, initialization, and any deliberately supported `TestMain`, rather than just assertions or names beginning with `Test`. This language fact defines the repair boundary; the narrow witness above does not rely on a hidden initializer. [Go initialization semantics](https://go.dev/ref/spec#Program_initialization).

## Controls that limit the finding

The build runs in a fresh temporary directory and removes it afterward. Tests use the shared build environment, configured target, and `CGO_ENABLED=0`; the environment is assembled from essential Go variables, explicit allowed variables, and project build configuration rather than blindly inheriting every secret. These are useful protections. A temporary working directory and disabled CGO do not constitute a filesystem, network, or subprocess capability sandbox for a native Go program. This report does not assert secret exposure. [Temporary workspace](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/autopoiesis/tool_compiler.go#L59-L69), [test environment](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/autopoiesis/tool_compiler.go#L150-L167), [environment construction](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/build/env.go#L125-L157).

The test gate has a context timeout, returns a failure on a nonzero test result, and retains diagnostics. Compilation failure reaches snapshot rollback rather than registration. Those controls protect publication and provide feedback; they do not retroactively undo an already executed test's arbitrary external effects. The current rollback fixture checks restoration of generated artifacts, not a transaction over every possible native test effect. [Gate](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/autopoiesis/tool_compiler.go#L150-L175), [rollback boundary](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/autopoiesis/ouroboros.go#L868-L920), [rollback tests](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/autopoiesis/commit_cleanup_test.go#L16-L149).

Existing tests prove that failed and uncompilable generated tests block successful compilation, and that empty `TestCode` is currently permitted to skip this gate. The multistage flow uses a simple passing generated test. None of these inspected fixtures establishes admission of a test-only capability absent from the implementation's grant. Do not remove their positive coverage while adding the new boundary. [Gate fixtures](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/autopoiesis/tool_compiler_gating_test.go#L10-L151), [multistage reply](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/autopoiesis/ouroboros_multistage_e2e_test.go#L58-L68).

## Proposed admission contract

Treat a generated candidate as an executable bundle, not just an implementation string. Bind the implementation, normalized test source, host wrapper/harness identity, target, policy version, and capability grants to the admission result. Validation must cover the actual bytes selected for execution, including regeneration and fallback paths. A stale result must not authorize changed tests. The per-tool publication lock and rollback must remain intact; they solve a different race and should not be replaced by a policy check.

Define a test-specific policy that permits the testing framework and reviewed fixture facilities while inheriting the operation's hard capability limits. Ordinary `testing` and legitimate test failure reporting must work. Any need for extra process, network, or filesystem authority needs an explicit, narrow host decision or a constrained fixture service; a model's choice to import a package is not such a grant. Keep this policy distinct from the production implementation policy, and do not silently widen the latter to make tests pass.

Perform source-bundle admission before native test execution and preferably before `go mod tidy` resolves imports from that bundle. Include dependency policy explicitly if third-party test helpers are allowed. Parsing and allowlisting a top-level file is not a claim of complete transitive behavioral confinement. If tests require broad native behavior, evaluate a real isolated runner with explicitly mounted inputs, bounded resources, scrubbed environment, and controlled network/process access. That is a larger security design, not a free consequence of using a temporary directory.

On denial, report the offending test source and capability separately from a failing assertion or a bad implementation. Preserve the test source for bounded diagnostic review according to existing privacy and artifact policy; do not simply erase tests and proceed to the final build, because that converts a safety refusal into a vacuous quality pass. A rejected test can be regenerated within an owned retry budget, but neither repeated attempts nor human confirmation of tool creation should silently add capabilities. A permitted empty-test route, where intentionally retained, must remain explicit rather than become the denial fallback.

## Costs and prospective evaluation

Deterministic admission adds parsing, fact construction, policy evaluation, and diagnostics proportional to the admitted source bundle. It needs test-aware language handling, policy-versioned receipts, and consistent normalization; dependency-aware checks or isolated execution cost more. Rejecting useful tests can reduce bug detection, and regeneration can add latency, model calls, and token cost. Those costs must be measured against actual safety coverage and retained test quality, not assumed away. No measured performance or spending improvement is claimed. The minimum policy integration does not inherently require another model call.

The following evaluations are proposed and unrun:

- Drive the actual authorized generation path with deterministic model responses, leaving the generator, checker, arena wiring, compiler, and publication boundary real. Use a pure implementation plus the benign test-only child invocation. Confirm that the current path reaches the child only under the stated prerequisites; the repaired path must deny before test execution under default authority.
- Move the identical `os/exec` use into the implementation as a negative control. Preserve current rejection. Under explicit process authority, verify a permitted test still runs without granting networking or unrelated capabilities. Include default-denied networking with a local, nonexternal fixture if that policy is evaluated.
- Exercise legitimate `testing`, table-driven assertions, failure reporting, context tests, host-provided fixtures, and generated fallback tests. Measure lost test coverage and false refusals; a policy that refuses every test fails the evaluation.
- Cover helper functions, aliases, package initialization, `TestMain`, supported dependencies, target/build selection, malformed input, changed test bytes after an admission receipt, and regeneration. Do not claim completeness merely because the ordinary `Test...` witness is denied.
- Preserve compile/vet failure, failed assertion, empty-test semantics, pre-cancellation, incompatible target, reuse, and actual uncached execution controls. Confirm test refusal never registers the candidate, overwrites the prior good registration, or becomes a silent test skip; retain existing rollback and same-name serialization evidence.
- Separate policy results from process lifecycle results. Qualify any isolated-runner or processutil change on its own cancellation, cleanup, platform, and partial-output contracts; do not use a fast return as proof that no test effect occurred.

Record policy decisions and checked bundle identities, subprocess starts, generation-stage transitions, publication/restoration outcomes, diagnostics, model/tool counts, wall time, CPU/memory, test coverage, and legitimate generation success. Use only harmless local fixtures and no real secrets. Closure requires evidence that the program actually executed is covered by the correct source-and-test authority, not merely a safe implementation report or a passing `go test` summary.
