# Semantic expansion: apply the new-file window after cross-tier exclusion

## Finding and decision

A healthy, fully ranked semantic corpus can produce no new Tier 4 file because the bounded result window is consumed by files already selected by earlier tiers. At main [`388205138ba6d47c1cff0c5e97c896dfa642a391`](https://github.com/theRebelliousNerd/codenerd/commit/388205138ba6d47c1cff0c5e97c896dfa642a391), the builder requests twice its Tier 4 allowance, the searcher truncates the complete score ranking to that global window, and only the consumer then removes already-added paths. It does not refill from the remaining scored candidates.

With default allocations, five Tier 4 slots mean ten global semantic matches. Ten higher-ranked files already supplied by Tier 1 can hide an eleventh, new file whose similarity clears the normal brief floor. The candidate is not unavailable, unembedded or out of policy: its score was computed, but its row was discarded before the expansion consumer could consider it.

**Decision:** retain the bounded semantic tier, duplicate suppression and final policy floor, but make the candidate window account for already-selected paths. Prefer exclusion-aware selection or a sufficient bounded one-call window over repeating the embedding query. This is a retrieval-quality and work-value refinement, not a claim that every tier must fill its allowance or that more files necessarily improve an answer.

This is static source analysis on October 30, 2026. No application, tests, model inference, benchmark or repository writes were performed. The witness below is conditional on a specified valid score ordering; it is not an observed provider result.

## Exact producer-to-consumer chain

### 1. Production activates the semantic searcher only when available

The system factory builds a process-shared semantic searcher when an embedding engine is configured, opens its persistent store when possible, and warms the corpus in the background. A missing engine leaves the definition-scan fallback; store-open failure permits memory-only use. Task retrieval receives that searcher through the normal session-executor wiring. The task retriever first asks the kernel whether the current intent wants retrieval. [Searcher ownership and warm-up](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/system/factory_semantic.go#L11-L43), [factory handoff](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/system/factory.go#L2696-L2708), [kernel-gated task pass](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/retrieval/decisions.go#L319-L356).

The builder uses one `addedFiles` set across mentioned files, keyword files, import neighbors and semantic expansion. Default total allowance fifty, Tier 1 fraction 0.30 and Tier 4 fraction 0.10 give fifteen mentioned-file slots and five semantic slots. Earlier selections remain useful context; the defect is not that they should be removed. [Defaults and slot calculation](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/retrieval/tiered_context.go#L91-L151), [tier ordering and shared exclusion set](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/retrieval/tiered_context.go#L206-L251).

### 2. The searcher ranks broadly, then returns a globally limited prefix

`semanticExpansion` calls `SimilarFiles(ctx, issueText, b.maxTier4*2)`; the search interface carries no excluded-path set. The production searcher embeds the query, enumerates the corpus, obtains its current-head vectors, computes compatible cosine scores, records `Covered`, and sorts all matches by score descending/path ascending. Only then does it truncate `matches[:limit]`. Under a fully warm stable corpus, this has already paid for current-head acquisition, score computation and the full sort before the top-ten result leaves the producer. [Interface](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/retrieval/semantic.go#L42-L61), [query, scoring and truncation](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/retrieval/semantic.go#L188-L266), [current-head validation and memory reuse](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/retrieval/semantic.go#L344-L382).

### 3. The consumer excludes after the finite window has been spent

`semanticMatchFiles` skips an empty path, a path already present in `addedFiles`, and a path that no longer stats successfully. It selects at most the Tier 4 allowance from the surviving returned matches. It cannot recover a match truncated upstream. [Post-window exclusion](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/retrieval/semantic.go#L522-L555).

If any file survives, the caller returns immediately, even when fewer than five survive. If none survives, it records `no_semantic_hits` and falls back to symbol-definition search. The reason means no usable match in the supplied window; it does not establish that the fully scored corpus has no new matching file. The attempted/used-backend distinction is retained correctly. [Window request, return and fallback](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/retrieval/tiered_context.go#L578-L642).

## Minimal default-path witness

Assume an admitted, stable workspace containing eleven small, nonbinary, non-test source files. The semantic searcher is configured, all eleven current heads have compatible valid vectors, and the pass finishes within its ordinary budget. There are no read errors, pending embeddings, stale vectors, path aliases or file mutations.

1. A lowercase request names ten existing files, `a01.go` through `a10.go`, separated by comma-space so all ten paths are extracted. For example, its prose asks to fix retry behavior in those files. The request has no capitalized symbol names, so `MentionedSymbols` is empty. The ten paths resolve successfully and fit the default fifteen-file Tier 1 allowance.
2. An eleventh file, `support.go`, is not named, has no keyword match for the extracted request terms, and is not an import neighbor of the selected files. It therefore has not entered `addedFiles` through tiers 1–3. This isolates semantic expansion, not a missing parser or lexical match.
3. The query and current file vectors give each named file score 0.9 and `support.go` score 0.8, a strict separation. A future deterministic fake engine can supply compatible vectors for that ordering; exact floating-point equality is unnecessary. Actual provider rankings must be measured rather than assumed.
4. `SimilarFiles` scores all eleven and truthfully reports `Eligible=11, Covered=11`. It returns the top ten, all named paths. `semanticMatchFiles` excludes all ten as already added.
5. The empty semantic selection enters definition fallback. With no mentioned symbols, that loop performs no symbol searches and adds no file. `support.go` has no Tier 4 selected-file row and hence no `tiered_context_file` fact from this path.

[Path/symbol extraction](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/retrieval/sparse.go#L167-L219), [Tier 1 admission](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/retrieval/tiered_context.go#L266-L297), [selected-file fact production](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/retrieval/facts.go#L400-L430).

This matters under the normal brief threshold, not only a permissive test configuration. A selected semantic score of 0.8 becomes an 80-percent relevance fact and clears the default floor sixty. The policy cannot admit this file through that rule when its selected-file fact was never produced. Lowering the floor does not recover an absent row. These are `tiered_context_file` facts, **not** the separate Tier 2 `candidate_file` evidence. [Default floor](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/config/retrieval.go#L13-L27), [brief rule](https://github.com/theRebelliousNerd/codenerd/blob/388205138ba6d47c1cff0c5e97c896dfa642a391/internal/core/defaults/policy/retrieval.mg#L24-L36).

A second fixture can place nine already-added paths and one new path in the top ten, with more suitable new files just beyond the cut. The one surviving file causes an immediate embedding return; there is neither refill nor definition fallback. This demonstrates the same candidate-window mismatch without an entirely empty Tier 4. It does not make underfilling, by itself, a defect: remaining scores and policy still determine whether extra candidates are useful.

Preserve that meaning rather than labeling a complete search partial merely because selection is bounded. If window exhaustion needs disclosure, model selection exhaustion separately from corpus-read/embedding incompleteness. ## Refine the selection boundary without repeating provider work

Prefer passing the exclusion set into the existing ranking once. Two bounded options deserve comparison; changing a fixed multiplier alone is not a general repair:

1. **Exclusion-aware selection:** give the searcher the caller's already-selected path identities, retain ordinary corpus coverage/scoring, and choose the best new candidates before applying the return limit. Exclusion means “already supplied in this context,” not “removed from the corpus.” It must not retire persistent vectors or weaken membership, embedding-space or source-freshness checks.
2. **Sufficient bounded one-call window:** for a unique-path ranking over stable existing files, requesting at least `K + E` candidates covers at most `E` already-added paths before selecting `K` new ones. Retain any larger existing cushion if desired. Use canonical identities and the number of relevant exclusions, not a guessed universal two-times multiplier. This bound does not magically cover arbitrary duplicate backend rows or paths disappearing during the subsequent stat checks; those need their own explicit semantics.

Both options can reuse the production searcher's already-computed ranking. Repeatedly calling `SimilarFiles` with increasing limits would re-enter query embedding, corpus observation and scoring; do not assume a warm file-vector cache makes that free. A bounded retained ranking or continuation tied to its observation is preferable if pagination is chosen. Leave the executive's brief floor, final file limits and permission decisions intact.

The tradeoff is more useful candidate opportunity, not guaranteed fewer tokens. Returning more candidates adds selection/identity work, facts and possibly brief paths; later reading useful files adds source/tool/model input. The current implementation already scores and sorts all compatible vectors, so this repair need not reduce that dominant work. It can avoid an unnecessary fallback in some symbol-bearing requests, but the clean witness has no symbols and therefore no fallback-scan cost to claim. Wider unrelated tails can add noise unless the same relevance and task-quality checks remain effective.

## Unrun evaluation and acceptance

- Use the real builder, semantic searcher, fact transduction and brief policy with deterministic fake embeddings: top ten all previously added; nine duplicates plus one survivor; overlap just below/at/above the returned window; no overlap; all candidates already supplied; and fewer than five genuinely new files. Verify exact selected paths, deterministic ties, score conversion, final policy rows and no duplicate output.
- Keep the minimal eleven-file default-floor witness. Add low-score controls that remain absent from the brief, incomplete/pending corpus, nil/error engines, failed stats, canceled passes and a genuine no-new-match corpus. Do not require false full coverage or remove successful fallback behavior.
- Count query embedding invocations, corpus/head reads, vector loads/hits, scoring/sorting work, returned/filtered/new candidates, fact volume, fallback searches, provider attempts and actual tokens. A one-call repair should not secretly introduce repeated query embeddings. Hold the same model, source revision, authority, file allowances and retrieval floor.
- Run paired complete tasks only after authorization, measuring useful-file recall/precision, verified correctness, later rediscovery/repair turns, all model/tool tokens, provider and local compute cost, wall time and cost per verified success. Report canceled/failed work and new initial-context costs. More filled slots or fewer fallback calls alone is not success.

**Acceptance:** the bounded Tier 4 opportunity is applied to new eligible paths, coverage retains its truthful corpus meaning, existing safeguards survive, and task quality justifies any additional context. No runtime saving or quality improvement is asserted without that evaluation.
