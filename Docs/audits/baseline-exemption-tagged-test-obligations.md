# Preserve tagged test obligations when baseline failures are exempted

## Decision and evidence boundary

A baseline exemption should remove responsibility for a known pre-existing default-test failure, not discharge a separate obligation to run a written tag-gated test. At the inspected revision, those decisions compose incorrectly: baseline attribution preserves a raw failed result; the tagged-test helper runs only after a raw pass; policy can subsequently accept the baseline-only failure as a passing `/test` gate. The written tagged test can therefore remain unmeasured.

This is a source-predicted composition gap at CodeNERD main `9dcb01b9736bf4763aa3ac391d29f133d73c6611`, not an executed reproduction. Current-source links pin that revision; the prior audit explicitly pins its publication. No tests, runtime, provider requests, inference, local Git were performed. The conclusion is narrower than overall completion: `/test` can be accepted without the written tagged test running; independent gates or review may still keep the turn unverified. No unconditional `/done` claim follows.

## Existing safeguards and the admissible witness

Use a test-only edit inside an **existing** `pkg/integration_test.go` whose valid `//go:build integration` header remains unchanged. Modify an assertion inside the existing `TestLane`, retaining its function name and header; test-retention checking sees no removed test name. Do not add a newly excluding header: the production write guard rejects added constraints that flip a file from included to excluded. It explicitly distinguishes already-present constraints and returns when none were added. This witness preserves that safeguard. [Build-exclusion guard](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/tools/build_exclusion.go#L16-L59).

The package has ordinary Go files and default tests, so it is not a wholly tag-gated package. The integration tag is absent from the effective default test environment, including configured tags and `GOFLAGS`. An existing default `TestExisting` has the same stable, named assertion failure before and after the edit. All written paths have known preimages; baseline attribution completes conclusively. There are no new or unnamed default failures, no importer blocker, and preferably no relevant importers.

The changed `TestLane` is syntactically valid but would fail when run with `integration`. Only the already-tagged test file changes; no production function changes. Assume an authorized, recognized write receipt, `VerifyTestsAfterEdits` enabled, an owed and scheduled `/test` round, the real embedded Mangle kernel active, a healthy toolchain, and no cancellation, timeout, or concurrent edits. Start with fresh execution evidence and no applicable memo entry. These conditions isolate deterministic scheduling and policy composition without model misclassification.

The negative control changes only the default-suite condition: if default tests pass, the helper runs the written tagged test and can detect its failure. The gap is not inability to execute tagged tests; it is their omission when raw failure is later accepted through baseline attribution.

Normal completed-tool-turn verification maps the `/test` round to `verifyAndRepairTests`. Policy derives the test round from its owed gate and owes coverage alongside it. With verification enabled, the driver calls `gateTests(..., true)` and stores its result in `TestCheck`. Memoization surrounds measurement but is not needed to produce this behavior. ## Counterevidence that limits the finding

Pinning is not universally blind to excluded tagged tests. When production units exist, `turnTests` counts changed tests excluded by build tags, and `verifyPinning` can return indeterminate when no usable tests remain but gated tests exist. A broader production-edit witness may therefore remain unverified. [Test selection](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/pin_gate.go#L396-L401), [excluded-test count](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/pin_gate.go#L445-L457), [pinning outcome](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/pin_gate.go#L534-L544).

The deliberately narrower test-only witness has no such production units: `pinUnits` skips test paths, and `verifyPinning` returns passed for an empty unit set before calling `turnTests`. This is why pinning does not establish that the changed test ran in this case. The pinning round itself uses the derived test gate, not simply the raw exit; it is not the same mistaken raw-pass guard. [Unit selection](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/pin_gate.go#L191-L216), [pinning admission](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/pin_gate.go#L787-L791).

Existing helper tests positively check a tagged run after raw green and explicitly require raw red to remain untouched. That supports an intentional component boundary, not evidence of the baseline-accepted-red composition being covered. These tests were read, not executed. [Existing controls](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/written_tag_gated_test_runs_test.go#L16-L86).

## Proposed obligation contract

Retain separate evidence for the raw default result, baseline identity and conclusiveness, and each applicable written-tagged check. A tagged obligation should identify its package, tag configuration, test selection, and revision, with an explicit measured or unresolved disposition. Exempting a default failure must not mark that other obligation complete.

Keep Go responsible for extracting constraints, assembling safe argument vectors, and executing checks; let Mangle decide what evidence is owed and whether it discharges the gate. Do not manufacture `VerifyPassed` merely to enter the existing helper: that erases the true default outcome and makes provenance harder to reason about.

A minimal scheduling repair could permit the targeted tagged check after conclusive all-baseline default failure, while preserving both raw default and tagged results. Alternatively, explicitly defer the tagged check and leave it unverified until its prerequisites settle. Unknown baseline, unnamed failures, timeouts, and cancellations must not silently satisfy it. Preserve importer checks and existing write guards; do not repair unrelated baseline failures solely to force a green entry condition.

Limit this proposal to a known required configuration, such as the single integration tag here. It does not authorize an unlimited tag matrix, service startup, or a general constraint solver. Avoid duplicate baseline runs per written file. Independent judges or other gates may catch defects, but cannot substitute for evidence that this required test ran.
