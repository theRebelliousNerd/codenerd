# Preserve slash command identity across the busy queue

## Decision and evidence boundary

The busy-input queue should preserve whether a submission is a slash command or natural-language work. At the inspected main commit, a slash command accepted during prework or wind-down can be queued as text and later sent directly to natural-language processing. The deterministic command dispatcher is not selected. The narrow witness is `/help`: idle submission invokes the local help renderer; queued submission does not.

This is an existing main integration-contract gap, not a regression attributed to the active branches. The review snapshot was 2026-10-29 at 12:38 UTC, main `9dcb01b9736bf4763aa3ac391d29f133d73c6611`. The inspected branch heads `a53cfc308e8836c72370adaa46deba3f7b00180d` and `80af1863d3a3aa46a722ac8b0c8a0985582d4995` do not change the relevant input or queue files. Links below pin that main snapshot.

This is a source-level finding, not an executed reproduction. No tests, runtime, provider requests, inference, were performed for this memo. The claim is loss of deterministic dispatch identity—not a particular model response, successful mutation, authorization bypass, FIFO failure, or premature reuse of the foreground slot.

## Pinned dispatch trace

In normal ChatView, Enter chooses `handleSubmit` only when both `!isLoading` and `turn.current() == 0`; otherwise it chooses `submitWhileBusy`. This is not every keypress: approval-modal handling and error-focus interception precede the normal submission path; Alt-Enter, paste handling, logic-pane focus, and clarification input also have distinct handling. The witness below excludes those contexts. [Key handling](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/model_key_handler.go#L20-L54), [normal Enter](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/model_key_handler.go#L226-L259).

Idle `handleSubmit` first honors patch mode, then uses trimmed text to recognize a slash prefix while passing the raw input onward after removing leading command whitespace. The command switch selects `handleCmdHelp` for `/help`, `/h`, and `/?`. That handler parses options, records the help metric, constructs `NewHelpRenderer`, appends `RenderHelp(arg)`, updates the viewport, resets the textarea, and returns no asynchronous command. It does not ask the model to invent help. [Submission](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/model_handlers.go#L104-L129), [help aliases](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/commands.go#L94-L95), [local help](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/commands_handlers_files.go#L209-L230).

Busy submission instead trims the textarea, resets it, and records a user message. If the foreground turn is stopping, or `workingOn() == ""`, it enqueues the string and shows a queued notice. Neither branch consults the slash dispatcher. A queue record contains only `id`, `input`, and `pending`; it has no command-kind field. [Busy admission](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/side_turn.go#L279-L295), [queue representation](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/side_turn.go#L68-L72).

When an update leaves the model nonloading with queued work, `Update` requests a drain. `startQueuedTurn` still checks both loading and foreground ownership, dequeues the oldest ready input, sets loading, and calls `processInput(next)` directly—not `handleSubmit` or `handleCommand`. A pending head prevents overtaking. Thus the dispatch mismatch does not require breaking ordering or settlement protection. [Update drain](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/model_update.go#L23-L30), [dequeue](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/side_turn.go#L233-L244), [queued execution](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/side_turn.go#L455-L467).

`processInput` takes ownership and uses the ordinary processing lifecycle. It checks transducer/client readiness and establishes cancellable execution context. Without the separate held-approved-work shortcut, the inspected path reaches perception through the firewall or transducer. There is no slash redispatch inside `processInput`. Its restriction and authorization context and later stop/hold/approve gates remain relevant; this finding does not show their circumvention. ## Nonmutating witness

1. Use normal command input mode in ChatView, excluding patch, clarification, and wizard modes; use ordinary non-paste, non-Alt Enter with no approval modal, focused error, or logic-pane interception.
2. Have a foreground turn admitted but still in prework, so the busy branch applies while `workingOn() == ""`. A stopping turn still winding down is an alternative.
3. Submit exactly `/help` and observe the source-defined enqueue path.
4. Let the old turn settle normally. Once ownership and loading permit draining, execute the returned queued command.
5. Compare with an idle `/help` submission under the same help configuration.

The expected difference is handler selection: idle help calls the local help backend; queued help enters `processInput`. For the perception-attempt variant, use healthy dependencies and no held/go-ahead work. Entering perception does not guarantee a live provider request; caching or short-circuiting may intervene. If dependencies are absent, the queued path can return “not ready” instead of local help; provider failure is not necessary to establish the primary mismatch. No specific generated answer or downstream effect is asserted.

The working-stage path is deliberately excluded from the minimal witness. Once `workingOn()` is nonempty, `sideTurn` reserves receipt order and classifies the submission. Later queueing depends on policy or noncanceled classification errors; canceled classification removes the reservation. Those are additional cases to evaluate, not prerequisites for the deterministic prework or wind-down case. [Working-stage admission](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/side_turn.go#L300-L327), [settlement outcomes](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/side_turn.go#L419-L444).

## Proposed submission contract

At receipt, capture an immutable submission envelope containing raw input, recognized input kind, receipt identity, and the context needed to validate later execution. Parsing for recognition should not destroy the command payload. Current textarea contents or mutable `inputMode` are not reliable historical evidence about an already queued request.

Use a shared submission dispatcher for direct and deferred requests, with explicit command lifecycle policy. Preserve the existing FIFO and owner-settlement rules. Admission, history insertion, textarea reset, and execution must be separable: replaying `handleSubmit` against current UI state risks duplicate history, double admission, changed interpretation, or requeue loops. In particular, blindly replacing `processInput` with `handleCommand` after setting `isLoading = true` would leave synchronous help returning no command while loading remains set. The dispatcher must distinguish synchronous completion from asynchronous ownership and must not leak loading or owner state.

Conservation does not mean “run every slash command immediately while busy.” A local read-only help policy can be explicit; mutating, configuration-changing, or session-changing commands may require serialized ownership, modal-context validation, original authorization, and stale-target checks. The slash string grants no new capability. Long-running command enrollment and cancellation are a separate lifecycle question; this memo does not solve it by blindly calling every command handler from the queue.

An explicit per-command reject or defer policy is acceptable if the user sees what happened. Silent natural-language reinterpretation should not be the fallback for recognized command syntax. Unknown commands should produce the selected explicit command error, not accidentally enter perception; the current idle dispatcher already has a deterministic unknown-command response. [Unknown command handling](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/commands.go#L284-L293).

## Failure handling and alternatives

A minimal alternative is to reject unsupported busy slash commands before recording them as accepted work. Another is a small reviewed allowlist of local commands plus serialized defer for the remainder. Both need clear feedback and must retain existing authorization boundaries.

For deferred execution, distinguish pending, in-flight, completed, rejected, canceled, and unverified outcomes. Claim an item once, retain actionable errors, and do not turn shutdown cancellation into an automatic retry. If an effect occurs but reporting fails, mark the outcome unverified rather than replaying the command. Queue bookkeeping alone cannot prove that an external effect did not happen.

Retain the modal, Alt-Enter, paste, clarification, and logic-focus controls. Test context or availability changes before drain and an explicit policy for whether stopping a foreground turn affects queued requests. For payload preservation, capture synthetic raw bytes in a fake handler rather than writing files.

The proposed recognition and routing are local; this design needs no new provider request. No latency, token, cache, or runtime-cost measurements were performed. Preserving raw input requires an explicit queue-memory policy alongside existing widget/input limits. Evaluate correctness and bounded storage before claiming performance benefits.
