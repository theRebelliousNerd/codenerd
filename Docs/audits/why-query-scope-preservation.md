# Preserving query scope in nerd why

## Finding and proposed decision

The current `nerd why` CLI accepts an explicit query pattern, preserves it while constructing and displaying the query, and then removes its arguments before calling a healthy `RealKernel.TraceQuery`. The resulting explanation can therefore cover a broader relation than the user requested. This is an argument and arity projection at the CLI boundary, not evidence that Mangle computes the wrong fixpoint. The narrow proposal is to preserve valid accepted patterns through that boundary, using the current typed query API. An intentionally predicate-only CLI is also defensible, but should reject patterns or explicitly obtain agreement to the broader scope instead of silently accepting and widening them. [CLI query construction and dispatch](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/cmd_query.go#L222-L287)

This is a source-derived finding, not a reproduced command result. No repository command, test, engine inference, benchmark, or implementation was run for this addendum. ## Exact path and preconditions

The help calls the argument a predicate and uses bare-predicate examples, which limits any claim of an explicit ground-query promise. Nevertheless, the implemented input path accepts one string argument and deliberately returns already-patterned input unchanged. `runWhy` trims the input, defaults to `next_action`, applies aliases only to bare names, requires an initialized workspace, and obtains a `RealKernel` through Cortex or the fresh-kernel fallback. [Help contract](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/cmd_query.go#L40-L56), [initialization and kernel selection](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/cmd_query.go#L169-L219)

After building and printing the full query, the CLI calls `whyTracePredicate`, which cuts the string at the first opening parenthesis. It passes only that prefix to `TraceQuery`. The core tracer passes its received query directly to `Query`, stores it in `trace.Query`, and creates a root for each returned fact. A healthy broad result therefore remains broad all the way to rendering. [CLI stripping and dispatch](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/cmd_query.go#L222-L254), [trace root construction](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/core/trace.go#L16-L48)

The hollow-tracer fallback is materially different: it receives the original query, but only after the primary `TraceQuery` returns an error. It does not repair successful overbroad results. A healthy empty result is also not an error; it takes the no-derivation path rather than invoking the hollow tracer. The relevant witness therefore requires successful initialization, ordinary default policy loading, a usable kernel, and a non-error primary query. [Error fallback and rendering](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/cmd_query.go#L225-L244), [hollow-tracer loading](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/cmd_query.go#L290-L311)

## Stock policy witness and limits

An illustrative, unexecuted fixture is:

```text
nerd why 'safe_action(/read_file)'
```

The stock schema declares unary `safe_action` with a name-valued argument. The stock constitution contains `safe_action(/read_file)` and other rows, including `/write_file`. Under the successful path above, the constructed goal remains `safe_action(/read_file)` for display but becomes bare `safe_action` for tracing. The root set can consequently include `/write_file` and the other safe-action rows. A direct valid patterned query should select only the `/read_file` row. No custom policy, learned rule, or private data is needed for this distinction. [Stock declaration](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/core/defaults/schemas_execution.mg#L60-L61), [stock facts](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/core/defaults/policy/constitution.mg#L128-L132)

A stronger no-match control is `safe_action(/not_a_shipped_action)`, but only after confirming that name is absent from the tested kernel snapshot. The exact goal should then have no roots; the stripped predicate can still return the stock rows. This conditional fixture must not be presented as an observed failure. Bare `safe_action` and the all-variable unary pattern are useful negative controls because their intended answer sets coincide here.

The impact is explanation scope, not a permission bypass. `safe_action` is a static action classification, not the full current `permitted(Action, Target, Payload)` authorization decision; asking why does not execute the listed actions. The rendered trace header uses `trace.Query`, so the broadened bare predicate can be visible. The finding is therefore not that the renderer literally asserts an absent requested goal is true, but that accepted and displayed scope is not preserved into the root-selection operation. [Authorization policy boundary](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/core/defaults/policy/constitution.mg#L5-L13), [trace header and roots](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/mangle/proof_tree.go#L395-L410)

## Narrow correction and remaining boundaries

Define the contract first: valid accepted goals must retain their typed arguments and arity from CLI construction through `TraceQuery` to root selection. Requested and actual query scope should remain truthful, and any fallback mode should be explicit. Prefer passing valid patterns unchanged through the existing typed API while preserving bare-predicate behavior, defaults, aliases, and nullary queries. If the CLI instead remains predicate-only, make that restriction explicit at input rather than accepting a pattern and discarding its constraints.

Do not implement filtering by comparing flattened public `Fact` strings: the existing typed-query path is the relevant identity-preserving boundary. Parsing must continue through the serialized wrapper. Invalid-input handling is a separate compatibility decision: current pattern parsing deliberately falls back to predicate-only behavior on malformed patterns. Simply forwarding the original string does not make invalid input fail closed. [Typed pattern path and permissive parse fallback](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/core/kernel_query.go#L64-L91), [parser behavior](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/core/kernel_query.go#L145-L164)

The TUI provides a negative control rather than another affected surface: production `/why` dispatch joins the supplied parts and passes the full query to `TraceQuery`, without this CLI helper. The Cortex bridge also forwards the original query to each selected real kernel and retains it on the merged trace. This is a query-preservation observation, not a general claim about Cortex routing scope. [Production dispatch](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/commands.go#L199-L205), [TUI command handler](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/commands_handlers_evolution.go#L70-L86), [TUI trace request](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/model_lifecycle.go#L219-L259), [Cortex trace bridge](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/core/cortex_kernel_inspect.go#L18-L50)

Preserving query scope does not turn heuristic premise construction into recorded derivation provenance. `/explain` explicitly owns the recorder-backed route; enabling recording and reevaluation is a separate choice with continuing cost until disabled, not the minimal correction here. Depth and cycle omissions in the heuristic tracer already receive explicit markers and should remain visible. [Explanation modes](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/cmd_explain.go#L1-L21), [depth and cycle markers](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/core/trace.go#L51-L119)

## Costs and fair evaluation

The narrow proposal incurs pattern parsing and query-planning work plus compatibility and regression-test effort. It changes formerly broad output to an empty result when a valid selective goal has no match. Selective queries may reduce root count, heuristic premise construction, and rendered output, but there is no measured latency or allocation improvement to report. Keep Cortex and provider startup costs separate and constant; preserving scope requires neither an additional LLM call nor automatic provenance activation.

The following are proposed tests, not completed results:

1. Use the stock `/read_file` fixture and direct typed `Query` on the same kernel snapshot as the root-membership oracle. Add the absent-name control only after proving absence in that snapshot.
2. Cover mixed constants and variables, all-variable patterns, bare predicates, default and alias paths, nullary relations, and overloaded arities. Exercise name versus same-text string, numbers, quoted commas, and escapes without decoding terms into ad hoc strings.
3. Assert the actual query received at the CLI trace boundary and the returned root membership, not merely the displayed text. Preserve intended bare-query behavior as a negative control.
4. Distinguish healthy nonempty results, healthy empty results, primary-query errors that invoke the hollow tracer, and Cortex versus fresh-kernel selection. Verify the original goal remains available to the error fallback.
5. Specify malformed-input behavior separately and retain heuristic labeling and depth/cycle markers. Check CLI and TUI argument-forwarding parity; compare row sets only with the same effective kernel snapshot and routing conditions, or account for shard coverage separately.

Compare the existing behavior with a minimal pattern-preserving candidate and, if considered, an explicitly pattern-rejecting contract. Use the same kernel snapshot; report fact counts, root counts, render bytes, CPU, allocations, and latency, with boot costs separated. A rejecting candidate succeeds only by making its narrower input contract clear, not by matching the selective query's results. The first acceptance criterion is preservation of valid requested root scope; broader proof-system claims and performance conclusions require separate evidence.
