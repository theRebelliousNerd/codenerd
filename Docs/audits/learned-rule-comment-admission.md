# Learned-rule admission: a leading comment must not exempt the following program

## Scope and verdict

Source-only review of `theRebelliousNerd/codenerd`, pinned to main **`6d8477940cbeaa795e1917330b79853048189ca2`**, rechecked 2026-10-29 at 04:15 UTC. No implementation, test execution, inference, training, local Git or computer tasks were performed. Examples and expected results below are static deductions, not reproduced runtime results.

**Definite admission-boundary defect; conditional downstream impact.** A candidate beginning with a Mangle `#` comment causes `ValidateLearnedRuleProtected` to accept the **entire text** before inspecting any heads. A well-formed, well-typed protected fact following that comment can consequently pass the live installation API's learned-head gate. Ordinary successful feedback sanitization removes comments and is meaningful protection; this review does **not** establish a default model-to-permission exploit. The kernel must nevertheless validate the final text it persists, independently of whether a particular upstream producer normalized it. [Gate](https://github.com/theRebelliousNerd/codenerd/blob/6d8477940cbeaa795e1917330b79853048189ca2/internal/mangle/schema_validator.go#L214-L237), [installation boundary](https://github.com/theRebelliousNerd/codenerd/blob/6d8477940cbeaa795e1917330b79853048189ca2/internal/core/kernel_policy.go#L392-L480), [separate-gates guidance](https://github.com/theRebelliousNerd/codenerd/blob/6d8477940cbeaa795e1917330b79853048189ca2/internal/mangle/agents.md#L1-L7).

## 1. Precise source chain

1. `ValidateLearnedRuleProtected` trims input, then returns `nil` when it is empty **or starts with `#`**. This is before the loop over `learnedHeads`, the grant-path uncertainty check, and subsequent schema checks. This is not a claim that the implementation lacks AST head traversal: `learnedHeads` already parses all clauses. The prefix branch makes that protection unreachable for this input shape. [Early return](https://github.com/theRebelliousNerd/codenerd/blob/6d8477940cbeaa795e1917330b79853048189ca2/internal/mangle/schema_validator.go#L221-L267), [existing AST traversal](https://github.com/theRebelliousNerd/codenerd/blob/6d8477940cbeaa795e1917330b79853048189ca2/internal/mangle/schema_validator.go#L51-L79).

2. `RealKernel.ValidateLearnedRule` delegates to this gate with current kernel protection. `HotLoadLearnedRule` first permits a repair interceptor to change the text, then normalizes it, checks unsafe negation, sandbox compilation and bounds, calls learned validation, checks pathological patterns, and finally persists/applies the text. `NormalizeRuleInput` does not remove comments; ordinary unescaped text returns unchanged. Syntax and type checks do not establish who is authorized to supply a fact. [Delegation](https://github.com/theRebelliousNerd/codenerd/blob/6d8477940cbeaa795e1917330b79853048189ca2/internal/core/kernel_validation.go#L20-L29), [ordered mutation path](https://github.com/theRebelliousNerd/codenerd/blob/6d8477940cbeaa795e1917330b79853048189ca2/internal/core/kernel_policy.go#L406-L480), [normalizer](https://github.com/theRebelliousNerd/codenerd/blob/6d8477940cbeaa795e1917330b79853048189ca2/internal/mangle/feedback/normalize.go#L17-L29).

3. The sandbox compiles the candidate together with the existing program, without independently applying learned-head authorization. Installation appends the same text to `k.learned` and marks policy dirty; normal program construction includes it. Thus the faulty return is on an installation/persistence boundary, not merely an advisory lint API. Subsequent compilation/evaluation is still required; this is not a claim of eager execution at the return from hot-load. [Sandbox and installation](https://github.com/theRebelliousNerd/codenerd/blob/6d8477940cbeaa795e1917330b79853048189ca2/internal/core/kernel_policy.go#L486-L515), [program construction](https://github.com/theRebelliousNerd/codenerd/blob/6d8477940cbeaa795e1917330b79853048189ca2/internal/core/kernel_eval.go#L81-L108).

## 2. Counterevidence and exact reachability limits

- **Successful stock feedback sanitization defeats this simple input.** Default generation enables auto-repair, then uses the sanitizer result before compilation and learned validation. The sanitizer emits AST declarations/clauses rather than preserving source comments. `ValidateOnly`, used in the direct-rule validation flow, also invokes sanitization. An ordinary successfully sanitized protected fact therefore reaches the gate without its hiding prefix and is refused. This materially limits immediate production exposure. [Default](https://github.com/theRebelliousNerd/codenerd/blob/6d8477940cbeaa795e1917330b79853048189ca2/internal/mangle/feedback/types.go#L110-L140), [generation and direct validation](https://github.com/theRebelliousNerd/codenerd/blob/6d8477940cbeaa795e1917330b79853048189ca2/internal/mangle/feedback/loop.go#L281-L379), [serialization](https://github.com/theRebelliousNerd/codenerd/blob/6d8477940cbeaa795e1917330b79853048189ca2/internal/mangle/transpiler/sanitizer.go#L417-L480).

- **The optional repair interceptor is not an independent authorization barrier.** It returns the original text unchanged when its initial checks report no error. Those checks comprise sandbox compilation, predicate inventory and basic safety patterns—not learned-head protection. If actual repair is triggered, its plain-output fallback can also accept code-block contents with a leading comment preserved, after earlier feedback sanitation. This is a *conditional* additional route: no concrete ordinary accepted candidate that necessarily triggers that repair route was established here. Do not report it as a demonstrated default exploit. ## 4. Proposed refinement and costs

**Keep authority at the final mutation boundary.** Classify empty/comment-only input using parsed structure, not the first source character. Validate every executable clause's head against static, current grant-path and host-only protection on the exact post-interceptor text that will be persisted. Preserve the distinction between harmless comments and a program following them. A parser failure must not silently establish authorization; retain existing syntax, bounds, narrowing-rule and declaration contracts. Do not use a naive comment-stripping regex: quoted `#`, multiline statements and ordinary comment syntax deserve parser semantics.

A narrowly scoped fix to the gate plus regressions is preferable to relying solely on adding another sanitizer pass. Canonicalizing after repair can be useful defense in depth, but canonicalization changes text and is not an authority policy. Startup and live installation should share a decision contract, even if their reporting/healing behavior remains different.

Costs are principally engineering/review and regression coverage, not model spend: no new model invocation, embedding, inference or training is necessary. Parsing previously skipped commented programs adds work proportional to candidate size and may add contention at the repository's serialized parser entry. Existing successful non-commented validation already parses heads; avoid gratuitous additional full-program parses or a large AST-cache redesign without measurements. Evaluate candidate-size limits and measure allocations/latency before asserting a performance benefit; no existing universal size cap is claimed here. Compatibility decisions include how comment-only input reports success/no-op, whether supplied source formatting is retained for provenance, and whether malformed/declaration-only input is rejected consistently. [Serialized parser contract](https://github.com/theRebelliousNerd/codenerd/blob/6d8477940cbeaa795e1917330b79853048189ca2/Docs/architecture/mangle/WIRING-AND-NOT-BUILT.md#L99-L103).

## 5. Fair evaluation proposal — not executed

1. **Comment-invariance oracle:** for each valid executable candidate, prepend zero/one/multiple comments, blank lines and indentation. Protected static heads, grant-path heads and host witnesses must retain the same refusal; allowed narrowing rules must remain admissible. Include multiple statements and a protected head after a benign first clause.
2. **Boundary assertions:** drive `HotLoadLearnedRule`, not only the schema helper. On refusal require no learned-file addition, no in-memory installation and unchanged derived permissions. Reuse the existing controlled pending-delete fixture, with no actual tool execution.
3. **Final-text ownership:** use a deterministic stub interceptor returning a comment-prefixed protected fact from benign input, and an unchanged valid narrowing rule. This isolates the post-repair contract without inference, and is explicitly not evidence that a stock model follows that route.
4. **Controls:** cover pure comments, quoted `#`, malformed source, bounds/type failures, unknown grant path, benign multiline facts/rules, and restart healing. Compare direct admission, ordinary sanitized feedback and startup behavior; publish which cases were previously mitigated upstream.
5. **Efficiency:** measure gate and end-to-end hot-load wall time, parser calls, allocations and lock contention across realistic candidate sizes and concurrency, holding program/policy and corpus fixed. No accuracy, exploit frequency or latency improvement is asserted before these measurements.

Success is consistent refusal at the authoritative boundary without sacrificing permitted narrowing rules—not merely a sanitizer making the sample disappear.
