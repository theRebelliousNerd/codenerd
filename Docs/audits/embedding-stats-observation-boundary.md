# Addendum: keep embedding statistics separate from engine activation

## Status and bounded conclusion

Source review at **2026-10-29 12:47 UTC**, pinned to main [`9dcb01b9736bf4763aa3ac391d29f133d73c6611`](https://github.com/theRebelliousNerd/codenerd/tree/9dcb01b9736bf4763aa3ac391d29f133d73c6611). No application, test, benchmark, provider inference, or training was run. This is an **operational and efficiency refinement**, not a claim of observed damage, permanent data loss, a panic, a goroutine leak, or a demonstrated next-start retrieval regression.

The CLI's `nerd embedding stats` currently activates an embedding engine merely to describe vector statistics. Engine attachment unconditionally drops/recreates `vec_index` and schedules its rebuild. The command then prints canonical-table counts and closes its store without requiring rebuild completion. An observational command therefore performs avoidable maintenance and can leave the disposable index less complete than it found it. The next normal engine attachment rebuilds that index anyway; canonical vectors are preserved. The strongest proposal is to avoid activation on the diagnostic path, not to add a whole-store availability mechanism.

The active Mangle/store lane, [`a53cfc308e8836c72370adaa46deba3f7b00180d`](https://github.com/theRebelliousNerd/codenerd/compare/9dcb01b9736bf4763aa3ac391d29f133d73c6611...a53cfc308e8836c72370adaa46deba3f7b00180d), changes the index metric/query and world-cache initialization, but retains this attach/rebuild/close behavior. Its KNN-limit issue is separate and already audited.

## Evidence: a production diagnostic invokes maintenance

1. **Actual CLI entry.** The registered stats command opens `.nerd/knowledge.db`, defers `ls.Close()`, loads embedding configuration, constructs an engine and calls `ls.SetEmbeddingEngine(engine)` when construction succeeds. It then calls `GetVectorStats`, prints, and returns. This is not a hypothetical custom caller. [CLI handler](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/embedding_cmd.go#L84-L135)

2. **Attachment is not a metadata setter.** Every non-nil attachment calls `initVecIndex`; for positive dimensions, that function attempts `DROP TABLE IF EXISTS vec_index` followed by creation. It has no same-engine/healthy-index no-op check. The setter immediately schedules a background backfill and records its completion channel. Successful DDL and sqlite-vec availability are conditions for the concrete empty-index witness below. [Setter](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/store/vector_store.go#L28-L89), [DDL](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/store/vector_store.go#L1005-L1022)

3. **Backfill copies the corpus, rather than embedding it again.** It selects eligible canonical rows, parses each vector, builds an in-memory list containing encoded vectors/content/metadata, and inserts batches of 100 in separate transactions. This is real potential corpus-sized CPU, memory and database-write work even when the existing index was already healthy. It does not itself call an embedding provider. [Backfill](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/store/vector_store.go#L1030-L1152)

4. **Statistics do not certify that work.** `GetVectorStats` checks counts from `vectors` and the engine-relative canonical coverage; it neither waits for backfill nor examines index completeness. Its compatibility counts can be correct while `vec_index` is incomplete. The existing counts are not alleged to be fabricated. [Statistics](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/store/vector_store.go#L1257-L1304)

5. **Close is resource-safe, not a rebuild completion receipt.** `LocalStore.Close` stops the reflection worker and closes the SQL handle; it does not call `waitForVecBackfill`. Go's SQL close prevents new queries while allowing already-started work to finish; that is not a promise to complete the application goroutine's future queries/transactions. The repository deliberately tests close-during-backfill safety and subsequently waits for the generation to settle. That test asserts safe settlement, not persistence of a complete rebuilt index. These are inspected test definitions, not test results from this review. [Close](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/store/local_core.go#L536-L540), [existing safety test](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/store/vector_backfill_race_test.go#L101-L127), [SQL contract](https://pkg.go.dev/database/sql#DB.Close)

**Positive control:** TUI `/embedding stats` simply reads statistics from the already-active `m.localDB`; the stats branch does not reattach an engine or recreate an index. It does not print all the CLI's newer compatibility fields, so output parity is a separate detail. [TUI handler](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/commands_handlers.go#L342-L374)

## Precise conditional witness and limits

Use one process and one command; no unsupported concurrent writer is needed.

- Begin with an existing, healthy `knowledge.db`, a complete sqlite-vec index, and nonempty valid canonical vectors stamped for the configured engine.
- Engine creation succeeds; index drop and recreation succeed.
- The new background worker has not begun its query when the command's statistics queries finish. This is an allowed scheduling order, not a prediction of how often it occurs.
- The command returns and its deferred close closes the handle. A later worker query cannot start, or process exit prevents the worker from proceeding. The recreated index can remain empty, while the canonical vectors and the reported canonical counts remain intact. An analogous inter-batch schedule can leave a partial index.

No such incompleteness is established when the worker finishes first. Neither fast completion nor small corpus size is a correctness barrier: they simply affect scheduling. The existing test-only hold illustrates a usable future evaluation seam; it is explicitly nil in production and is not part of this production witness. [Scheduling and test hook](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/store/vector_store.go#L55-L95)

This does **not** establish a supported concurrent CLI/TUI quality regression. Store guidance explicitly assumes a single-writer SQLite process and says not to assume multi-writer/multi-process access. It also does **not** establish a next-start retrieval defect: normal attachment rebuilds again, and maintenance reconciliation already repairs missing eligible index rows. Avoid presenting this as new generic ANN drift, data corruption, or missing recovery. [Concurrency guidance](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/Docs/architecture/store/04-ARCHITECTURAL-PRINCIPLES.md#L14-L16), [reconciliation](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/store/vector_store.go#L697-L730), [documented recovery](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/Docs/architecture/store/TODO.md#L8-L14)

The meaningful operator distinction is narrower: asking for statistics can change the derived state being investigated and launch work unnecessary to answer the question. A normal boot also performs this work; that limits incremental next-boot harm, but does not make diagnostic maintenance useful.

## Optional provider setup is another cost of the same boundary

The stats path uses contextless `NewEngine`, which delegates with a background context. In the Ollama branch, construction performs best-effort `EnsureModel` under an eight-second startup context. This can list models and, if the configured model is absent, attempt to pull that exact model. A readiness failure is warned about but can still return an engine, so provider unavailability does not necessarily avoid index recreation. This is optional/provider-specific setup, **not evidence that stats performs model inference or an unbounded download**. The pull request receives the ensure context; server-side behavior after cancellation was not investigated. [Factory](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/embedding/engine.go#L101-L168), [ensure/list](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/embedding/ollama.go#L461-L549), [pull request](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/embedding/ollama.go#L552-L577)

## Proposed contract and alternatives

**Preferred small boundary change: observation without runtime activation.**

- Provide a diagnostic read path that reports canonical counts, stored embedding identities, configured identity and optional index-presence/drift information without attaching an engine, running provider readiness, or scheduling backfill.
- Keep configured identity distinct from resolved live-engine identity. Ollama can resolve a bare name to an installed tagged name; do not silently compare raw configuration as though it were the provider's canonical `Name()`, or stamp legacy rows by guesswork. Report unresolved identity explicitly, or use a shared side-effect-free canonical descriptor with documented limitations. Preserve the existing foreign/unattributed eligibility rules.
- Do not claim that removing the setter alone makes the entire command read-only: `NewLocalStore` creates directories, initializes/migrates schema, probes sqlite-vec and fills missing content hashes. A truly observational path should open an existing database without maintenance; absent or unsupported schema should produce a diagnostic, not a silent migration. SQLite read-only/WAL compatibility must be considered rather than adding `immutable` indiscriminately. [Constructor](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/store/local_core.go#L84-L145), [identity limitations already recorded](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/Docs/audits/embedding-representation-and-migration.md#L62-L65)
- Keep repair/re-embed explicit. If requested diagnostics include network readiness, make that an opt-in, cancellable check distinct from model installation.

**Alternative: idempotent engine attachment.** Avoid rebuilding when identity, dimensions, metric, schema version and completeness are already valid. This helps other callers too, but dimensions or engine name alone are insufficient, and checking completeness has a cost. This is broader and riskier than removing activation from stats.

**Completion policy, not a new leak claim.** If an explicit rebuild operation promises completion, expose/join its completion and return its status before reporting success. Preserve the currently intentional safe best-effort close behavior unless its API contract is deliberately changed. Making every close wait for a potentially large rebuild would add shutdown latency and cancellation/deadlock obligations; it still would not justify initiating maintenance in a stats command.

## Costs and fair acceptance evaluation

Let N be eligible vectors, d their dimension, and B the copied text/metadata bytes. Completed backfill parses/encodes O(Nd) values and retains roughly O(Nd+B) temporary payload before its batched writes; index rebuild also incurs SQLite write/journal work. These are source-derived work shapes, **not measured latency or monetary savings**. Counts still scan relevant database rows; the proposed diagnostic is not promised O(1). A separate read path adds schema-version handling and identity-resolution maintenance, while a broad idempotence mechanism adds persistent index-state/version complexity.

If implementation/evaluation is later authorized:

1. Compare current CLI, TUI stats as a non-reattaching control, and the proposed diagnostic on identical copied fixtures: healthy current identity, absent index, missing database, old schema, foreign/unstamped rows, malformed vectors, and unavailable sqlite-vec.
2. Assert canonical rows/identities are unchanged in all observational cases; separately compare index schema/membership and record whether maintenance was attempted. Preserve errors instead of reporting healthy zero counts.
3. Exercise delayed worker start and between-batch closure separately from a fully completed rebuild. Retain the existing safe-close/no-hang expectation; test completion only where promised.
4. For a sequential normal boot after stats, compare eventual eligible recall against a no-stats baseline after backfill settles. This is a control against overstating lasting retrieval harm, not an expected regression.
5. Measure cold/warm wall time, allocation peak, SQL writes/WAL bytes, provider-request counts and cancellation responsiveness over increasing N and d. Use local fake provider endpoints to distinguish tags/pull attempts from embedding calls; do not infer real provider costs from those fakes.
6. Require repeated diagnostics to leave healthy index membership unchanged and make no model-install requests by default. Keep corpus coverage output equivalent or explicitly qualify unresolved live identity.
