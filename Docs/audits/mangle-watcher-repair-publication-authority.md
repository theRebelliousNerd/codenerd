# Mangle watcher repair publication: freshness, destination authority, and policy ingestion

## Scope and verdict

Source-only audit of `theRebelliousNerd/codenerd`, pinned to **`8fdeadce7c60c2f0461f7a2a711937911686ffbc`**, inspected 2026-11-02. No implementation, repository mutation, test execution, provider call, live repair, or exploit reproduction was performed. Proposed witnesses and outcomes below are evaluation requirements, not passing or failing results.

**The demonstrated defect is an unguarded disk-publication boundary, not an established live permission bypass.** The watcher reads a file, lets an interceptor inspect or repair its extracted text, then writes a reconstruction of the old snapshot to the original pathname. It does not establish that the file still exists unchanged, that the destination remains the same object, that the final file is authorized for that destination, or that publication is atomic. This admits source-derived lost-update, deleted-file recreation, and partial-write scenarios. A second, conditional security concern follows because the same watcher can rewrite files subsequently ingested as schema or trusted policy rather than as learned rules. [Publication path](https://github.com/theRebelliousNerd/codenerd/blob/8fdeadce7c60c2f0461f7a2a711937911686ffbc/internal/core/mangle_watcher.go#L237-L317), [boot ingestion classes](https://github.com/theRebelliousNerd/codenerd/blob/8fdeadce7c60c2f0461f7a2a711937911686ffbc/internal/core/kernel_init.go#L356-L402).

The watcher **does not install the repaired text in the running kernel**. The repair validator's `HotLoadRule` is compile-only. `learned.mg` has a separate protected-head boot-healing path, and `HotLoadLearnedRule` has a final learned-rule admission gate before persistence. Those protections must be credited, not conflated with this watcher. No runtime file-reload consumer or end-to-end model-to-policy exploit was established here. [Compile-only validator](https://github.com/theRebelliousNerd/codenerd/blob/8fdeadce7c60c2f0461f7a2a711937911686ffbc/internal/core/kernel_policy.go#L183-L254), [learned loader](https://github.com/theRebelliousNerd/codenerd/blob/8fdeadce7c60c2f0461f7a2a711937911686ffbc/internal/core/kernel_policy.go#L454-L479), [learned boot healing](https://github.com/theRebelliousNerd/codenerd/blob/8fdeadce7c60c2f0461f7a2a711937911686ffbc/internal/core/kernel_init.go#L453-L498).

## 1. Exact source chain and limits

1. Chat boot constructs the watcher with the workspace and primary real kernel and starts it with `context.Background()`. This is a reachable production construction site, not proof that every session has a usable repair interceptor or model client. [Chat boot](https://github.com/theRebelliousNerd/codenerd/blob/8fdeadce7c60c2f0461f7a2a711937911686ffbc/cmd/nerd/chat/session_shared_boot.go#L259-L268).

2. The watcher adds `.nerd/mangle` and, if present, `internal/mangle`. It filters events by the `.mg` suffix, not by file ownership or ingestion class. Events are collected by pathname, debounced for 500 ms, then processed synchronously. This is not a recursive watch of every Mangle source directory. [Construction and watches](https://github.com/theRebelliousNerd/codenerd/blob/8fdeadce7c60c2f0461f7a2a711937911686ffbc/internal/core/mangle_watcher.go#L47-L105), [event and debounce handling](https://github.com/theRebelliousNerd/codenerd/blob/8fdeadce7c60c2f0461f7a2a711937911686ffbc/internal/core/mangle_watcher.go#L170-L234).

3. `validateAndRepair` reads the whole file. Without an interceptor it performs warning-only basic checks and returns without rewriting. With one, it passes extracted rule text to `InterceptLearnedRule`, substitutes changed results into the original text, and calls `os.WriteFile` if any substitution occurred. The interface supplies no source path, source digest, destination class, or publication authorization. [Repair and write](https://github.com/theRebelliousNerd/codenerd/blob/8fdeadce7c60c2f0461f7a2a711937911686ffbc/internal/core/mangle_watcher.go#L237-L317).

4. The concrete repair shard initially validates, may add a missing period deterministically, and may request model repair with bounded retries and cost checks. Structured output requires a single clause and forbids declarations, packages, and uses, with a plain-output fallback. Accepted repair output is revalidated. These are real mitigations, but neither shape restrictions nor syntax checks confer permission to change policy. [Repair flow and cost guards](https://github.com/theRebelliousNerd/codenerd/blob/8fdeadce7c60c2f0461f7a2a711937911686ffbc/internal/shards/system/mangle_repair.go#L261-L439), [deterministic repair and interceptor](https://github.com/theRebelliousNerd/codenerd/blob/8fdeadce7c60c2f0461f7a2a711937911686ffbc/internal/shards/system/mangle_repair.go#L456-L490).

5. Repair validation calls `HotLoadRule`, then corpus predicate checks and basic safety heuristics. `HotLoadRule` performs sandbox compilation and bounds checking but does not call `ValidateLearnedRule` or install the rule. The corpus extraction deliberately skips a rule head when there is a body. In contrast, the learned installation API checks the final candidate with `ValidateLearnedRule` before persistence and application. [Repair validation](https://github.com/theRebelliousNerd/codenerd/blob/8fdeadce7c60c2f0461f7a2a711937911686ffbc/internal/shards/system/mangle_repair.go#L493-L563), [compile-only boundary](https://github.com/theRebelliousNerd/codenerd/blob/8fdeadce7c60c2f0461f7a2a711937911686ffbc/internal/core/kernel_policy.go#L201-L254), [final learned guard](https://github.com/theRebelliousNerd/codenerd/blob/8fdeadce7c60c2f0461f7a2a711937911686ffbc/internal/core/kernel_policy.go#L407-L479).

6. At boot, `extensions.mg` contributes logic to schemas and `policy_overrides.mg` contributes logic to policy. `learned.mg` follows a different path: its logic is healed before appending, with protected-head validation of learned statements. Merely writing an arbitrary watched `.mg` filename does not prove that boot consumes it. [Privileged extension ingestion](https://github.com/theRebelliousNerd/codenerd/blob/8fdeadce7c60c2f0461f7a2a711937911686ffbc/internal/core/kernel_init.go#L372-L402), [learned ingestion](https://github.com/theRebelliousNerd/codenerd/blob/8fdeadce7c60c2f0461f7a2a711937911686ffbc/internal/core/kernel_init.go#L453-L498), [boot authority check](https://github.com/theRebelliousNerd/codenerd/blob/8fdeadce7c60c2f0461f7a2a711937911686ffbc/internal/core/kernel_validation.go#L219-L303).

## 2. Findings

### F1 — A repair can publish over a newer edit or recreate a deleted file

**Established source defect; runtime incidence unmeasured.** There is no reread, source digest comparison, identity check, generation token, or writer coordination between the initial read and the final write. The mutex protects watcher state, not the filesystem transaction. An editor, another process, or another invocation can change the path during repair. Serial execution in one event loop does not serialize those writers.

A minimal deterministic witness should block the interceptor after snapshot A is read, replace the file with B, then release a repair of A. The source path writes repaired A over B. Deleting the file instead permits `WriteFile` to recreate it if the parent remains writable. Neither scenario needs an attacker, model call, or protected predicate. [Read-to-write interval](https://github.com/theRebelliousNerd/codenerd/blob/8fdeadce7c60c2f0461f7a2a711937911686ffbc/internal/core/mangle_watcher.go#L241-L315), [Go WriteFile contract](https://pkg.go.dev/os#WriteFile).

A 500 ms quiet interval is not a completed-write protocol. fsnotify explicitly states that a write event does not mean writing has finished; later writes may follow. Directory watches are the correct starting point for atomic-save editors, but they do not create snapshot isolation. [fsnotify event semantics](https://pkg.go.dev/github.com/fsnotify/fsnotify#Op), [fsnotify directory-watch advice](https://github.com/fsnotify/fsnotify#watching-a-file-doesnt-work-well).

### F2 — Publication erases the distinction between learned repair and policy-authoring authority

**Established missing publication gate; conditional downstream privilege impact.** The watcher applies the same repair mechanism to learned rules, policy overrides, schema extensions, and other watched `.mg` files. The final write does not perform destination-aware authorization or the learned API's protected-head check. On a later boot, file role selects the ingestion class.

The consequential scenario requires all of the following: a repair interceptor is attached; a privileged destination actually receives repair; the returned change affects an authority-bearing clause or removes a restriction; the replacement is published; and a later consumer successfully loads and evaluates it. A conforming one-clause repair can still change authority. Conversely, source inspection alone does not establish that the production model will emit such a clause, that all validator gates admit any particular example, or that an executable action becomes permitted.

This is not a claim that authorized human policy overrides must be treated as learned rules. They intentionally have a different role. The defect is that permission to propose a learned-rule repair is not explicitly separated from permission to overwrite an artifact boot treats as policy or schema. The existing learned gate and boot healing reduce risk for `learned.mg`; they do not establish the same protection for a repaired `policy_overrides.mg`. [Watcher write boundary](https://github.com/theRebelliousNerd/codenerd/blob/8fdeadce7c60c2f0461f7a2a711937911686ffbc/internal/core/mangle_watcher.go#L266-L315), [distinct ingestion](https://github.com/theRebelliousNerd/codenerd/blob/8fdeadce7c60c2f0461f7a2a711937911686ffbc/internal/core/kernel_init.go#L372-L402).

Cedar provides a useful design comparison, not evidence that codeNERD uses Cedar: schema validation checks policy consistency, while authority to edit permissions is a separate application-level meta-permission. A successful compiler verdict is not an authorization grant to its author. [Cedar validation](https://docs.cedarpolicy.com/policies/validation.html), [Cedar meta-permissions](https://docs.cedarpolicy.com/bestpractices/bp-meta-permissions.html).

### F3 — Successful repair publication is neither atomic nor durably acknowledged

**Established use of a nontransactional write; failure outcome conditional.** `os.WriteFile` truncates an existing file before writing and may leave partial contents on error. The watcher logs the error but has no preserved-generation restore protocol. Concurrent readers may observe incomplete bytes; a failed write may destroy the prior valid file. The `0644` argument does not chmod an existing file; it controls creation mode before umask, including the deletion/recreation case. [Write site](https://github.com/theRebelliousNerd/codenerd/blob/8fdeadce7c60c2f0461f7a2a711937911686ffbc/internal/core/mangle_watcher.go#L305-L315), [Go WriteFile](https://pkg.go.dev/os#WriteFile).

Atomic visibility, freshness, and durability are three separate properties. On Linux, same-filesystem rename can atomically replace a pathname, but it does not compare the destination generation. File synchronization does not by itself persist the containing directory entry; directory synchronization is needed for that durability requirement. Go also warns that `Rename` is not atomic on non-Unix platforms, so a portable implementation needs an explicit platform contract. No particular crash-loss result was reproduced here. [Linux rename](https://man7.org/linux/man-pages/man2/rename.2.html), [Linux fsync](https://man7.org/linux/man-pages/man2/fsync.2.html), [Go Rename](https://pkg.go.dev/os#Rename).

### F4 — Operational failure and invalidity share a destructive publication outcome

**Established error conflation; downstream policy effect conditional.** Any interceptor error is converted to an in-place commented-out rule. Yet the repair shard can reject because there is no model client, the cost guard refuses another call, or prompt construction fails; these do not establish that disabling the original clause is authorized. Even a truly invalid clause should not be removed from a privileged artifact merely because a generic learned-rule repair helper could not fix it. [Watcher error branch](https://github.com/theRebelliousNerd/codenerd/blob/8fdeadce7c60c2f0461f7a2a711937911686ffbc/internal/core/mangle_watcher.go#L281-L301), [operational repair failures](https://github.com/theRebelliousNerd/codenerd/blob/8fdeadce7c60c2f0461f7a2a711937911686ffbc/internal/shards/system/mangle_repair.go#L302-L344).

Cancellation is not checked again at commit. A cancellation-aware interceptor can return an error, which this branch turns into a mutation rather than abandonment. `Stop` closes the stop channel and waits for the event loop; it does not itself cancel an in-flight interceptor context. This is a lifecycle/publication contract issue, not a claim that a particular provider hangs indefinitely. [Stop and run](https://github.com/theRebelliousNerd/codenerd/blob/8fdeadce7c60c2f0461f7a2a711937911686ffbc/internal/core/mangle_watcher.go#L110-L167).

## 3. Required publication contract

A repair is a proposal until all of these conditions hold:

- **Identity:** the request binds canonical destination, ingestion class, source bytes/digest, and relevant schema/policy generation. File type and symlink policy are explicit; suffix matching alone is not authorization.
- **Freshness:** cancellation, deletion, replacement, or a newer source generation invalidates the proposal. No automatic resurrection. Conflict leaves the newer bytes untouched and schedules fresh assessment only if appropriate.
- **Authority:** the publisher, not the model or interceptor's success flag, determines whether this actor may alter that destination. Learned output passes the shared protected-head/schema gates. Policy and schema output requires distinct ownership/approval; otherwise offer a quarantined patch.
- **Final artifact:** validation covers the exact assembled output and intended program composition, excluding the old version being replaced. Validating fragments against the current kernel is not proof that their combined replacement file is valid.
- **Commit:** readers see either the complete old generation or complete new generation under the supported platform contract. Preserve required metadata; durably acknowledge only after the configured file/directory synchronization succeeds.
- **Outcome:** distinguish unchanged, proposed, invalid, conflict, cancelled, published, and durability-uncertain. An operational error must not silently become deletion of a rule. Counters distinguish attempted repair from committed repair.

These are audit recommendations, not an assertion that a generic final learned-head validator should be applied to every human-authored policy file.

## 4. Remediation options, costs, and trade-offs

**First contain authority.** Make privileged paths diagnostic-only or proposal-only for automatic repair. Let authorized users approve an exact content hash and destination; never let the candidate approve its own publication. Retain legitimate human policy editing. This is a relatively small surface change but reduces unattended recovery and adds review latency.

**Separate proposal from commit.** Bind proposals to source and program generations; use a per-path publication coordinator. A reread-and-compare is useful but is not an atomic compare-and-swap against an uncooperative external writer: another edit can land between comparison and rename. For strict no-clobber guarantees, require cooperative writer locking/versioned publication or leave the proposal uncommitted for owner reconciliation. State this limit rather than claiming a hash check plus rename solves every race.

**Publish a complete generation.** Use a same-directory temporary artifact, explicit permissions/metadata, checked write/close/sync steps as required, and an OS-appropriate atomic replacement mechanism. Preserve the prior version until the commit outcome is known. This costs extra disk space, hashing/read bandwidth, platform-specific handling, and synchronization latency. Atomic rename alone addresses neither freshness nor authority.

**Use bounded work without losing reconciliation.** Move expensive repair off the event reader into a bounded queue with per-path coalescing and generation cancellation; do not use unbounded goroutines. Keep quotas on bytes, candidates, provider calls, and wall time. Queue saturation or event overflow should mark the directory for reconciliation rather than silently imply coverage. The current loop performs repair synchronously and only logs/increments errors from fsnotify. [Current loop](https://github.com/theRebelliousNerd/codenerd/blob/8fdeadce7c60c2f0461f7a2a711937911686ffbc/internal/core/mangle_watcher.go#L132-L167), [overflow contract](https://pkg.go.dev/github.com/fsnotify/fsnotify#ErrEventOverflow).

More concurrency can increase spend and conflict frequency; a worker pool is not itself a correctness fix. Whole-artifact validation may add compilation cost and needs a stable program snapshot. Measure those costs rather than remove existing safety checks for throughput. Existing deterministic fixes, retry limits, cost guards, and unchanged-file no-write behavior are useful baselines to retain.

## 5. Fair offline evaluation and acceptance criteria

Use a temporary workspace and the pinned production entry paths. Start with deterministic, blocked interceptors for publication mechanics, then exercise the concrete repair shard and real kernel for authority semantics. No provider or destructive routed action is needed. Do not replace the real validator with a permissive stub and describe the result as a production exploit.

| Case | Controlled witness and required result |
|---|---|
| Newer edit | Pause after read A, publish B externally, release repaired A. B remains byte-identical; report conflict, not success. |
| Delete or replace | Delete the destination, or replace its identity during the pause. No resurrection and no overwrite of replacement. |
| Cancellation/stop | Cancel before validation, during repair, and immediately before commit. No new commit after cancellation; stopping drains admitted work under a bounded documented contract. |
| Operational refusal | Inject unavailable client, exhausted budget, prompt error, and cancellation. Preserve original artifact; emit the correct nonpublication reason. |
| Write failure | Inject write, close, replace, and sync failures separately. Preserve the prior valid generation where the contract permits; do not label uncertain durability durable success. |
| Exact authority chain | Select an un-commented, correctly declared authority-bearing candidate and a legitimate narrowing control. Exercise real repair validation, watcher publication to each file class, then actual boot ingestion and kernel queries. Record which stage accepts or rejects. Do not execute the queried action. |
| Learned controls | Require repaired learned candidates to pass final shared protection, and verify boot healing refuses the un-commented prohibited-head control. Keep the existing leading-comment audit separate; gate presence is not blanket proof of safety. A privileged-destination test must not be misreported as a `learned.mg` boot bypass. |
| Policy-owner control | Authorized human policy/schema editing remains supported through its distinct path; automatic repair does not erase that capability. |
| Preservation | Retain comments, neighboring rules, LF/CRLF behavior, and permissions; repeated unchanged validation produces no writes or endless repair loop. |
| Event/reconciliation | Test atomic editor saves, slow writes, bursts, overflow, and directory replacement on supported OSes. Record eventual latest-generation coverage, not just event counts. |

The existing watcher test explicitly covers preservation of the rest of the file and LF/CRLF behavior; it should remain a positive control. It also lists concurrency and extreme-input TODOs. This audit inspected the source but did not run those tests or establish suite-wide coverage. [Existing regression and TODOs](https://github.com/theRebelliousNerd/codenerd/blob/8fdeadce7c60c2f0461f7a2a711937911686ffbc/internal/core/mangle_watcher_test.go#L334-L420).

Compare baseline and proposed implementation on identical fixtures, filesystem/OS, program corpus, and injected schedules. Separate deterministic correctness tests from nondeterministic stress and provider-quality evaluation. Report stale writes, lost edits, unexpected recreations, incorrect authority admissions, missed latest generations, and false invalidations; also p50/p95/p99 latency, queue depth, memory, CPU/compilation time, disk writes/syncs, conflict rate, and provider calls/tokens. No benchmark numbers are claimed here. A faster implementation that drops validation or stops processing events is not an improvement.

## 6. Recommended disposition

Prioritize **freshness/no-clobber publication and destination-authority containment** before increasing repair parallelism. Treat non-atomic writes and operational-error mutation as part of the same publication redesign. Keep the documented distinction between compilation, learned-rule admission, disk publication, and boot/runtime consumption.

Closure requires an offline witness through the real publication boundary and, for the authority concern, the real ingestion/evaluation path with positive controls. Until then, the supported conclusion is: **a source-demonstrated unsafe publication protocol with conditional trusted-policy ingestion risk, not a demonstrated default-model exploit or live runtime permission bypass**.
