# Mission receipts omit error free group witnesses

## Decision and evidence boundary

Mission-linked recurse needs a source-bound receipt for the focused witness it runs when repairing an optional error-free gate finding. That witness currently contributes a boolean to the ratchet, but its result does not reach the mission's durable check record. The mission's support calculation instead reads the ordinary workspace-gate map, where this kind of attempt has no key. A kept repair from this route consequently remains `/unknown`, even when its focused after-witness exits successfully.

Keeping `/unknown` is correct with the evidence currently available. The defect is the missing observation and persistence path, not an excessively conservative policy rule. Do not repair it by relabeling `TargetOK` as source-bound support. The required change is to capture compatible before and after witness observations at exact source snapshots, preserve their outputs, and let mission policy judge that evidence.

This is a static source review of public main [`8d373fb6ca05ef03fec59b923c5f1925066d623a`](https://github.com/theRebelliousNerd/codenerd/commit/8d373fb6ca05ef03fec59b923c5f1925066d623a), revalidated on October 30, 2026. The affected mission, recurse, CLI and architecture files were re-fetched at that revision and were unchanged from the initial inspection at `d490b08dc891d00087525f4d521ac7caa99a5c83`. An independent source reviewer corroborated the missing-key and discarded-result path. No tests, benchmarks, application execution, model calls, inference or training were performed. The proposed evaluations below have not run.

The affected production combination is a mission invocation with optional CLI `--gates` measurement that selects an error-free finding group. Ordinary recurse without a mission does not promise a mission receipt; ordinary workspace/node-gate repairs use a separate path that already carries source-bracketed measurements. This report does not demonstrate an unsafe commit, weakened ratchet, false mission satisfaction, or observed user loss.

## Primary provenance reference

[SLSA’s provenance specification](https://slsa.dev/spec/v1.0/provenance) describes binding artifact production to verifiable identities and inputs. It motivates retaining explicit source and check identity here; the proposed mission receipt is not represented as SLSA provenance and gains no automatic SLSA guarantee.

## What the production path implements

The CLI constructs a `RecurseMission` when `--mission` is supplied and passes it together with the optional `MeasureGates` callback to the same recurse driver. The mission contract explicitly retains the existing optional error-free measurement behavior. It also says the mission sidecars preserve complete measured check output and comparison domains, and distinguishes historical gate-deficit support from satisfaction of the owner's free-text mission. [CLI mission construction](https://github.com/theRebelliousNerd/codenerd/blob/8d373fb6ca05ef03fec59b923c5f1925066d623a/cmd/nerd/cmd_campaign_recurse.go#L206-L220), [shared loop wiring](https://github.com/theRebelliousNerd/codenerd/blob/8d373fb6ca05ef03fec59b923c5f1925066d623a/cmd/nerd/cmd_campaign_recurse.go#L249-L260), [durable receipt contract](https://github.com/theRebelliousNerd/codenerd/blob/8d373fb6ca05ef03fec59b923c5f1925066d623a/Docs/architecture/campaign/MISSION-IMPROVEMENT.md#L50-L74), [optional gate scope](https://github.com/theRebelliousNerd/codenerd/blob/8d373fb6ca05ef03fec59b923c5f1925066d623a/Docs/architecture/campaign/MISSION-IMPROVEMENT.md#L113-L119).

Error-free measurements produce groups by gate, check and package. Only supported selectable checks receive a witness command: examples include a vet analyzer, a staticcheck check or a golangci-lint linter over the selected package. Build, test and other gates without this focused command do not enter the same group route. `errorFreeSpec` carries the group, its symptom text and its witness argv into the attempt. [Group construction](https://github.com/theRebelliousNerd/codenerd/blob/8d373fb6ca05ef03fec59b923c5f1925066d623a/internal/gates/errorfree_groups.go#L18-L82), [supported witness selectors](https://github.com/theRebelliousNerd/codenerd/blob/8d373fb6ca05ef03fec59b923c5f1925066d623a/internal/gates/errorfree_groups.go#L101-L132), [attempt construction](https://github.com/theRebelliousNerd/codenerd/blob/8d373fb6ca05ef03fec59b923c5f1925066d623a/internal/campaign/recurse_error_free.go#L81-L101).

The repair still runs as a normal attempt campaign, with the witness command as campaign acceptance when present. Separately, the outer recurse driver reruns the focused group witness after a changed attempt. Its result is not trusted from model prose: `RunWitness` returns the command's success, exit code and complete combined output, with cancellation or launch failures returned as errors. [Campaign acceptance command](https://github.com/theRebelliousNerd/codenerd/blob/8d373fb6ca05ef03fec59b923c5f1925066d623a/internal/campaign/recurse_attempt.go#L105-L119), [host witness result and runner](https://github.com/theRebelliousNerd/codenerd/blob/8d373fb6ca05ef03fec59b923c5f1925066d623a/internal/gates/errorfree_groups.go#L134-L180).

## The source identity path is missing for these groups

Ordinary workspace/node-gate measurements have a `gateRun.snapshot`. In mission mode, `measure` takes a workspace snapshot before the gate and another after it; it publishes the first identity only when the second matches. The map keys are formed as `gateID + "@" + node`. Normal finding attempts populate `attemptSpec.targetKey` with the appropriate map key. [Source-bracketed ordinary measurement](https://github.com/theRebelliousNerd/codenerd/blob/8d373fb6ca05ef03fec59b923c5f1925066d623a/internal/campaign/recurse_cycle.go#L573-L624), [normal finding key](https://github.com/theRebelliousNerd/codenerd/blob/8d373fb6ca05ef03fec59b923c5f1925066d623a/internal/campaign/recurse_cycle.go#L929-L941).

`errorFreeSpec` does not set `targetKey`. It leaves the string empty while still setting `finding`. The common run path therefore assigns `a.WitnessSnapshot = r.state[spec.targetKey].snapshot` from `r.state[""]`. Production state entries use the gate/node key scheme, not an empty key, so this lookup yields the zero-value empty snapshot. [Missing target key](https://github.com/theRebelliousNerd/codenerd/blob/8d373fb6ca05ef03fec59b923c5f1925066d623a/internal/campaign/recurse_error_free.go#L92-L100), [common snapshot lookup](https://github.com/theRebelliousNerd/codenerd/blob/8d373fb6ca05ef03fec59b923c5f1925066d623a/internal/campaign/recurse_cycle.go#L996-L1005).

After the focused witness runs, the mission support branch requires all of the following: a finding, `TargetOK`, a nonempty `a.WitnessSnapshot`, equality with the mission's before snapshot, and an after measurement whose snapshot equals the mission's final source snapshot. The group route cannot meet the nonempty requirement, and `after[spec.targetKey]` addresses the same missing key. `missionWitness` stays `/unknown`. Mangle then correctly derives `/unknown` for a kept observation whose witness is not `/resolved`. [Support admission](https://github.com/theRebelliousNerd/codenerd/blob/8d373fb6ca05ef03fec59b923c5f1925066d623a/internal/campaign/recurse_cycle.go#L1177-L1188), [mission evidence policy](https://github.com/theRebelliousNerd/codenerd/blob/8d373fb6ca05ef03fec59b923c5f1925066d623a/internal/core/defaults/policy/mission.mg#L26-L29).

A gate snapshot ID or its `Head` field is not a substitute. `gates.Snapshot` explicitly permits dirty trees; `Head` identifies the starting commit, while its ID is time-based. Neither is the whole-working-tree content identity used by mission support. Composed baselines can additionally combine observations from different measurements. Merely copying such an ID into `WitnessSnapshot` would make the types agree without establishing the claimed evidence. [Snapshot identity contract](https://github.com/theRebelliousNerd/codenerd/blob/8d373fb6ca05ef03fec59b923c5f1925066d623a/internal/gates/errorfree_snapshot.go#L19-L43).

## The focused ratchet result is not retained in the mission sidecar

The outer loop stores `RunWitness` in a block-local `res`, derives `in.TargetOK`, and logs errors or nonpassing output. It does not place that result in `after`, attach it to the attempt receipt, or pass it to `recordChecks`. The durable recorder receives the ordinary before/after gate maps and the error-free comparison snapshots. These are useful observations, but they are not the return value of the focused command that just decided the group's target. [Focused witness consumption](https://github.com/theRebelliousNerd/codenerd/blob/8d373fb6ca05ef03fec59b923c5f1925066d623a/internal/campaign/recurse_cycle.go#L1138-L1151), [recorder call](https://github.com/theRebelliousNerd/codenerd/blob/8d373fb6ca05ef03fec59b923c5f1925066d623a/internal/campaign/recurse_cycle.go#L1177-L1188), [durable sidecar shape](https://github.com/theRebelliousNerd/codenerd/blob/8d373fb6ca05ef03fec59b923c5f1925066d623a/internal/campaign/recurse_mission_storage.go#L87-L121).

This does not mean all gate output disappears. The mission retains broad measurement snapshots and ordinary gate output, and a failed focused witness can be printed to progress. The attempt campaign may also have run its own acceptance invocation. None of those facts establishes that the mission sidecar preserves this outer ratchet invocation's output, exit, error and source interval. In particular, successful focused output is not logged by the shown branch. A durable record should distinguish the campaign's invocation from the later ratchet invocation rather than relying on incidental nearby logs.

The deterministic conditional case is therefore narrow: a mission selects a supported error-free group, executes a changed repair, obtains a successful focused after-witness, and passes the independent keep conditions. The cycle may be kept, but its mission evidence remains unknown and the mission check sidecar lacks the focused ratchet result. No claim is made that a particular repair has been executed or that every selected group can be successfully repaired.

## Controls and overlap

The repair must preserve the existing independent controls. The current loop checks changed paths against owned-write postimages, pinned verification inputs, protected paths and admitted mission scope. It runs ordinary applicable gates, evaluates the error-free comparison, and asks the ratchet for the outcome. Those checks do not become optional merely because a source-bound focused witness is added. [Mission write and attribution checks](https://github.com/theRebelliousNerd/codenerd/blob/8d373fb6ca05ef03fec59b923c5f1925066d623a/internal/campaign/recurse_cycle.go#L1090-L1128), [additional measurements and ratchet](https://github.com/theRebelliousNerd/codenerd/blob/8d373fb6ca05ef03fec59b923c5f1925066d623a/internal/campaign/recurse_cycle.go#L1130-L1176).

The inspected [gate comparison domain audit](https://github.com/theRebelliousNerd/codenerd/blob/8d373fb6ca05ef03fec59b923c5f1925066d623a/Docs/audits/gate-comparison-domain-admission.md) and [scoped recurse addendum](https://github.com/theRebelliousNerd/codenerd/blob/8d373fb6ca05ef03fec59b923c5f1925066d623a/Docs/audits/gate-scoped-recurse-current-main-addendum.md) address comparable measurement domains, opaque failures, restriction and composed-baseline validity. This report does not repeat their historical claims about current comparison behavior. Its distinct boundary is the optional group's focused host witness entering mission source support and durable receipts. Stronger gate-domain comparison alone does not populate the missing mission witness path.

The [compile diagnostic witness audit](https://github.com/theRebelliousNerd/codenerd/blob/8d373fb6ca05ef03fec59b923c5f1925066d623a/Docs/audits/compile-diagnostic-witness-admission.md) concerns whether a normalized diagnostic names a valid selectable analyzer. Here the conditional witness is valid and passes; its observation still lacks the mission source and persistence path. The independent overlap review also distinguished `recurse-gate-contract-continuity`, about environment and passing-exit continuity, and `recurse-gate-subsumption`, about work suppression. Those are different boundaries from retaining the selected focused invocation as mission evidence.

The existing production mission fixture is useful counterevidence to an overbroad claim that all mission receipts lack gate evidence. It asserts supported evidence and checks the `go:test@store` ordinary gate rows. That authored fixture does not exercise optional error-free groups, and this review did not run it. [Existing receipt and ordinary gate assertions](https://github.com/theRebelliousNerd/codenerd/blob/8d373fb6ca05ef03fec59b923c5f1925066d623a/cmd/nerd/cmd_campaign_mission_test.go#L244-L275).

## Proposed observation contract

Add an explicit mission witness observation for the selected work item rather than overloading the ordinary gate map with a synthetic empty key. It should retain the mission and cycle identity, group identity, gate/check/package domain, command identity, observation role, exit status or execution error, complete output or an immutable output sidecar, and source identities measured immediately before and after the observation.

The before evidence must establish the selected deficit at the mission's admitted source; the after evidence must establish its resolution at the retained source. A fresh focused before-witness is one conservative approach. Reusing an existing broader observation is acceptable only when it already retains compatible source and check-domain evidence sufficient to establish that same deficit. The present gate snapshot ID and starting HEAD do not provide that evidence.

Go should measure and persist these facts. Mangle should determine whether source stability, domain compatibility, the observed deficit, successful resolution and kept outcome support `/supported_gate_deficit`. Missing, interrupted, stale or incompatible evidence must retain `/unknown` with a useful reason. A stable successful after-command alone cannot demonstrate a resolved before-deficit.

Keep raw output persistence separate from support admission. A failed or canceled witness is still an observation worth retaining; publishing it does not make it supportive. Use the existing mission sidecar and atomic-write conventions, record the exact invocation role, and preserve recovery ambiguity if result persistence fails. Do not manufacture evidence for older receipts from commit messages, group names, `TargetOK`, or an unrelated acceptance run.

## Evaluation and cost

The smallest useful validation is an authorized production-path fixture using a scripted model, real kernel, normal campaign dispatch and a real focused host witness. It should select a supported error-free group through `--mission` plus `--gates`, establish the deficit before the attempt, repair only an admitted source path, and compare the final source, ratchet result and reloaded mission sidecars. This is a proposed test, not a completed reproduction.

Include these controls:

- A kept group repair with compatible, stable before/after evidence produces historical gate-deficit support and retains both observations.
- The same repair without a mission preserves ordinary recurse behavior.
- An ordinary workspace-gate mission repair preserves its existing support path.
- A passing focused after-witness with missing or stale before evidence remains unknown.
- Source changes during either observation, changed check/package domain, unavailable tools, cancellation and partial results remain unknown and retain diagnostic evidence.
- A successful target witness with a forbidden write, worsening independent gate or failed attribution still cannot obtain a kept outcome.
- Reverted or unchanged attempts never become supported merely because a witness passed.
- Sidecar write failures, restart and reload preserve unresolved intent rather than presenting a complete receipt.
- Existing receipts without the new observations remain readable as historical unknowns; no migration invents source identity.

Compare the current implementation with result-persistence alone, source-bound focused observations, and any evidence-reuse optimization. Score retained result completeness, support correctness, false support, false unknown, source-drift detection and restart fidelity. Require the same repair and independent safety outcomes across variants.

Report additional host processes, compiler/linter CPU, wall time, source hashing I/O, peak memory, output bytes, sidecar storage, kernel facts and persistence latency. A fresh before-witness adds real work; bracketing observations can require whole-workspace hashing. Large output should use bounded in-memory handling with complete durable capture rather than silently truncate evidence. If supported evidence later reduces repeated investigation or model turns, measure those savings separately and include the new observation costs. No reliability, token or performance improvement has been measured here.

The completion criterion is a checkable mission record for the selected optional gate witness, not a more optimistic label. The system should either retain source-bound evidence that justifies its historical support statement or explain why that support remains unknown.
