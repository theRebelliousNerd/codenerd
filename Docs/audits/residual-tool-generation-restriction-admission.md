# Residual TUI tool-generation request admission

## Status and precise correction

This independent correction/addendum concerns public repository `theRebelliousNerd/codenerd`, pinned to commit `9dcb01b9736bf4763aa3ac391d29f133d73c6611` (main rechecked at 14:21 UTC on 2026-10-29). It leaves the protected predecessor unchanged. Assessment is limited to source inspection: no tests, inference calls, benchmarks, or runtime experiments were run for this addendum; no observed production failure is claimed.

The earlier [restriction-continuity audit, lines 265–275](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/Docs/audits/perception-restriction-continuity.md#L265-L275), already defers admission outside the session executor. Its narrower clause at line 269—“the chat's residual information-gathering path only reads”—needs correction: that helper also consumes `/generate_tool`. The omitted consumer, rather than a rediscovery of the general admission boundary, is this addendum’s subject.

**Conditional finding:** when processing reaches the residual action query, a live eligible missing-tool fact can select generation; the helper can then invoke the audited generator without an explicit current-request restriction admission check in that branch. This does not mean every read request generates tools, generation inevitably writes, or existing session-executor protections are bypassed generally.

## Conditional route and eligibility

The residual path therefore has restriction-bearing context; “lost context” is not the explanation here. ## Why generation needs request admission

This is not the old shallow-generator issue. [autopoiesis_tools.go, lines 18–66](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/autopoiesis/autopoiesis_tools.go#L18-L66) routes `GenerateTool` through the full audited Ouroboros flow, rejecting errors. `DetectToolNeed` itself asserts `missing_tool_for` at lines 26–30: detection publishes an observation, not permission. That flow validates/reuses candidates, performs safety and Jev code checks, optionally runs Thunderdome, and requires Mangle simulation before commit. See [ouroboros.go, lines 351–407](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/autopoiesis/ouroboros.go#L351-L407) and [lines 493–706](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/autopoiesis/ouroboros.go#L493-L706).

Successful commit can write tool source, invoke compilation, and register the result, with snapshots and rollback: [ouroboros.go, lines 851–925](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/autopoiesis/ouroboros.go#L851-L925). The [factory passes its workspace to default configuration](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/system/factory.go#L1952-L1959); [defaults](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/autopoiesis/ouroboros.go#L162-L186) use a workspace `.nerd/tools` source directory and a `.compiled` artifact directory. Runtime networking/exec defaults are disabled, but that does not authorize compiler/source-write effects. Reuse or failures can prevent some or all effects.

Code safety is not permission from the current requester. The examined generator path does not consume `RestrictionFromContext` as request admission. Its [simulation builds a fresh engine with state schemas and simulation facts](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/autopoiesis/ouroboros.go#L751-L804), not current-request restriction policy. The [Jev tool questions](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/autopoiesis/tool_jev.go#L15-L35) concern duplication and code; [toolRequestOf](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/autopoiesis/tool_jev.go#L96-L99) carries name, purpose, input, and output, not restriction. Model judgment can reduce generation, but is not restriction measurement. Jev-off/error behavior is not itself the claimed bypass.

Existing effective-catalog, exact-permission, and approval protections remain relevant to ordinary executor tools. The prior audit’s [context/effect distinction at lines 247–252](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/Docs/audits/perception-restriction-continuity.md#L247-L252) should remain intact: `read_only`, `no_changes`, `dry_run`, and `hypothetical` bar write/execute/unknown effects; external-effect restrictions are narrower; confirmation has its own broker. This finding claims neither arbitrary generated-code execution nor a blanket `permitted` bypass or false completion.

## Proposed admission contract

The minimum patch would block this residual generation consumer under incompatible restrictions before detector/generator spending. It corrects the local omission, but is weaker than shared admission: another generation entry point could still lack request ownership or equivalent checks. The recommended design is a cheap, bounded host-policy decision, not another LLM permission prompt.

1. **Measure the operation.** Treat fresh generation as write and execute work, including source/artifact destinations and registration. Define reuse separately according to its actual effects. Distinguish user-workspace tooling from intentionally excluded service-owned learning or disk bookkeeping; do not silently exempt tool creation as bookkeeping.
2. **Bind an immutable envelope.** Include owner turn/request ID, restriction digest, measured effect kinds, capability and need/payload identity, origin, root/output destinations, and operation scope. Proposals and missing-tool observations remain observations, never authority. Prevent pre-admission observation publication from becoming an ambient mutation trigger; scope detection-produced facts to their proposal and owner. This is a design requirement, not a claim of demonstrated cross-consumer propagation. Missing or ambiguous ownership must not grant a user-request generation operation.
3. **Use exact shared admission.** Apply one host/Mangle admission boundary to residual, delegated, and backend generation entry points. Reject hard-bar conflicts before detection where the proposed generation effects are already known. Request-scoped confirmation must identify the exact operation and human decision; it cannot lift an incompatible hard restriction. No-host or permissive interaction modes must not manufacture confirmation.
4. **Revalidate before effects.** Recheck ownership, cancellation, restriction identity, destinations, and operation binding immediately before commit. Prevent retries, duplicate races, and replay from borrowing another request’s authorization. Preserve safety auditing, simulation, compiler validation, snapshots, and rollback as additional layers.

Background ownership requires a separate design decision. [factory.go, lines 2753–2802](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/system/factory.go#L2753-L2802) owns background autopoiesis lifetime and listener startup; [autopoiesis_delegation.go](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/autopoiesis/autopoiesis_delegation.go#L21-L122) reads delegation tasks, constructs needs, and runs the loop, with [listener lifetime handling](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/autopoiesis/autopoiesis_delegation.go#L175-L231). Evaluate shared admission there too, while explicitly authorizing service maintenance separately. This adjacent lifecycle is not evidence of a complete normal-TUI model-update-to-listener exploit route.

## Costs and fair evaluation

Early denial can avoid detector/model, simulation, and compiler work. Authorized generation still pays for detection, generation, Jev evaluation, and applicable adversarial checks; the proposal does not make that work free. Shared envelopes introduce context/ownership plumbing, synchronization, duplicate handling, and cleanup/retirement complexity. Overbroad classification can falsely deny legitimate explicit generation. Receipt storage also has byte, retention, and privacy costs. No latency, token, or spending improvements are quantified here.

Compare the current implementation, a minimal residual block, and shared admission on identical scripted inputs. Measure detector/generator/handler, compiler, and registry invocation counts; source and compiled artifacts; reuse behavior; latency, tokens, spending, cancellation, and retries. Check authorized output quality rather than treating a reassuring response string as success. Separate saved work on denial from unchanged costs of authorized generation.

The following are proposed fixtures, not executed results. Preserve the routing counterexample: a `hypothetical` request normally diverted into the dream path does not reach this residual branch. Test its effect bar directly at shared admission or establish a compatible route; do not assume residual reachability from the restriction alone.

- **Eligibility baseline:** ordinary stock read with no missing fact produces no generation selection. Separately seed a live eligible fact in the queried kernel and demonstrate residual reachability; do not rely on an assumed model response.
- **Detector boundaries:** scripted nil/error, `0.59`, and `0.6` outcomes expose the current threshold. Under `read_only`, `no_changes`, or `dry_run`, the proposed early gate should allow zero generation/effect calls; verify `hypothetical` and narrower external restrictions according to their distinct effect policies.
- **Authorization:** unrestricted eligible generation retains the full audited loop. Confirmation rejection, no confirmation host, and permissive/“yolo” mode do not grant a confirmation-required operation. Approval plus a hard bar still denies it. Named dangerous capabilities remain blocked.
- **Route controls:** earlier returns and absent autopoiesis never create a generation witness. Read/search siblings retain their behavior. Exercise existing-tool reuse without presuming that reuse writes or compiles.
- **Failures and ownership:** assert no commit on safety/simulation rejection and snapshot restoration on applicable commit-stage failure, including compilation failure. Cover two concurrent owners, stale facts under current restrictions, cancellation/retry, and separately authorized background maintenance. Assert no cross-owner authorization contamination.

## Receipts and exit criteria

A request-bound receipt should distinguish observed need, eligibility, proposal, denial, confirmation, reuse, generation, registration, and failure. Include the restriction digest and measured effects, while minimizing payload exposure. A warning or successful tool-generation message alone is insufficient proof of admission or effect completion.

Closure requires correcting exactly the omitted consumer’s documented scope, demonstrating that restricted requests cannot authorize generation effects through it, and preserving legitimate generation through the audited path. Shared admission additionally needs evidence for each covered owner/entry point, not a claim that one residual-branch fix protects every lifecycle.
