# Manual learning evidence conservation

*Scoped addendum to the learned correction integrity audit. Source inspection only.*

Two manual-learning paths lose information before a learned fact reaches durable storage. Bare `/learn` converts individual UI messages into successful exchanges, including its own status notice. Separately, confirmation by candidate ID reconstructs a fact without the qualifier or confidence originally proposed by the critic. The first changes the evidence presented to the model; the second deterministically changes the fact submitted for persistence when the original fields differ. Neither proves an incorrect future classification or bypasses explicit confirmation.

**Baseline:** public repository `theRebelliousNerd/codenerd`, main [`9dcb01b9736bf4763aa3ac391d29f133d73c6611`](https://github.com/theRebelliousNerd/codenerd/commit/9dcb01b9736bf4763aa3ac391d29f133d73c6611), unchanged at the 2026-10-29 15:18 UTC check. At 15:12 UTC, the five inspected implementation paths were byte-identical on active lane heads `a53cfc308e8836c72370adaa46deba3f7b00180d`, `80af1863d3a3aa46a722ac8b0c8a0985582d4995`, and `aa7988dec4c62116656ea722ff73b687a8509908`. Both findings received independent source challenges. No tests, application execution, model inference, or benchmarks were performed. All examples below are synthetic.

|---|---|---|
| UI history to manual critic input | Roles, request–response association, and truthful outcome meaning | A critic can still infer a correct fact, return empty, or fail |
| Candidate staging to confirmation by ID | Original qualifier and confidence | Persistence needs explicit confirmation and healthy configured dependencies |

## Manual learning misrepresents UI messages as successful exchanges

The reachable route is an idle, normal chat submission. Enter calls `handleSubmit` only when no turn is running; clarification mode takes a different branch. Slash dispatch occurs before the ordinary user-message append, and `/learn` selects `handleLearnCommand`. Thus the command itself does not become a new user history entry. [Enter routing](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/model_key_handler.go#L229-L255), [submission order](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/model_handlers.go#L124-L145), [command dispatch](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/commands.go#L168-L169).

The handler first appends an assistant status notice announcing the critic. Its callback then builds one trace per history `Message`: every `Response` is that message’s content, every `Success` is `true`, and `UserPrompt` is `"..."` except for a user message, whose content is copied into both fields. A user correction is consequently labeled as its own “Agent Action”; an assistant response has no originating request; the new status notice is another successful action. [Status and trace construction](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/commands_handlers.go#L578-L604).

For example, two UI messages containing a request and its answer produce two traces rather than one exchange. After the notice is appended, the input has three traces. The critic formatter takes the last five **traces**, labels each `User`, `Agent Action`, and `Success`, and head-bounds each text side to 2,000 runes plus a truncation marker. On this path the window contains the status and at most four preceding UI messages, not five completed exchanges. With initially empty history, the notice also defeats the downstream empty-history short circuit. It creates work eligibility, not a guaranteed model call: missing client or JIT prompt configuration can still return an error. [Empty-history guard and formatter](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/perception/learning.go#L235-L274), [required JIT compiler](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/perception/learning.go#L114-L131), [rune-safe bound](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/perception/learning.go#L515-L525).

This matters because the live `learning_critic` role is instructed to find misclassifications, explicit corrections, and recurring user qualifiers. Its contract allows one bare `learned_exemplar` or an empty result. The malformed association changes evidence for that task, but does not force the model to learn a bad mapping. The returned fact is staged for confirmation, not directly persisted by the bare command. [Critic atoms](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/atoms/perception/learning_critic.yaml#L10-L66), [call and return](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/perception/learning.go#L269-L308), [staging](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/commands_handlers.go#L608-L615).

The executor supplies a useful comparison, not a complete replacement. `tracesFromHistory` pairs a user entry with a following assistant entry and drops incomplete pairs. Its caller supplies a measured verdict only for the last exchange; earlier boolean values default to false. This avoids asserting success for every historical message, but false is not an explicit unknown state. Nor would naïvely pairing the UI ledger distinguish a real answer from an assistant-role notice. [Executor projection](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/executor_learning.go#L237-L294).

## Confirmation by ID discards the proposed qualifier and confidence

Candidate staging parses the full learned fact but retains only phrase, verb, and target for `RecordLearningCandidate`, alongside the reason. The original fact remains in a transient `learning_candidate_fact` kernel fact. The durable candidate type, insert, select, and table schema have no qualifier or confidence fields; their identity is phrase, verb, target, and reason. [Staging and transient retention](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/model_handlers.go#L278-L330), [candidate store](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/store/learning_candidates.go#L9-L103), [SQL schema](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/store/local_core.go#L335-L349).

The two confirmation routes then diverge. Inline confirmation prefers the original transient fact. Its fallback, and the ID route unconditionally, reconstruct:

```text
learned_exemplar("PHRASE", /verb, "TARGET", "", 0.90).
```

The ID route lists the most recent 100 candidates without a status filter, locates the requested ID, updates its status, and passes this reconstruction to `PersistLearnedFact` when the taxonomy is available. It never loads the transient full fact, even if that fact still exists. [Inline preservation and fallback](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/model_handlers.go#L374-L402), [ID lookup and reconstruction](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/commands_handlers.go#L455-L531).

A bounded source-derived witness starts with a valid critic result:

```text
learned_exemplar("add a feature", /create, "feature", "include a regression test", 0.97).
```

Assume successful candidate staging, an available local database, the candidate still among the 100 queried rows, and healthy taxonomy, workspace, and persistence dependencies. Inline acceptance can preserve the qualifier and 0.97. For a normal-mode ID route, the user can first explicitly answer No, [return to normal chat](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/model_handlers.go#L451-L458), then reconsider using `/learn list` and `/learn confirm <id>`. The ID must be known or visible in the list, which shows the most recent 50 candidates. [List behavior](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/commands_handlers.go#L419-L442). Rejection updates status rather than deleting the SQL row and clears the transient facts; the ID query accepts all statuses. This is explicit reconsideration, not a rejection bypass. Typing a slash command while still in clarification is not the witness, because Enter routes that text to the clarification handler. [Rejection and clearing](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/model_handlers.go#L505-L511), [cleared predicates](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/model_handlers.go#L260-L276), [SQL status update](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/store/learning_candidates.go#L105-L151).

Under those preconditions, the ID route submits an empty qualifier and 0.90 instead. `PersistLearnedFact` cannot recover the lost fields: it normalizes its supplied fact, hot-loads and appends that normalized fact, then parses the supplied original for knowledge and semantic projections. Healthy persistence preserves the reconstruction, not the critic proposal. [Persistence](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/perception/learning.go#L319-L412).

The qualifier is learned text, not an enforcement capability. This finding establishes content inequality, not automatic execution, widened permissions, guaranteed future misclassification, or a claim that every displayed confirmation means every projection succeeded.

## A bounded conservation contract

The smallest coherent repair should transport evidence deterministically rather than ask another model to repair missing context.

Capture an immutable learning input before appending command status. Preserve message identity, role, source kind, and known outcome evidence. Project completed exchanges; explicitly represent any incomplete material retained for corrections. Exclude status notices by provenance, not by their wording. Select a bounded window with documented truncation rules, preserve unknown outcomes as unknown, and treat genuinely empty analysis as a no-op. Reuse existing pairing logic only where its input contract holds. Keep manual-request admission distinct from background cadence: one completed exchange containing explicit teaching may suffice, and an unpaired latest correction can be useful if honestly marked incomplete. Do not repair labels by silently discarding those signals.

Persist a typed, normalized candidate payload before presenting confirmation. Carry qualifier, confidence, provenance, schema version, and a stable payload identity or digest. Both inline and ID confirmation should review and consume that same payload and return idempotent outcome receipts. Confidence remains evidence, never authority. Display the complete proposed mapping and qualifier so the user can judge the actual payload. Today the inline question shows phrase and verb; the list shows phrase, verb, target, status, and count, but neither displays the original qualifier. [Inline question](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/model_handlers.go#L342-L350), [list columns](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/commands_handlers.go#L433-L442).

Legacy rows with missing fields must remain distinguishable from facts that explicitly proposed an empty qualifier. Require review or reteaching when the original cannot be recovered; silently supplying empty text and 0.90 is not recovery. Candidate identity and deduplication must not merge distinct qualified proposals merely because phrase, verb, target, and reason agree. That collision follows from the current schema; it is not a separately observed production incident. Retain the original evidence reference, and bound or refuse oversized payloads without silently truncating away conditions. Do not reconstruct an unavailable original from a merely matching later candidate.

These changes must preserve explicit confirmation, normalized learned-fact parsing, existing permission boundaries, and JIT ownership of model-facing behavior. They do not require additional LLM calls or a broader automatic-learning policy. The repository’s [spec-first and JIT contract](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/agents.md#L92-L110) should govern any implementation.

Costs are real. Projection requires a bounded scan or O(n) history pass, snapshot ownership, and source retention. Typed candidates add storage proportional to retained payload bytes, migration work, digest computation, changed deduplication, and potentially more review friction. Five completed exchanges can contain more tokens than the current four preceding UI messages plus notice. Truncation must preserve correction context fairly, including Unicode boundaries. No token or latency saving is established; an empty-input guard avoids critic work only when no other work is required.

## Evidence needed before claiming a repair

The existing executor tests specify pairing and incomplete-turn behavior. The real-kernel candidate staging test uses no local database, an empty qualifier, and confidence 0.9, so it cannot establish durable confirmation parity. The store tests cover counts and status transitions rather than preservation of the full fact. These test definitions were inspected, not run. [Pairing tests](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/executor_learning_test.go#L185-L238), [staging fixture](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/cmd/nerd/chat/learning_candidate_stage_test.go#L9-L26), [store tests](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/store/learning_candidates_test.go#L8-L90).

A deterministic acceptance suite should exercise the actual idle TUI dispatcher and capture the JIT critic request. Assert correct associations and outcome meaning for ordinary exchanges, errors, tool messages, asynchronous notices, empty history, incomplete turns, window boundaries, and Unicode truncation. A synthetic critic should then return a full fact with a nonempty qualifier and non-0.9 confidence. Compare inline acceptance with explicit rejection followed by ID reconsideration through staging and persistence. Add legacy rows, duplicate phrases with different qualifiers, rejection without learning, database and persistence failures, and reopen cases once the relevant rehydration route is verified.

Only after those transport invariants hold would a model study answer whether the repair improves learning. A future, unrun study should hold tasks, provider, and budget fixed; measure exact mapping and qualifier recall, later intent and constraint accuracy, wrong learning, no-pattern behavior, calls, tokens, latency, and review burden; and include positive controls. Source proof establishes what information crosses each boundary. Empirical evaluation is still needed to establish the effect on model behavior. The deterministic exit is narrower: the same source messages produce correctly typed manual input, and the same normalized candidate payload is confirmed through either path without inventing unknown fields.
