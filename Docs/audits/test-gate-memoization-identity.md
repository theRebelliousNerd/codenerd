## Decision and review scope

The branch memoization key is not a sufficient identity for the test gate it reuses. It can equate states with different written-test obligations, different importer test inputs, or different discovery outcomes. Preserve the performance goal of avoiding redundant test processes, but do not treat this key as evidence that the current gate was measured. The defect is incomplete identity, not memoization itself.

This is a source audit of `theRebelliousNerd/codenerd`, pinned to branch commit `7291bb758f847a0a628dccc470d38af34b74f8c1` and main commit `b2be2799914ec942c90e08a7b487adc405c6428c`, with main checked at 08:42 UTC on October 29, 2026. Main still calls the own-test and importer measurements directly; the branch adds the lookup layer. The findings below are conditional, source-derived witnesses, not observed executions. No tests, benchmarks, inference, or training were run, and no timing claims were verified. [Main gate](https://github.com/theRebelliousNerd/codenerd/blob/b2be2799914ec942c90e08a7b487adc405c6428c/internal/session/build_verify.go#L513-L555), [branch gate](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/build_verify.go#L513-L587).

## What the key actually identifies

`writtenFingerprint` starts with explicitly written paths, adds immediate regular-file siblings from their directories, sorts the resulting paths, and hashes their contents. It distinguishes absent and unreadable files. It does not recurse into subdirectories, and directory-entry symlinks are not added as regular neighbors. `gateKey` combines measurement kind, workspace, and that fingerprint. Consequently, adding an already-hashed sibling to `WrittenPaths` can leave the key unchanged: the key contains the expanded file set, not exact write-set membership. [Fingerprint and key](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/gate_memo.go#L39-L85).

The measured operation depends on more. Own-test measurement derives packages from `WrittenPaths`, filters coverage with it, attributes failures using `PreWriteContents`, and runs specially tagged tests selected by the written paths. Importer measurement discovers other packages before running them. Neither preimages nor discovery results are encoded in the key. This is a mismatch between what the cache identifies and what the gate computes. [Own measurement](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/build_verify.go#L571-L587), [importer measurement](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/importer_packages.go#L94-L110).

The cache is a private field of `ExecutionResult`; `ProcessWithIntent` constructs a fresh result. Its scope is therefore the current result/turn, not persistent cross-turn reuse. Within that scope, `rememberGate` excludes only canceled and indeterminate verdicts, retaining passed, failed, and skipped outcomes. [Storage](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/executor.go#L956-L959), [fresh result](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/executor.go#L1181-L1185), [retention policy](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/gate_memo.go#L95-L103).

## Witness one adds an obligation without changing bytes

Consider a turn that has written `pkg/a.go`. The same directory already contains a regular `integration_test.go`, excluded by `//go:build integration`, whose named test would fail when selected under that tag. Assume the default own suite passes. At the first covered measurement, the fingerprint already includes the tagged sibling, but the helper does not select it because it is not yet in `WrittenPaths`. That helper explicitly iterates written test files and invokes their named tests with `-count=1`, their tags, and a `-run` selector. [Tagged-test obligation](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/tag_gated_packages.go#L205-L249).

Next, a successful recognized write tool writes exactly the existing bytes to `integration_test.go`. This is not an assumed bypass of write tracking. `settleToolEffects` records successful write targets before returning for unchanged bytes; `recordWrittenPaths` adds normalized unique paths. Thus the written-test obligation expands even though the fingerprint does not. [Successful unchanged writes](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/tool_effects.go#L226-L270), [path recording](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/executor_tools.go#L1102-L1111).

There is a concrete conditional recheck route. If enabled coverage repair is entered with uncovered blocks and a passing suite, its `writesTests` mode admits existing sibling test files, subject to the parent guard and tool permissions. Its recheck calls `recheckOwnTests`, which calls `gateOwnTests`. The covered-key hit returns the earlier pass before applying the new obligation. Main would reach the tagged-test helper; the branch can omit the newly required failing test. This route does not assume that a no-op write forces closure remeasurement. It proves a missed obligation, not inevitable final `/done`. [Coverage repair](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/change_gates.go#L352-L428), [sibling permission](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/write_guard.go#L108-L148), [recheck](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/change_gates.go#L519-L533), [memo return](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/build_verify.go#L546-L568).

Coverage has the same policy-identity problem. Coverage parsing already filters blocks by `writtenPaths`; the memo stores that filtered list. Adding an existing sibling to the write set can therefore reuse coverage projected for a narrower scope. This does not establish that any particular block is uncovered; it establishes that the returned projection need not match the current scope. [Coverage filtering](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/coverage_profile.go#L242-L277), [cached projection](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/build_verify.go#L546-L568).

## Witness two changes an importer outside the fingerprint

Let the turn write `a/a.go`, with package `b` importing `a`, and assume the first own and importer runs pass. An admitted external edit then changes only `b/b_test.go` to introduce a failing assertion, without adding `b` to `WrittenPaths`. The fingerprint over `a` and its immediate regular neighbors stays unchanged. On a later `gateTests` call, the importer hit restores `ImporterCheck` before either package discovery or testing. A test-only assertion failure need not break the separately rerun build. This is conditional on such a within-turn external mutation being possible; it is not a claim that an ordinary typed write to `b` escapes tracking. [Importer lookup](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/build_verify.go#L513-L540), [tracked write handling](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/tool_effects.go#L250-L265).

The measurement's reach is demonstrably wider than the fingerprint: discovery uses `go list ./...` and production, test, and external-test imports, then runs the selected importers. Dependency sources, nested test data, module/workspace files outside hashed directories, and environment/toolchain inputs also belong in an input-contract inventory. These are audit questions, not separately demonstrated production schedules. A regular same-directory content change, addition, or deletion generally changes the existing fingerprint; a tracked write in another directory generally expands it. [Discovery and execution](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/importer_packages.go#L35-L107), [fingerprint boundary](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/gate_memo.go#L39-L79).

## Witness three makes failed discovery sticky

Both import-path resolution and importer listing return no packages when their command does not pass. `verifyImporters` converts an empty runnable set into `VerifySkipped` with the reason that nothing imports the turn's writes. Suppose a transient discovery failure occurs after the own suite passes. Because skipped outcomes are memoized, a same-key later call returns that skip without retrying discovery, even if the transient problem has cleared. [Discovery failures](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/importer_packages.go#L35-L74), [skip conversion](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/importer_packages.go#L89-L107), [cache policy](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/gate_memo.go#L95-L103).

The preexisting fail-open discovery behavior is not introduced by memoization. The new effect is prolonging the absence of evidence across later gate calls that previously rediscovered importers. A skipped importer leaves the own verdict standing in `suiteExit`, so this distinction affects interpretation, not merely diagnostics. Excluding top-level canceled/indeterminate results does not address a failed discovery already converted into a skip. [Suite interpretation](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/importer_gate_facts.go#L29-L41).

## Closure and existing safeguards do not establish complete identity

Closure snapshots the workspace, conditionally remeasures, and requires a stable after/current snapshot before recording checks passed. That guards against movement around closure; it does not make the memo key include the snapshot. `remeasureGates` reruns the build but calls the memoized `gateTests` for tests. Consequently, detecting an outside change can lead to a test lookup that still reuses incomplete-key evidence. `noteWrite` updates sequence facts rather than clearing the memo. [Closure](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/change_evidence.go#L70-L107), [remeasurement](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/change_evidence.go#L133-L152), [write sequencing](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/gate_facts.go#L658-L668).

Important safeguards remain: per-result lifetime, separate measurement kinds and workspaces, content rather than timestamp hashing, and no storage of top-level canceled/indeterminate runs. A plain result cannot satisfy a covered request; a covered result deliberately can satisfy a plain request. These narrow the risk but do not repair missing inputs. Moreover, independent acceptance verification can still reject a turn, so the witnesses should not be inflated into universal false completion. [Lookup rules](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/build_verify.go#L546-L568), [acceptance verification](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/change_evidence.go#L108-L118).

## Preserve savings with an explicit reuse contract

The existing test verifies unchanged-tree coverage/plain reuse and invalidation after changing the written source file, including a changed importer verdict. It does not exercise same-byte membership growth, newly scoped tagged tests, outside-importer changes, or discovery-failure recovery. Those omissions limit what its success could establish; this audit did not execute it. [Memoization test](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/gate_memo_test.go#L30-L72).

Recommended design options are to separate raw execution identity from current policy projections. Raw identity should describe the invocation, environment/toolchain, discovery, and relevant read closure. Written membership, baseline preimages, tagged-test obligations, and coverage filtering must either enter that identity or be recomputed correctly from reusable raw evidence. Retaining a full coverage profile would support reprojection better than retaining only filtered blocks. Incomplete discovery should not be reused as successful evidence of no importers. Coverage availability should likewise be explicit rather than inferred from the `own+coverage` label: the helper can return a test verdict with no profile. These are proposals, not implemented fixes. [Coverage fallback](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/coverage_profile.go#L248-L275).

Validate a measurement against a before/after identity, or conservatively rerun when identity is uncertain. The current covered key is computed before measurement and stored afterward without a post-run fingerprint comparison. A whole-workspace snapshot is a conservative filesystem option, not complete environment identity; a write-generation counter alone misses untracked changes. [Measurement sequence](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/build_verify.go#L546-L568).

Cost must be measured rather than assumed. The current lookup reads and hashes all included regular files, including non-Go neighbors; an own covered-key miss also computes the plain key, even for a covered request, and importer lookup hashes again. Broader manifests add discovery and hashing costs, but may still save expensive process launches. Measure bytes hashed, hashing/discovery time, launches avoided, total latency, and evidence freshness separately. [Hashing](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/gate_memo.go#L39-L79), [lookup sequence](https://github.com/theRebelliousNerd/codenerd/blob/7291bb758f847a0a628dccc470d38af34b74f8c1/internal/session/build_verify.go#L533-L568).

Proposed evaluation should pair positive reuse cases with adversarial changes: same-directory bytes; same-byte written membership and tagged tests; external importer/dependency/test-data edits; environment changes; transient discovery failure; cancellation/budget exhaustion; unavailable coverage; writes during a run; and a fresh result. Require correct verdicts, scope, and freshness labels before comparing performance. Until that contract is supported, conservative closure reruns are preferable to claiming a current measurement from an incomplete key.
