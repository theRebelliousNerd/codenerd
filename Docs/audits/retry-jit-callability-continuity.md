# Retry JIT must preserve callability, not restore the grant list

## Decision and evidence boundary

**Current-main refinement**, inspected October 29, 2026 at `9dcb01b9736bf4763aa3ac391d29f133d73c6611` (rechecked unchanged at 14:16 UTC). This is an addendum to the [request-visible tool contract audit](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/Docs/audits/request-visible-tool-contract-and-investigation-affordances.md#L301-L332), whose initial-call split is present and should be preserved. That audit marks the initial granted-versus-offered mismatch fixed; the distinct remaining edge is the no-tool retry rebuilding the JIT catalog from unsplit grants. A weaker, separate compiler-cache dependency omission is also recorded below.

The source predicts a contradictory retry prompt under explicit conditions; it does not establish an observed production incident, measured model confusion, unauthorized execution, or false task completion. No application execution, tests, model inference, training or benchmarks were performed.

The proposed contract is: **the initial compile and every retry must describe the actual callable projection of the final authorized envelope on the serving channel. Unavailable dispositions are rendering inputs, not authority, and must participate in complete compiled-result identity.**

## 1. The initial split is correct; the retry overwrites it

The production executor builds its compilation context through `resolveAvailableTools`. Both precompiled configurations and kernel-derived grants pass through `splitOfferable`. A modular tool is callable; a generated-only tool is callable on the text channel but receives an unavailable reason on the native channel; a name with no backend receives a different unavailable reason. The lists are separate. [Resolution](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/executor.go#L1685-L1720), [projection](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/tool_offer.go#L89-L122).

The runtime config deliberately retains the grant envelope: `compileConfig` returns a precompiled config or assigns the derived names to `AllowedTools`. Before entering the tool loop, existing turn restrictions narrow the config; that is a safeguard, not a backend/channel projection. [Config](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/executor.go#L1723-L1761), [narrowing and loop handoff](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/executor.go#L1377-L1448).

The shared tool loop obtains the first response, then requests a retry when it contains no tool calls and the kernel says this intent requires a tool call. Importantly, it first rejects the case with **zero native modular definitions**. This witness therefore needs at least one such callable tool; an all-unavailable catalog does not reach it. [Live trigger and guard](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/executor_tools.go#L84-L165).

The retry clones the original context, sets `PreviousAttemptNoToolCall`, and then replaces `AvailableTools` with `cfg.AllowedTools` when that list is nonempty. It does not reapply the split, and the clone retains `UnavailableTools`. It compiles this context and sends the result through `generateResponse`, preserving project/file context. [Overwrite and reissue](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/executor_tools.go#L2352-L2401), [clone](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/context.go#L487-L501).

### Conditional, fresh-compile witness

Assume an authorized configuration has a registered modular `write_file` and a generated-only `generated_example`, neither withheld for the turn. The serving client uses native tools. The generated tool has no modular definition, so the existing channel rule cannot offer it natively. The first response contains no tool calls; the kernel derives the tool-call obligation; compilation, fitting and request preparation succeed.

| Stage | Callable list given to JIT | Unavailable disposition |
|---|---|---|
| Initial projection | `write_file` | `generated_example`: native channel cannot carry its untyped schema |
| Retry overwrite | `write_file, generated_example` | The same unavailable disposition remains |

The shipped mandatory retry atom is selected by `no_tool_call_retry` and uses `{{available_tools}}`. Its renderer prints every `AvailableTools` name as a tool bullet, then separately prints every unavailable disposition. Consequently the retry can instruct the model to choose the generated name while also saying that the request cannot call it. This requires no registry change, stale cache, concurrency, malicious input, or inference prediction. It is a source-level consequence of the two lists reaching that renderer. [Retry atom](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/atoms/system/tool_nudge.yaml#L9-L41), [renderer](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/assembler.go#L512-L543).

The same wrongly broadened list feeds Go's `atomToolSatisfied` and Mangle's `available_tool` facts. This can remove a capability veto **if an independently eligible atom actually requires that unavailable tool**; it does not prove any particular stock atom newly selects. In particular, do not use the grounded-search atom as a `requires_tools` witness: its inspected definition has no such declaration. Other selectors, dependencies, conflicts and fitting still apply. [Go requirement check](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/atoms.go#L774-L805), [fact producer](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/selector.go#L1478-L1489), [Mangle veto](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/core/defaults/policy/jit_selection.mg#L326-L337), [grounded-search definition](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/atoms/capability/grounded_web_search.yaml).

### What still protects execution

Native definitions are independently built from registered modular tools, skipping the generated-only name. `generateResponse` uses those definitions; the working path passes the supplied system text and independently narrowed definitions to the provider. Actual dispatch still checks the effective allowlist and applicable safety/permission gates. A prompt bullet neither registers a backend nor grants authority. This is a **prompt/offer consistency defect**, not proof that an unavailable or unauthorized effect executes. [Native offer](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/tool_offer.go#L32-L53), [response dispatch](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/executor.go#L1814-L1846), [working request](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/working_context.go#L1005-L1025), [allowlist and safety](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/executor_tools.go#L2445-L2459), [gate](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/executor_tools.go#L2513-L2535).

No retry, an all-callable grant list, a zero-definition refusal, an earlier error/cancellation, or failure to produce/send the retry prompt prevents this exact outcome. The synthetic mixed grant list is a supported configuration shape, not a claim about every default installation.

## 2. Separate, weaker edge: unavailable dispositions are absent from cache identity

`CompilationContext` declares and clones `UnavailableTools`; the renderer consumes it. But `Hash` includes retry state and `AvailableTools`, not `UnavailableTools`. Two otherwise identical contexts with different unavailable descriptions therefore have equal context hashes but different fresh template output. [Field](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/context.go#L287-L292), [hash](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/context.go#L655-L770).

For a compiled-result collision, additionally require the same kernel fingerprint, compiler configuration revision and tracked source vector; successful cacheable compilation containing the template; and a retained prior entry or matching in-flight compilation. The pipeline uses that key for both cache lookup and singleflight. Under those conditions, the second caller can receive the first caller's disposition. A forced-fresh compile would differ. This is a direct compiler-contract witness, **not an established natural same-key production sequence**. [Key, cache and sharing](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/compiler_pipeline.go#L105-L170).

Strong counterevidence matters: ordinary generated-tool registration injects kernel facts and unregistering retracts them. Changed admitted facts normally change the dynamic fingerprint; they cannot simply be ignored to manufacture a same-key registry-transition story. The compiler fingerprints its private kernel and checks non-kernel source generations. Callable-list, retry-state, provider/model, budget and other context changes can also separate keys. The retry overwrite itself usually changes `AvailableTools`, so the primary witness does not depend on this omission. [Registry publication](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/core/tool_registry.go#L176-L213), [retraction](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/core/tool_registry.go#L305-L393), [kernel fingerprint](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/compiler_kernel.go#L164-L191), [source vector](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/compiler_generation.go#L119-L156).

The inspected tests cover fresh unavailable rendering and cloning, and distinct retry/callable-tool hashes, but not the missing disposition-hash case or this retry projection. These are statements about test definitions, not results from running them. [Template test](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/available_tools_template_test.go#L7-L30), [hash tests](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/context_hash_test.go#L56-L71), [initial split test](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/session/tool_offer_test.go#L83-L116).

## 3. Proposed refinement, costs and acceptance

1. Preserve one explicit distinction between **granted**, **callable on this request**, and **unavailable with reason**. For retry, either retain the frozen resolved projection and intersect it with the final narrowed config, or reproject the final config using the already resolved serving client and current admitted backend snapshot. Do not rederive a broader grant list, change provider, invent schemas, or expand permissions merely to make the nudge work.
2. Keep the two rendered lists disjoint. If backend/channel state changes, refresh both together under an explicit snapshot/version contract; do not append fresh availability onto old reasons. Preserve turn restrictions, commit/search regimes and project instructions.
3. Include unavailable rendering data in compiled-cache and singleflight identity, with a versioned encoding. Ordered hashing matches today's renderer; canonical-set hashing is valid only if rendering uses equivalent canonical semantics. Keep preflight reuse: its existing key depends on kernel identity/context facts, not this rendering-only list. [Preflight key](https://github.com/theRebelliousNerd/codenerd/blob/9dcb01b9736bf4763aa3ac391d29f133d73c6611/internal/prompt/compiler_cache.go#L95-L126).
4. Preserve fresh dispatch authorization. Prompt identity is not a permission receipt.

Projection adds registry lookups, locks and small allocations unless a coherent snapshot is reused. Structured snapshots introduce lifecycle/version maintenance and storage. Hashing adds work proportional to the disposition bytes; complete identity creates legitimate additional cache entries/misses and less singleflight sharing, potentially repeating collection, vector/relevance work, rendering and provider-backed judging. Conversely, misleading guidance can waste model calls, input/output tokens and tool-repair attempts—but none of those savings is measured here. Keep diagnostics bounded without silently dropping required capability explanations; account for any added prompt/prefill/cache-write cost.

**Proposed evaluations, not performed:**

- Drive the production-shaped no-tool retry with a controlled first response and a mixed modular/generated native catalog. Inspect the second actual system prompt, JIT input and offered definitions; an unavailable name must not become a callable bullet. Repeat with a missing backend, all-callable controls, zero definitions, no retry, and generated tools on the text channel.
- Use a separate eligible capability-atom fixture to test the Mangle/Go gate; do not infer atom admission merely from list membership. Preserve dependent-atom pruning and budget behavior.
- Exercise final restrictions, commit/search regimes, cancellation, project/file context and bounded request preparation. A lower retry rate caused by suppressing a required task is not success.
- For the cache edge, independently vary unavailable name/reason under a deliberately fixed full identity. Compare warm hit, forced-fresh and concurrent singleflight results. Use ordinary kernel-changing registration as a negative control that should change identity.
- Compare baseline, projection-only and projection-plus-identity variants with matched grants, models, budgets and tasks. Record exact prompt/catalog differences, erroneous tool suggestions, capability explanations, successful authorized observations, task acceptance and human repair; measure registry/hash/compile work, wall time, peak memory, cache/join rates, inference/embedding/judging calls and disjoint token categories. Deterministic wiring checks need no model inference; downstream quality claims require a separate authorized evaluation.
