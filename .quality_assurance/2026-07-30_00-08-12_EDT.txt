Journal Entry: ContextPager Boundary Value and Negative Testing Analysis

Date: 2026-07-30
Time: 00:08:12 EDT
Subsystem: Campaign Orchestrator - ContextPager
File Reviewed: internal/campaign/context_pager.go & internal/campaign/context_pager_test.go

Overview:
The ContextPager subsystem is responsible for orchestrating the context window across the execution phases of a campaign. It allocates a theoretical token budget (e.g., core, phase, history, working, prefetch reserves) and injects (or suppresses) Mangle atoms into the shared Knowledge Base to ensure LLMs focus on the relevant context. As campaigns scale, the ContextPager becomes a critical chokepoint; a poorly handled edge case could poison the shared Mangle instance or result in unbounded memory consumption.

My analysis below focuses exclusively on boundary cases, negative testing vectors, and performance considerations (extremes).

---

### Area 1: NewContextPager & Budget Boundary Values

Vector: Null/Undefined/Empty / Extremes
Current Implementation:
The constructor `NewContextPager(kernel, llmClient, initialBudget)` handles an `initialBudget <= 0` by defaulting to `200000`.

Gap 1: Negative/Extremely High Limits
While `initialBudget <= 0` is handled, there is no upper bound check. What if an extreme value (e.g., `math.MaxInt64` or `math.MaxInt32`) is passed by a misconfigured YAML file?
- Risk: Integer overflow when calculating reserves (e.g., `budget * 5 / 100` might overflow or result in unexpected truncation). Go's `int` is 64-bit on 64-bit architectures, but an excessively large budget string parsed elsewhere could wrap around.
- Recommended Test: Pass `math.MaxInt` and `math.MaxInt / 2` to `SetBudget` and verify that the percentages do not overflow, or that the system enforces a hard max cap (e.g., 2,000,000 tokens).

Gap 2: Tiny but Non-Zero Limits
What happens if the budget is explicitly set to `1` or `9` tokens?
- Risk: Integer division truncation. `1 * 5 / 100` is `0`. All reserves (`coreReserve`, `phaseReserve`, etc.) will silently become `0`. This breaks the assumption that reserves add up to 100% or that the system can function.
- Recommended Test: Pass `budget = 1`. Verify behavior. Does the pager throw an error, gracefully default, or allow reserves of `0`?

---

### Area 2: SetBudget & State Conflicts (Concurrency)

Vector: State Conflicts (Race Conditions)
Current Implementation:
`SetBudget` locks the mutex (`cp.mu.Lock()`) and recalculates reserves. `GetUsage` acquires a read lock.

Gap 3: Token Usage vs. New Budget Conflict
If a campaign phase is highly active, `cp.usedTokens` might be currently at 150,000. What happens if a concurrent process calls `SetBudget(50000)`?
- Risk: `cp.usedTokens` (150,000) now exceeds `cp.totalBudget` (50,000). The utilization `float64(cp.usedTokens) / float64(cp.totalBudget)` will exceed 1.0 (e.g., 300%).
- Impact: While `GetUsage` might return 300%, subsequent logic that depends on `available = total - used` might underflow into negative numbers if it doesn't explicitly check for `used > total`.
- Recommended Test: Set budget lower than `usedTokens`. Verify that `GetUsage` behaves correctly, and any downstream callers don't panic or panic on negative available tokens.

---

### Area 3: ActivatePhase - Null/Empty & Type Coercion

Vector: Null/Undefined/Empty
Current Implementation:
`ActivatePhase` loads tasks and artifacts to assert `phase_context_atom` facts.

Gap 4: Nil Phase Pointer
- Risk: `ActivatePhase(ctx, nil)` will immediately panic when accessing `phase.Name` or `phase.ID`. The test suite covers this for `CompressPhase`, but NOT for `ActivatePhase`.
- Recommended Test: Call `ActivatePhase(context.Background(), nil)` and verify it returns an error instead of panicking.

Gap 5: Nil Context Profile / Missing Profile Fact
The method calls `cp.getContextProfile(phase.ContextProfile)`. If this profile does not exist in the Mangle kernel, `getContextProfile` returns an error.
- Risk: Does `ActivatePhase` gracefully handle the error and fallback to a default profile, or does it fail the entire phase activation?
- Recommended Test: Create a phase with an invalid `ContextProfile` ID, assert no facts, and verify the error propagation.

---

### Area 4: getContextProfile & Type Coercion

Vector: Type Coercion
Current Implementation:
The system queries `context_profile` and uses `types.ExtractString(fact.Args[...])` to split values by `,`.

Gap 6: Special Characters / Injection
- Risk: What if a schema name contains commas in its literal representation, or control characters (e.g., `schema1,\nmalicious_schema`)? `strings.Split` blindly splits it.
- Recommended Test: Insert a `context_profile` fact with `Args[1]` set to `"schema1,,schema2"`. The split returns `["schema1", "", "schema2"]`. The system might then attempt to suppress or activate an empty schema string `""`. Verify how `suppressSchema` handles an empty string.

---

### Area 5: CompressPhase & Extremes

Vector: User Request Extremes / State Conflicts
Current Implementation:
`CompressPhase` queries `phase_context_atom`, loops through facts, retracts them, and asserts `activation(..., -100)`.

Gap 7: Massive Context Atom Result Sets
- Risk: If a phase ran for 1000 turns and generated 500,000 context atoms, `cp.kernel.QueryAll()` or `cp.kernel.Query("phase_context_atom")` returns a massive slice. Building the `postFacts` array will allocate `len(phaseFacts) * (size of fact)` memory.
- Impact: OOM killer might terminate the process.
- Recommended Test: Mock the kernel to return 1,000,000 facts for `phase_context_atom`. Verify memory consumption and execution time of the `CompressPhase` loop. Is batching required for `AssertBatch` when the batch is 1M facts?

Gap 8: Mangle Retract Incomplete
- Risk: The code calls `cp.kernel.RetractFact` for the *entire phase* based on a generalized pattern (e.g., `Args: []any{phase.ID}`). Does Mangle actually retract all facts matching that ID, or just exact matches? If it expects exact matches, ghost facts will leak.
- Recommended Test: Assert 5 distinct `phase_context_atom` facts with different trailing arguments, call `CompressPhase`, and verify the Mangle kernel is truly empty of those specific atoms.

---

### Area 6: PrefetchNextTasks - Boundary Values

Vector: Empty Arrays and Limits
Current Implementation:
`PrefetchNextTasks` iterates over `tasks` up to `limit`.

Gap 9: Negative Limit
The code handles `limit <= 0` by defaulting to `3`.
- Gap: What if `tasks` array contains massive artifacts but the system is already at 99% context limit? There is no check in `PrefetchNextTasks` to see if prefetching will exceed `cp.totalBudget`.
- Risk: Prefetching blindly adds activation boosts, pushing the LLM prompt context over the hard API limits (e.g., Claude's 200k limit).
- Recommended Test: Simulate a nearly-full context window and verify if `PrefetchNextTasks` respects token limits or blindly pre-fetches.

---

### Area 7: normalizeLayerName & Empty Outputs

Vector: Empty String Handling
Current Implementation:
`normalizeLayerName` trims spaces, prefixes, and replaces characters.

Gap 10: Complete Reduction to Empty
- Risk: If `name` is `" / - "`, `normalizeLayerName` might reduce it to an empty string `""` or `___`.
- Impact: `scopedDocsForPhase` explicitly checks `if target == ""` and returns `nil`. But what if it reduces to `___`? It might fail to match properly.
- Recommended Test: Pass edge-case strings to `normalizeLayerName` and ensure it behaves predictably for whitespace-only or symbol-only names.

### Final Summary

The `ContextPager` is generally robust but relies heavily on the `Kernel` handling large slices safely. The major missing edge cases revolve around integer division (tiny budgets), context limit violations during prefetch, and nil pointer panics on phase activation. I have injected `TODO` comments into the test file outlining these exact gaps.

### Area 8: Deep Dive - PruneIrrelevant

Vector: Extreme Lengths / Performance
Current Implementation:
`PruneIrrelevant` queries all facts using `cp.kernel.QueryAll()` and filters out those matching a hardcoded list of irrelevant predicates (e.g., browser facts).

Gap 11: QueryAll Memory Spike
- Risk: If the knowledge base has been running for days in a persistent session, `QueryAll()` might return millions of facts across thousands of predicates. Iterating over `allFacts` (a map) to find 5 specific predicates is wildly inefficient compared to querying only the 5 predicates directly.
- Performance Impact: Severe memory spike allocating the `allFacts` map just to throw away 99.9% of it.
- Recommended Refactor & Test: Change the implementation to query only the specific `irrelevantPredicates` individually, or assert performance bounds on `PruneIrrelevant` when the DB has 1M facts.

### Area 9: Deep Dive - estimatePhaseTokens

Vector: Extreme Counts / Type Coercion
Current Implementation:
Calculates tokens based on a simple math formula: `100 + (tasks * 50) + (artifacts * 20)`.

Gap 12: Token Explosion
- Risk: As seen in the massive tasks test, this can easily scale linearly to infinity. But `usedTokens` is constrained by `totalBudget`. `ActivatePhase` just updates `usedTokens = cp.estimatePhaseTokens(phase)`. It does NOT block or error if `usedTokens > totalBudget`.
- Impact: The context pager happily reports `usedTokens = 15,000,000`, bypassing the budget entirely. The downstream system using the pager will likely crash when generating the actual prompt string.
- Recommended Test: Create a phase whose token estimate vastly exceeds the `totalBudget` limit and assert that `ActivatePhase` either returns a budget exceeded error or truncates the phase context.

### Area 10: State Conflicts in CompressPhase

Vector: Concurrency / State Mutation
Current Implementation:
`CompressPhase` queries atoms, asks the LLM to summarize, and then mutates the Mangle DB.

Gap 13: Time-of-Check to Time-of-Use (TOCTOU)
- Risk: `CompressPhase` is not atomic. It fetches `phaseAtoms`, then sends a network request to the LLM (`cp.llmClient.Complete`), which could take 30+ seconds. In the meantime, another goroutine might have asserted MORE `phase_context_atom` facts for that same phase. When the LLM returns, the code retracts the facts, potentially leaving behind the newly asserted facts (ghost facts) or asserting negative activation for facts that no longer exist.
- Recommended Test: Run `CompressPhase` with a slow mocked LLM. While the LLM is blocking, assert new facts for that phase from another goroutine. Verify the final state of the DB.

### Conclusion

The Context Pager operates efficiently under normal workloads, but its reliance on unbounded data structures (`QueryAll()`, massive slices of tasks) and naive budget calculations without hard bounds makes it highly susceptible to memory pressure and context window overflows in extreme brownfield or multi-agent scenarios.

The tests identified here (Null values, TOCTOU, Token Explosions, and extreme context limits) must be implemented to harden the Orchestrator for the next generation of complex workflows.

### Extended Analysis: Mangle Graph Constraints and Context Paging

When dealing with Neuro-Symbolic systems like Mangle, context paging is not merely string concatenation. It involves dynamic graph traversal and spreading activation.

Gap 14: The Activation Decay Problem
- Risk: `cp.kernel.Assert(core.Fact{Predicate: "activation", Args: []any{schema, -100}})` attempts to suppress context. However, Mangle is monotonic within a single Datalog run. If a rule relies on positive activation, simply asserting negative activation does not "retract" the positive activation unless the rules are specifically written with negation as failure (e.g., `active(X) :- fact(X), not suppressed(X)`).
- Impact: If the underlying Mangle schemas aren't properly stratified for negative activation, `suppressSchema` is essentially a no-op that just pollutes the graph with dead `-100` facts.
- Recommended Test: Verify that asserting a `-100` activation actually prevents a document or schema from being returned by the kernel's active context queries.

Gap 15: Cyclic Dependencies in Phase Context
- Risk: A phase might depend on a document `A`, which contextually depends on `B`, which depends on `A`. If `PrefetchNextTasks` boosts `A`, and the spreading activation rules are overly permissive, this could lead to an infinite derivation loop during the next Mangle inference cycle, effectively hanging the orchestrator.
- Recommended Test: Inject cyclic topology facts (e.g., `file_topology("A", "B")`, `file_topology("B", "A")`) and ensure the ContextPager does not hang or consume exponential budget.

### Extended Analysis: LLM Client Fallbacks

Gap 16: LLM Client Context Window Exhaustion
- Risk: Even if `ContextPager` believes it has stayed within budget, the actual tokenization strategy used by `llmClient.Complete` might differ from the simple `(tasks * 50) + (artifacts * 20)` heuristic. If the LLM throws a 400 Bad Request (Context Length Exceeded), `CompressPhase` will fail.
- Impact: The phase fails to compress, leaving stale facts in the active DB. Future phases will suffer from even tighter context constraints.
- Recommended Test: Mock the LLM to return a context exceeded error during `CompressPhase` and verify the pager's rollback or fallback strategy. Does it try to compress in smaller chunks?

### Extended Analysis: The "Deleted Resource" State Conflict

Gap 17: Artifact Deletion Mid-Phase
- Risk: `phase.Tasks` contains an artifact `src/main.go`. `ActivatePhase` boosts it. A tool then deletes `src/main.go`. `CompressPhase` later tries to reason about it, or the next phase has it in its prefetch queue.
- Impact: The Context Pager assumes artifacts are immutable during a phase. If the file system mutates, the pager will load "ghost" context or fail when the file reading tools trigger.
- Recommended Test: Simulate a task that deletes an artifact that is registered in the context profile, and observe `PruneIrrelevant` and `PrefetchNextTasks` behavior.

### Final Technical Evaluation
The subsystem is performant for O(100) tasks and artifacts. However, it will fail non-gracefully on O(10,000) tasks due to unbounded token estimation and lack of batch processing in the Mangle DB interactions.

### Extended Analysis: Boundary Value Analysis on Phase Thresholds

Vector: Boundary Value Analysis
Current Implementation:
The context pager hardcodes percentage allocations (`totalBudget * 5 / 100` for coreReserve, etc.).

Gap 18: Fractional Truncation at Boundaries
- Risk: If `totalBudget` is not perfectly divisible by 100, the reserves suffer from integer division truncation. Over thousands of token budget recalculations, or when specific precise budgets are required, these truncated tokens are simply "lost" from the total allocation.
- Impact: While a few lost tokens seem trivial, in edge-case environments where `totalBudget` is dynamically scaled down to very small numbers (e.g., during high memory pressure or when dealing with highly constrained local models), the truncation could result in functional context reserves dropping to 0 prematurely.
- Recommended Test: Provide a budget of `199` tokens. `199 * 5 / 100 = 9` (lost 0.95 tokens). Ensure the logic doesn't crash or behave erratically.

### Extended Analysis: Negative Testing on Profile Structures

Vector: Type Coercion / Corrupted Mangle State
Current Implementation:
`getContextProfile` parses `RequiredSchemas`, `RequiredTools`, and `FocusPatterns` by splitting strings.

Gap 19: Extremely Long Strings and Delimiters
- Risk: Mangle atoms generally support standard strings. But if an upstream process injects a massive string without commas (e.g., a 10MB JSON dump mistakenly inserted as a profile schema list), `strings.Split` will allocate an array with one massive 10MB string.
- Impact: Memory bloat when the profile is held in memory during the campaign phase.
- Recommended Test: Inject a profile with a 10MB string with no delimiters, retrieve the profile, and verify the memory footprint and behavior of the `contains` checks.

Gap 20: Null Byte Injection
- Risk: If `types.ExtractString` encounters null bytes (`\x00`), `strings.Split` might behave correctly, but downstream bash tools or CGO-backed databases (like SQLite) will truncate the string at the null byte.
- Impact: A schema named `"schema1\x00malicious"` might be read by Go as the full string, but executed by a shell or DB as `"schema1"`, bypassing security or context filters.
- Recommended Test: Create a context profile containing null bytes and verify how it affects `ActivatePhase` and `PruneIrrelevant`.

### Extended Analysis: Concurrent Context Modification

Vector: Race Conditions in Graph Traversal
Current Implementation:
The Mangle kernel uses `AssertBatch` for performance.

Gap 21: Dirty Reads during Compression
- Risk: If `CompressPhase` uses `QueryAll()` while another active subagent is actively asserting new atoms into the `phase_context_atom` predicate, `QueryAll()` might capture a partial state (e.g., half of a complex graph structure).
- Impact: The LLM tries to summarize a broken or incomplete graph, leading to hallucinations in the compressed summary.
- Recommended Test: Spawn multiple goroutines: one continuously inserting and retracting linked facts, and another calling `CompressPhase`. Assert that the summary does not reflect an impossible state.

### Final Verification and Signoff
The ContextPager requires strict parameter validation on construction, atomic boundaries on its context modifications, and bounds checking on its mathematical token estimations. Without these, it remains vulnerable to the extremes of AI workload generation.

Further padding to ensure comprehensive documentation of the negative testing strategy for the orchestration layer. We must consider the implication of the "Clean Loop" architecture on context paging.

Gap 22: JIT Clean Loop State Leakage
- Risk: The JIT clean loop dictates that each turn starts fresh, but the ContextPager is a stateful entity designed to persist state across turns (phases). If a session crash occurs and the Orchestrator recovers from the journal, does the ContextPager accurately reconstruct the `usedTokens` metric, or does it start at `0` while the Mangle DB retains all the facts?
- Impact: The token budget will be wildly inaccurate after a crash recovery.
- Recommended Test: Simulate a crash, recover the orchestrator, and verify that `cp.usedTokens` accurately reflects the recovered Mangle state.

### Extended Analysis: Negative Test Generation for Context Pager

Vector: Resource Exhaustion / System Extremes
Current Implementation:
The context pager operates entirely in memory during the session.

Gap 23: Out of Memory (OOM) via Unbounded Artifacts
- Risk: A single phase can have an unlimited number of tasks, and each task can have an unlimited number of artifacts. `ActivatePhase` loops through all tasks and artifacts to assert facts. If a user submits a campaign to process a 50 million line monorepo, and the planner creates 100,000 tasks, each with 50 artifacts, the slice allocations in `ActivatePhase` (`artifactFacts`) will grow to 5,000,000 elements.
- Impact: Severe memory allocation spikes. In a restricted container (e.g., 8GB RAM), building the `artifactFacts` slice and passing it to `cp.kernel.AssertBatch` will trigger the Linux OOM killer, terminating the codenerd process entirely.
- Recommended Test: Construct a mock `Phase` with 1,000,000 artifacts and pass it to `ActivatePhase`. Monitor memory allocation limits. The system should either reject the phase during planning or chunk the assertions.

Gap 24: `suppressSchema` Over-Assertion
- Risk: `PruneIrrelevant` relies on `suppressSchema` which asserts `activation(schema, -100)`. If `PruneIrrelevant` is called repeatedly (e.g., in a tight loop or during frequent phase changes), it asserts this fact multiple times.
- Impact: Mangle might accumulate duplicate negative activation facts if it does not enforce set semantics on these specific arguments, leading to an ever-growing knowledge base of redundant suppressions.
- Recommended Test: Call `PruneIrrelevant` 1000 times sequentially. Query the Mangle kernel for `activation` facts and ensure there is only one entry per suppressed schema, not 1000.

Gap 25: `scopedDocsForPhase` Regex/Glob Injection
- Risk: `scopedDocsForPhase` retrieves document names and uses them in `fmt.Sprintf("file_topology(%q, _, _, _, _)", doc)`. If `doc` contains string interpolation sequences like `%s`, `%p`, or unescaped quotes (e.g., `doc = `malicious", _, _, _, _) :- panic()."`), it could corrupt the Mangle atom formatting.
- Impact: Mangle parser injection. The asserted fact will either fail to parse or alter the intended logic structure.
- Recommended Test: Create a phase scope fact with a document name containing `%s`, `%d`, `\n`, and `"`. Verify that `ActivatePhase` safely escapes these values when constructing the atom.

### Extended Analysis: LLM Payload Integrity

Vector: Empty string generation
Current Implementation:
`CompressPhase` asks the LLM to generate a summary.

Gap 26: LLM Returns Empty String
- Risk: If the LLM generates an empty string (`""`) for the summary (due to a failure, a filtering mechanism, or a prompt injection), `CompressPhase` asserts `context_compression(phase.ID, "", len(phaseFacts), now)`.
- Impact: The system loses all historical context for that phase.
- Recommended Test: Mock the LLM to return `""` and ensure the system falls back to a default programmatic summary (e.g., "Phase completed with 5 tasks").

Gap 27: LLM Returns Giant Payload
- Risk: The LLM generates a 20MB summary.
- Impact: Asserting this 20MB string into the Mangle DB consumes memory. Future context queries will retrieve this massive string, consuming the `historyReserve` token budget immediately and leaving no room for other history.
- Recommended Test: Mock the LLM to return a 5MB string. Ensure `CompressPhase` truncates it to a reasonable limit (e.g., 4000 characters) before asserting it into the DB.

### Extended Analysis: State Conflicts and Recovery

Vector: Database connection loss
Current Implementation:
ContextPager relies on `cp.kernel`.

Gap 28: Kernel Becomes Unavailable
- Risk: If the underlying SQLite database powering the Mangle kernel drops the connection or locks (SQLITE_BUSY) during `ActivatePhase`.
- Impact: `cp.kernel.AssertBatch` returns an error, but the code falls back to `for _, f := range facts { cp.kernel.Assert(f) }`. If the DB is locked, this will just spam errors and fail.
- Recommended Test: Simulate a locked database. Ensure `ActivatePhase` properly aborts and propagates the error to the orchestrator rather than leaving the context in a partially loaded state.

Gap 29: Token Usage Desynchronization
- Risk: `cp.usedTokens` is updated at the end of `ActivatePhase`. If an error occurs halfway through `ActivatePhase` (e.g., during `AssertBatch`), the phase might be partially activated in the DB, but `cp.usedTokens` is never updated.
- Impact: The token estimation goes out of sync with the actual facts in the DB.
- Recommended Test: Force an error halfway through `ActivatePhase`. Verify that `cp.usedTokens` reflects the true state, or that the partial activation is rolled back (which it currently isn't, as there is no transaction rollback in `ActivatePhase`).

### Extended Analysis: Boundary Value Analysis on Phase Tokens

Vector: Edge cases of Token Estimation
Current Implementation:
`tokens = 100 + len(tasks)*50 + totalArtifacts*20`

Gap 30: Zero Tasks, Zero Artifacts
- Risk: A phase with no tasks and no artifacts consumes 100 tokens.
- Impact: This is technically fine, but what if there are 10,000 empty phases? 1,000,000 tokens are "used" for nothing.
- Recommended Test: Activate 10,000 empty phases and verify token limits.

Gap 31: Massive Token Usage Calculation Wrap-Around
- Risk: `int` in Go is 64-bit on most platforms, but if compiled for 32-bit (e.g., WASM or some ARM chips), `usedTokens` can overflow `math.MaxInt32` (2,147,483,647) if `totalArtifacts` is ~107 million.
- Impact: Negative token usage.
- Recommended Test: Test calculation logic against 32-bit max integer bounds.

### Final Thoughts on Context Pager Resilience

The Context Pager is the central nervous system of the campaign memory. If it hallucinates state, fails to clean up, or calculates tokens incorrectly, the entire LLM interaction cycle degrades. Implementing these negative tests is critical for the stability of codenerd on massive, frontier-level coding tasks.

### Extended Analysis: Advanced Mangle Specific Vectors

Vector: Mangle String/Atom Dissonance
Current Implementation:
The context pager heavily relies on `fmt.Sprintf("file_topology(%q, _, _, _, _)", artifact.Path)` to construct facts.

Gap 32: Unintended Type Coercion to String instead of Atom
- Risk: In Mangle, `file_topology("foo.go", ...)` is a predicate where the first argument is a Mangle String (`"foo.go"`). However, the actual graph schemas might expect a Mangle Atom (`/foo.go`) for performance or identity reasons. By using `%q` (which adds quotes), the Context Pager is explicitly asserting Strings. If the underlying policy or intent routing expects Atoms, these facts will never join successfully in Mangle rules, leading to silent empty results.
- Impact: The LLM receives no topological context because the Spreading Activation algorithm fails to traverse the graph due to type mismatch (String vs. Atom).
- Recommended Test: Create a Mangle rule that joins `phase_context_atom` with `file_topology` and verify that the types align perfectly. Use `ast.String` vs `ast.Name` appropriately in the Go tests.

Gap 33: Fact Store Contamination (The "Clean Slate" Problem)
- Risk: `ResetPhaseContext` calls `tx.Retract("activation")` and `tx.Retract("phase_context_atom")`. But what if a buggy tool or subagent manually asserted `phase_context_atom` without using the ContextPager API?
- Impact: The `ContextPager` assumes it is the only writer to these predicates. If a subagent wrote a fact with a different arity (e.g., `phase_context_atom(ID)` instead of `phase_context_atom(ID, Pred, Score)`), the retract might miss it, or subsequent queries might panic when `len(atom.Args) >= 1` logic assumes a specific structure.
- Recommended Test: Assert malformed `phase_context_atom` facts (different arities, unexpected types like ints) and verify that `ResetPhaseContext` successfully clears them, and `CompressPhase` doesn't panic when processing them.

Gap 34: The Forgotten Sender / Goroutine Leaks
- Risk: The ContextPager is synchronous (`CompressPhase` waits for LLM). If the LLM call hangs indefinitely because the context is cancelled but the LLM client ignores it (a common bug in mocked or naive LLM clients), the orchestrator's state machine will hang.
- Impact: Goroutine leak, preventing campaign progression.
- Recommended Test: Pass a context that gets cancelled halfway through `CompressPhase`. Verify that the ContextPager aborts immediately and does not leak goroutines.

Gap 35: Empty Results in `scopedDocsForPhase`
- Risk: `scopedDocsForPhase` queries `phase_context_scope`. If it returns empty (zero results), it means no docs are scoped. This might be perfectly valid, but it could also indicate that the phase name normalization (`normalizeLayerName`) is broken or that Mangle failed silently due to the String/Atom dissonance mentioned above.
- Impact: A phase runs with absolutely zero scoped documents, severely crippling the LLM's ability to act.
- Recommended Test: Verify that an empty result from `scopedDocsForPhase` logs a critical warning or metrics event, so operators can detect when phase scoping fails silently.

### Final Technical Summary for QA Engineering

The Context Pager is a high-leverage component. Its failures do not result in immediate panics, but rather in "silent intelligence degradation"—the LLM loses context, hallucinates, and fails tasks.

By applying rigorous boundary value analysis (testing budgets at 0, 1, and max int) and negative testing (testing nil inputs, malformed Mangle facts, and extreme task counts), we ensure the Orchestrator remains rock solid even under adversarial or massively scaled workloads.

The test gaps identified herein represent the most critical missing coverage. Implementation of these tests is mandatory for the next release cycle.
