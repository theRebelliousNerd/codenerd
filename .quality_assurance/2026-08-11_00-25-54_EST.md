# QA Journal Entry: Boundary Value Analysis and Negative Testing for internal/prompt/CompilationContext
## Date: 2026-08-11_00-25-54_EST
## Target Subsystem: internal/prompt (Specifically CompilationContext)

### 1. Executive Summary

This journal entry documents a deep-dive Quality Assurance review of the `internal/prompt/CompilationContext` struct and its associated `Validate()` function within the codeNERD architecture. The primary focus is on Boundary Value Analysis (BVA), negative testing, and identifying systemic edge cases that fall outside the traditional "Happy Path" scenarios.

As codeNERD operates as a high-assurance Logic-First CLI coding agent utilizing a Creative-Executive Partnership (where Mangle logic serves as the executive), the integrity of the data flowing from the Go runtime (Perception Transducer/Go structs) into the Mangle Kernel is paramount. The `CompilationContext` represents the critical 10-tier state that drives prompt atom selection. If this state is malformed, contradictory, or maliciously crafted via extreme user requests, the resulting Mangle `compile_context` facts will be invalid, potentially leading to rule stratification failures, infinite loops in the solver, or silent omission of required persona shards.

Currently, the `Validate()` method in `internal/prompt/context.go` only verifies three simple integer bounds:
- `TokenBudget > 0`
- `ReservedTokens >= 0`
- `ReservedTokens < TokenBudget`

It conspicuously lacks validation for string formats (especially Mangle atom formatting), state conflicts, and array boundary conditions. This document outlines the gaps, proposes specific negative test vectors, and evaluates the performance implications of closing these gaps.

### 2. Analysis of Edge Cases and Missing Test Vectors

#### 2.1 Null / Undefined / Empty Scenarios

In Go, strings are not "null," but they default to empty strings (`""`). The `CompilationContext` contains numerous strings representing critical Mangle atoms (e.g., `OperationalMode`, `CampaignPhase`, `IntentVerb`).

**Missing Vectors:**
- **Empty Core Atoms:** What happens if `OperationalMode` is `""`? Mangle expects atoms to be strings starting with a slash (e.g., `/active`). An empty string is not a valid atom in this schema.
- **Empty Slices:** What happens if `Frameworks` is an empty slice `[]string{}` versus a nil slice? Does `ToContextFacts()` handle this safely, or does it attempt to assert a fact with an empty string?
- **Empty SemanticQuery with TopK > 0:** If `SemanticQuery` is `""` but `SemanticTopK` is `10`, the VectorSearcher might execute an unconstrained search returning garbage atoms, polluting the context.

**Mangle Impact:** Asserting a fact like `compile_context("intent_verb", "")` when Mangle rules expect `compile_context("intent_verb", /fix)` will result in a silent failure—the rules simply won't match, and the prompt will lack the necessary tools/instructions.

#### 2.2 Type Coercion and Format Violations (The Atom/String Dissonance)

Mangle strictly differentiates between Atoms (e.g., `/fix`) and Strings (e.g., `"fix"`). The Go `CompilationContext` uses `string` types for fields that represent Mangle Atoms.

**Missing Vectors:**
- **Missing Leading Slash:** What if `OperationalMode` is set to `"active"` instead of `"/active"`? The `Validate()` function does not check for the `/` prefix.
- **Invalid Characters in Atoms:** Mangle atoms generally follow specific character sets (alphanumeric and underscores). What if a user request injects spaces or special characters into `CampaignID` or `ShardID` (e.g., `/my shard!`)?
- **Case Sensitivity:** Mangle atoms are often case-sensitive. What if the intent is `"/FIX"` instead of `"/fix"`?

**Mangle Impact:** This is the most common AI failure mode ("Atom/String Dissonance"). Passing raw Go strings without validating their format as Mangle Atoms causes joins to fail silently (producing zero results) when the schema expects specific Atoms.

#### 2.3 User Request Extremes

The agent must handle frontier-level coding benchmark questions and extreme user environments.

**Missing Vectors:**
- **Maximum Integer Limits:** What if `TokenBudget` is `math.MaxInt`? While `Validate()` checks if it's > 0, an extremely large value might cause integer overflows during fallback ratio calculations downstream in the prompt assembler.
- **Zero or Negative Fallback Ratios:** `ReservedTokensFallbackRatio` defaults to 10. What if it is set to 0 or a negative number? Downstream division by this ratio will cause a panic (division by zero) or result in negative reserved tokens.
- **Massive String Lengths:** What if `SemanticQuery` contains a 10MB string due to a user pasting an entire codebase into a single prompt? The token budget might handle it eventually, but the immediate struct allocation and context generation could OOM (Out Of Memory) the JIT compiler.
- **Max TopK:** What if `SemanticTopK` is set to `1,000,000`? The Vector Searcher would try to retrieve and rank the entire corpus, halting the Clean Loop.

#### 2.4 State Conflicts (Logical Inconsistencies)

A structurally valid context might still be logically impossible.

**Missing Vectors:**
- **Dream Mode Constraints:** If `OperationalMode` is `/dream` (Quiescent Boot / Precog Safety), then `IsHighChurn` and `FailingTestCount` should logically be false/zero, as the agent is not actively mutating code.
- **Init Phase vs. Active Campaign:** If `InitPhase` is `/setup`, then `CampaignPhase` should not be `/completed`.
- **Shard ID without Type:** If `ShardID` is populated, `ShardType` must also be populated to resolve the correct JIT config.

**Mangle Impact:** Conflicting states cause Mangle rules to derive contradictory policies, potentially triggering safety panics in the Constitutional Gate or resulting in "schizophrenic" prompt generation where the agent receives instructions for two mutually exclusive modes.

### 4. Performance Implications of Enhanced Validation

Adding robust validation to `CompilationContext.Validate()` is necessary but must be highly performant, as this function is called inside the JIT Clean Loop for every single user interaction and subagent spawn.

**Current Performance:**
The current 3 integer checks take negligible time (< 1 ns).

**Proposed Performance Impact:**
- **String Empty Checks (`len(str) == 0`):** Extremely fast, < 1 ns.
- **Mangle Atom Prefix Checks (`str[0] == '/'`):** Fast, but requires length check first to avoid panic. O(1).
- **Character Whitelist Checks (Regex):** Using `regexp.MatchString` is too slow for the hot path. We must use a custom byte-iteration loop or pre-compiled global regex (as per codebase memory guidelines) if absolute validation is needed.
- **State Conflict Checks:** Boolean logic and simple comparisons (e.g., `cc.OperationalMode == "/dream" && cc.IsHighChurn`) are very fast, O(1).

**Recommendation for High Performance:**
Instead of full regex validation in the hot path, `Validate()` should implement fast-path structural checks:
1. Ensure required strings are `len() > 0`.
2. Ensure atom strings begin with `/` (`len(str) > 0 && str[0] == '/'`).
3. Enforce strict numerical bounds (e.g., `SemanticTopK < 100`, `ReservedTokensFallbackRatio > 0`).

This ensures the Mangle kernel receives structurally sound facts without bogging down the Go runtime.

### 5. Proposed Changes to `Validate()` Function

```go
func (cc *CompilationContext) Validate() error {
	// Existing checks
	if cc.TokenBudget <= 0 {
		return fmt.Errorf("token budget must be positive, got %d", cc.TokenBudget)
	}
	if cc.ReservedTokens < 0 {
		return fmt.Errorf("reserved tokens cannot be negative, got %d", cc.ReservedTokens)
	}
	if cc.ReservedTokens >= cc.TokenBudget {
		return fmt.Errorf("reserved tokens (%d) must be less than budget (%d)", cc.ReservedTokens, cc.TokenBudget)
	}

	// NEW: Ratio check to prevent division by zero
	if cc.ReservedTokensFallbackRatio <= 0 {
		return fmt.Errorf("fallback ratio must be > 0, got %d", cc.ReservedTokensFallbackRatio)
	}

	// NEW: Required Atom checks (fast path)
	if len(cc.OperationalMode) == 0 || cc.OperationalMode[0] != '/' {
		return fmt.Errorf("invalid OperationalMode atom: %q", cc.OperationalMode)
	}
	// ... repeat for IntentVerb, CampaignPhase, etc.

	// NEW: Limit checks
	if cc.SemanticTopK < 0 || cc.SemanticTopK > 1000 {
		return fmt.Errorf("SemanticTopK out of bounds: %d", cc.SemanticTopK)
	}

	// NEW: State Conflicts
	if cc.OperationalMode == "/dream" && cc.FailingTestCount > 0 {
		return fmt.Errorf("state conflict: /dream mode cannot have failing tests")
	}

	return nil
}
```

### 6. Conclusion and Next Steps

The current test suite for `CompilationContext` heavily favors the Happy Path and basic bounds checking. Given its role as the connective tissue between the Go execution loop and the Mangle reasoning engine, this lack of rigor is a severe risk. Empty strings or missing prefixes will cause silent deduction failures in Mangle, manifesting as degraded AI performance or missing tool access.

**Action Items:**
1. Update `internal/prompt/context_test.go` to include the negative test vectors outlined above.
2. Refactor `CompilationContext.Validate()` to implement fast-path structural validation and state conflict checks.
3. Verify that these new validations do not introduce noticeable latency in the JIT Clean Loop.
4. Ensure all SubAgents and Transducers emitting `CompilationContext` data are updated to conform to the new strict validation rules.
