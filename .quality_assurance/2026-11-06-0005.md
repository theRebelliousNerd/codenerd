## 1. Executive Summary

This journal entry provides an exhaustive, multi-dimensional analysis of the Perception Transducer subsystem, which is responsible for taking unstructured natural language input or LLM-generated JSON intents and converting them into strongly typed, safe Mangle logic facts.

As a QA Automation Engineer specializing in Boundary Value Analysis (BVA) and Negative Testing, I have reviewed the codeNERD architecture, the specific Mangle language semantics (which differ from pure Datalog and involve strict stratification, type systems, and a JIT Clean Loop architecture), and the existing test suite for the `perception` package.

The goal of this analysis is to go beyond the "Happy Path" and traditional out-of-vocabulary edge cases. We are pushing the boundaries of what the system can handle across four primary vectors:
1. Null, Undefined, and Empty States
2. Type Coercion and Schema Drift
3. Extreme User Requests and Payload Dimensions
4. State Conflicts and Race Conditions

For each vector, we assess the potential failure modes, the performance implications (e.g., whether the transducer is performant enough to handle the edge case), and architectural considerations required to harden the system.

## 2. Architectural Context: The Perception Transducer and Mangle

Before diving into the specific edge cases, it is crucial to understand the role of the Perception Transducer within the codeNERD JIT Clean Loop architecture.

The transducer is the "frontier" or boundary layer. It takes LLM output (typically JSON) and maps it into Mangle `user_intent` facts. The Mangle engine is monotonic, declarative, and heavily relies on type strictness. In Mangle, an Atom `/active` is disjoint from a String `"active"`. If the Perception Transducer passes raw strings where Atoms are expected, the resulting Mangle joins will fail silently, yielding zero results, which is a valid logical state but incorrect application behavior.

Furthermore, Mangle rules must be stratified. If adversarial input can inject logic that violates stratification (e.g., `p :- not p.`), the analysis phase (`analysis.Analyze`) should catch it. However, if the injection occurs during the fact assertion phase where raw arguments are just treated as terms, we risk corrupting the "Clean Slate" Fact Store.

The performance of the transducer is generally bounded by the `json.Unmarshal` process and string sanitization. Since Go is a compiled, highly performant language, the raw CPU cost of parsing is low, but the memory allocations during Unmarshal can create garbage collection (GC) pressure if payloads are malicious.

## 3. Vector 1: Null, Undefined, and Empty States

### 3.1 The Empty Map and Missing Keys
In standard operation, the LLM returns a fully populated JSON object:
`{"understanding": {"primary_intent": "doit", "semantic_type": "DO_THE_MAGIC", "action_type": "NUKE_AND_REWRITE"}}`

**Negative Scenario:** What happens if the LLM returns an empty map for the `understanding` key, or omits keys entirely?
`{"understanding": {}}`

**Analysis:**
Go's `json.Unmarshal` will leave the target struct fields at their zero values. For strings, this is the empty string `""`. The current test suite checks what happens with an Out-of-Vocabulary (OOV) action type, which correctly maps to a `/explain` fallback. However, an empty string `""` might bypass explicit OOV checks if those checks only match known bad strings, or it might trigger an index-out-of-bounds if the system attempts to read the first character (e.g., checking if it starts with a `/`).
**Performance Impact:** High performance. Handling zero-values in Go is virtually free. The risk is a logical crash, not a performance bottleneck.

### 3.2 Explicit Nulls in Primitives
**Negative Scenario:** The LLM returns explicit JSON `null` values for string fields.
`{"understanding": {"primary_intent": null, "action_type": null}}`

**Analysis:**
If the Go struct uses value types (`string`, `float64`), the `json.Unmarshal` function will silently ignore the `null` and keep the zero value. However, if the struct uses pointer types (`*string`), the field will be set to `nil`. Subsequent code in the transducer that calls methods on these pointers or passes them to `len()` without a nil check will trigger a panic.
**Mangle Implication:** Passing a `nil` pointer as an argument to a Mangle fact constructor will likely cause a panic in the AST builder or stringifier.
**Performance Impact:** Negligible overhead for unmarshaling, but a panic will tear down the goroutine, potentially leaking channel resources if it was part of an asynchronous JIT selection loop.

### 3.3 Empty and Null Arrays
**Negative Scenario:** The `tools_needed` or `user_constraints` arrays are returned as `null` or `[]`.

**Analysis:**
A `null` array unmarshals to a `nil` slice in Go. Iterating over a `nil` slice is perfectly safe (`for _, t := range nilSlice` does nothing). However, if the logic assumes that certain intents *must* have constraints or tools (e.g., `tools_needed[0]`), a bounds out of range panic will occur.
**Test Gap:** The tests must explicitly simulate a null array and assert that the fallback mechanism operates gracefully, producing a baseline Mangle fact with empty lists.

## 4. Vector 2: Type Coercion and Schema Drift

### 4.1 String-to-Number Coercion
**Negative Scenario:** The `confidence` field is a float, used to gate intelligence risk. The LLM hallucinates and returns a string instead of a number:
`{"understanding": {"confidence": "0.99"}}` or `{"understanding": {"confidence": "high"}}`

**Analysis:**
By default, Go's `json.Unmarshal` will return a `*json.UnmarshalTypeError` and fail the *entire* parsing operation. The entire intent is lost, even if the primary intent and target were perfectly valid.
**Architectural Impact:** This is a fragility in the boundary. If the system fails completely on a single type mismatch, it becomes brittle to minor LLM schema drift.
**Performance Impact:** The failure is fast, but if the orchestrator is configured to retry on parsing failures, this deterministically failing payload will trigger a retry storm, wasting LLM tokens and causing significant latency (seconds to minutes) for the end-user.

### 4.2 Number-to-String Coercion
**Negative Scenario:** A field expecting a string (like `urgency`) receives a number:
`{"signals": {"urgency": 1}}` (instead of `"urgency": "critical"`)

**Analysis:**
Similar to the above, this causes a hard unmarshal error. The transducer should ideally use custom unmarshaling logic (e.g., via the `json.Unmarshaler` interface) to coerce common types, or use a looser intermediate representation (like `map[string]any`) to gracefully degrade the specific field while preserving the rest of the intent.

### 4.3 Boolean as String
**Negative Scenario:**
`{"signals": {"is_question": "true"}}`

**Analysis:**
This type coercion failure is incredibly common with LLMs. If the transducer drops the entire message because of `"true"`, it represents a critical usability gap.

## 5. Vector 3: Extreme User Requests and Payload Dimensions

### 5.1 Deeply Nested JSON (Stack Exhaustion)
**Negative Scenario:** An adversarial user crafts a prompt that forces the LLM to output a massive nested JSON object within a constraint or target field:
`{"user_constraints": [{"nested": {"nested": ... }}]}`

**Analysis:**
Go's standard `encoding/json` package uses recursive function calls to unmarshal nested objects. While Go has dynamic stacks, extremely deep nesting can lead to high memory consumption, GC pauses, and eventually, a stack overflow (though Go 1.20+ is quite resilient, it still allocates heavily).
**Performance Impact:** Highly detrimental. Parsing 100,000 layers of nesting will stall the CPU thread and cause massive heap allocations. The Perception Transducer *must* implement a custom `io.LimitReader` or use a JSON decoder with a configured maximum depth to prevent this Denial of Service (DoS) vector.

### 5.2 Unicode and Control Character Extremes
**Negative Scenario:** The user requests a campaign involving filenames or targets constructed with zero-width spaces, right-to-left (RTL) overrides, or invalid UTF-8 sequences.
`"target": "auth‮.go"`

**Analysis:**
The test `TestE2E_Perception_Adversarial_MangleInjection` notes that `sanitizeFactArg` strips control characters but preserves Mangle syntax. However, Unicode directionality overrides can spoof the CLI display, making it appear that one file is being modified while another actually is.
**Mangle Implications:** If Mangle's AST parser relies on standard UTF-8 string length for indexing, invalid byte sequences might cause out-of-bounds panics during string manipulation.
**Performance Impact:** Low, but the security and usability implications are severe.

### 5.3 Extreme Length and Token Defeat Boundaries
**Negative Scenario:** The truncation test verifies behavior at 100,000 characters. What if the input is exactly 50,000 characters (the truncation boundary)? What if it is 50,001?
What if the 100KB input is a single, unbroken word (e.g., `FixAABBC...[100k times]...Z`)?

**Analysis:**
If the truncation logic attempts to find a word boundary (space) to cleanly truncate, a single massive word will defeat it, either bypassing truncation or causing an infinite loop.
If the truncation uses raw byte slicing (`str[:50000]`), and the 50,000th byte is in the middle of a multi-byte UTF-8 rune, the resulting string will contain invalid UTF-8. When this invalid string is passed to Mangle, it may fail parsing.
**Performance Impact:** Slicing is O(1) in Go, but validating UTF-8 boundaries is O(N). The system is performant enough to handle this, provided it uses `utf8.ValidString` or rune-aware slicing.

### 5.4 The "Brownfield Monorepo" Request
**Negative Scenario:** A user requests the system to "Analyze my 50 million line monorepo and fix all security vulnerabilities", running on an 8GB RAM laptop.

**Analysis:**
While the Perception Transducer's job is just to parse this request, the resulting Mangle intent (e.g., `scope: {"level": "repository", "target": "all"}`) will trigger downstream components (the orchestrator, the VirtualStore) to attempt to load massive state into memory.
**Performance Impact:** The transducer is fast enough, but it acts as the gateway. The QA gap here is that the transducer does not emit a "resource bounds" constraint to Mangle. It should recognize extreme scopes and append a constraint fact (e.g., `memory_limit_exceeded(Target)`) that the Mangle kernel can use to reject the intent before executing it.

## 6. Vector 4: State Conflicts and Race Conditions

### 6.1 Concurrent Perception Transducer Access
**Negative Scenario:** Multiple asynchronous events (e.g., incoming chat messages, piggyback control packets) trigger `ParseIntentWithContext` concurrently on the *same* Transducer instance.

**Analysis:**
The Transducer struct might hold state, such as caching the last parsed intent, maintaining an internal buffer, or utilizing a shared Mangle `kernel` instance for intermediate verification.
If `ParseIntentWithContext` mutates any fields on the `UnderstandingTransducer` receiver (e.g., `t.lastIntent = intent`), concurrent calls will result in a data race.
**Mangle Implications:** If the shared Mangle kernel is not thread-safe for simultaneous `Assert` and `Query` operations during the parsing validation, concurrent parsing will corrupt the "Clean Slate" Fact Store, leading to "ghost facts" bleeding across completely unrelated user requests.
**Performance Impact:** Lock contention. If a global mutex is used to protect the transducer, concurrent requests will serialize, degrading throughput. The system should ideally be entirely stateless.

### 6.2 Transient Failure State Conflict
**Negative Scenario:** The network connection to the LLM provider is flapping. The transducer experiences a timeout, immediately followed by a rapid success with a malformed payload, followed by another timeout.

**Analysis:**
The system's error handling and state recovery are tested under these conditions. Does the transducer maintain an error count? If the JIT Clean Loop architecture requires a clean shutdown and restart on failure, rapid oscillations might cause the system to spin, burning CPU cycles and thrashing the scheduler.
**Architectural Solution:** The transducer should emit specific Mangle facts representing its own health (e.g., `transducer_health(/degraded)`). The orchestrator can query these facts to implement circuit breakers.

## 7. Mangle-Specific QA Requirements

Writing truly useful Golang tests for a Mangle-based system requires bridging the gap between Go's imperative runtime and Mangle's declarative logic. Based on the memory files and architecture docs, we must enforce the following in our QA automation:

### 7.1 The "Clean Slate" Requirement
Mangle's evaluation is monotonic and stateful. Reusing a store across tests leads to ghost facts.
In our edge case testing, if we test a deeply nested JSON payload and it successfully parses, we must ensure that the test instantiates a `factstore.NewSimpleInMemoryStore()` inside the test loop. Otherwise, the fact asserted in the first test will persist and falsely validate the second test.

### 7.2 Atom/String Dissonance
When testing the Type Coercion edge cases, we must use AST helpers that force type choice:
* `ast.Name("active")` for Atoms `/active`
* `ast.String("active")` for Strings `"active"`
If the transducer incorrectly parses an unmarshaled string into a Mangle String instead of a Mangle Atom, the rules will fail. Our tests must assert the exact type of the arguments in the resulting `user_intent` fact.

### 7.3 Termination Verification
When testing extreme inputs, we must ensure the engine halts. We must wrap the transducer's parsing logic in a `context.WithTimeout` and verify that even with pathological JSON payloads, the system reaches a steady state (or fails safely) within the deadline, without leaking goroutines.

## 10. Deep Dive: Mangle Type Strictness and Boundary Failures

In the codeNERD architecture, the Mangle logic engine operates with strict type disjointness. The Perception Transducer is the critical boundary where unstructured string data is coerced into these strict types. We must analyze specific edge cases where this coercion fails silently or catastrophically.

### 10.1 The Atom vs. String Boundary Condition
When parsing `tools_needed`, the system likely maps a string like "read_file" to an Atom `/read_file`.
**Scenario:** What if the LLM returns an array containing both expected tools and malformed strings that resemble Atoms?
`"tools_needed": ["read_file", "/write_file"]`
**Analysis:** If the transducer naively prepends a `/` to create an Atom, it might create `//write_file`. When this is passed to Mangle, it might be parsed as an invalid Atom or a comment block, leading to syntax errors during fact assertion.
**Performance/Reliability:** This requires a dedicated normalization step in the transducer to strip leading slashes before coercion. Without this, the system is brittle to minor LLM hallucinations, leading to failed execution plans.

### 10.2 Variable Binding Failures in Generated Intents
**Scenario:** The LLM returns a constraint containing variables, intended to be evaluated by Mangle:
`"user_constraints": ["safe_action(Action)"]`
**Analysis:** In Mangle, `Action` is a variable (starts with a capital letter). However, when the transducer asserts this as a fact, it might assert it as a raw string `"safe_action(Action)"`. If a downstream component attempts to dynamically execute this constraint, it will fail because `Action` is not bound in the scope of the assertion.
**Resolution:** The QA test suite must include tests that verify how the transducer handles Mangle variables embedded within string fields. The expected behavior is that the transducer explicitly rejects or escapes these to prevent Unbound Variable errors during the `analysis.Analyze` phase.

## 11. Advanced Concurrency and Resource Contention Vectors

The JIT Clean Loop architecture relies on rapid teardown and setup of execution contexts. We must evaluate the transducer's role in this lifecycle under extreme pressure.

### 11.1 The "Thundering Herd" Perception Storm
**Scenario:** In a multi-user workspace or a highly parallel autonomous campaign, 50 concurrent intents arrive at the Perception Transducer exactly simultaneously.
**Analysis:** Even if the Transducer is stateless, the underlying Go runtime must allocate memory for 50 concurrent JSON unmarshaling operations. If each payload is the maximum allowed size (e.g., 50KB), this causes an immediate 2.5MB allocation spike on the heap, accompanied by thousands of small object allocations for the JSON AST.
**Performance Impact:** This will trigger a minor GC pause. If the transducer also performs synchronous Mangle validation (e.g., parsing the rule to ensure it is safe before passing it on), the CPU will spike to 100%. The test suite must include a benchmark (`BenchmarkPerceptionThunderingHerd`) to ensure the p99 latency remains within acceptable bounds (e.g., < 100ms) under this load.

### 11.2 Context Cancellation and Resource Leaks
**Scenario:** A user submits a massive, complex intent, but immediately hits Ctrl+C, cancelling the parent context.
**Analysis:** The `ParseIntentWithContext` function accepts a `context.Context`. However, `json.Unmarshal` in standard Go is not context-aware. It cannot be interrupted mid-parse.
**Risk:** If the parsing step takes significant time (e.g., due to deep nesting or massive size), the goroutine will continue executing until unmarshaling finishes, even though the result will be discarded. This leads to temporary goroutine leaks and wasted CPU.
**Resolution:** For extreme payload sizes, the transducer should implement chunked reading or check the context cancellation state before entering the unmarshal phase, or immediately after, before proceeding to Mangle assertion.

## 12. Security and Privilege Escalation Boundaries

The Transducer is the first line of defense against prompt-injected privilege escalation.

### 12.1 The "Ghost Fact" Injection
**Scenario:** An adversarial intent attempts to inject facts directly into the target string.
`"target": "file.txt). admin(/user). p(X"`
**Analysis:** As noted in the existing tests, `sanitizeFactArg` preserves Mangle syntax. The current test correctly identifies this as a critical gap. But we must go further. What if the injected fact attempts to override the core `permitted` policy?
`"target": "file.txt). permitted(/nuke_everything, _, _). p(X"`
**Risk:** If this injected fact bypasses sanitization and is asserted into the "Clean Slate" store, the attacker gains full control over the execution environment. This is a Level 0 (Silent Fail) critical vulnerability.
**Test Requirement:** The test suite must assert not only that the injection fails, but that it fails at Level 5 (Impossible) or Level 4 (Prevented), meaning the type system or validation layer strictly rejects it before it even reaches the Fact Store.

## 13. Systemic Resilience and Self-Healing Interactions

CodeNERD implements a self-healing loop. How does the transducer interact with this?

### 13.1 Transducer-Triggered Self-Healing
**Scenario:** The transducer encounters an unrecoverable type coercion error (e.g., a boolean where a string was expected).
**Analysis:** Instead of just failing, does the transducer emit a `validation_error` fact that triggers the self-healing loop? The self-healing system (Ouroboros) might attempt to dynamically rewrite the LLM prompt or adjust the JSON schema expectation.
**QA Gap:** The test suite does not currently assert the integration between the Transducer's failure modes and the Self-Healing system. We need a test that feeds malformed JSON and verifies that a `repair_attempt` fact is subsequently logged by the system shards.

### 13.2 Infinite Repair Loops
**Scenario:** The self-healing loop attempts to fix the malformed intent, but the LLM deterministically produces the same malformed output.
**Analysis:** If the transducer continually rejects the input, and the self-healing loop continually retries, the system enters an infinite loop.
**Resolution:** The transducer must include a provenance ID or recursion depth counter in its context. The QA tests must simulate a deterministically failing LLM and assert that the system halts with a `healing_critical` failure after a bounded number of attempts, rather than spinning forever.

## 14. Observability and Debugging Boundaries

When the transducer fails, the operator must be able to diagnose why.

### 14.1 Log Truncation and Data Loss
**Scenario:** A massive, 100KB malformed JSON payload crashes the transducer.
**Analysis:** If the system attempts to log the entire payload to the debug logs (`.nerd/logs/`), it will flood the disk and make the logs unreadable. Conversely, if it aggressively truncates the log, the operator might lose the crucial bytes that caused the failure.
**QA Requirement:** The test suite must verify the observability behavior. It should assert that when a massive payload fails, the logs contain a bounded, heavily sanitized snippet of the failure point, along with a checksum or hash of the full payload for forensic analysis, without writing the entire 100KB to disk.

## 15. Final Summary of Architectural Imperatives

The Perception Transducer is fundamentally a boundary-crossing mechanism. It translates the probabilistic, unstructured output of an LLM into the deterministic, strictly-typed world of Mangle logic.

Based on this exhaustive QA analysis across Null/Empty vectors, Type Coercion, Extreme dimensions, Concurrency, and Security, the following architectural imperatives are clear:

1.  **Strict Demarcation of Parsing vs. Assertion:** The parsing phase (`json.Unmarshal`) must be isolated from the assertion phase. Parsing failures should result in controlled retries, while assertion failures (e.g., Mangle type mismatches) should trigger security alerts.
2.  **Statelessness:** The Transducer must hold zero state between requests to prevent "ghost fact" contamination and eliminate race conditions during concurrent perception storms.
3.  **Defensive Unmarshaling:** Standard `encoding/json` is insufficient for the frontier boundary. A custom unmarshaler with maximum depth limits, explicit type coercion fallbacks (e.g., converting `"true"` to `true`), and strict context cancellation awareness is required.
4.  **Absolute Sanitization:** The `sanitizeFactArg` function must be upgraded from a Level 1 (Logged) band-aid to a Level 4 (Prevented) validation gate, actively stripping or escaping all characters with Mangle syntactic meaning (`(`, `)`, `.`, `:-`, `,`) from any field destined to be a raw string term in a fact.

By addressing these vectors, the Perception Transducer will move from being a fragile integration point to a robust, adversarial-resistant boundary layer, ensuring the stability and security of the entire codeNERD JIT Clean Loop architecture.

## 17. Expanded Boundary Value Scenarios (Systemic Interactions)

To thoroughly exhaust the negative testing vectors for the Perception Transducer, we must evaluate how it interacts with the broader codeNERD ecosystem, specifically the VirtualStore, the JIT clean loop, and the campaign orchestrator.

### 17.1 Interaction with VirtualStore Rate Limits
**Scenario:** A malicious intent dictates an array of 5,000 distinct tools to be executed simultaneously.
`"tools_needed": ["tool_1", "tool_2", ..., "tool_5000"]`
**Analysis:** If the Transducer successfully parses this and passes it to the downstream VirtualStore, it may trigger massive parallel execution. While the transducer itself handles the parsing quickly, it acts as an enabler for downstream DoS attacks.
**Boundary Value:** The array size boundary must be strictly enforced at the Transducer level. A max constraint of `len(tools_needed) <= 10` should be instituted, and any intent exceeding this should be explicitly rejected with a `validation_error` fact.

### 17.2 The "Missing Kernel" State
**Scenario:** The JIT Clean loop tears down the active execution context just as an asynchronous `ParseIntentWithContext` call attempts to access the underlying Mangle kernel.
**Analysis:** The Perception Transducer depends on a valid Mangle Kernel reference to instantiate `user_intent` facts. If this kernel reference is nilled out or closed by the JIT clean loop mid-execution, a panic will occur.
**QA Gap:** We must inject a test that actively races the `Kernel.Close()` method against the transducer's `ParseIntentWithContext` method to ensure that the transducer gracefully degrades (returns an error) rather than panicking when its underlying fact store disappears.

### 17.3 Semantic Type Contradictions
**Scenario:** The LLM returns a JSON payload where the fields are technically of the correct type but logically contradictory according to the domain rules.
`{"understanding": {"primary_intent": "read", "action_type": "NUKE_AND_REWRITE"}}`
**Analysis:** The transducer currently accepts these at face value, converting them directly into Mangle facts. However, this creates a schizophrenic intent object.
**Resolution:** While full semantic validation might belong to the orchestrator, the transducer should ideally catch basic contradictions (e.g., an intent marked as `is_question: true` but `action_type: mutation`) and normalize them to a safe default before they corrupt the execution planner.

### 17.4 Campaign Lifecycle Token Exhaustion
**Scenario:** During a long-running autonomous campaign, the Perception Transducer processes thousands of intents sequentially.
**Analysis:** If the Transducer leaks even a small amount of memory per parse (e.g., by retaining references to large strings in an underlying map), a 24-hour campaign will eventually hit an OOM (Out of Memory) condition.
**QA Requirement:** A long-running stress test must be implemented that feeds 1,000,000 randomized intents through the transducer and asserts that heap memory remains completely flat after garbage collection.

### 17.5 The "Null Character" Vulnerability
**Scenario:** A string field contains the null byte character ` `.
`"target": "file.txt _hidden"`
**Analysis:** Go handles null bytes in strings perfectly fine (they are just `[]byte{0}`). However, if this string is eventually passed to a CGO boundary (e.g., SQLite underlying the VirtualStore), it will act as a C-string terminator. The string will be silently truncated at the null byte.
**Risk:** This allows a classic bypass where the system thinks it is operating on `file.txt _hidden`, but the underlying C library operates on `file.txt`. The transducer's sanitization must explicitly strip or reject ` `.

### 17.6 The "NaN" and "Infinity" Float Vectors
**Scenario:** The `confidence` float field receives a non-standard numeric representation from a hallucinating LLM.
`{"confidence": NaN}` or `{"confidence": Infinity}`
**Analysis:** Standard JSON does not officially support NaN or Infinity, but some permissive parsers allow it. If the Go unmarshaler accepts it (or if it's passed as a string and manually coerced), these values will propagate. When Mangle attempts to evaluate numeric constraints (e.g., `confidence > 0.8`), NaN comparisons typically evaluate to false, leading to unpredictable logic flow.
**Boundary Test:** We must explicitly test NaN/Infinity injection and assert that the Transducer normalizes these to `0.0`.

## 18. Architectural Review of the "Outcome" Object

The `Outcome` object is tightly coupled with the transducer's intent parsing.

### 18.1 Malformed Outcome JSON
**Scenario:** The LLM returns a malformed structure specifically for the nested `suggested_approach`.
`{"suggested_approach": "just do it"}` (String instead of Object)
**Analysis:** This is a Type Coercion vector specific to a nested struct. If the main struct fails, everything fails. The transducer should ideally use a two-pass parsing strategy or partial unmarshaling to salvage the `primary_intent` even if the `suggested_approach` is garbage, ensuring the system can at least log what the user wanted before failing.

### 18.2 Unknown Primary Shard Routing
**Scenario:** The `primary_shard` dictates where the JIT compiler sends the intent. What if the LLM hallucinates a non-existent shard?
`{"suggested_approach": {"primary_shard": "quantum_computer"}}`
**Analysis:** The transducer must normalize this to the `root` or `default` shard. If it passes the raw hallucinated string to the Mangle engine, the resulting routing facts will join with nothing, causing the execution to hang indefinitely as no shard claims the task.
**Resolution:** The transducer must validate `primary_shard` against a strict enum of registered shards (`coder`, `reviewer`, `root`, etc.).

## 19. Final Testing Directives

To properly implement the QA strategy outlined in this journal, the development team must adhere to the following directives:

1.  **Do not rely on `assert.Equal` for Mangle facts.** Sets are unordered. Use set membership checks (`store.Read(...)`) to verify specific facts exist after parsing.
2.  **Avoid goroutine leaks.** Ensure all context cancellations in the new adversarial tests use `defer cancel()` to tear down the transducer cleanly.
3.  **Use golden files for logic.** For complex intent parsing, store the expected IDB (derived facts) in a `.golden` file and compare, rather than hardcoding brittle Go structs.
