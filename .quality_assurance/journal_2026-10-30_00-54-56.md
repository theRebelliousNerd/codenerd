Date: 2026-10-30 00:54:56 EDT
Component: internal/world/cartographer_multilang.go & cartographer_multilang_test.go

## 1. System Context and Architectural Overview
The Cartographer component in codeNERD is responsible for 'deep mapping' source files.
This involves parsing code to extract definitions (classes, functions, methods) and call graphs.
While the Go implementation (`cartographer.go`) is heavily tested, `cartographer_multilang.go`
extends this capability to Python, JavaScript, TypeScript, and Rust using tree-sitter.
The core of this multi-language support revolves around `tsParserSet` for managing parser instances
and `deepMapper` for walking the AST generated by tree-sitter.
This deep mapping is critical because the fast scanner's `symbol_graph` cannot substitute:
it carries no line range, so nothing can slice a function body out of a file, and it records no call edges.
The architectural intent is that MapFileAs is called for each file, and deepMappableExt filters them.
When we test these systems, we have to consider not just standard unit tests (happy paths),
but boundary value analysis and negative testing.
Negative testing ensures the system fails gracefully rather than catastrophically.
Boundary value analysis checks behavior at the extreme edges of expected input.

## Core Gaps Identified in Test Suite

### Gap 01: Null/Undefined/Empty: Empty File Inputs
Empty inputs are a fundamental boundary. `mapNonGoFile` begins by reading the file:
If `fsPath` points to a 0-byte file, `content` is an empty byte slice.
The tree-sitter parser is invoked on empty bytes.
According to the tree-sitter documentation, parsing an empty string is valid and produces
an empty root node. However, `m.walk(tree.RootNode(), "")` will receive a root node with
zero children. The test suite needs to explicitly assert this doesn't panic and returns zero facts.

### Gap 02: Null/Undefined/Empty: Empty Language Strings
Furthermore, what if `lang` is an empty string? `c.parsers.get("")` defaults to returning `nil`
and closing an uninitialized parser, which leads `mapNonGoFile` to return `(nil, nil)`. This is safe,
but lacks explicit test coverage in `cartographer_multilang_test.go`.
We must ensure the system handles unsupported language requests securely.

### Gap 03: Null/Undefined/Empty: Missing File Permissions
An explicitly missing file triggers `os.ReadFile` to return `os.ErrNotExist`, which propagates.
But if the file exists but has no read permissions, `os.ErrPermission` is returned.
The caller needs to distinguish between 'no facts because file is unparseable' and 'no facts because permission denied'.
A negative test must set `chmod 000` on a test fixture and verify the error bubble-up.

### Gap 04: Null/Undefined/Empty: Whitespace-Only Files
We must test the case where `os.ReadFile` returns data, but the data is just whitespaces (spaces, tabs, newlines).
Tree-sitter will parse this, but there will be no function definitions.
The system should gracefully return an empty set of facts without attempting to access out-of-bounds nodes.

### Gap 05: Type Coercion: Malformed Syntax Injection
The system assumes that if a file ends in `.py`, it contains valid Python. What happens if a `.py`
file contains raw binary data, or valid TypeScript instead?
Tree-sitter is famously robust and will generate an AST with `ERROR` nodes. The `deepMapper.walk`
function does not explicitly check for `n.Type() == "ERROR"`.
It blindly switches on expected types like `function_definition` (Python).
A test case injecting invalid syntax is necessary to verify this degradation behavior remains stable.

### Gap 06: Type Coercion: Invalid UTF-8 Boundaries
If the content contains invalid UTF-8 bytes, tree-sitter may attempt recovery,
but the extracted text could contain invalid runes. The `core.Fact` emission must handle this.
CGO boundaries are notoriously fragile with malformed string encodings.
A test injecting `\xff\xfe` sequences into identifiers must be written.

### Gap 07: Type Coercion: Subtle Syntax Errors (Missing Parens)
What if the syntax error is subtle, like a missing closing parenthesis? `def foo( `.
Tree-sitter might still emit a `function_definition` node but mark it with an error flag.
Because `deepMapper` ignores error flags, it might still emit the definition.
We need a negative test to verify if partial definitions are useful or harmful to Mangle evaluation.

### Gap 08: User Request Extremes: Deep Recursion (Stack Overflow)
`deepMapper.walk` is a recursive function.
If a user submits a maliciously or automatically generated file (e.g., a massive JSON-like structure
in JS or thousands of nested arrow functions) resulting in a tree-sitter AST with a depth of 20,000,
the recursive `m.walk` will blow the Go goroutine stack.
A generative test creating 10,000 layers of nested blocks is required to ensure the system either
handles the depth or panics safely without taking down the entire kernel.

### Gap 09: User Request Extremes: Massive Horizontal Breadth
Instead of deep recursion, what about horizontal breadth? A file with 1 million flat functions.
This will test memory allocation for the `m.facts` slice.
Slice reallocation could cause GC thrashing and OOM errors.
A test mapping a file with 1,000,000 flat function declarations is required.

### Gap 10: State Conflicts: Concurrent MapFileAs Access
The `tsParserSet` uses a `sync.Mutex` to protect the initialization of the `parsers` map.
However, the *returned* `*sitter.Parser` is then used *outside* the lock in `mapNonGoFile`.
If `mapNonGoFile` is called concurrently for two Python files on the same `Cartographer` instance,
both goroutines will receive the *same* `*sitter.Parser`.
Tree-sitter parsers are explicitly documented as *not thread-safe*.
A test explicitly spawning multiple goroutines calling `MapFileAs` on the same instance is needed
to verify if this architectural assumption holds, or if it constitutes a critical fragility.

### Gap 11: State Conflicts: Time-of-Check to Time-of-Use (TOCTOU)
Files are discovered and then later mapped.
Between discovery and `os.ReadFile(fsPath)` in `mapNonGoFile`, the file might be deleted or locked
by another process.
An orchestrated test deleting the file after `NewCartographer()` but before `MapFileAs()` is necessary.
This validates that `os.PathError` is handled securely in highly concurrent workspaces.

### Gap 12: Null/Undefined/Empty: Nil Child Node Handling
If `n.Child(i)` returns a `nil` node for some reason (corrupt C state), `m.walk` handles it
with `if n == nil { return }`. This is good defensive programming, but we should assert
that this path is actually exercised in tests by artificially injecting a nil child via mock AST.
Otherwise, it's dead code that could rot.

### Gap 13: Type Coercion: Symlink Loop Exhaustion
If `fsPath` points to a special file (like `/dev/urandom` or a symlink loop),
`os.ReadFile` will read forever until memory is exhausted and OOM kills the process.
This is a classic negative test: prevent mapping of non-regular files.
A test mocking a symlink loop in the temporary directory must be created.

### Gap 14: Extremes: Extreme Identifier Length
What happens if a function name is 1MB long?
The string is passed to `code_defines` as the second argument.
Mangle atoms and strings have limits. If the ID is too long, the Mangle parser
during evaluation might reject the fact.
A negative test should create a file with a ridiculously long function name.

### Gap 15: Type Coercion: Invalid Mangle Atoms
The `deepMapper.define` function unconditionally converts the `kind` string to a `core.MangleAtom`.
Mangle semantics require atoms to be lowercase and alphanumeric (with underscores).
If an invalid atom is emitted, the Mangle engine might reject the entire fact graph later.
The test suite needs a boundary test that attempts to force the emission of malformed Mangle facts.

### Gap 16: State Conflicts: Symbolic Path Namespace Collisions
The function `moduleIDForPath` strips the file extension to create a namespace.
For example, `widget.py` becomes `widget`. If a project contains both `widget.py` and `widget.ts`
in the same directory, and both define a function `render`, `moduleIDForPath` will return `widget`
for both files. The `deepMapper.define` function will then emit the exact same identity:
`widget.render` for both functions, causing cross-language collision boundaries.
This must be tested explicitly.

### Gap 17: User Request Extremes: Context Cancellation Timeouts
`parser.ParseCtx(context.Background(), ...)` passes a background context.
This means the parse operation cannot be cancelled or timed out.
If tree-sitter encounters a degenerate regex or a massively nested structure that takes 10 minutes to parse,
the goroutine is permanently blocked. There is no timeout.
A test should be written that passes a context with a 1-millisecond timeout.

### Gap 18: Null/Undefined/Empty: Context Cancelled before Walk
Even if the parse completes, `m.walk` traverses the tree synchronously.
If context is cancelled during the walk of a 50MB file, the walk continues to the end.
A negative test needs to verify that `m.walk` checks context.Done() intermittently.

### Gap 19: Type Coercion: Single-Line Minified Files
Source files minified by tools like Webpack often compress everything into a single line.
If a line exceeds buffer capacities in internal string processing functions within `go-tree-sitter`,
or within our text extraction `m.text()`, it could lead to memory overallocation.
Negative testing must verify that single-line 50MB files do not cause sudden OOM kills.

### Gap 20: User Request Extremes: Fact ID Wrapper Wraparound
The facts emitted include line numbers: `int64(n.StartPoint().Row) + 1`.
What if the file is a single line with 10 million characters?
Does `Row` overflow? Does `Column` overflow? Tree-sitter uses `uint32` for row/column in its C struct.
A single line of 10M characters will not overflow a `uint32` (which holds 4 billion),
but if we have a file with 5 billion lines, `Row` will wrap around to 0.
A negative test simulating a 5-billion-line file is necessary to verify Mangle facts aren't corrupted.

### Gap 21: Type Coercion: Duplicate Method Names
In Python or JS, you can define a method twice in the same class.
The AST will contain two nodes with the same name.
`deepMapper.define` will emit two `code_defines` facts with the exact same ID (`module.method`).
Mangle will treat these as a set, but if they have different line numbers, they are distinct facts.
When a `code_calls` edge points to `module.method`, it will join against *both* definitions,
potentially doubling the impact score during holographic ranking.
A negative test should verify that duplicate definitions either emit a warning or are deduplicated.

### Gap 22: Null/Undefined/Empty: Missing Name Nodes in AST
If an expected field like `name` or `value` is absent from a node due to syntax errors,
`ChildByFieldName` might return `nil`. `m.text(nil)` safely returns an empty string.
However, calling `define` with an empty string is handled (returns empty), but does it log
a warning about the missing name? No. We need tests verifying that empty strings from `m.text` are dropped gracefully.

### Gap 23: State Conflicts: CGO Segfault Isolation
Tree-sitter is a C library. When `parser.ParseCtx` is invoked, execution crosses the CGO boundary.
Go's `recover()` mechanism cannot catch segfaults that occur inside C code.
If a specific combination of malformed input bytes triggers a buffer overflow or null pointer
dereference inside the tree-sitter C library, the entire Go process will instantly terminate
with a fatal signal (SIGSEGV). A test needs to verify CGO boundaries are isolated if possible.

### Gap 24: Type Coercion: Unrecognized File Extensions in Bypass
If `MapFileAs` is called on a `.jpeg` or a `.zip` by mistake, `deepMappableExt` handles
early filtering for deep scans. But if explicitly requested bypassing the filter, it might try to parse binary.
Testing must verify that binary data doesn't trap the tree-sitter parser in an infinite loop.

### Gap 25: User Request Extremes: Massive Pathological Regexes
JavaScript and Python allow complex regular expressions.
Tree-sitter must tokenize these regexes. Some regexes can cause ReDoS (Regular Expression
Denial of Service) if the tokenization algorithm is flawed.
We need a test that creates a file with a known pathological regex and verifies that
`MapFileAs` returns within a reasonable timeframe (e.g., < 100ms).

### Gap 26: Null/Undefined/Empty: Anonymous Functions Edge Cases
In JS: let x = [function() { return 1; }].
The `deepMapper` switches over expected node types. A `variable_declarator` may contain an array or object
that itself contains a function. But `m.walk` traverses all children, so it should find them.
However, how are these anonymous functions named? They have no `name` field.
`m.text(n.ChildByFieldName("name"))` will be empty. `define` checks `if name == "" { return "" }`.
A negative test should explicitly verify that callbacks do not crash the mapper and
confirm the current expected behavior (that they are ignored).

### Gap 27: State Conflicts: The Ouroboros Feedback Loop Failure
If the Cartographer maps a newly LLM-generated tool containing malformed syntax,
the Cartographer silently fails to extract symbols (due to ERROR nodes).
The LLM, seeing no symbols, might assume the tool is empty and attempt to regenerate it indefinitely.
This constitutes a system-level infinite loop caused by a silent failure at the perception layer.
A test must verify that `mapNonGoFile` can differentiate between 'parsed successfully, zero symbols found'
and 'parse failed due to malformed AST'.

### Gap 28: Type Coercion: Mixed Language TSX/JSX Parsing
The code handles `.tsx`. The `switch m.lang` blocks process typescript.
If `.tsx` is passed to the TS parser, it will likely generate `ERROR` nodes for JSX syntax.
This is a major potential bug that requires a negative test where TSX syntax is provided,
and we verify if the parser gracefully handles or fails.

### Gap 29: Type Coercion: Cross-Language FFI Symbol Matching
If a Python file calls a Rust function via FFI (e.g., `lib.helper()`),
the python `calleeName` will emit `module.lib.helper` or similar.
The Rust definition is `lib.helper`.
The `code_calls` edge might not join correctly because the Python module qualifier prefixes the FFI call.
A negative test involving cross-language FFI patterns is needed to verify if the call graph connects.

### Gap 30: Null/Undefined/Empty: DataFlow Extraction Panics
The extraction is guarded by `if c.dataFlowExtractor != nil`.
If `c.dataFlowExtractor.ExtractDataFlowForLanguage` panics internally (simulated in test),
does `mapNonGoFile` catch it, or does it crash the entire pipeline?
A negative test must mock a panicking dataFlowExtractor to verify robust error boundaries.

### Gap 31: Null/Undefined/Empty: Dangling Symlinks
If `fsPath` is a dangling symlink, `os.ReadFile` returns `os.ErrNotExist`.
The code handles `err != nil`, but does it log it as an error, a warning, or silently drop it?
We need to verify the logging level in `MapFileAs` for non-existent files.

### Gap 32: User Request Extremes: Read timeout on network drives
If the workspace is mounted on a slow network drive (NFS), `os.ReadFile` can block indefinitely.

A negative test mocking a slow file system is required.

### Gap 33: Null/Undefined/Empty: lastSegment with empty strings
If `lastSegment` receives an empty string or a string composed only of delimiters like `::` or `()`,
what does it return? `lastSegment("::")` returns `""`. `lastSegment("()")` returns `""`.
This is correct, but needs explicit boundary tests to ensure it doesn't panic on index out of bounds.

### Gap 34: Null/Undefined/Empty: moduleIDForPath with no extension

### Gap 35: User Request Extremes: moduleIDForPath with multiple extensions
If a file is named `archive.tar.gz.py`, `strings.Index` will find the first dot.

### Gap 36: Type Coercion: Escaped Strings in Macros

### Gap 37: State Conflicts: Tree-sitter ABI Version Mismatch

### Gap 38: Type Coercion: Deeply nested object destructuring

### Gap 39: Type Coercion: Generator Functions and yields

### Gap 40: Type Coercion: Optional Chaining resolution

### Gap 41: State Conflicts: Unclosed Tree-sitter instances
