# QA Automation Engineering Journal: Boundary Value Analysis and Negative Testing
# Module: ContextPager (internal/campaign/context_pager.go)

## Executive Summary
This journal entry documents a deep dive into the ContextPager module of the campaign orchestrator. As a critical component responsible for maintaining the neuro-symbolic "working memory" limits within the codenerd JIT-compiled loop, the ContextPager enforces context boundaries across various reserves (Core, Phase, History, Working, Prefetch).

The goal of this analysis is to identify critical gaps in the existing test suite (`context_pager_test.go`), specifically focusing on Negative Testing and Boundary Value Analysis (BVA). We move beyond "Happy Path" testing to stress the edges of the implementation: what happens under extreme conditions, with malformed data types, and under concurrent stress?

## 1. Null / Undefined / Empty Input Vectors

### 1.1 Constructor Instantiation
**Gap:** `TestNewContextPager` handles positive budget values but doesn't test boundary instantiation where `kernel` or `llmClient` dependencies are strictly `nil`.
**Impact:** A nil `kernel` will cause a fatal panic when `cp.kernel.Query` is invoked during `ActivatePhase` or `CompressPhase`. A nil `llmClient` is somewhat checked in `CompressPhase`, but early initialization needs strong assertions.
**Performance/Resilience:** The system currently relies on the user or DI container to provide valid interfaces. An explicit nil-check and return of an error or no-op implementation from the constructor would improve resilience against catastrophic boot failures.

### 1.2 Empty Phase Tasks
**Gap:** `TestPrefetchNextTasks` lacks coverage for cases where `tasks` is an empty slice or explicitly `nil`.
**Impact:** `PrefetchNextTasks` iterates over the tasks slice. A `nil` slice evaluates safely in Go (`range` over `nil` is a no-op), but it is a best practice to test this boundary. Furthermore, if `limit` is negative or 0, the code corrects it to `limit = 3`.
**Performance/Resilience:** The correction logic `if limit <= 0 { limit = 3 }` handles zero or negative values but alters intended behavior (what if the caller legitimately wanted to disable prefetch?).

## 2. Type Coercion Vectors

### 2.1 Malformed Profile IDs
**Gap:** `TestGetContextProfile_Malformed` tests if it handles malformed strings, but what if the kernel returns unexpected Mangle facts where the ID is stored as an integer atom or a boolean, instead of a string?
**Impact:** In `getContextProfile`, `types.ExtractString(fact.Args[0])` is called. If `ExtractString` panics on unexpected types, the system crashes.
**Performance/Resilience:** `ExtractString` in `types/mangle_helpers.go` should handle coercion, but the test suite must prove it. Given Mangle is an untyped Datalog offshoot, atomic propositions are extremely vulnerable to type drift.

### 2.2 Phase Fact Assertions
**Gap:** `cp.suppressSchema(schema)` asserts `-100` activation. What if a schema string contains arbitrary characters or SQL-injection style datalog strings `schema"), 100). p("`?
**Impact:** The `fmt.Sprintf` implementation strings together Mangle Datalog facts. Unsanitized strings could inadvertently inject valid datalog rules altering the inference graph.
**Performance/Resilience:** The codebase must use Mangle's AST builders rather than raw string concatenation to prevent injection attacks on the knowledge base.

## 3. User Request Extremes Vectors

### 3.1 Massive Context Compression
**Gap:** `TestCompressPhase_MassiveAccomplishments` tests large artifacts, but how does the LLM client handle massive textual contexts when `CompressPhase` is called on a phase with thousands of distinct task accomplishments?
**Impact:** `CompressPhase` builds a prompt string: `strings.Join(accomplishments, "\n")`. If accomplishments contain 50MB of text, the system will hit Out-Of-Memory (OOM) or exceed context limits for the `llmClient.Complete` call.
**Performance/Resilience:** `CompressPhase` needs defensive truncation. The `ContextPager` currently limits its *internal* Datalog budget but blindly concatenates strings to send to the LLM. It is NOT performant enough to handle an extreme edge case (e.g. a "Brownfield monorepo ingestion phase") without hitting prompt token limits.

### 3.2 Extreme Tokens Configuration
**Gap:** `ContextPager` defaults to `200000` tokens if budget is `<= 0`. What if the configuration dynamically sets budget to `2,000,000,000` tokens?
**Impact:** `coreReserve = budget * 5 / 100`. Go integer math will handle this without overflowing `int` (on 64-bit systems), but if used to allocate slices or byte buffers down the line, it could panic.
**Performance/Resilience:** The math is safe on 64-bit, but limits should be enforced.

## 4. State Conflict Vectors

### 4.1 Concurrent Token Accounting
**Gap:** `TestSetBudget` does not evaluate `SetBudget` under concurrent conditions where `ActivatePhase` or `GetUsage` is simultaneously running.
**Impact:** The `ContextPager` uses `cp.mu.Lock()` and `cp.mu.Unlock()` around `usedTokens`. However, `cp.totalBudget`, `cp.coreReserve`, etc. are mutated in `SetBudget` without acquiring the write lock `cp.mu.Lock()`.
**Performance/Resilience:** THIS IS A CRITICAL DATA RACE. `SetBudget` updates variables while `ActivatePhase` or `GetUsage` might read them. Go's race detector will likely catch this. `SetBudget` needs to lock `cp.mu`.

## 6. Deep Dive: Memory Allocation & Performance Extremes
When analyzing the `ContextPager` for extreme user requests, we must evaluate its memory allocation footprint and its reliance on the Go GC (Garbage Collector).

### 6.1 The "God Mode" Monorepo Request
Consider a user request targeting a 50 million line monorepo. The user instructs codenerd to "refactor the entire network layer." The Orchestrator spins up a Campaign.

*   **File Topology Fan-Out:** During `ActivatePhase`, the `Tasks` array might contain references to 50,000 files as artifacts.
*   **Mangle Assertions:** The `ContextPager` loops over these artifacts and asserts: `file_topology("path/to/file", _, _, _, _)`.
*   **Memory Pressure:** Mangle's `factstore.NewSimpleInMemoryStore()` is set-based. Asserting 50,000 complex string facts requires string allocation and map resizing. If the `ContextPager` asserts these individually via `cp.kernel.Assert()`, the cross-boundary cost (Go -> Mangle AST -> Memory Store) is non-trivial.
*   **Current State:** The code uses `cp.kernel.AssertBatch(facts)`. This is a crucial optimization. However, the `facts` slice is allocated inside a loop: `facts := make([]core.Fact, 0)`.
*   **Gap identified:** While `AssertBatch` is used, the pre-allocation of the `facts` slice is naive. It should use `make([]core.Fact, 0, len(tasks)*estimated_artifacts)`. In extreme cases, Go's slice `append()` will reallocate and copy the backing array logarithmically, causing memory fragmentation and GC thrashing.

### 6.2 The Context "Compression" Black Hole
The `CompressPhase` method attempts to summarize a phase before paging it out of active memory.

*   **Accomplishment Concatenation:** It creates `accomplishments []string` and appends a string for every completed task and artifact.
*   **LLM Prompting:** It interpolates these into a prompt: `fmt.Sprintf("...%s", strings.Join(accomplishments, "\n"))`.
*   **The Attack Vector:** If a phase generates 500,000 log lines (e.g., a massive test failure phase), the `strings.Join` will attempt to allocate a contiguous block of memory for the resulting massive string. If the machine has 8GB RAM (as specified in the prompt extreme parameters), this single operation can trigger an OOM kill.
*   **LLM Timeout:** Even if memory holds, sending a 50MB payload to `llmClient.Complete` will either fail payload limits or result in a timeout. The `ContextPager` has no backoff, no chunking, and no truncation for this payload.
*   **Performance Reality:** The system is **NOT performant enough** to handle extreme edge cases during compression. It needs a truncation mechanism or a streaming summary mechanism to limit memory use.

## 7. Deep Dive: State Conflicts and the Data Race
The `ContextPager` struct tracks `usedTokens` and budget limits.

### 7.1 The Concurrent Paging Scenario
Imagine a scenario where the `IntelligenceGatherer` is concurrently pulling context while the `CampaignOrchestrator` decides to reprioritize and adjust the budget.

*   Goroutine 1: `cp.SetBudget(500000)`
*   Goroutine 2: `cp.ActivatePhase(ctx, phase)`

Let's look at `SetBudget` (hypothetically, based on the `ContextPager` struct):
```go
func (cp *ContextPager) SetBudget(tokens int) {
    cp.totalBudget = tokens
    cp.coreReserve = tokens * 5 / 100
    // ... no mutex lock!
}
```

And `ActivatePhase` (which uses `cp.usedTokens = cp.estimatePhaseTokens(phase)` inside a mutex, but evaluates bounds against `cp.totalBudget` outside it).

*   **The Data Race:** Go's memory model makes no guarantees about the visibility of writes across goroutines without explicit synchronization. A partial read of `totalBudget` or the reserves could lead to a negative token accounting state or a division by zero if an intermediate state is observed.
*   **Testing Gap:** `context_pager_test.go` has `TestContextPager_GetUsageConcurrent`, but it does not test `SetBudget` running concurrently with `ActivatePhase` or `GetUsage`.

## 8. Deep Dive: Type Coercion and the Neuro-Symbolic Interface
Codenerd's unique architecture bridges strict-typed Go and untyped Mangle Datalog.

### 8.1 The Fact Extraction Assumption
In `getContextProfile`:
```go
types.ExtractString(fact.Args[0]) == profileID
```

*   **The Assumption:** The code assumes that if `predicate == "context_profile"`, then `Args[0]` is safely extractable as a Go string.
*   **The Reality:** Mangle facts are dynamically asserted. An adversarial intent or a hallucinating LLM (via the transducer) could assert: `context_profile(12345, /schema, /tool, /focus)`.
*   **The Panic:** If `types.ExtractString` expects an `ast.String` or `ast.Atom` and casts blindly: `arg.(ast.String).String()`, it will cause a runtime panic: `interface conversion: interface {} is ast.Number, not ast.String`.
*   **Testing Gap:** The tests do not assert `context_profile` facts with integer, boolean, or nested map Mangle types to verify that `ContextPager` gracefully handles or ignores invalid schema types without crashing the entire system process.

The `ContextPager` is robust for standard operations, but the test suite is notably deficient in Boundary Value Analysis and Negative Testing. To make this system frontier-model ready and capable of handling 50M line monorepos on constrained hardware, we must implement tests that actively attempt to break it via OOM conditions, concurrent mutations, and Type Coercion across the Go/Mangle boundary.


## 10. Extended Analysis: The "Null/Undefined/Empty" Vectors in Depth
When evaluating the resilience of a system, "Empty" states are often more insidious than strict `nil` values because they often bypass basic `if x == nil` checks, propagating deeper into the logic until they cause semantic failures.

### 10.1 The Empty Profile String
In `ActivatePhase`, the system looks up a context profile: `cp.getContextProfile(phase.ContextProfile)`.
*   **Vector:** What happens if `phase.ContextProfile` is `""` (empty string)?
*   **Behavior:** The code will query all `context_profile` facts. If it doesn't find `""`, it returns an error: `fmt.Errorf("context profile %s not found", profileID)`.
*   **Consequence:** The phase activation fails. But should an empty profile default to a baseline? The test suite doesn't establish the contracted behavior for an empty profile ID. If the system's transducer hallucinates a missing profile, the campaign stops dead.

### 10.2 The Zero-Length Arrays in Phase Compression
In `CompressPhase`, we check: `if len(accomplishments) > 0`.
*   **Vector:** What if the phase had 10 tasks, but none of them reached the `TaskCompleted` status?
*   **Behavior:** `len(accomplishments)` is 0. The code falls back to: `summary = fmt.Sprintf("Phase '%s' completed with no recorded accomplishments.", phase.Name)`.
*   **Consequence:** This is actually handled well! However, the *test suite* must have an explicit negative test proving this branch. Without it, future refactors might optimize away this branch, leading to empty LLM prompts.

### 10.3 The Undefined LLM Client State
The `ContextPager` receives an `llmClient` interface.
*   **Vector:** What if the `llmClient` is an initialized struct, but its internal API keys or connection pools are undefined/closed?
*   **Behavior:** `llmClient.Complete(ctx, prompt)` will return a network error or authentication error.
*   **Consequence:** The `CompressPhase` method catches `if err != nil` and falls back to a deterministic string summary. This is excellent defensive programming.
*   **Testing Gap:** There is no test that mocks `llmClient.Complete` to return a forced network error (e.g., `context.DeadlineExceeded` or `tls.CertificateVerificationError`) to explicitly verify this fallback logic works under duress.

## 11. Extended Analysis: System Performance and Scalability

### 11.1 The "Time-to-Live" (TTL) Fact Purge Problem
The ContextPager manages memory by boosting and suppressing "activation" facts in the Mangle knowledge base.
*   **The Mechanism:** Instead of deleting facts (which is non-monotonic in Datalog), it asserts `activation(schema, -100)`.
*   **The Performance Degradation:** As a campaign runs for hours, thousands of suppressed facts accumulate. Mangle still has to evaluate these facts during joins, even if their activation score filters them out later.
*   **The Edge Case:** A campaign with 50 phases. The `ContextPager` asserts suppression facts 50 times. The Knowledge Base grows linearly.
*   **Verdict:** The system is NOT performant enough for infinite-length campaigns. It relies on the assumption that campaigns are short-lived. A true garbage collection mechanism (actually retracting facts between major phase boundaries) is necessary.

### 11.2 String Interpolation Overhead
In `ActivatePhase`, the pager creates patterns: `fmt.Sprintf("file_pattern(%q)", pattern)`.
*   **Performance Hit:** Go's `fmt.Sprintf` uses reflection and allocates a new string. When dealing with 10,000 files in a directory scan, this becomes a CPU bottleneck and GC burden.
*   **Improvement:** For extreme performance, `strings.Builder` or pre-compiled string constants should be used.

## 12. Final Thoughts on Testing Strategy
Negative testing is about assuming the universe is hostile. The Transducer will lie to the ContextPager. The LLM will hallucinate 50MB strings. The OS will pause the goroutine for 500ms right in the middle of a budget update.

The gaps identified here—specifically around Type Coercion across the boundary, concurrent mutations without locks, and OOM-inducing string concatenations—must be represented in the test suite as explicit `// TODO` markers to guide the next wave of QA automation.

### 13.1 Deeper Look at `estimatePhaseTokens`
The function `estimatePhaseTokens(phase *Phase)` uses a hardcoded heuristic:
```go
tokens := 100 // Base
for _, task := range phase.Tasks {
    tokens += 50 // Description
    tokens += len(task.Artifacts) * 20
}
```
*   **The Flaw:** It assumes task descriptions are ~50 tokens. What if a user pastes a 10,000 token error log into the task description?
*   **The Edge Case:** The ContextPager will severely underestimate the token usage. It will report `usedTokens = 150`, but the actual prompt generated will blow past the 200k context window of the LLM.
*   **The Fix:** The estimation function must use a real tokenizer (like tiktoken) or a strict character-count-to-token ratio (e.g., `len(task.Description) / 4`), rather than hardcoded constants.

### 13.2 Deeper Look at `scopedDocsForPhase`
The function normalizes layer names using `strings.ReplaceAll(name, "-", "_")`.
*   **The Vector:** What if the phase name is `../../../etc/passwd`?
*   **The Consequence:** The normalization converts it to `../../../etc/passwd`. If this string is later used in file system operations to load scoped documentation, it's a classic Path Traversal vulnerability.
*   **The Mitigation:** While `scopedDocsForPhase` just queries the kernel, if the downstream consumer assumes the result is a safe path, the system is compromised. The ContextPager should probably sanitize phase names to strictly alphanumeric and underscores.

### 13.3 Context Pager Memory Leak Vectors
The `ContextPager` struct holds a reference to `core.Kernel`. If the Kernel holds a reference back to the Pager (e.g., via a registered callback), they form a cyclic dependency. In Go, the GC handles cycles, but if the cycle involves goroutines (e.g., the pager starts a background worker listening to kernel events), the goroutine will never terminate, leaking the entire pager and kernel memory.
*   **Testing Gap:** There are no `runtime.ReadMemStats` assertions in the test suite to prove that a `ContextPager` is successfully garbage collected after a campaign ends.

### 13.4 Theoretical Attack on the Holographic Memory
Codenerd's "Holographic Context" means that touching one file activates siblings.
*   **The Attack:** An attacker submits a PR with a folder containing 10,000 deeply nested, symlinked, or recursively imported files.
*   **The Mechanism:** The ContextPager attempts to build the file topology. The Spreading Activation algorithm (Orient phase) cascades.
*   **The Failure:** The system OOMs or hits a stack overflow during recursive activation calculation.
*   **The Requirement:** The ContextPager must enforce a maximum graph depth and a hard cap on total activated nodes, regardless of token budget, to protect the runtime.

## 14. Addendum: Mangle Specific Edge Cases
*   **Atom vs String Dissonance:** Mangle treats `/active` and `"active"` as completely different types. If `ContextPager` expects a string but the DB has an atom, the join fails silently. This is the most common AI failure mode in Mangle.
*   **Fixpoint Non-Termination:** If the pager injects rules (rather than just facts) that create a cycle (e.g., `boost(X) :- boost(X).`), the Mangle engine will never halt. The ContextPager currently only asserts facts, so this is safe, but any future feature allowing dynamic rule insertion must be heavily tested for termination.
