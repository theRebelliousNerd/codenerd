# Boundary Value Analysis and Negative Testing: Context Pager

## System Under Test: `internal/campaign/context_pager.go`

**Timestamp:** 2026-04-11 04:15:23 AM EST

### System Overview
The `ContextPager` manages the context window limits (token budget) for campaigns, dynamically activating and reprioritizing facts (`phase_context_atom`, `activation` states) based on the current execution phase. It interacts closely with the Mangle kernel for fact assertion/retraction, and an LLM Client for summarizing finished phases (`CompressPhase`).
The concept of context paging is critical to long-running autonomous campaigns. As the campaign evolves through potentially hundreds of tasks, the raw prompt size would quickly exceed the LLM context window (typically 128k to 200k tokens) if every file, log, and artifact were retained in working memory. The `ContextPager` solves this by treating the LLM context window like an operating system treats physical RAM: it swaps "pages" of context in and out based on their relevance to the current phase.

This "paging" is orchestrated using Mangle's spreading activation mechanism. By asserting or retracting `activation` facts, the system signals which concepts (schemas, tools, files) should be prioritized during prompt assembly.

### Test Suite Evaluation
The existing test suite (`context_pager_test.go`) covers the general happy path. It tests that:
1. `NewContextPager` allocates budgets correctly based on percentages.
2. `ActivatePhase` successfully pushes `activation` and `phase_context_atom` facts into the Mangle kernel.
3. `CompressPhase` correctly invokes the LLM client to summarize a phase and reduces the activation of its constituent atoms.

However, because the `ContextPager` fundamentally controls token usage—a resource strictly constrained by API boundaries and critical to the stability of the entire codeNERD framework—it requires extensive boundary, negative, and concurrency testing. The current tests almost entirely ignore failure modes, malformed inputs, edge cases, and scale.

Below is an exhaustive breakdown of the identified testing gaps, categorized by the requested edge case vectors, along with detailed implementation strategies for how these gaps should be closed.

### Edge Case Vector 1: Null/Undefined/Empty

#### 1. Nil Phase Processing in `ActivatePhase`
**The Gap:** `ActivatePhase(ctx context.Context, phase *Phase)` currently accepts a pointer to a `Phase`. The code has a basic nil check:
```go
if phase == nil {
	return nil
}
```
However, the test suite does not verify this behavior. Furthermore, it assumes that if `phase` is non-nil, its constituent fields (`Tasks`, `Artifacts`, `ID`) are well-formed.
**The Risk:** If a `Phase` object is dynamically generated by an autopoietic process or a faulty subagent, it might contain a nil `Tasks` slice. The iteration `for _, task := range phase.Tasks` is technically safe in Go for a nil slice, but what if a specific `task` struct within that slice is uninitialized or contains a nil `Artifacts` slice?
**Testing Strategy:**
*   **Test Case 1.1:** Pass an explicitly `nil` phase pointer to `ActivatePhase` and verify it returns `nil` without mutating the kernel.
```go
func TestActivatePhase_NilPhase(t *testing.T) {
    kernel := &MockKernel{}
    cp := NewContextPager(kernel, &MockLLMClient{}, 100000)
    err := cp.ActivatePhase(context.Background(), nil)
    if err != nil {
        t.Errorf("Expected nil error, got %v", err)
    }
    if len(kernel.Facts) > 0 {
        t.Errorf("Expected no kernel modifications")
    }
}
```
*   **Test Case 1.2:** Pass a phase where `Tasks == nil` and verify the budget calculation and token estimates do not panic.
```go
func TestActivatePhase_NilTasks(t *testing.T) {
    kernel := &MockKernel{}
    cp := NewContextPager(kernel, &MockLLMClient{}, 100000)
    phase := &Phase{ID: "test", Tasks: nil}
    err := cp.ActivatePhase(context.Background(), phase)
    if err != nil {
        t.Errorf("Expected nil error, got %v", err)
    }
}
```
*   **Test Case 1.3:** Pass a phase containing tasks where `Artifacts == nil` and verify the inner boosting loops skip gracefully.

#### 2. Nil Phase Processing in `CompressPhase`
**The Gap:** Similar to `ActivatePhase`, `CompressPhase` handles a nil phase pointer by returning zero values.
**The Risk:** The function relies heavily on iterating `phase.Tasks` to build an `accomplishments` list.
**Testing Strategy:**
*   **Test Case 1.4:** Pass an explicitly `nil` phase pointer to `CompressPhase` and verify the zero-value returns.

#### 3. Empty Accomplishments List Fallback
**The Gap:** In `CompressPhase`, if a phase has zero completed tasks, the `accomplishments` list is empty. The code falls back to:
```go
summary = fmt.Sprintf("Phase '%s' completed with no recorded accomplishments.", phase.Name)
```
**The Risk:** If a phase was completely aborted or contained only informational tasks that weren't marked "Completed", the summary skips the LLM call entirely. We need to verify that this fallback string is generated correctly and that the subsequent `context_compression` fact is asserted smoothly without LLM interaction.
**Testing Strategy:**
*   **Test Case 1.5:** Construct a `Phase` with 5 tasks, but set their statuses to `TaskPending` or `TaskFailed`. Verify that the LLM client is *not* called (using a mock that panics if invoked) and the fallback string is stored in the kernel.

#### 4. Nil LLM Client
**The Gap:** `ContextPager` is instantiated with an `LLMClient` interface.
**The Risk:** If dependency injection fails and `llmClient` is nil, calling `CompressPhase` will cause a nil pointer dereference when it attempts `cp.llmClient.Complete(ctx, prompt)`. While Go doesn't have "undefined", passing a nil interface is a common source of runtime panics.
**Testing Strategy:**
*   **Test Case 1.6:** Instantiate `NewContextPager` with `llmClient = nil`. Construct a valid phase with completed tasks. Assert that calling `CompressPhase` returns an error rather than crashing the agent.
```go
func TestCompressPhase_NilLLMClient(t *testing.T) {
    kernel := &MockKernel{}
    cp := NewContextPager(kernel, nil, 100000)
    phase := &Phase{
        ID: "test",
        Tasks: []Task{{Status: TaskCompleted, Description: "Done"}},
    }
    // Should handle gracefully or return error without panic
    summary, _, _, err := cp.CompressPhase(context.Background(), phase)
    if err == nil {
        t.Errorf("Expected error handling nil LLM client")
    }
}
```

#### 5. Empty Target Layer in `scopedDocsForPhase`
**The Gap:** `normalizeLayerName` handles stripping leading slashes, lowercase conversion, and replacing hyphens/spaces. If the input is just "/", "-", or spaces, the normalized output is an empty string.
**The Risk:** If `phaseName` normalizes to an empty string, the function returns nil early. We must verify this defense mechanism works.
**Testing Strategy:**
*   **Test Case 1.7:** Pass `phaseName = "  / -  "` to `scopedDocsForPhase` and verify it returns a nil slice without querying the kernel.

### Edge Case Vector 2: Type Coercion

#### 1. Kernel Fact Types: Mangle Atoms vs. Strings
**The Gap:** The `ContextPager` queries the Mangle kernel for facts like `phase_context_scope` and `context_profile`. It expects the arguments to these facts to be strings. It uses `types.ExtractString(fact.Args[0])`.
**The Risk:** Mangle is a logic language with distinct types. A Mangle Atom (e.g., `/my_phase`) is structurally different from a Mangle String (e.g., `"my_phase"`). If the `kernel.Query` returns an Atom, does `types.ExtractString` correctly convert it to the expected Go string format, or does it return a serialized representation like `"/my_phase"` which then fails equality checks (e.g., `if phaseVal != target`)?
Furthermore, what if a malicious or hallucinating subagent asserted a number or a boolean as the phase name?
**Testing Strategy:**
*   **Test Case 2.1:** Mock the kernel to return `phase_context_scope` facts where `Args[0]` is a `mangle.Atom` type instead of a native Go string. Verify `scopedDocsForPhase` correctly resolves it.
*   **Test Case 2.2:** Mock the kernel to return integers (e.g., `404`) and booleans (`true`) as arguments. Verify `types.ExtractString` coerces them safely without panicking, even if the subsequent match fails.

#### 2. Context Profile IDs containing Non-UTF8 or Binary Data
**The Gap:** `getContextProfile` queries the kernel for `context_profile(ID, Schemas, Tools, Patterns)`.
**The Risk:** If a chaotic LLM generates a Profile ID containing null bytes (`\x00`), invalid UTF-8 sequences, or massive continuous strings, the `strings.Split` operations might behave unexpectedly or consume excessive memory.
**Testing Strategy:**
*   **Test Case 2.3:** Inject a `context_profile` fact into the mock kernel where the `RequiredSchemas` string contains invalid UTF-8 and null bytes. Verify `getContextProfile` parses it into the struct without corrupting the Go runtime strings.

#### 3. Stringly Typed Budget Parsing
**The Gap:** While `SetBudget` takes an integer, budget configurations are often loaded from JSON or YAML files where they might be strings (e.g., `"200000"` instead of `200000`). If a conversion failure upstream passes `0` or negative numbers to `SetBudget`.
**The Risk:** Passing a negative token budget.
**Testing Strategy:**
*   **Test Case 2.4:** Call `SetBudget(-50000)`. The current implementation will blindly calculate negative reserves (`cp.workingReserve = -20000`). Verify this behavior and flag it for a fix (it should clamp to 0 or a minimum safe value).

### Edge Case Vector 3: User Request Extremes

#### 1. Massive Task and Artifact Lists (Performance & Memory)
**The Gap:** In `ActivatePhase`, there are nested loops:
```go
for _, task := range phase.Tasks {
	for _, artifact := range task.Artifacts {
		// Append to artifactFacts
	}
}
```
**The Risk:** What happens if a user submits a "brownfield request to work on a 50 million line monorepo" and a faulty planning module decomposes this into a single phase with 10,000 tasks, each modifying 100 artifacts?
The `artifactFacts` slice will attempt to allocate 1,000,000 `core.Fact` structs. If the agent is running on a laptop with 8GB of RAM, this sudden allocation spike might trigger the OOM killer. Furthermore, asserting 1,000,000 facts via `cp.kernel.AssertBatch(artifactFacts)` might block the primary thread for an unacceptable amount of time, starving the rest of the agent.
**Testing Strategy:**
*   **Test Case 3.1:** Construct a `Phase` with 10,000 tasks and 100 artifacts each. Run `ActivatePhase`. Wrap the test in a `context.WithTimeout(ctx, 2*time.Second)` to verify the loop and batch assertion complete within a strict time bound.
*   **Test Case 3.2:** Monitor memory allocations during this test to ensure the slice growth doesn't exceed reasonable boundaries (e.g., < 100MB).

#### 2. Massive 'Accomplishments' Output (Context Overflow & OOM)
**The Gap:** `CompressPhase` builds an `accomplishments` string array, joins it with newlines, and sends it to the LLM.
**The Risk:** If a phase completed 5,000 tasks, the generated prompt could easily exceed the LLM's context window (e.g., > 128k tokens for standard models). This will cause the LLM API call to fail with a `context_length_exceeded` error. The fallback logic will then kick in, but the fallback itself also joins the array: `strings.Join(accomplishments[:min(3, len(accomplishments))], "; ")`.
Even worse, building the initial `prompt` string could consume massive memory.
**Testing Strategy:**
*   **Test Case 3.3:** Construct a phase with 10,000 completed tasks, each with extremely long descriptions (e.g., 10KB strings). Verify that `CompressPhase` does not OOM while building the prompt.
*   **Test Case 3.4:** Mock the LLM client to return an immediate `context_length_exceeded` error when the prompt is too large. Verify the fallback logic triggers safely and correctly truncates the list.

#### 3. Linear Scan Performance on 1,000,000 `phase_context_scope` Facts
**The Gap:** `scopedDocsForPhase` retrieves *all* `phase_context_scope` facts using `cp.kernel.Query("phase_context_scope")` and iterates over them sequentially.
**The Risk:** In an extremely long-running campaign, there might be millions of facts in the kernel. The query might return hundreds of thousands of facts for this specific predicate. A linear scan inside `scopedDocsForPhase` for every phase activation could become a severe performance bottleneck.
**Testing Strategy:**
*   **Test Case 3.5:** Inject 1,000,000 mock `phase_context_scope` facts into the mock kernel. Call `scopedDocsForPhase`. Ensure the function completes in under 50ms.
```go
func TestScopedDocsForPhase_Performance(t *testing.T) {
    kernel := &MockKernel{}
    cp := NewContextPager(kernel, &MockLLMClient{}, 100000)
    for i := 0; i < 1000000; i++ {
        kernel.Assert(core.Fact{
            Predicate: "phase_context_scope",
            Args:      []interface{}{"test_phase", fmt.Sprintf("doc_%d.md", i)},
        })
    }

    start := time.Now()
    docs := cp.scopedDocsForPhase("test_phase")
    elapsed := time.Since(start)

    if elapsed > 50*time.Millisecond {
        t.Errorf("Performance test failed: took %v, expected < 50ms", elapsed)
    }
    if len(docs) != 1000000 {
        t.Errorf("Expected 1000000 docs, got %d", len(docs))
    }
}
```

#### 4. Estimate Phase Tokens Exceeding Total Budget
**The Gap:** `estimatePhaseTokens` calculates the rough token footprint of a phase.
**The Risk:** What if the calculated estimate (`cp.usedTokens = cp.estimatePhaseTokens(phase)`) exceeds `cp.totalBudget`? The current implementation logs it, but does nothing to prevent the LLM from blowing up when the actual execution happens.
**Testing Strategy:**
*   **Test Case 3.6:** Create a phase dense enough that `estimatePhaseTokens` returns 300,000, while `totalBudget` is set to 100,000. Verify the usage metrics return > 100% utilization. (This highlights a missing safety gate in the system design).

#### 5. Extreme Length Phase IDs and Document Paths
**The Gap:** File paths and phase IDs are injected directly into Mangle string facts.
**The Risk:** If a path is 32,000 characters long, does `fmt.Sprintf("file_topology(%q, _, _, _, _)", artifact.Path)` break the parser? Does Mangle have length limits on atom/string sizes?
**Testing Strategy:**
*   **Test Case 3.7:** Activate a phase where an artifact path is a 64KB string consisting of repeated "a/" directories. Verify successful assertion without Mangle syntax errors.

### Edge Case Vector 4: State Conflicts

#### 1. Double Activation Idempotency
**The Gap:** `ActivatePhase` is called when a phase starts. It asserts `activation` and `phase_context_atom` facts.
**The Risk:** If a campaign orchestration bug causes `ActivatePhase` to be called twice for the same phase without an intervening `ResetPhaseContext` or `CompressPhase`, what happens?
The current implementation asserts `activation` boosts (e.g., `+120`). If called twice, does the Mangle engine accumulate these values (yielding `+240`), or does it replace them? If it accumulates, double activation could hyper-prioritize wrong contexts, starving the working memory.
**Testing Strategy:**
*   **Test Case 4.1:** Call `ActivatePhase` on `PhaseA`. Record the activation score of a specific artifact. Call `ActivatePhase` on `PhaseA` a second time. Query the kernel to ensure the activation score is exactly 120, not 240.

#### 2. Transaction Rollback Failures in `ResetPhaseContext`
**The Gap:** `ResetPhaseContext` uses a `KernelTx` to retract `activation` and `phase_context_atom` facts. It logs a warning if `tx.Commit()` fails, but does not return an error or retry.
**The Risk:** If the transaction fails (e.g., due to a lock timeout in a highly concurrent environment), "ghost facts" from a previous phase will persist into the next phase. This is a critical state leak, leading to "context contamination" where the LLM becomes confused by irrelevant files from old phases.
**Testing Strategy:**
*   **Test Case 4.2:** Use a specialized `MockKernel` that forcibly returns an error on `tx.Commit()`. Call `ResetPhaseContext`. Verify the warning is logged. While the current code cannot fix the failure, the test must prove the failure mode is silent beyond the log.

#### 3. Concurrent Access to `GetUsage` and `SetBudget`
**The Gap:** `ContextPager` stores `totalBudget`, `usedTokens`, and reserve integers as plain fields.
**The Risk:** The codeNERD architecture uses a concurrent "Clean Loop" (Subagents executing in parallel). If Subagent A is running `ActivatePhase` (which modifies `cp.usedTokens`), and Subagent B simultaneously calls `GetUsage()` or `SetBudget()`, a race condition occurs. In Go, this can lead to torn reads or data corruption.
**Testing Strategy:**
*   **Test Case 4.3:** Spin up 100 goroutines. Half of them repeatedly call `ActivatePhase` with different phases. The other half repeatedly call `GetUsage()`. Run the test with `go test -race`. This will definitively prove the lack of thread-safety in the struct and necessitate the addition of a `sync.RWMutex`.
```go
func TestContextPager_Concurrency(t *testing.T) {
    kernel := &MockKernel{}
    cp := NewContextPager(kernel, &MockLLMClient{}, 100000)

    var wg sync.WaitGroup
    for i := 0; i < 100; i++ {
        wg.Add(2)
        go func(idx int) {
            defer wg.Done()
            phase := &Phase{ID: fmt.Sprintf("p_%d", idx)}
            _ = cp.ActivatePhase(context.Background(), phase)
        }(i)

        go func() {
            defer wg.Done()
            _, _, _ = cp.GetUsage()
        }()
    }
    wg.Wait()
}
```

#### 4. Orphaned Context Atoms During Compression
**The Gap:** In `CompressPhase`, the code queries `phase_context_atom`, filters them for the current phase, and then retracts the overarching `phase_context_atom(PhaseID)` fact:
```go
_ = cp.kernel.RetractFact(core.Fact{
	Predicate: "phase_context_atom",
	Args:      []interface{}{phase.ID},
})
```
**The Risk:** The query returns facts structured as `phase_context_atom(PhaseID, TargetPredicate, Score)`. The retract statement attempts to retract a fact with only one argument `(PhaseID)`. In logic programming, arity matters. Retracting `p(A)` does not remove `p(A, B, C)`. Therefore, the phase-specific context atoms are likely *never actually removed from the kernel*, leading to a permanent, slow memory leak over the lifespan of the campaign.
**Testing Strategy:**
*   **Test Case 4.4:** Assert several `phase_context_atom("phase1", "some_file", 100)` facts. Run `CompressPhase("phase1")`. Query the kernel for `phase_context_atom`. If the facts are still there, it proves the retraction logic is completely broken due to an arity mismatch.

#### 5. Prefetch Tasks Concurrency Issues
**The Gap:** `PrefetchNextTasks` modifies kernel facts without transactional boundaries or locking, making it susceptible to state races if prefetching occurs simultaneously with phase activation.
**The Risk:** Interleaved fact insertions from prefetching and phase activations could cause unintended overwrites or fact duplication.
**Testing Strategy:**
*   **Test Case 4.5:** Run `PrefetchNextTasks` and `ActivatePhase` concurrently, verifying that the kernel eventually reaches a correct state where both the prefetched artifacts and active artifacts are properly asserted without race condition panics.

#### 6. Cross-Phase Reference Integrity
**The Gap:** Sometimes `CompressPhase` reduces activation limits on resources that may overlap with the *next* phase's active context.
**The Risk:** If Phase 2 depends on Artifact A, but Phase 1 just finished and `CompressPhase` applies a negative `activation` boost to Artifact A, Phase 2 might start with a disabled artifact, harming LLM generation performance.
**Testing Strategy:**
*   **Test Case 4.6:** Simulate an execution path where Phase 1 and Phase 2 share a common artifact. Validate that the activation boost calculation in `ActivatePhase(Phase 2)` properly resolves or overwrites the suppression applied by `CompressPhase(Phase 1)`.

#### 7. Error Handling on Context Compression Deactivation Fact Batching
**The Gap:** When `CompressPhase` reduces the activation of specific facts via `AssertBatch`, errors from the engine cause an immediate fallback to loop iteration insertions.
```go
if err := cp.kernel.AssertBatch(postFacts); err != nil {
	for _, f := range postFacts {
		cp.kernel.Assert(f)
	}
}
```
**The Risk:** If the underlying kernel fails a batch insertion due to constraint violations, retrying element-by-element without returning an error masks the failure and leaves the context in an unpredictable, partially-retracted state.
**Testing Strategy:**
*   **Test Case 4.7:** Introduce a mock failure in `AssertBatch` that specifically targets one element of `postFacts`. Ensure the error propagates safely to the logger, and ideally, an architectural plan is devised to surface these issues to the execution loop instead of failing silently.

### Conclusion and Architectural Verdict

The `ContextPager` system, while conceptually sound, currently lacks the defensive programming required for a production-grade neuro-symbolic agent.

**Is the system performant enough to handle these vectors?**
*   **No.** The reliance on linear slice appending for potentially massive task/artifact lists (`ActivatePhase`), unbounded string joining for LLM prompts (`CompressPhase`), and linear queries over unstructured fact lists (`scopedDocsForPhase`) means the system will degrade exponentially as campaigns grow longer or codebases get larger.
*   The missing mutexes guarantee race conditions in a multi-agent setup.
*   The arity mismatch in `CompressPhase` retraction guarantees a state leak.

By implementing the test strategies outlined in this journal, the engineering team will be forced to harden the `ContextPager` with strict timeout contexts, bounded string buffers, proper sync primitives, and arity-correct Mangle retractions.

#### 8. Extreme Input Data Formatting for Error Generation
**The Gap:** LLMs are known to generate output that can be unpredictable or adversarial in formatting. When `CompressPhase` is invoked, it passes strings directly constructed from these tasks without length enforcement or sanity checks.
**The Risk:** If a task description contains ANSI escape codes, zero-width characters, or recursive payload structures disguised as strings, it could compromise downstream prompt token counting or logic parsers.
**Testing Strategy:**
*   **Test Case 4.8:** Provide `Phase` structs where `task.Description` contains 50,000 recursive characters like 'A' mixed with zero-width non-joiners. Validate that the truncation or formatting in `CompressPhase` bounds the output successfully without freezing the regex engine or the string builder.

#### 9. Malformed Budget Calculations (Integer Overflow/Underflow)
**The Gap:** `SetBudget` and `NewContextPager` assign percentage-based budget metrics:
```go
cp.phaseReserve = tokens * 30 / 100
```
**The Risk:** If `tokens` is provided as `math.MaxInt` or a sufficiently large value that overflows standard integer sizes on specific architectures (like 32-bit platforms), the math will overflow, resulting in negative budget reserves. This could throw off token limits drastically, breaking the entire campaign logic.
**Testing Strategy:**
*   **Test Case 4.9:** Initialize `ContextPager` with `math.MaxInt` or near max values, and ensure integer overflow doesn't cause reserve calculations to drop below zero.

#### 10. Missing Edge Cases on Artifact Path Validations
**The Gap:** Artifact paths are blindly accepted and asserted to the Mangle Engine.
**The Risk:** The filesystem topology might have artifacts represented by `..` / relative directories, or absolute paths. Pushing paths like `../../../etc/passwd` into the kernel might allow cross-agent data extraction if another system reads `phase_context_atom` blindly for filesystem execution contexts.
**Testing Strategy:**
*   **Test Case 4.10:** Inject an artifact path consisting of directory traversal markers (`../../../malicious/path.go`). Verify that it either successfully sanitizes these inputs or explicitly validates them against an allowed workspace directory.

#### 11. Overriding Profile Logic Errors
**The Gap:** `ActivatePhase` suppresses irrelevant schemas:
```go
if !contains(profile.RequiredSchemas, schema) {
    cp.suppressSchema(schema)
}
```
**The Risk:** What if a profile explicitly provides a schema that *should* be suppressed according to standard security rules but the override allows it? If a conflict exists between global core reserves and phase overrides, there is no explicit test verifying which takes precedence.
**Testing Strategy:**
*   **Test Case 4.11:** Create a context profile that attempts to enforce both a suppression and a boost on the same schema simultaneously (e.g., passing a schema globally to be suppressed, but specifying it in `RequiredSchemas`). Verify the resolution path is deterministic and stable.

#### 12. MockKernel Interface Completeness
**The Gap:** The `MockKernel` in `context_pager_test.go` may not fully mimic the transactional bounds and error propagation paths of the real Mangle Kernel.
**The Risk:** Tests passing on `MockKernel` may fail in production because the real kernel will enforce arity types, string serialization formatting, and concurrent transaction locking that the Mock simply bypasses.
**Testing Strategy:**
*   **Test Case 4.12:** Introduce specific Mangle parser tests into the mock or write integration tests that validate `ContextPager` against an instantiated, real Mangle Kernel, particularly testing the `AssertBatch` and `RetractFact` failure handling mentioned in previous edge cases.

#### 13. Deeply Nested Artifact Topologies
**The Gap:** `ActivatePhase` pushes artifacts into a `file_topology` predicate: `file_topology("path", _, _, _, _)`.
**The Risk:** Does `Mangle` allow facts with nested list parameters that might be embedded in `task.Artifacts` if it's an extended schema? While currently strings, the architecture should be tested against future extensions.
**Testing Strategy:**
*   **Test Case 4.13:** Assert complex artifact structures and confirm `ContextPager` formatting strips them back to strings or properly serializes them into valid Mangle syntax.

#### 14. Performance of `PruneIrrelevant`
**The Gap:** `PruneIrrelevant` fetches `allFacts` from the kernel and iterates them to find predicates.
**The Risk:** `kernel.QueryAll()` is an extremely expensive operation in Mangle when the database has grown.
**Testing Strategy:**
*   **Test Case 4.14:** Test `PruneIrrelevant` with a mock kernel containing 500,000 random facts, verifying the loop completes rapidly and the memory usage doesn't spike. This highlights the need to query specific schemas rather than `QueryAll`.


#### 15. The 'Forgotten Sender' Leak
**The Gap:** When querying `phase_context_scope` or fetching `context_profile`, the underlying kernel implementation (if it streams results across a channel like Mangle often does) might be prematurely terminated if an error occurs mid-scan, or if a `break` is executed.
**The Risk:** If the Mangle evaluation engine is sending facts over a channel and `ContextPager` returns early due to an error, the engine goroutine will block forever waiting to send the next fact, leaking memory.
**Testing Strategy:**
*   **Test Case 4.15:** Implement a mock kernel that simulates channel-based fact streaming. Inject a panic or a forced early return inside the `scopedDocsForPhase` processing loop. Verify via `runtime.NumGoroutine()` that no goroutines leak after the function exits. This necessitates enforcing `context.WithCancel` patterns.

#### 16. OOM on Massive `phase.Tasks`
**The Gap:** In `CompressPhase`, an array of strings is built (`accomplishments`).
**The Risk:** A rogue generation loop might produce thousands of tasks.
**Testing Strategy:**
*   **Test Case 4.16:** Create 1,000,000 dummy tasks and run `CompressPhase`. Evaluate if string joining mechanisms use excessive memory compared to `strings.Builder`.

#### 17. Null Context Object
**The Gap:** `ActivatePhase` and `CompressPhase` take a `context.Context`.
**The Risk:** If a caller passes `nil` instead of `context.TODO()` or `context.Background()`, the `cp.llmClient.Complete` call will likely panic.
**Testing Strategy:**
*   **Test Case 4.17:** Call these functions with a `nil` context and verify they handle it safely.

#### 18. Mismatched Artifact and Topology Assertions
**The Gap:** Artifact paths are formatted with `%q`.
**The Risk:** If the path itself contains special quotation marks or escaping, `%q` might generate Mangle string syntax that the engine refuses to parse (e.g., generating `""path""` instead of `"path"`).
**Testing Strategy:**
*   **Test Case 4.18:** Pass an artifact path named `"my_wierd_\"file\".go"` and verify the Mangle engine accepts the output from `fmt.Sprintf("file_topology(%q, _, _, _, _)", artifact.Path)`.

#### 19. Repeated Prefetching Idempotency
**The Gap:** `PrefetchNextTasks` asserts activation hints for artifacts.
**The Risk:** If called repeatedly for the same list of upcoming tasks, it boosts the activation continuously.
**Testing Strategy:**
*   **Test Case 4.19:** Call `PrefetchNextTasks` multiple times with the same task list and verify that the target facts do not have out-of-control activation scores.

#### 20. Token Usage Arithmetic Overflow
**The Gap:** `estimatePhaseTokens` uses simple integer addition.
**The Risk:** For highly dense tasks, this could overflow a 32-bit int.
**Testing Strategy:**
*   **Test Case 4.20:** Construct tasks with sufficiently large values to verify overflow bounds.

#### 21. `PruneIrrelevant` Panic on Nil Kernel
**The Gap:** If `cp.kernel` is somehow uninitialized or explicitly passed as nil in a rogue unit test, `PruneIrrelevant` will panic on `cp.kernel.QueryAll()`.
**The Risk:** Panics in cleanup/pruning routines often bring down the entire subagent process if not recovered.
**Testing Strategy:**
*   **Test Case 4.21:** Test with a nil kernel and expect graceful degradation (no-op or error).

#### 22. Phase Name Truncation
**The Gap:** `normalizeLayerName` strips spaces and replaces hyphens, but does not enforce a maximum length.
**The Risk:** Very long phase names (e.g., thousands of characters) could blow up log outputs or database indexes when stored as a `phase_context_scope` fact.
**Testing Strategy:**
*   **Test Case 4.22:** Pass a 1MB string to `normalizeLayerName` and ensure it operates efficiently and should ideally be truncated.

#### 23. Invalid Profile Formats
**The Gap:** `getContextProfile` expects facts with a specific arity (4 arguments).
**The Risk:** If the Mangle engine returns a fact with fewer than 4 arguments, `types.ExtractString(fact.Args[3])` will index out of bounds and panic.
**Testing Strategy:**
