# Session Executor Boundary Value & Negative Testing Analysis

## Subsystem Overview
The `Executor` (`internal/session/executor.go`) acts as the "Clean Loop" boundary connecting user intent via the Kernel's derived facts to actionable state mutations. It parses, resolves, and evaluates `ToolCall` executions using dynamic registry routing (Modular Go registry vs Ouroboros compiled tools), governed heavily by the Constitutional Gate via Mangle logic queries (`pending_action`, `permitted`).

## Evaluated Vectors

### 1. Null/Undefined/Empty

*   **Nil Arguments in ToolCall:** The `checkSafety` method extracts a target via `extractTarget(call.Args)`. If `call.Args` is entirely `nil`, the executor shouldn't panic, but rather default gracefully or reject the call explicitly. The existing test `TestExecutor_NilArgsInToolCall` verifies it doesn't panic, but lacks strict assertion on the outcome.
*   **Empty Tool Names:** `checkSafety` appends a prefix `/` to the tool name. If `call.Name` is empty, it becomes `/`. This might clash with root-level Mangle schemas or produce confusing audit logs. A gap exists to ensure empty action names are categorically rejected prior to the safety query.
*   **Nil AgentConfig:** In `buildToolDefinitions` and `executeToolCall`, the `cfg` (*config.AgentConfig) might be nil if the configuration factory fails. The code somewhat guards this (`if cfg == nil`), but a comprehensive test ensuring complete execution rejection when a strict configuration is expected is needed.
*   **Empty ExtractTarget Result:** `extractTarget` returns `"unknown"` if no matching keys (`path`, `url`, etc.) are found. The system should gracefully handle evaluating constitutional safety for purely side-effect-free or computational tools where a target resource physically doesn't exist.

### 2. Type Coercion

*   **Mangle Atom vs String Parsing:** `parseMangleArg` differentiates `"/atom"` and `""string""`. A critical edge case exists where a tool payload legitimately contains a string that coincidentally starts with `/`. For example, passing a Unix filepath `"/etc/passwd"`. Mangle type coercion may silently truncate or mishandle this if not explicitly quoted or typed, leading to false safety evaluations.
*   **Unserializable Tool Arguments:** In `executeToolCall`, the `Ouroboros` path blindly marshals `call.Args`. If `call.Args` contains recursive maps or function pointers generated dynamically (e.g., via a bug in an upstream intent transducer), `json.Marshal` will error out. A test gap exists to verify this failure mode does not leak into a panic.

### 3. User Request Extremes

*   **Massive Payload Strings:** The constitutional gate asserts a `pending_action` fact where the `payload` is the JSON-marshaled string of `call.Args`. If an LLM generates a 100MB string in `call.Args` (e.g., attempting to write a massive codebase chunk in one go), asserting this into Mangle memory could cause significant GC spikes or OOMs. The length of payloads passed to Mangle must be tested and potentially truncated.
*   **High-Frequency Repeated Executions:** The executor loop processes multiple facts at once. An extreme scenario is 10,000 `next_action` derivations hitting the engine instantly. Can the virtual store handle dispatching 10,000 identical actions efficiently, and does it timeout correctly?

### 4. State Conflicts

*   **Constitutional Gate Defer State:** `checkSafety` asserts `pending_action` and defers its retraction. If `kernel.Query` blocks indefinitely (or for a long timeout), the deferred retraction delays, leaving ghost facts in Mangle. If the goroutine is killed entirely (e.g., parent context cancelled), does the defer execute? A test gap exists for verifying atomicity of these temporary facts under context cancellation.
*   **Concurrent Tool Registration Mutex Contention:** While the executor holds an RLock on `e.ouroborosRegistry`, an autopoiesis loop might be attempting an exclusive Lock to register a newly forged tool. Does executing a slow tool block tool registration globally?
