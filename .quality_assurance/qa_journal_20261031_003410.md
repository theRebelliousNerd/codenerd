# Quality Assurance Journal - 2026-10-31 00:34:10 EST

## Subsystem Review: cmd/nerd/chat (Operation Context)

### Target System Analysis

The `sessionOperationContext` function in `cmd/nerd/chat/operation_context.go` creates long-lived contexts for chat operations (delegations, scans, tool runs). It relies on `m.shutdownCtx` and attaches `usage.Tracker`, `sessionID`, and `sessionlog` properties.

### Missing Boundary Value and Negative Testing Vectors

#### 1. Null/Undefined/Empty Vector
- **Null `m.usageTracker`**: The code currently checks `if m.usageTracker != nil`, but what happens to the downstream systems (like `usage.RecordFromContext` or the API client tracking) when the tracker is explicitly initialized to a zero-value struct or if the context key exists but points to a nil tracker? The tests only verify the happy path where a valid tracker is attached.
- **Empty `m.sessionID`**: What if `m.sessionID` is an empty string (`""`)? `usage.WithSessionID` will likely embed it. Do downstream aggregators group all empty-string sessions together? Is this a data leak or a nil pointer dereference risk when querying stats?
- **Nil `m.shutdownCtx` Fallback**: The code falls back to `context.Background()`. The test `TestSessionOperationContext_CarriesUsageTrackerAndSession` does not verify this fallback behavior. What if the operation relies on a timeout that is absent when falling back to `Background()`?

#### 2. Type Coercion / Data Corruption Vector
- **Invalid `sessionID` Types**: Although `sessionID` is a string in Go, what happens when extremely long strings (e.g., 100MB strings) or strings with non-UTF8 binary data (null bytes) are passed as `m.sessionID`? Does `tracker.Stats().BySession` allocate infinite memory and cause an OOM panic? Can log injection occur through `m.sessionID`?
- **Context Key Collision**: Are the keys used by `usage.NewContext` and `usage.WithSessionID` strongly typed unexported types, or are they strings? If strings, can a user payload coerce a string to overwrite the usage tracker in the context tree?

#### 3. User Request Extremes Vector
- **Massive Concurrency (Goroutine Leak)**: What happens if `sessionOperationContext` is called 1,000,000 times concurrently? Each call creates a child context using `context.WithCancel`. Since the cancel function must be called to free resources in the parent `shutdownCtx`, what happens if the caller forgets to call `defer cancel()`? The test doesn't check for goroutine/memory leaks when cancellations are omitted.
- **Extremely Long Execution Times**: How does the usage tracker behave if an operation context is held open for 45 days? Does the tracker accumulate stats infinitely in memory before writing to disk, leading to an OOM on the 8GB RAM laptop?

#### 4. State Conflicts Vector
- **Race Conditions on Tracker**: The usage tracker is attached to multiple concurrent operation contexts. If multiple goroutines call `usage.RecordFromContext` simultaneously using the same context/tracker, does the tracker use mutexes properly? The test `TestSessionOperationContext_CarriesUsageTrackerAndSession` runs sequentially. We need a `-race` enabled test where 100 goroutines write usage stats to the same session simultaneously.
- **Context Cancellation Race**: What if `cancel()` is called at the exact moment a deeply nested operation attempts to read or write usage stats? Does it panic? Does the usage drop entirely?

### Performance Implications

The system appears performant enough for simple context creation. However, the use of `context.WithCancel` attached to a long-lived parent (`shutdownCtx`) means that every child context adds a node to the parent's internal children map. Under heavy load (e.g., 50M line monorepo scanning requiring 10,000 parallel operations), this map will grow. If `cancel()` is not rigorously called, the parent context will leak memory for every created operation until the entire app shuts down. The usage tracker's concurrent write capability is the biggest performance unknown. If it uses a coarse-grained sync.Mutex, heavy concurrent usage reporting will severely bottleneck parallel processing.
