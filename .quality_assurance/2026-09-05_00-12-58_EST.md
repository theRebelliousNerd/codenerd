# Boundary Value Analysis & Negative Testing Journal: Mangle
Type System

**Date:** 2026-09-05 00:12:58 EDT
**Target Subsystem:** Mangle Kernel
(internal/mangle/torture_test.go)

## Overview and Context

As requested, this analysis targets the `internal/mangle`
package, specifically focusing on the `torture_test.go`
suite which exercises the core logic engine of codeNERD. The
Mangle kernel is the most critical subsystem in the
architecture, evaluating declarative logic programs that
govern routing, safety, execution, and state across the
agent framework.

I've selected the Mangle Type System boundary tests
(`TestTorture_TypeSystem_*`) as the area of focus. While the
suite is comprehensive for standard boundary conditions
(NaN, Infinity, MaxInt, boolean coercion), it exhibits
several gaps when exposed to the specific failure modes
characteristic of neuro-symbolic AI integrations. The AI
agent frequently generates semi-structured, untyped, or
hallucinated facts that bridge Go's imperative typing with
Mangle's declarative Atoms/Strings.

This journal outlines negative testing scenarios and edge
cases that should be formalized into the torture test suite
to ensure the engine remains robust against chaotic inputs
generated by the perception and articulation layers.

## Identified Edge Cases & Test Gaps

### 1. Null/Undefined/Empty Vectors
The boundaries of "nothingness" are often handled
inconsistently when crossing the Go-to-Mangle barrier.

- **Explicit Nil Interfaces:** When `nil` is passed as an `any` argument to `engine.AddFact()`, does it panic during reflection, convert to a Mangle string `"nil"`, or properly evaluate as an unbound variable (or reject as an invalid literal)? The engine must strictly reject nil values in ground facts rather than allowing them to poison the fact store.
- **Empty Slices and Collections:** If a dynamic array of arguments evaluates to empty (e.g., passing `[]any{}` to `AddFact` when the predicate expects arity > 0), the arity mismatch check must reliably fire. However, what if a predicate has arity 0? Does `[]any{}` correctly insert a zero-arity fact, or does the Go variadic spread operator `...` cause unexpected behavior?
- **Nil Schema Strings:** Calling `engine.LoadSchemaString(nil)` (if passing via an interface or unsafe cast) or `engine.LoadSchemaString("")`. The current tests check empty strings during parsing, but dynamic JIT loading from corrupted files might yield null bytes or completely absent buffers.

### 2. Type Coercion Vectors
The "Atom vs String Dissonance" is the most prevalent AI
failure mode in this architecture.

- **The Disjoint Types Dissonance:** Mangle treats `/active` (Atom) and `"active"` (String) as distinct, non-joinable types. If an AI agent attempts to query `user_intent(_, "query", ...)` when the schema expects `/query`, the result is a silent failure (zero tuples). Tests must explicitly verify that `ast.Name("query")` and `ast.String("query")` do NOT join, and that passing `"query"` into a Go `AddFact` wrapper that expects an Atom safely fails or coerces correctly according to strict schema definitions.
- **Struct/Pointer Poisoning:** AI-generated tools may attempt to dump raw Go structs or pointers into the fact store (e.g., `AddFact("context", &http.Request{})`). The engine must strictly reject non-primitive Go types before they reach the Mangle abstract syntax tree, rather than attempting to serialize them or causing a panic during evaluation.
- **Numeric Precision Loss:** While `int64` and `int` coercion are tested, what happens when large floating-point numbers or scientific notation strings (e.g., `"1e99"`) are parsed dynamically? Does it silently truncate, drop to zero, or maintain fidelity?

### 3. User Request Extremes & System Stress
The engine must handle extreme, nonsensical, or massive
inputs without degrading the shared session state.

- **Extreme String Lengths:** An agent might attempt to store an entire 50,000-line source file as a single string argument in a fact (e.g., `file_content("main.go", "<50k lines>")`). Can the SQLite-backed fact store or the in-memory evaluator handle multi-megabyte atoms? We need tests verifying the engine either gracefully truncates, rejects, or successfully processes massive literal arguments without OOMing the JIT Clean Loop.
- **Hallucinated Predicate Floods:** If a runaway prompt loop generates 10,000 novel, undeclared predicates and attempts to assert them, the schema validator must reject them in bounded time (O(1) or O(log N) per fact). The system must not lock up while iterating over a massive undeclared dictionary.
- **Recursive Type Aliasing:** If a user invents a complex, deeply nested logic program that attempts to alias types infinitely (e.g., a rule that generates strings which are parsed as atoms which generate strings), the stratification and safety checks must terminate analysis in bounded time.

### 4. State Conflicts & Concurrency Vectors
The JIT Clean Loop relies on ephemeral fact isolation, but
races can occur.

- **Retract/Query Races:** If a subagent retracts a fact (e.g., `/current_intent`) at the exact millisecond the router queries it, does the engine guarantee snapshot isolation, or will the query yield a torn read or partial tuple?
- **Ghost Facts in Reused Stores:** The AI failure mode guide explicitly warns against reusing fact stores. We must write a negative test that intentionally attempts to evaluate a program twice on a dirty store and asserts that the evaluation fails or produces contaminated results, explicitly documenting *why* the clean-slate pattern is required.

## Performance & Feasibility Analysis

Can the codeNERD Mangle engine handle these edge cases?

Yes, but it requires strict discipline at the boundary. The
Mangle evaluator itself (ported from Google) is robust
against logic loops via its Datalog fixpoint semantics and
stratification checks. Infinite recursion is statically
rejected during `analysis.Analyze()`.

The primary performance risk lies in the Go-to-Mangle
boundary (the `AddFact` and proxy layers). If we allow
massive strings or complex structs to hit the Mangle AST,
the memory overhead of the AST nodes will skyrocket. The
engine is performant enough to handle millions of facts, but
it expects them to be small, primitive Datalog types (Int,
String, Name/Atom).

By enforcing strict type rejection at the `engine.AddFact`
boundary (rejecting nils, structs, and pointers), we protect
the core evaluator from memory bloat. The SQLite vector
store is more than capable of handling large texts if
explicitly routed there, but the Mangle in-memory store
should remain lean. The proposed negative tests will ensure
these defenses are active and functioning correctly.


## Extended Architectural Implications of Neuro-Symbolic Integration

When building an agent framework like codeNERD, the Mangle
engine is not just evaluating facts; it's arbitrating truth
for an intrinsically stochastic intelligence. This puts
unique pressures on the type system and the boundary logic
that standard Datalog implementations (like those used for
pure static analysis or access control) do not face.

### The Problem of Contextual Truth
A standard Datalog engine assumes that if a fact is
asserted, it is true. However, when an AI model extracts a
fact from a prompt, its truth value is contextual. For
instance, the AI might hallucinate a tool call, and the
resulting fact `delegation_candidate("research_subagent")`
is asserted. If the perception layer later realizes this was
a hallucination and attempts to retract it, the engine must
handle the retraction cleanly. But what if a derivation rule
has already fired?

Negative tests must simulate this "flickering truth"
problem. The engine's differential evaluation mode (deltas
and overlays) must be tested against high-frequency
assert/retract cycles to ensure that derived facts correctly
disappear when their base facts are retracted. If they
don't, the JIT Clean Loop becomes contaminated, and the
agent acts on obsolete information.

### Memory Layout and Deduplication Bottlenecks
Mangle relies on structural sharing and deduplication for
its `ast.Term` types. If the AI agent is reading a
50-million-line brownfield monorepo (as per the User Request
Extremes requirement), it will generate an enormous volume
of distinct strings.

The current `torture_test.go` suite does not adequately
stress the string interner. If an agent loops over a
codebase and asserts `file_path("src/module_a/file1.go")`,
`file_path("src/module_a/file2.go")`, the interner must
efficiently deduplicate the common prefixes or at least not
choke on the volume. A specific boundary test should inject
10 million uniquely generated but similarly structured
strings and measure the pause time during GC sweeps. Go's
garbage collector can struggle with millions of small, long-
lived string pointers, and this is a critical performance
boundary for the system.

### Option Injection via Fact Assertions
A subtle but critical negative testing vector involves
Option Injection at the logical layer. While we typically
think of Option Injection in the context of `os/exec` (e.g.,
passing `--rm` to a command), it can happen in logic engines
too.

Consider a rule: `execute_command(Cmd) :- action(Cmd,
args)`. If the AI generates an action fact where the `Cmd`
string contains logical injection sequences (e.g., embedded
Mangle syntax or SQLite control characters), the engine must
treat the string strictly as a literal value.

Negative tests must be written to explicitly attempt to
"break out" of the literal bounds. Passing a string like
`"); drop table facts; --` or `) :- true.` into `AddFact`
must be verifiably safe. The current tests handle basic
Unicode, but lack adversarial syntax injection tests.

### State Conflicts in the Ouroboros Loop
The Ouroboros Loop in codeNERD allows the agent to reflect
on its own execution and dynamically adjust its logic. This
introduces a meta-level state conflict risk.

What happens if the agent asserts a new rule that
invalidates an existing rule during the same fixpoint
evaluation? Mangle's stratification analysis requires the
ruleset to be fixed during evaluation. Therefore, any
attempt to dynamically alter the schema or policy rules
*while* a query is running must be blocked by a strict
`RWMutex` or return a concurrent modification error.

The torture tests need a concurrent scenario where Goroutine
A is running a heavy 10-second query, and Goroutine B
attempts to `LoadSchemaString()` with a new conflicting
rule. The boundary test must guarantee that Goroutine A's
evaluation completes using the snapshot of the schema at the
time it started, or fails safely. It must never use a hybrid
schema.

### Precision Loss in Confidence Scoring
If the framework eventually moves toward Probabilistic
Datalog (where facts have confidence scores between 0.0 and
1.0), the numeric type coercion becomes even more critical.

Currently, Mangle handles `int64` and `float64`. However,
floating-point math is notorious for precision loss and non-
associativity. A boundary test must be established for deep
recursive rules that accumulate scores. For instance, if an
agent infers a fact with 0.9 confidence, and a transitive
rule applies a 0.9 multiplier 100 times, the resulting float
will eventually underflow or hit denormalized ranges.

The engine must explicitly handle denormalized floats and
subnormal numbers without causing severe performance
penalties (which can happen on some CPU architectures when
processing subnormal floats). A specific negative test must
inject `math.SmallestNonzeroFloat64` and run math builtins
against it.

### The "Empty Array" Ambiguity
When mapping Go structs or JSON to Datalog, an empty array
`[]` presents a semantic problem. In Datalog, you generally
model relationships. A struct `User { Roles []string }`
might be modeled as `user_role("alice", "admin")`. But what
if Alice has no roles?

If the Go boundary code passes an empty slice to `AddFact`,
the engine currently might throw an arity error or silently
do nothing. This needs explicit negative testing. The test
should verify that passing an empty slice to a variadic
function either returns a strongly typed `ErrEmptyVariadic`
or is cleanly rejected by the schema validator for arity
mismatch. It must not result in a panic or a zero-arity fact
`user_role()` being inserted unless explicitly declared.

### Exhaustion of the Virtual Predicate Registry
CodeNERD allows subagents to register Virtual Predicates
(predicates backed by Go functions instead of stored facts,
such as `file_exists(Path)`).

A boundary value test must target the registry itself. What
happens if an AI script stuck in a loop attempts to register
50,000 unique virtual predicates? Does the registry consume
unbounded memory? Does the lookup time during evaluation
degrade from O(1) to O(N)?

The test must assert that there is a hard limit on virtual
predicate registrations per session, or that the internal
map scales safely without impacting the critical path
performance of core policy evaluations.

### Conclusion on Architectural Resilience
The tests proposed in this journal move beyond simple unit
testing; they are system-level stress tests disguised as
boundary checks. By forcing the Mangle kernel to handle nil
interfaces, structural poisoning, extreme string lengths,
and concurrent adversarial mutations, we guarantee the
bedrock of the codeNERD architecture.

The JIT Clean Loop's promise—that every session starts fresh
and executes predictably—relies entirely on the Mangle
engine being an immovable object against the unstoppable
force of LLM-generated chaos. Implementing these tests
ensures that promise is kept.


## Granular Negative Test Specifications

### Specification 01: Variadic Spread with Nil Slice
- **Context:** Go's `...` operator can accept a `nil` slice.
- **Implementation:** `engine.AddFact("predicate", nilSlice...)`
- **Verification:** Ensure `convertToGoValue` or the variadic receiver detects the nil state, avoids panic, and returns `ErrInvalidArity`.

### Specification 02: Explicit Nil Interface Injection
- **Context:** Passing `nil` explicitly as a positional argument.
- **Implementation:** `engine.AddFact("predicate", "valid_arg", nil)`
- **Verification:** The reflection logic must intercept the `nil` interface, preventing it from reaching the `ast` constructor, returning `ErrUnsupportedGoType`.

### Specification 03: Maximum String Allocation Boundary
- **Context:** Verifying memory bounds for literal parsing.
- **Implementation:** Generate a 128MB string in Go. Attempt to assert it via `AddFact`.
- **Verification:** The system must either successfully allocate it if within limits, or return a predefined size limit error. It must not trigger an OS OOM kill on the process.

### Specification 04: The Hallucinated Predicate Flood
- **Context:** An AI generates thousands of undeclared facts.
- **Implementation:** Loop 100,000 times, generating `AddFact(fmt.Sprintf("hallucinated_%d", i), "value")`.
- **Verification:** The schema validator must reject each in O(1) time. Total execution time for the loop must be under 1 second, proving no O(N) degradation in schema lookups.

### Specification 05: Concurrent Transaction Rollback
- **Context:** Differential overlay stores handling concurrent resets.
- **Implementation:** Goroutine A applies a 10,000 fact delta. Goroutine B calls `Clear()` midway through A's application.
- **Verification:** The final state must be deterministic. Either A's transaction is fully rolled back by the `Clear()`, or A's transaction completes and `Clear()` fails due to context cancellation.

### Specification 06: Deep Transitive Recursion Overflow
- **Context:** Testing the limits of the Datalog fixpoint loop.
- **Implementation:** Define `p(X, Y) :- q(X, Z), p(Z, Y)`. Provide a linked list of 50,000 `q` facts.
- **Verification:** The engine must evaluate the transitive closure without overflowing the Go call stack, utilizing heap-based iteration instead.

### Specification 07: Unbound Variable in Builtin Evaluation
- **Context:** Malformed logic programs bypassing safety checks.
- **Implementation:** `p(X) :- X = Y + 1.` (where Y is unbound).
- **Verification:** `analysis.Analyze()` must statically reject the program because `Y` is not bound by an extensional or intensional predicate before the arithmetic evaluation.

### Specification 08: Floating Point NaN Deduplication
- **Context:** Testing how Mangle handles indistinguishable NaNs.
- **Implementation:** Assert `math.NaN()` twice to the same predicate.
- **Verification:** Retrieve the facts. The engine must specify whether NaNs are deduplicated into a single fact or stored as distinct facts. The behavior must be explicitly documented and tested.

### Specification 09: Malformed Unicode Replacement Character Handling
- **Context:** Dealing with corrupted text from LLM outputs.
- **Implementation:** Pass strings containing invalid UTF-8 sequences.
- **Verification:** Ensure that internal string representations and SQLite proxy serializers do not crash or silently truncate data when encountering invalid runes.

### Specification 10: Infinite Type Alias Cycle
- **Context:** Ensuring the schema parser terminates.
- **Implementation:** Load `Decl type_a(TypeB.Type<Atom>). Decl type_b(TypeA.Type<Atom>).`
- **Verification:** The parser must detect the cycle and return an error immediately, rather than entering an infinite recursion during type resolution.

### Specification 11: Negative Arity Validations
- **Context:** Ensuring the arity parameter is strongly enforced.
- **Implementation:** Load `Decl type_c(TypeA.Type<Atom>).` with arity -1 or max int.
- **Verification:** The parser must detect this boundary value and return an error.

### Specification 12: Zero-Arity Constraints
- **Context:** Ensuring the engine enforces zero arity predicates.
- **Implementation:** Add fact to a zero-arity predicate with a single string arg.
- **Verification:** The engine must error with `ErrInvalidArity` and explicitly avoid nil-pointer deference or out-of-bounds panics when matching arguments against a zero-length schema definition slice.

### Specification 13: Time Serialization Bound Errors
- **Context:** The handling of max/min values for timestamps.
- **Implementation:** Load facts with `time.Time` values set to the maximum possible time value.
- **Verification:** Validate that the values are correctly preserved in the engine and across persistence mechanisms.

### Specification 14: Duration Precision Constraints
- **Context:** Processing nanosecond precision.
- **Implementation:** Load facts with `time.Duration` set to `time.Nanosecond`.
- **Verification:** Verify that numeric coercions do not inadvertently truncate duration values.

### Specification 15: Cross-Process Shared Store Locking
- **Context:** Handling shared locks on shared persistence layers.
- **Implementation:** Attempt to lock a shared database from two concurrent Mangle engine instances.
- **Verification:** Ensure graceful failure and appropriate `ErrDatabaseLocked` returns.

### Specification 16: File Stream Descriptors Handling
- **Context:** Handling injected IO stream interfaces.
- **Implementation:** Try injecting `os.File` directly into `AddFact`.
- **Verification:** It must return `ErrUnsupportedGoType` safely without panicking.

### Specification 17: Multi-Layer Overlay Evaluation
- **Context:** Checking performance across multiple overlay layers.
- **Implementation:** Layer 10 chained fact stores. Evaluate across all 10 layers.
- **Verification:** The response time should scale predictably without polynomial regressions.

### Specification 18: Builtin Predicate Re-Declaration
- **Context:** Ensuring built-ins are immutable.
- **Implementation:** Try to `Decl` an internal builtin like `sum`.
- **Verification:** Return `ErrBuiltinRedeclaration`.

### Specification 19: Cyclic Type Inference Dependency
- **Context:** Catching unbound type resolution cycles.
- **Implementation:** Attempt to evaluate terms where their type dependencies form a cyclic reference.
- **Verification:** The analysis stage must reject with a specific error related to type inference cycle.

### Specification 20: Aggregation of Unbound Terms
- **Context:** Mangle aggregates require bound grouping terms.
- **Implementation:** Execute a rule aggregating on an anonymous term.
- **Verification:** Reject statically.

### Specification 21: Excessive Output Predicate Cardinality
- **Context:** Preventing a rule from generating too many facts.
- **Implementation:** Construct a cartesian join yielding 1M facts.
- **Verification:** Catch memory spikes and evaluate maximum allowable threshold configurations.

### Specification 22: Null Byte Prefix Poisoning
- **Context:** Validating internal identifier logic against null byte prefixes.
- **Implementation:** Assert an atom name starting with a null byte.
- **Verification:** Ensure parser stability.

### Specification 23: Mixed Arity Overloads
- **Context:** Mangle doesn't traditionally support arity overloading.
- **Implementation:** Declare two predicates with the same name but different arities.
- **Verification:** Must error cleanly during parsing.

### Specification 24: Unbound Argument in Virtual Predicate
- **Context:** Passing unbound variables to Go backed functions.
- **Implementation:** Execute a virtual predicate with an unbound variable parameter.
- **Verification:** Must return `ErrUnboundVariable` rather than passing a nil interface to the Go function.

### Specification 25: Escaping Control Characters
- **Context:** Robustness of string literal representation.
- **Implementation:** Load facts with string literals containing unescaped newline and tab characters.
- **Verification:** Ensure correct serialization and parser integrity upon retrieval.

### Conclusion on Test Vector Adequacy

The integration of these 25 detailed specifications into the `internal/mangle/torture_test.go` suite will comprehensively cover the operational bounds identified during this QA session.

The "Atom vs String Dissonance" alongside unconstrained AI hallucinations are the greatest sources of instability in neuro-symbolic systems. By aggressively applying this Boundary Value Analysis against the Datalog translation layer, codeNERD can ensure deterministic execution even when prompted maliciously.

### Specification 26: Subagent Execution Context Isolation
- **Context:** Ensuring subagent boundaries don't leak logic contexts.
- **Implementation:** Spawn two distinct subagents asserting contradictory facts concurrently.
- **Verification:** Ensure their fact stores maintain completely disjoint states throughout evaluation.

### Specification 27: Recursive Data Structure Injection
- **Context:** Preventing recursive Go maps or slices from crashing reflection.
- **Implementation:** Pass a self-referential map to the AddFact function.
- **Verification:** The convertToGoValue function must detect the recursion or halt depth traversal with ErrUnsupportedGoType.

### Specification 28: Exhaustion of Deduplication Maps
- **Context:** Checking scaling of internal hash maps.
- **Implementation:** Generate a very large volume (1M+) of unique string atoms.
- **Verification:** Validate memory usage doesn't spike non-linearly due to map resizing collisions.

### Specification 29: Datalog Rule Re-evaluation Loop
- **Context:** Ensuring deterministic fixpoint completion.
- **Implementation:** Force a state that repeatedly bounces near but never hits fixpoint.
- **Verification:** Ensure that MaxEvaluationDepth bounds the evaluation correctly without infinite looping.

### Specification 30: Unsafe Schema Dynamic Loading
- **Context:** Preventing dynamically generated schemas from breaking engine safety.
- **Implementation:** Dynamically execute `LoadSchemaString` with unsafe rules after initialization.
- **Verification:** Must run through full static analysis and return errors gracefully rather than panic.
