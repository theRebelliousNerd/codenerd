## 1. Executive Summary
This document serves as an exhaustive Boundary Value Analysis (BVA) and Negative Testing evaluation for the `semantic_classifier` module located in `internal/perception/semantic_classifier.go`. The semantic classifier is a crucial neuro-symbolic bridge in the codenerd architecture, responsible for translating ambiguous natural language user intents into strict Mangle facts (atoms) for the logic kernel.
The analysis specifically avoids 'Happy Path' scenarios (e.g., standard intent mapping) and focuses entirely on systemic failure modes, edge conditions, and state corruption vulnerabilities.

## 2. Architectural Context
Before diving into the test vectors, it is vital to understand the constraints of the system:
- **EmbeddedCorpusStore:** Read-heavy, initialized from the Mangle kernel on boot, backed by a SQLite cache for performance.
- **LearnedCorpusStore:** Read-write, dynamically updated during runtime as the system learns user preferences, backed by `.nerd/learned_patterns.db`.
- **Embedding Engine Interface:** Pluggable backend (e.g., Gemini, local Ollama) that converts text to `[]float32`. Dimensions are typically 768 or 3072.
- **The Mangle Constraint:** Mangle is strictly typed. Stringly-typed Go data passing the neuro-symbolic boundary without proper wrapping will cause silent evaluation failures (empty derivations).

## 3. Vector Analysis: Null / Undefined / Empty
### 3.1 Analysis
The most common failure mode in Go applications interacting with external APIs (like LLMs or Vector databases) is unhandled nil pointers or zero-length slices returned during transient network failures.

### 3.2 Identified Gaps & Missing Test Scenarios
#### Scenario A: The Null Embedding Engine Output
**Description:** If the configured `EmbeddingEngine` returns `nil, nil` or an empty slice `[]float32{}` without an explicit error (e.g., due to a malformed API response).
**Impact:** The `CosineSimilarity` function inside `embedding/` may panic due to slice index out of bounds, or return a misleading `0.0` score.
**Proposed Test Pseudocode:**
```go
func TestSemanticClassifier_EmptyEmbedding(t *testing.T) {
    mockEngine := &MockEngine{ ReturnEmpty: true }
    sc := NewSemanticClassifier(kernel, config, mockEngine)
    matches, err := sc.Classify(ctx, "valid text")
    assert.NoError(t, err) // Should handle gracefully
    assert.Empty(t, matches) // Should return zero matches, not panic
}
```

#### Scenario B: The Empty Kernel Boot
**Description:** During initialization, `LoadFromKernel` queries the kernel for `intent_definition`. What if the kernel is entirely empty (a valid state for a freshly installed, unconfigured agent)?
**Impact:** The system must initialize the `EmbeddedCorpusStore` with 0 entries, successfully close the initialization sequence, and be ready to accept runtime patterns.
**Proposed Test Pseudocode:**
```go
func TestEmbeddedCorpusStore_EmptyKernel(t *testing.T) {
    emptyKernel := &MockKernel{ AssertedFacts: nil }
    store, _ := NewEmbeddedCorpusStore(768)
    err := store.LoadFromKernel(ctx, emptyKernel, validEngine)
    assert.NoError(t, err)
    assert.Equal(t, 0, len(store.entries))
}
```

#### Scenario C: Empty Input Strings
**Description:** The user submits a purely whitespace prompt or an empty string.
**Impact:** The system currently has `TestSemanticClassifier_EmptyInput`, but it needs to ensure that the API backend is not called with empty payloads, which often results in 400 Bad Request errors from LLM providers.

## 4. Vector Analysis: Type Coercion
### 4.1 Analysis
The neuro-symbolic boundary is where Go's loose interface{} types meet Mangle's strict Datalog types. The `argToString` function is the primary defense here.

### 4.2 Identified Gaps & Missing Test Scenarios
#### Scenario D: Mangle Atom vs Raw String Coercion
**Description:** `argToString` handles `core.MangleAtom` specifically. However, if a caller passes a raw string `"/intent"` instead of `core.MangleAtom("/intent")`, Mangle treats it as a string constant. When the rule checks `intent(/intent)`, it will fail because `"/intent" != /intent`.
**Impact:** Silent failure of intent mapping. The logs will look correct, but the Mangle kernel will derive no next actions.
**Proposed Test Pseudocode:**
```go
func TestSemanticClassifier_AtomCoercion(t *testing.T) {
    // Explicitly test the difference between string and MangleAtom
    res1 := argToString("/verb")
    res2 := argToString(core.MangleAtom("/verb"))
    // res1 should be "/verb" (string)
    // res2 should be "/verb" (atom representation)
    // The test must ensure injectFacts uses the latter.
}
```

#### Scenario E: SQLite Float32 Blob Corruption
**Description:** The `LearnedCorpusStore` serializes `[]float32` into SQLite blobs. What if the byte array retrieved is not a multiple of 4 bytes (due to disk corruption or bad writes)?
**Impact:** `bytesToFloat32` uses `binary.LittleEndian.Uint32`, which will panic if it attempts to read 4 bytes from a 2-byte slice remainder.
**Proposed Test Pseudocode:**
```go
func TestLearnedCorpusStore_CorruptedBlob(t *testing.T) {
    corruptBytes := []byte{0x01, 0x02} // Only 2 bytes, not 4
    // Need to mock the SQLite read layer to inject this byte array
    // and ensure the system logs an error rather than panicking.
}
```

## 5. Vector Analysis: User Request Extremes
### 5.1 Analysis
Users and automated integrations (like LSP clients) can send data that wildly exceeds expected norms.

### 5.2 Identified Gaps & Missing Test Scenarios
#### Scenario F: The Massive Context Dump (Token Exhaustion)
**Description:** The user pastes a 10MB log file into the chat, which is piped directly to `Classify`.
**Impact:** The `EmbeddingEngine` attempts to embed the 10MB string. API limits are exceeded, leading to immediate HTTP 413 or 429 errors. Alternatively, local LLMs will OOM.
**Mitigation Plan:** The classifier must implement a hard truncation limit (e.g., first 4000 characters) before sending to the embedding engine, as semantic intent is usually captured early in the string.
**Proposed Test Pseudocode:**
```go
func TestSemanticClassifier_ExtremeLength(t *testing.T) {
    massiveInput := strings.Repeat("A", 10_000_000)
    matches, err := sc.Classify(ctx, massiveInput)
    // System must truncate and process, or return a specific size limit error.
    // It must NOT hang or allocate 10MB to the embedding engine.
}
```

#### Scenario G: Extreme TopK Parameters
**Description:** A malicious or bugged internal component calls `Search` with `topK = 2147483647`.
**Impact:** If the logic blindly allocates slices based on `topK` (e.g., `make([]SemanticMatch, topK)`), this results in immediate out-of-memory panics.
**Proposed Test Pseudocode:**
```go
func TestSemanticClassifier_ExtremeTopK(t *testing.T) {
    matches, err := sc.ClassifyWithTopK(ctx, "input", math.MaxInt32)
    assert.NoError(t, err)
    assert.LessOrEqual(t, len(matches), len(sc.entries)) // Bounded by actual entries
}
```

#### Scenario H: The "New Language" Hallucination
**Description:** The user asks for help in a completely fabricated programming language or framework.
**Impact:** The embedding engine will return a vector that maps poorly to the existing corpus. The system must correctly apply the `minSimilarity` threshold and return empty, falling back to a default LLM planning mode rather than hallucinating an incorrect specific intent (like mapping it to Python).

## 6. Vector Analysis: State Conflicts and Race Conditions
### 6.1 Analysis
The system relies heavily on `sync.RWMutex`. While safe for single-node execution, the interaction between the in-memory cache and the SQLite database backend creates potential blocking issues.

### 6.2 Identified Gaps & Missing Test Scenarios
#### Scenario I: Concurrent LoadFromKernel and Search
**Description:** `LoadFromKernel` can take several seconds if the corpus is large and the embedding API is rate-limited. If a user submits a query during this boot phase, what happens?
**Impact:** Because `LoadFromKernel` locks the store, `Search` will block entirely. This causes UI lockups.
**Mitigation Plan:** Implement context deadline awareness inside the RWMutex acquisition, or maintain a double-buffered state where the old state is searchable while the new state loads.
**Proposed Test Pseudocode:**
```go
func TestSemanticClassifier_ConcurrentLoadAndSearch(t *testing.T) {
    // Mock an engine that sleeps for 2 seconds
    go sc.LoadFromKernel(ctx, kernel, slowEngine)
    time.Sleep(100 * time.Millisecond)

    searchCtx, cancel := context.WithTimeout(context.Background(), 50*time.Millisecond)
    defer cancel()
    _, err := sc.Classify(searchCtx, "query")
    // Should return context.DeadlineExceeded rather than blocking forever.
}
```

#### Scenario J: SQLite Database Locked (WAL Contention)
**Description:** Multiple autopoiesis agents attempt to `AddLearnedPattern` simultaneously.
**Impact:** If SQLite is not in WAL mode, or if a write transaction is held too long, concurrent writers will receive a `database is locked` error (SQLITE_BUSY).
**Proposed Test Pseudocode:**
```go
func TestLearnedCorpusStore_ConcurrentAdd(t *testing.T) {
    var wg sync.WaitGroup
    for i := 0; i < 100; i++ {
        wg.Add(1)
        go func(i int) {
            defer wg.Done()
            store.Add(entry, validEmbed)
        }(i)
    }
    wg.Wait() // Run with -race and verify no SQLITE_BUSY errors.
}
```

#### Scenario K: Mangle Fact Injection Overwrites
**Description:** The `injectFacts` method uses `m.Kernel.AssertBatch()`. If two concurrent classification requests finish at the exact same millisecond, they both inject facts.
**Impact:** The kernel state for `semantic_match` could become polluted with matches from multiple disparate intents, confusing the Dreamer component evaluating safety.

## 7. Performance Assessment Summary
The `semantic_classifier` is generally highly performant under standard load. The Go runtime handles the CPU-bound `CosineSimilarity` matrix math easily for small corpora (<10,000 entries). However, the system is fundamentally bottlenecked by:
1. Network latency to the `EmbeddingEngine`.
2. SQLite locking on the `LearnedCorpusStore`.
3. String allocation overhead when mapping massive user inputs.

Addressing the gaps identified above—specifically by adding truncation logic, validating SQLite WAL mode, and implementing strict type checking for Mangle atoms—will elevate the resilience of this subsystem to enterprise-grade levels.
