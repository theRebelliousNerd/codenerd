# QA Journal Entry: TokenBudgetManager Boundary Value Analysis
Date: 2026-08-10 00:31:56 EST

## Context and Architectural Review
CodeNERD utilizes the Mangle kernel for deterministic logic processing and the TokenBudgetManager for JIT context prompt generation. CodeNERD's architecture uses a JIT Clean Loop where Domain shards have been removed and replaced by JIT-driven SubAgents.
The TokenBudgetManager allocates tokens across various categories based on priorities (PriorityMandatory, PriorityHigh, etc.).

## Identified Edge Cases

### 1. Null/Undefined/Empty
- What happens if the `atoms` slice passed to `Fit` contains completely nil entries or partially nil entries (e.g., `OrderedAtom` is not nil, but `OrderedAtom.Atom` is nil)? The system has a basic check `if oa == nil || oa.Atom == nil`, but comprehensive boundary tests are missing.
- What if the categories passed for allocations calculation are completely empty?
- What if `ContentConcise` and `ContentMin` (verified in `contentForMode`) are empty strings and `contentForMode` needs to fall back?

### 2. Type Coercion
- The system heavily relies on `float64` for `BasePercent` in `CategoryBudget` and converts to integer allocations.
- What happens if a user submits a campaign with a `BasePercent` set to `NaN` or `Infinity` via a corrupted configuration or Mangle rule? Go's rounding behavior and float-to-int cast could cause unexpected token limits.
- The proportional calculations divide by the total percent. If this total percent is a very small float value nearing zero, it could trigger unexpected large allocations.

### 3. User Request Extremes
- If a brownfield request targets a 50-million line monorepo, the user might set `totalBudget` to the maximum integer value (`math.MaxInt64` or `math.MaxInt`).
- In allocation calculations, the floating point multiplication of the total budget by normalized percentages might lose precision or overflow if the total budget is enormous.
- Extremely large prompt atoms passing through `truncateAtomToBudget` could cause performance bottlenecks when iterating UTF-8 strings.

### 4. State Conflicts (Race Conditions)
- `Fit` and `SetCategoryBudget` properly acquire Mutex locks.
- However, `GenerateReport` does *not* lock the mutex while executing. If `SetCategoryBudget` is called concurrently with `GenerateReport`, it conceptually triggers a data race since `GenerateReport` processes un-mutexed internal state while `SetCategoryBudget` mutates the budgets.
