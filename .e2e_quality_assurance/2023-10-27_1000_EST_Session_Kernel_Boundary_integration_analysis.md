## System Interaction Map

* `session.Executor.Process()` -> `perception.Transducer.Parse()`: The executor delegates natural language input parsing to the transducer, which returns a structured `perception.Intent`.
* `session.Executor` uses `session.Intent` to assert facts into `core.Kernel` via `Kernel.Assert(intent.ToFact())`. This pushes the `user_intent` fact into the kernel's EDB.
* `session.Executor` triggers `Kernel.Query("persona(P)")` to run the logic layer (defined in `intent_routing.mg`) to map the `user_intent` to a specific persona.
* `session.Executor` triggers `Kernel.Query("next_action(A)")` to get the derived action after routing.
* `internal/mangle/intent_routing.mg` provides the declarative rules that the Kernel uses to evaluate the query.
* `session.Executor` passes execution to the `VirtualStore` routing tools via `VirtualStore.ExecuteTool()`.
* `session.Executor` reads facts asserted during `VirtualStore` execution.

## Contract Analysis

* **Contract 1: Fact assertion idempotency.** If the Executor asserts `user_intent` multiple times (e.g., retries), the Kernel should handle it gracefully without crashing or creating duplicate active intents that break routing.
* **Contract 2: Query result formatting.** `Kernel.Query("persona(P)")` is expected to return exactly one primary persona for routing. If it returns 0 or multiple, the Executor must have a fallback or fail safely.
* **Contract 3: Fact cleanup across sessions.** Ephemeral facts asserted by the Executor (like `user_intent`) must not pollute the global Kernel state across independent subagent invocations, especially when concurrent.
* **Contract 4: Syntactic valid Mangle.** The `user_intent` generated by Perception/Executor must be valid Mangle Atoms. If a user inputs raw Mangle syntax, it must be escaped.
* **Contract 5: Context Lifecycle.** The `core.Kernel` queries can be computationally expensive (e.g., recursive logic). If the `session.Executor` context is cancelled, the `Kernel.Query` must immediately halt to prevent goroutine leaks.
* **Contract 6: Thread Safety under Concurrent Access.** With Shards removed, multiple `session.Executor` instances hit the same `Kernel`. `Assert`, `Query`, and `Retract` must be thread-safe.
* **Contract 7: Schema Validation.** The `Kernel` must reject facts that do not conform to the schema defined in `schemas.mg` (e.g., wrong arity, type mismatch).
* **Contract 8: Virtual Store Reflection.** Results generated by the `VirtualStore` tool executions must be serializable back into the `Kernel` as facts without type coercion panics.
* **Contract 9: JIT Configuration Binding.** The selected persona must strictly map to a valid `ConfigAtom` that defines `AllowedTools`. If the persona fails to map, the configuration must gracefully fallback or fail.
* **Contract 10: State Translucency.** The `Executor` relies on `Kernel.Query` to introspect system state. If `Retract` silently fails, the `Executor` makes decisions on stale data.

## Failure Mode Enumeration

1. **Temporal:** Kernel `Query` hangs due to a complex or unstratified rule evaluation. Session hangs indefinitely.
2. **Semantic:** Kernel returns multiple contradictory `persona(P)` facts (e.g., `/coder` and `/tester` simultaneously). Executor might crash, pick randomly, or enter an undefined state.
3. **Semantic:** The asserted `user_intent` contains unescaped Mangle characters, causing `Kernel.Assert` to return a Parse Error. Executor swallows it or halts execution entirely.
4. **Ordering:** A query for `persona` is made *before* `user_intent` is asserted due to a race condition or incorrect async setup.
5. **Partial:** Kernel asserts part of a complex fact structure (e.g., multi-arity relationships) but fails midway, leaving the database in a logically inconsistent state.
6. **Corruption:** Two concurrent subagents assert conflicting `user_intent` facts into the shared global Kernel, causing cross-talk and misrouting.
7. **Resource Leaks:** Subagents fail to retract their `user_intent` after execution, causing the EDB to swell and queries to degrade in performance.
8. **Type Dissonance:** The Transducer outputs a string for the verb, but `intent_routing.mg` expects an atom. Query returns empty, halting execution.
9. **Injection:** User input successfully breaks out of the string literal in `intent.ToFact()`, allowing them to define new predicates in the kernel.
10. **Panic via Null Pointer:** `Kernel.Assert` receives a malformed Fact pointer and panics, crashing the parent `session.Executor` and the whole application process.

## Adversarial Scenario Design

### Semantic Integrity & Contract Violations
1. **Scenario: Mangle Syntax Injection in Intent Target.** Pass a target like `"auth.go). nasty_fact(/hacked). p("` to see if `Kernel.Assert` prevents injection. Expected: Sanitized or rejected safely. Severity: P0.
2. **Scenario: Conflicting Persona Routing.** Inject rules that cause `user_intent` to map to BOTH `/coder` and `/tester`. Expected: Executor resolves deterministically or returns clear error. Severity: P1.
3. **Scenario: Empty Persona Resolution.** Assert an intent that matches no rules in `intent_routing.mg`. Expected: Executor falls back to a default persona (e.g. `/general`). Severity: P2.
4. **Scenario: Malformed Atom Types.** Force assertion of `user_intent` with a String instead of an Atom for the verb. Expected: `Kernel.Query("persona(P)")` fails to join because of string vs atom dissonance. Executor handles empty result. Severity: P1.
5. **Scenario: Invalid Fact Arity.** Assert a `user_intent` fact with 4 arguments instead of 5. Expected: Kernel rejects the fact during schema validation. Severity: P2.
6. **Scenario: Invalid Mangle Name.** Try to assert a fact where the Predicate contains spaces or starts with a number. Expected: `Kernel.Assert` returns a parse error. Severity: P2.
7. **Scenario: Null Target.** Provide a nil or empty string for the target. Expected: Safe fallback to a non-existent target atom like `/none`. Severity: P3.
8. **Scenario: Control Characters.** Input an intent with null bytes or unprintable characters. Expected: Sanitization strips them before assertion. Severity: P1.
9. **Scenario: Massive String Arguments.** Provide a 10MB string as the constraint. Expected: Truncation or safe rejection without memory exhaustion. Severity: P1.
10. **Scenario: Unescaped Quotes.** Input an intent target with `""`. Expected: `ToFact()` properly escapes the quotes. Severity: P0.

### Concurrency & State Corruption
11. **Scenario: Concurrent State Corruption.** Run 50 goroutines asserting different `user_intent` and querying `persona` simultaneously. Expected: Thread safety in Kernel, but logic errors if they share the same Kernel instance without session scope. Severity: P1.
12. **Scenario: Read-Modify-Write Race.** SubAgent A retracts a fact while SubAgent B is actively querying relations derived from that fact. Expected: `sync.RWMutex` prevents panic, returns consistent snapshot. Severity: P1.
13. **Scenario: Duplicate Fact Assertion.** Assert the exact same `user_intent` from concurrent goroutines. Expected: Mangle's set semantics de-duplicate it without corrupting the store. Severity: P2.
14. **Scenario: Concurrent Retraction.** 10 goroutines attempt to retract the exact same fact simultaneously. Expected: No deadlocks, no double-free panics. Severity: P1.
15. **Scenario: High-Contention Routing.** Flood the Kernel with `user_intent` assertions from 1000 subagents to test the RWMutex bottleneck. Expected: Performance degradation but no crashes. Severity: P2.
16. **Scenario: Session Cross-Talk.** SubAgent A queries for `next_action`, but gets an action derived from SubAgent B's intent because facts aren't session-scoped. Expected: Isolation breach. Severity: P0.

### Resource Exhaustion & Stress
17. **Scenario: Massive Fact Volume (Width).** Assert 100,000 unique `user_intent` facts in a loop. Expected: Kernel performance degrades but no OOM or panic. Severity: P2.
18. **Scenario: Deep Rule Recursion (Depth).** Load a recursive rule into the kernel and query it. Expected: Engine halts or hits depth limit without stack overflow. Severity: P1.
19. **Scenario: Query Result Explosion.** Design a query that returns the Cartesian product of 10,000 facts. Expected: Kernel caps the result set or returns an error. Severity: P1.
20. **Scenario: Continuous Assertion Loop.** A broken subagent gets stuck in a retry loop, asserting the same fact repeatedly. Expected: Set deduplication prevents memory growth. Severity: P2.

### Temporal Failures & Timeouts
21. **Scenario: Context Cancellation during Query.** Cancel context during `Kernel.Query`. Expected: Immediate return, no goroutine leak. Severity: P1.
22. **Scenario: Timeout during Assertion.** Set a 1ns timeout on the context before calling `Kernel.Assert`. Expected: Fact assertion is safely aborted, store is not partially mutated. Severity: P2.
23. **Scenario: Timeout during Transduction.** Cancel context during the `Executor.Process` transducer step. Expected: Executor halts immediately and returns the cancellation error to the surface. Severity: P2.
24. **Scenario: Stalled VirtualStore.** A tool execution hangs, stalling the Executor. The Kernel facts become stale. Expected: Context timeout aborts the tool. Severity: P1.
25. **Scenario: Async Context Leak.** An asynchronous task executor is launched but its context is detached. It continues asserting facts into the Kernel indefinitely. Expected: Hard limits on subagent lifespans. Severity: P1.

### Cascading Failures
26. **Scenario: Upstream Transducer Failure.** Transducer returns a garbage/empty Intent. Expected: `Kernel.Assert` fails validation, Executor surfaces the error gracefully without crashing. Severity: P1.
27. **Scenario: Downstream JIT Failure.** `Kernel.Query` succeeds but returns a persona that doesn't exist in the prompt library. Expected: `ConfigFactory` fails cleanly, `Executor` propagates error. Severity: P1.
28. **Scenario: Missing Rule File.** The Kernel initializes but fails to load `intent_routing.mg`. Queries for `persona` return empty. Expected: Executor fails fast with configuration error. Severity: P0.

### Recovery

## Cascading Failure Analysis

* **Subsystem A (Transducer) fails -> Subsystem B (Kernel):** If the Transducer produces an intent with missing parameters (e.g. nil constraints), the `user_intent` fact will have incorrect arity. The `Kernel.Assert` must catch this via schema validation. If it doesn't, subsequent logic queries will fail silently (zero results) due to atom arity mismatch, starving the JIT compiler.
* **Subsystem B (Kernel) fails -> Subsystem C (Executor):** If the Kernel returns 0 personas due to bad `user_intent` types, the ConfigFactory might panic if passed an empty persona string, or the JIT compiler might fail to load the prompt. This starves the SubAgent before the LLM is even called.
* **Subsystem B (Kernel) concurrency bleed:** If concurrent SubAgents share the same kernel without isolation (since Shards were removed), SubAgent A might route based on SubAgent B's `user_intent`, causing the Coder agent to try to execute Researcher tasks. This cascades into the LLM receiving the wrong system prompt for the task.
* **VirtualStore Result Corruption -> Kernel -> Executor:** If a tool executes successfully but returns a malformed string containing Mangle syntax, and the VirtualStore blindly asserts this as `tool_result`, the Kernel might evaluate this injected logic. The Executor then queries the Kernel and executes the injected action. This is the deepest cascading failure path.

## Detailed Context and Mitigations

### 1. Fact Assertion Idempotency
When an intent is extracted, the Executor converts it to a Mangle Fact. Because Mangle operates on a set-based Datalog foundation, inserting the exact same fact multiple times should theoretically be a no-op. However, if the underlying Go implementation uses lists instead of maps for EDB storage without deduplication, the storage will grow unboundedly. Mitigation: Ensure `core.Kernel` implementations deduplicate facts at the assertion layer.

### 2. The Atom/String Type Dissonance
The most common AI failure mode documented in the architecture is confusing Mangle Atoms (`/active`) with Strings (`"active"`). The `session.Executor` must explicitly map Go string values to `ast.Name` (for Atoms) or `ast.String` (for strings). If the Transducer extracts the verb `"fix"` but it is serialized as a string instead of the atom `/fix`, the rule `persona(/coder) :- user_intent(_, _, /fix, _, _)` will fail to match. Mitigation: The `perception.Intent.ToFact()` method must guarantee strict type mapping.

### 3. Concurrency and Cross-Talk
The migration away from isolated `Shard` instances means all `session.Executor` loops share a single `core.Kernel` instance. In a multi-user or concurrent environment, this is highly dangerous. If user A says "fix this" and user B says "test this", both `user_intent` facts are asserted into the global EDB. The logic engine cannot distinguish which intent belongs to which session unless the rules explicitly bind to a `SessionID`. Mitigation: Every ephemeral fact must include a `SessionID` as its first argument, and the JIT compiler must inject rules that filter by this ID.

### 4. Injection Vulnerabilities
The `Target` field of an intent is derived from raw user input. If a user inputs `auth.go). malicious_rule(X) :- file(X`, the serialization layer might naively concatenate this into a Mangle string. Mitigation: `ast.String` must safely escape all input, and `Kernel.Assert` should only accept structured `ast.Fact` objects, never raw Mangle strings.

### 5. Graceful Degradation
If the `ConfigFactory` cannot generate a configuration because the `Kernel` returned an unknown persona, the `Executor` must not panic. It should have a fallback `DefaultConfig` (e.g., a generic assistant) to continue the OODA loop and ask the user for clarification.

### 6. Goroutine Leaks
Mangle evaluation can be computationally expensive. If the user cancels the request (e.g., closes the browser or hits Ctrl+C), the `context.Context` is cancelled. The `Kernel.Query` must respect this context, breaking out of its fixpoint loop immediately. Failure to do so will result in goroutine leaks and eventual Out Of Memory (OOM) crashes.

### 7. Ouroboros Self-Modification
The system includes an `Autopoiesis` layer that can dynamically inject rules into the Kernel. If the `Session Executor` is actively querying the Kernel while the `Ouroboros` loop is asserting new rules, there is a Read-Write race condition. Mitigation: The Kernel must use robust `sync.RWMutex` locking to ensure queries run against a consistent snapshot of the EDB/IDB.

### 8. Null Pointer Dereference in `user_intent` parameters
If the perception transducer fails to parse an empty input completely, the resulting struct could have zero-value primitives. A null pointer issue could emerge if the executor layer does not adequately check `intent.Verb` before trying to cast it into an Atom. If `ast.Name(intent.Verb)` receives an empty string, the Mangle parser validation within the Go binding will panic. Mitigation: The `Session Executor` must preemptively catch empty verbs and fallback safely, bypassing `Kernel.Assert`.

### 9. Context Paging Exhaustion
Campaigns often involve long running background loops (Campaign Orchestrator). The `Executor` must query the Kernel repeatedly to understand context bounds. If `next_action` derivation grows quadratically with the depth of the campaign, the `Kernel.Query` evaluation time could exceed the `Executor` timeouts, resulting in partial campaign failure. This is mitigated by explicitly tagging `ephemeral` facts for pruning and strictly limiting derivation depth on recursive planning rules.

### 10. `ConfigFactory` Silent Omission
If the JIT Compiler asks the `ConfigFactory` to generate a configuration but none of the declared `policies` within the generated `ConfigAtom` exist on disk, the subsystem will quietly omit the policy. While this prevents a direct panic, it fails open, bypassing safety gates (e.g. bypassing `code_safety.mg`). Mitigation: The `Executor` must strictly validate that all policies requested by the persona are successfully loaded into the `Kernel` before initiating the LLM call.

### 11. LLM Tool Overload via Persona Injection
If an adversarial input manipulates the intent routing such that the `persona(P)` resolution returns a highly privileged admin persona (e.g. `/system`), the `Executor` might JIT compile an `AgentConfig` granting unrestricted bash and filesystem access to the LLM. Mitigation: Mangle rules must strictly enforce RBAC using the `user_role` facts which should never be user-mutable, limiting the extent of cross-persona privilege escalation.

### 12. Streaming Goroutine Synchronization
The `perception.Transducer` frequently invokes streaming `LLMClient` calls. The `Session Executor` typically awaits a synchronization signal before finalizing the `perception.Intent`. If the streaming interface abruptly closes due to network failure, the `Executor` must ensure any partial intent is discarded. Otherwise, the partial string might still pass `Kernel.Assert` validation but contain logically flawed assertions that misroute the agent. Mitigation: Ensure that stream completion logic only passes the payload to `Kernel.Assert` upon a definitive HTTP 200/Done termination.

### 13. Mangle Type System Boundaries
The Mangle transpiler within `core.Kernel` heavily relies on Go's `any` interface for arguments. This dynamic typing requires strict bounds checking during pattern matching. If `Session Executor` attempts to assert an intent with an argument type the transpiler doesn't recognize (e.g., passing a `context.Context` struct or a channel by accident instead of a string primitive), the kernel's serialization logic will likely trigger a runtime reflection panic. Mitigation: The boundary must strictly enforce the use of primitive wrappers (`ast.String`, `ast.Number`, `ast.Name`).

### 14. Tenant Data Segregation
In environments where multiple users share the same underlying CodeNERD instance, the `Session Executor` must enforce tenant isolation. If the `core.Kernel` is not explicitly designed with multi-tenant namespaces, user A's query could evaluate against user B's workspace facts. Mitigation: The boundary contract must evolve to require an explicit `TenantID` context on every `Kernel.Query` and `Kernel.Assert` call, forcing the Mangle logic to filter on tenant.

### 15. The Empty Constraint Fallback
The `user_intent` fact expects a `Constraint` argument. In many natural language queries, there is no explicit constraint. If the `Transducer` passes an empty string, the `ToFact()` serializer might convert this into an empty `ast.String`. If rules expect the atom `/none`, routing fails. Mitigation: Explicit fallback logic in `intent.ToFact()` to normalize empty constraints to standard atoms.

### 16. Mangle Stratification Breaches
If `intent_routing.mg` is updated with a rule that introduces a cyclic dependency involving negation, the Mangle engine will fail to evaluate any queries. If the `Kernel.Assert` does not validate stratification upon loading new rules, the entire system's routing will crash. Mitigation: All logic updates must pass `analysis.Analyze(parsed)` before entering the IDB.

### 17. The Control Packet Illusion
The Piggyback Protocol allows the LLM to send JSON control packets. If an adversarial user injects a payload into their prompt that perfectly mimics a Piggyback packet, the `Transducer` might fail to strip it, and the `Executor` might execute it. Mitigation: Cryptographic signatures or strict sequence markers on legitimate LLM control packets.

### 18. JIT Configuration Collision
If two subagents simultaneously trigger JIT compilation for the same persona but under different contexts (e.g., different working directories), and the `ConfigFactory` caches the resulting `AgentConfig` globally, they will collide. Mitigation: JIT compilation artifacts must be scoped to the `SessionID`.

### 19. Retraction Race Conditions
When a subagent completes, it must retract its ephemeral facts. If it crashes mid-execution, those facts linger. Mitigation: The `Executor` must defer a cleanup function that guarantees retraction even on panic.

### 20. The Unknown Atom Fallback
If `Kernel.Query("persona(P)")` returns an atom that the `ConfigFactory` has never seen (e.g., `/hacker`), it must not crash. It needs a safe failure path that emits an error to the user and halts execution. Mitigation: Strict validation of returned atoms against a known registry in the `ConfigFactory`.
