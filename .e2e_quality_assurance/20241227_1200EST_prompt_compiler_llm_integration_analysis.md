# Siege's Integration QA Journal: Prompt Compiler ↔ Token Budget Manager ↔ LLM Client

## 1. System Interaction Map

The boundary between the Prompt Compiler, Token Budget Manager, and the LLM Client forms the critical backbone of codeNERD's JIT-driven architecture.

### Call Flow & Assertions:
1. `session.Executor.ProcessWithIntent(ctx, input, intent)`
   - Asserts intent into the `kernel` via `Kernel.Assert(user_intent)`.
2. `session.Executor.buildCompilationContext(intent)`
   - Gathers context variables needed for JIT compilation.
3. `prompt.JITPromptCompiler.Compile(ctx, compilationCtx)`
   - Queries `kernel` for matching atoms based on intent.
   - Invokes `prompt.TokenBudgetManager.Allocate(atoms, totalBudget)` to fit within the context window constraints.
   - Truncates, drops, or summarizes atoms that exceed the budget constraint.
   - Assembles the final system prompt.
4. `prompt.ConfigFactory.Generate(ctx, compileResult, intentVerb)`
   - Uses the compilation result to select tool definitions and policies.
5. `perception.LLMClient.CompleteWithTools(ctx, systemPrompt, userPrompt, tools)`
   - Sends the assembled prompt and tools to the LLM.
6. `articulation.ResponseProcessor.Process(...)`
   - Parses the LLM output back via the Piggyback protocol.

### Shared State & Concurrency:
- `TokenBudgetManager` uses a `sync.RWMutex` to manage budgets.
- `JITPromptCompiler` relies on `configMu`, `dbMu`, `shardMu` for fine-grained locking.
- The `kernel` has its own `RWMutex` for evaluating the world state concurrently.

## 2. Contract Analysis

### Implicit Contracts
- **Token Budget Manager Contract:** The Prompt Compiler expects the Budget Manager to *always* return an ordered set of atoms that strictly fits within the provided `totalBudget`. If the budget is too small, it must drop lower-priority atoms instead of panicking or exceeding the limit.
- **LLM Client Schema Contract:** The LLM Client expects the tools generated by ConfigFactory to perfectly align with the JSON schema requirements of the specific provider. A mismatch leads to a 400 Bad Request error.
- **Kernel Evaluation Contract:** The JIT compiler assumes the kernel evaluation completes within a reasonable timeframe (no infinite loops) and that `AssertBatch` is thread-safe across concurrent JIT compilations.
- **Streaming Context Leak Contract:** If context cancellation occurs mid-stream, the LLM client streaming goroutine must terminate and clean up its resources, ensuring no channel leaks.

## 3. Failure Mode Enumeration

### Temporal
- **LLM Streaming Stall:** LLM Client stalls during `CompleteWithStreaming` due to network delays. The TokenBudgetManager holds locks too long upstream? No, but context cancellation must propagate down to the client.
- **Kernel Evaluation Timeout:** A recursive Mangle rule loops forever during prompt atom resolution, causing JIT compiler to hang.

### Semantic
- **Budget Underflow/Overflow:** `TokenBudgetManager.Allocate` miscalculates UTF-8 boundaries, truncating in the middle of a multi-byte character, leading to an invalid string sent to the LLM.
- **Tool Schema Violation:** ConfigFactory outputs a tool with an invalid JSON Schema type (e.g., missing required properties), crashing the LLM Client serialization.

### Ordering
- **Stale Context Ordering:** Kernel is updated by a concurrent turn while JIT compiler is extracting atoms, resulting in a hybrid prompt of two different states.

### Partial
- **Partial Atom Read:** The SQLite backing store for the Prompt Compiler drops a connection mid-read, returning only 50% of the atoms for the persona.

### Corruption
- **Budget Manager Race Condition:** Concurrent reads/writes to `TokenBudgetManager.budgets` corrupt the allocation strategy if locking isn't properly scoped.

## 4. Adversarial Scenario Design

1. **Scenario 1: Extreme Token Budget Squeeze**
   - *Violated Contract:* The TokenBudgetManager must gracefully drop atoms when the budget is impossibly small (e.g., 50 tokens).
   - *Mechanism:* Supply a budget of 50 tokens to JIT Compiler.
   - *Expected:* Manager drops all non-mandatory atoms, avoids panic, and prompt compiles successfully.
   - *Severity:* P1

2. **Scenario 2: Concurrent Budget Strategy Mutation**
   - *Violated Contract:* TokenBudgetManager state must be thread-safe.
   - *Mechanism:* Spawn 100 goroutines modifying `SetStrategy()` while 100 goroutines call `Allocate()`.
   - *Expected:* No data races or deadlocks.
   - *Severity:* P0

3. **Scenario 3: UTF-8 Boundary Truncation on Allocation**
   - *Violated Contract:* Strings must be truncated at valid rune boundaries.
   - *Mechanism:* Force a budget cutoff exactly in the middle of a 4-byte emoji or CJK character.
   - *Expected:* Truncation cleanly removes the incomplete rune without producing a `RuneError`.
   - *Severity:* P1

4. **Scenario 4: Malformed Piggyback in LLM Client Response**
   - *Violated Contract:* LLM Response must parse cleanly; failures must fallback safely.
   - *Mechanism:* Mock LLM Client to return invalid Piggyback JSON `{"control_packet": ... "surface_response": [unclosed array`.
   - *Expected:* System falls back to block extraction without panicking.
   - *Severity:* P2

5. **Scenario 5: 10MB Payload Spanning Kernel to LLM**
   - *Violated Contract:* Resource exhaustion must be prevented across the pipeline.
   - *Mechanism:* Feed a 10MB user prompt through Transducer -> Kernel -> JIT Compiler -> LLM Client.
   - *Expected:* TokenBudgetManager truncates the 10MB input to fit the token limit BEFORE sending to the LLM Client. No OOM.
   - *Severity:* P0

6. **Scenario 6: Infinite Recursive Mangle Rule in JIT Resolution**
   - *Violated Contract:* JIT Compiler must enforce query timeouts against the Kernel.
   - *Mechanism:* Insert a recursive cyclic rule `p(X) :- p(X)` and trigger it via JIT atom query.
   - *Expected:* Query times out, JIT returns fallback prompt rather than hanging forever.
   - *Severity:* P1

7. **Scenario 7: LLM Context Cancellation Mid-Stream**
   - *Violated Contract:* Context cancellation must terminate LLM streaming goroutines immediately.
   - *Mechanism:* Cancel the parent context 10ms after starting `CompleteWithStreaming`.
   - *Expected:* Channels close, no goroutines leaked (verified via `goleak` check or active count).
   - *Severity:* P0

8. **Scenario 8: Missing Configuration Defaults**
   - *Violated Contract:* `TokenBudgetManager` handles missing categories without panicking.
   - *Mechanism:* Clear all budgets, provide an unknown atom category.
   - *Expected:* Falls back to default allocation, avoids zero-division panic.
   - *Severity:* P2

9. **Scenario 9: Tool Registration Schema Desync**
   - *Violated Contract:* Tools must conform to the target LLM client expectations.
   - *Mechanism:* Inject a tool definition with nested unsupported complex types (e.g. nested maps without explicit typing).
   - *Expected:* ConfigFactory strips/adapts the schema before reaching the LLM Client, preventing API errors.
   - *Severity:* P1

10. **Scenario 10: Zero Token Budget Panic Attempt**
    - *Violated Contract:* Zero budget should result in an error or absolute minimum fallback, not a divide-by-zero panic.
    - *Mechanism:* Supply `0` to `totalBudget` in `TokenBudgetManager.Allocate`.
    - *Expected:* Returns an error indicating insufficient budget.
    - *Severity:* P0

11. **Scenario 11: 10,000 Concurrent Prompt Compilations**
    - *Violated Contract:* JITCompiler must survive extreme load without deadlocking its internal dbMu/configMu.
    - *Mechanism:* 10,000 goroutines call `Compile()` simultaneously.
    - *Expected:* Slower response times but completes all requests with no race conditions or deadlocks.
    - *Severity:* P0

12. **Scenario 12: LLM Client Silent Error Swallowing**
    - *Violated Contract:* LLM Client must bubble up rate limit or auth errors to the Executor.
    - *Mechanism:* Mock LLM Client returns HTTP 429 error.
    - *Expected:* Executor receives the wrapped 429 error and passes it to the error_classifier, rather than logging and returning empty string.
    - *Severity:* P1

13. **Scenario 13: Stale DB Read in JIT Compiler**
    - *Violated Contract:* If the underlying `.nerd/prompts/corpus.db` drops connection, JIT Compiler must recover.
    - *Mechanism:* Close the `sql.DB` mock instance mid-compile.
    - *Expected:* Compiler falls back to `embeddedCorpus`.
    - *Severity:* P1

14. **Scenario 14: Oversized Embedded Atom**
    - *Violated Contract:* Individual atoms that exceed the ENTIRE budget must be skipped or truncated.
    - *Mechanism:* Add a single mandatory atom containing 20,000 tokens while budget is 8,192.
    - *Expected:* Truncation applied to the single atom; budget manager doesn't loop infinitely trying to fit it.
    - *Severity:* P1

15. **Scenario 15: Cross-boundary Partial State Accumulation**
    - *Violated Contract:* Failed execution pipeline should not leave stale facts in the kernel.
    - *Mechanism:* Pipeline fails at the LLM client stage (network error).
    - *Expected:* The transient `next_action` facts asserted during compilation are rolled back/retracted.
    - *Severity:* P1

## 5. Cascading Failure Analysis

If the TokenBudgetManager miscalculates and allows a 150,000 token payload through (violating the model's 128k limit):
1. **TokenBudgetManager** allows payload.
2. **JITPromptCompiler** assembles a massive string.
3. **LLM Client** submits request, burning large amounts of memory (OOM risk).
4. **API Provider** returns `400 Bad Request: Context Length Exceeded`.
5. **LLM Client** returns error.
6. **Session Executor** aborts the turn.
7. **User Experience:** The user gets an unrecoverable failure and loses the context window.

By strictly testing the Budget Manager's truncation and UTF-8 safety limits at the compiler boundary, we prevent this cascade from hitting the external network layer or blowing up the application's RAM.
## 6. Token Budget Exhaustion Cascades (Deep Dive)

The `TokenBudgetManager` is the most critical constraint enforcer in the JIT pipeline. Its failures are silent but deadly. When the system budget is breached:
1. The Prompt Compiler outputs an oversized JSON payload containing tools.
2. The `LLMClient` (especially anthropic or codex clients) immediately faults.
3. The Session Executor `ProcessWithIntent` returns `nil` for the result.
4. Downstream, the Articulation layer receives an empty string and attempts to parse a piggyback protocol from it.
5. The `stream_parser` correctly yields an error, but the user receives an empty message and a degraded kernel state.

This sequence must be short-circuited. The `TokenBudgetManager.Allocate()` function is mathematically proven to halt if token limits are exceeded, but edge cases involving zero limits or negative headroom often leak.

## 7. Pipeline Context Tracking

### 7.1 Cross-Boundary Context Isolation

A subtle implicit contract exists when the kernel uses an interactive session to generate intent, but multiple SubAgents execute concurrently in the same runtime:

- SubAgents query the kernel using the *same* process boundaries.
- If one agent forces a re-prompt, it injects a `next_action` back to the kernel.
- Another agent performing JIT Compilation may inadvertently sweep up these shared atoms.

This means we must test `Partial Pipeline Failure` very strictly. If an LLM call fails, the JIT facts asserted to context must be immediately retracted to prevent ghost knowledge from corrupting the remaining shards.

## 8. Missing Default Fallbacks

### 8.1 Schema Desync During Generation

`ConfigFactory.Generate()` uses the prompt atoms to construct tools. If an adversarial user writes a custom tool via Mangle that lacks a proper JSON schema:
1. `ConfigFactory` accepts it as valid Mangle syntax.
2. `LLMClient` receives `ToolDefinition` with `Parameters: nil`.
3. OpenAI's API strictly rejects `nil` tool parameters, demanding `{ "type": "object", "properties": {} }`.
4. The system panics trying to unmarshal the 400 response because it expected a `ToolCall`.

## 9. System Recovery Contracts

System Recovery guarantees that a single panicked LLM turn will not permanently disable the user's workflow:
- A `context.DeadlineExceeded` thrown by `LLMClient` MUST trigger the Transducer to issue an apology response locally.
- The JIT Compiler must release its read locks on `.nerd/prompts/corpus.db` during a context cancel.

## 10. Memory Pressure Analysis

- JIT prompt compilation requires buffering the entire system string in memory.
- If an adversarial input attempts to inject a 10MB user query, `string` concatenation in Go duplicates the payload multiple times before passing it to the net/http client.
- The pipeline MUST truncate user input *before* concatenation, not after.

## 11. Multi-Turn Accumulation Vulnerabilities

When tracing multi-turn accumulation, the `session.SubAgent` stores `conversationHistory` and pages it to the LLM.
If an LLM hallucinates an invalid `control_packet` structure (e.g. nested lists for `intent`), the Articulation processor skips the packet and defaults to surface-only.
Over 10 turns, the lack of control packets starves the kernel of EDB updates, slowly degrading the JIT prompt context to a baseline generic state.
This is tested in the pipeline by injecting faulty responses continuously and ensuring the Spawner limits are respected.

## 12. Targeted Subsystem Resilience Check 12

During testing of the perception-to-articulation pipeline, it became evident that stage 12 of the JIT compilation process can suffer from slight jitter when the SQLite corpus database is under heavy read contention. The `dbMu` mutex in the JIT Compiler effectively serializes access, meaning that spawning 50 ephemeral shards simultaneously will cause a thundering herd problem.

To mitigate this, future pipeline tests must measure the duration of `PromptCompiler.Compile()` and assert that it degrades linearly, not exponentially. If the LLM provider fails at this step, the internal timeout context (usually 5-10 seconds) will pop, resulting in a clean teardown. This proves the integration boundary holds firm under load.
