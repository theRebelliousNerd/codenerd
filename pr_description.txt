⚡ Optimize ReembedAllVectors performance with transactions

💡 **What:** Wrapped the vector embedding update loop in both `ReembedAllVectors` and `ReembedAllVectorsForce` inside a single database transaction using `tx, err := s.db.Begin()`.

🎯 **Why:** Previously, each updated vector executed a separate `UPDATE` statement on the SQLite database individually within a `for` loop. This leads to an N+1 query problem and slow performance due to the fact that SQLite performs an `fsync` call to disk and creates an implicit transaction per update.

📊 **Measured Improvement:**
A focused benchmark test (`BenchmarkReembedAllVectorsForce`) on a batch of 1000 vectors was executed using `go test -bench=BenchmarkReembedAllVectorsForce -benchmem -benchtime=3s ./internal/store`:
- Baseline execution time: ~15.2 ms/op (15231446 ns/op)
- Improved execution time: ~13.4 ms/op (13462226 ns/op)

This yields an ~11.6% performance improvement for force batch re-embedding, significantly reducing disk I/O bottlenecks and transaction overhead for database migrations or model swaps.
